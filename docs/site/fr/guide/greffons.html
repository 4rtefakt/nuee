Greffons

Un greffon ajoute à Nuée un type de modèle écrit en R par quelqu’un d’autre : une fonction R et son manifeste (plugin.json), qui deviennent une entrée de menu avec son dialogue, ses résultats, son texte des méthodes et sa citation, et son export vers R. Il se partage en un seul fichier, un .nueeplugin. Deux greffons d’exemple accompagnent la documentation de Nuée : « Occupation des sites (une saison) », le modèle d’occupation de MacKenzie et al. (2002) ajusté par maximum de vraisemblance, et « Test de tendance de Mann–Kendall et pente de Sen ». Téléchargez-les sur le site de la documentation, https://4rtefakt.github.io/nuee/greffons/occupancy.nueeplugin et https://4rtefakt.github.io/nuee/greffons/mann-kendall.nueeplugin, ou trouvez-les dans le dépôt : https://github.com/4rtefakt/nuee/tree/main/exemple/plugins (avec les données du premier, docs/site/donnees/woodpecker_occupancy.csv).

  • En installer un : Fichier › Greffons…, Installer depuis un fichier…, puis le .nueeplugin. Nuée le lit sans rien exécuter et montre sa carte (son nom, sa version, ses auteurs et leur ORCID, sa licence, sa citation, les paquets R qu’il demande, la plus ancienne Nuée avec laquelle il marche) et son code. Un greffon est du code R : il s’exécute avec vos droits, comme du code tapé dans la console R, et peut lire ou changer vos fichiers ; n’installez que les greffons auxquels vous faites confiance. En installer un l’approuve sur cet ordinateur (son empreinte, le SHA-256 de ses fichiers, rejoint le code que vous avez approuvé) : les modèles faits avec lui s’ajustent ensuite sans rien demander. Une autre version du même greffon le remplace.
  • Fichier › Greffons… liste les greffons installés, les vôtres et ceux que votre organisation donne à tous, chacun avec sa carte : Copier le BibTeX de sa citation ; ses paquets, présents ou absents (Installer les paquets manquants les installe depuis le CRAN dans la bibliothèque de l’utilisateur du R qu’utilise Nuée, comme Fichier › Réglages… pour ceux du moteur) ; Montrer (son code) ; Nouveau modèle… ; Retirer (les vôtres seulement). Un greffon dont les fichiers ont changé depuis son installation ne s’exécute pas tant qu’il n’est pas installé de nouveau.
  • En utiliser un : Modèle › Greffons › son nom… (il est aussi dans la liste des types de Nouveau modèle). Son dialogue est fait d’après son manifeste : dans l’onglet Général, ses entrées, les variables du projet qu’il prend (une, dans une liste, ou plusieurs, à cocher, avec une recherche quand le projet en a beaucoup ; seules les quantitatives, qualitatives ou les deux qu’il accepte sont proposées) et ses options (des nombres, des choix, des cases à cocher, des textes), chacune avec son aide ; dans l’onglet Observations, les observations du modèle, comme pour les autres modèles (cochées, une condition). Ajuster : la fonction du greffon reçoit les données du modèle et ce qui a été choisi.
  • Ses résultats sont ceux d’un modèle de code R (voir « Votre propre modèle en code R ») : Résumé (ce que le greffon affiche, et sa carte : le greffon, sa version, ses auteurs, les variables et les options choisies ; Modifier le modèle), Coefficients, Résidus, Graphiques du code, Valeurs et tableaux, tels que le greffon les donne, et Le greffon (sa carte, son empreinte, son code). Modèle › Modifier le modèle rouvre son dialogue. Ce qui a changé, les documents ({{M1.valeurs.psi}}, {{M1.coef.psi.forest}}), Exporter, le rapport et Mettre à jour les données comme pour les autres modèles. Le texte des méthodes nomme le greffon, sa version et ses auteurs, cite ce que le greffon demande de citer (MacKenzie et al., 2002) et les paquets qu’il utilise, avec leur version ; Exporter vers R écrit le code du greffon et l’appel de sa fonction, un script qui s’exécute dans R seul.
  • Partager : un projet qui utilise un greffon le garde en entier (son manifeste et son code) dans son fichier. Ouvert sur un autre ordinateur, ses modèles attendent, non ajustés, sous une barre qui nomme le greffon, sa version et ses auteurs : Montrer (sa carte et son code), puis Installer et exécuter (installé depuis le projet, approuvé, ses modèles ajustés). Quand une autre version du greffon y est installée, la barre le dit, et c’est la version du projet qui refait ses modèles (Exécuter la version 1.0.0), à moins que vous ne choisissiez l’installée (Utiliser la version 1.1.0 : ses modèles sont refaits avec elle, leurs entrées et leurs options gardées, puis ajustés ; Ctrl+Z le défait). Retirer un greffon ne casse pas vos projets : ils gardent leur copie, toujours approuvée sur cet ordinateur.
  • Les organisations : le service informatique peut donner des greffons à tous (un dossier choisi par la politique PluginsFolder : ils sont proposés et s’exécutent sans rien demander) et, avec la politique DisableCustomCode, ne permettre qu’eux : les modèles de code R et les greffons que les utilisateurs installeraient sont alors désactivés. docs/deploiement.md, dans le dépôt de Nuée, dit comment.

Cette page reprend le guide installé avec Nuée (LISEZ-MOI-APPLICATION.txt, aussi dans Aide › Guide d’utilisation).
