Plugins

A plugin adds a model type written in R by someone else to Nuée: an R function and its manifest (plugin.json), which become a menu item with its dialog, its results, its Methods text and citation, and its Export to R. It is shared as one file, a .nueeplugin. Two example plugins come with Nuée’s documentation: “Site occupancy (single season)”, the occupancy model of MacKenzie et al. (2002) fitted by maximum likelihood, and “Mann–Kendall trend test and Sen’s slope”. Download them from the documentation website, https://4rtefakt.github.io/nuee/greffons/occupancy.nueeplugin and https://4rtefakt.github.io/nuee/greffons/mann-kendall.nueeplugin, or find them in the repository: https://github.com/4rtefakt/nuee/tree/main/exemple/plugins (and the data of the first, docs/site/donnees/woodpecker_occupancy.csv).

  • Installing one: File › Plugins…, Install from file…, then the .nueeplugin. Nuée reads it without running anything and shows its card (its name, version, authors and their ORCID, licence, citation, the R packages it needs, the oldest Nuée it works with) and its code. A plugin is R code: it runs with your rights, like code typed in the R console, and can read or change your files; install only the plugins you trust. Installing one approves it on this computer (its fingerprint, the SHA-256 of its files, joins the code you approved): models made with it are then fitted without asking. Another version of the same plugin replaces it.
  • File › Plugins… lists the plugins installed, yours and those your organisation gives everyone, each with its card: Copy the BibTeX of its citation; its packages, present or missing (Install the missing packages installs them from CRAN into the user library of the R Nuée uses, as File › Settings… does for the engine’s own); Show (its code); New model…; Remove (yours only). A plugin whose files changed since it was installed doesn’t run until it is installed again.
  • Using one: Model › Plugins › its name… (it is also in New model’s Type list). Its dialog is made from its manifest: on the General tab its inputs, the project’s variables it takes (one, from a list, or several, to tick, with a search when the project has many; only the quantitative, qualitative or both that it accepts are offered) and its options (numbers, choices, boxes to tick, texts), each with its help; on the Observations tab the model’s observations, as for the other models (ticked, a condition). Fit: the plugin’s function receives the model’s data and what was chosen.
  • Its results are those of an R-code model (see “Your own model in R code”): Summary (what the plugin prints, and its card: the plugin, its version, its authors, the variables and options chosen; Edit the model), Coefficients, Residuals, Plots of the code, Values and tables, as the plugin gives them, and The plugin (its card, its fingerprint, its code). Model › Edit model opens its dialog again. What changed, documents ({{M1.valeurs.psi}}, {{M1.coef.psi.forest}}), Export, the report and Update the data as for the other models. The Methods text names the plugin, its version and its authors, cites what the plugin asks to be cited (MacKenzie et al., 2002) and the packages it uses, with their versions; Export to R writes the plugin’s code and the call of its function, a script that runs in R alone.
  • Sharing: a project that uses a plugin keeps it whole (its manifest and its code) in its file. Opened on another computer, its models wait, not fitted, under a bar that names the plugin, its version and its authors: Show (its card and its code), then Install and run (installed from the project, approved, its models fitted). When another version of the plugin is installed there, the bar says so, and the project’s own version is what redoes its models (Run version 1.0.0), unless you choose the installed one (Use version 1.1.0: its models are made again with it, their inputs and options kept, and fitted; Ctrl+Z undoes it). Removing a plugin doesn’t break your projects: they keep their copy, still approved on this computer.
  • Organisations: IT can give plugins to everyone (a folder set by the PluginsFolder policy: they are offered and run without asking), and, with the DisableCustomCode policy, allow only those: R-code models and the plugins users would install are then turned off. docs/deploiement.md, in Nuée’s repository, says how.
