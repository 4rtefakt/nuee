Getting started

To install Nuée, double-click "Nuee-Setup-<version>.exe" and follow the steps: for you alone (no administrator rights needed) or for every user of the computer. R is included. Nuée appears in Settings › Apps › Installed apps, where it can be uninstalled; projects and settings are kept.

If Windows shows "Windows protected your PC" (unknown publisher), click "More info", then "Run anyway".

For IT departments installing Nuée on many computers (silent installation, Intune, Configuration Manager, Group Policy, turning the update check off): the deployment guide, https://github.com/4rtefakt/nuee/blob/main/docs/deploiement.md

On macOS, R is included too: open Nuee-<version>-arm64.dmg (Apple silicon, macOS 14 or later) or Nuee-<version>-x64.dmg (Intel, macOS 13 or later) and drag Nuée into Applications. The first time, macOS says it couldn't check the application (it isn't signed by Apple): click "Done", then "Open Anyway" in System Settings › Privacy & Security, and confirm. Settings are in ~/Library/Application Support/Nuee.

On Linux, Nuée uses the computer's R.

  • Debian, Ubuntu and their derivatives: sudo apt install ./Nuee-<version>-amd64.deb also installs R and the R packages needed. Nuée appears in the applications menu.
  • Other distributions: Nuee-<version>-x86_64.AppImage (make it executable, then run it) or Nuee-<version>-x64.tar.gz (unpack it, then run ./nuee). Install R first, then in R: install.packages(c("httpuv", "jsonlite", "openxlsx", "haven", "readxl", "foreign", "nlme", "mgcv", "MASS", "rpart", "cluster", "RSQLite", "ranger")).

.usp projects need python3. For another R than the PATH's: File › Settings... (see R used by Nuée), or start Nuée with RSCRIPT=/path/to/Rscript. Settings are in ~/.config/Nuee.

Opening

File › Open (Ctrl+O):

  • a .usp project: the data, models and results stored in the file;
  • a project saved by the application (.nuee; .json for versions before 0.9.1);

  • a table, one row per observation:

    Excel .xlsx, .xlsm, .xls        text .csv, .txt, .tsv (separator, decimal comma and
R .rds, .RData                    encoding detected, Excel's "Unicode text" included)
SPSS .sav, .zsav, .por          SAS .sas7bdat, .xpt
Stata .dta                      dBase .dbf, Weka .arff
jamovi .omv                     spectra: JCAMP-DX .jdx, .dx, .jcm and SPC .spc (see Spectra)
GeoPackage .gpkg (a layer of QGIS: see Maps and spatial data)

    An export of KoboToolbox or ODK Central (.xlsx, .csv, or ODK's .zip) is recognised by its columns and opens through its import (see Field data from KoboToolbox or ODK).

    The first column names the observations if it holds text, or if it is called "ID", "Obs", "Name"... (for an R file, the row names). Other text columns whose values all differ (one code per observation) become secondary identifiers: they serve as labels but don't enter the models. The remaining text columns, R factors and labelled SPSS or Stata variables are qualitative variables (in the order of their categories). For a workbook with several sheets, or an R file with several tables, the application asks which one to open.

    A column of measurements with a few text cells (<0.5, <LOD, nd, n.d., #N/A...) stays a quantitative variable: those cells are read as missing, and the status bar says how many, in which variables (and which are below the detection limit). Excel dates and times stay dates (2024-05-03), as text, like those of a text file (as written: 14/05/2019) or of R: a column of dates is a qualitative variable when dates repeat (sectors counted the same day), a secondary identifier when they all differ, the observation names when it is the first column (move it further to make it a time); variable or identifier, it can be the time (see Dates as time). An Excel number without a date format (43599) stays a number. A text file with a line holding more values than the header is refused, with the line number, rather than shifting the columns. An R file must hold tables; any other object is refused. R files open only with R 4.4 or newer (included on Windows): with an older R, such as that of Ubuntu 22.04 or 24.04 or Debian 12, a .rds or .RData file could run code as soon as it is read (CVE-2024-27322), so Nuée refuses it; save the table as CSV or Excel instead.

File › Paste a table (Ctrl+V): cells copied from Excel, LibreOffice, Google Sheets or jamovi become a project (the first row gives the variable names). The project has no file yet: save it (Ctrl+S).

File › Import from KoboToolbox or ODK...: the phone surveys exported by KoboToolbox or ODK Central (see Field data from KoboToolbox or ODK).

File › Import spectra: files of spectra made into one project (see Spectra).

Dropping files on the window (drag and drop from Explorer) opens them the same way: JCAMP-DX or SPC spectra together make one project, as Import spectra; other files each open as with File › Open. Double-clicking a .nuee project in Windows Explorer opens it in Nuée (in the window already open, if there is one).

The last files opened are in File › Open recent.

To try it, Help › Example projects:

  • Apples: 120 made-up apples (four varieties, organic or conventional growing, a dozen measurements and a tasting score) with four ready models: a PCA, a PLS of the score, a PLS-DA of the varieties and an OPLS-DA of the growing method. The original table, orchards.csv, is next to it (resources\exemple), to try opening a table.
  • Skylark monitoring: the two projects of the monitoring tutorial, a skylark counted on 40 sites over 17 years (TRIM and a negative binomial mixed model, fitted) and its line transects (distance sampling: density and abundance).
  • A weir removed: the young trout of the BACI tutorial, before and after a weir was removed, with the before/after view of Statistical tests and its mixed model.

Their data are made up or simulated (the tutorials' tables can be downloaded from the documentation website). Each opens as a new project, its models fitted and its views open; Save asks where to put it. While a project of the skylarks or the trout is in front, the status bar links to its tutorial.

Saving and getting your work back

File › Save project (Ctrl+S) writes the project (.nuee) with its data, its models and the current session: fitted models, open panels and their layout, plot settings (axes, colours, labels, titles), selections, VIP choices, dendrogram groups. When the project is opened again, the models are refitted and everything comes back in place.

The project is written to a file next to the old one, which then takes its place: a network cut or a full disk during the save leaves the old file intact. If another program keeps the file open (a sync client, an antivirus), Nuée tries again for five seconds, then leaves it as it was and says so: save again, or Save as.... If the file was changed elsewhere since you opened or saved it (a colleague, on a shared folder; another window), Nuée says so and offers to merge their changes with yours (see Working together), Overwrite, Save as... or Cancel; for a project recovered after a crash, Save as..., Overwrite or Cancel. The file also records which versions of Nuée and R wrote it, and the name of who saved it; a project saved by a newer Nuée is pointed out when it opens. Nuée also keeps versions of each saved project by itself, to go back to: see History and versions.

Opening a file that is already open (a recent file, a double-click in Explorer) shows the open project instead of opening a second copy.

Closing the application with unsaved changes offers "Save and close". Every two minutes it also keeps a recovery copy of unsaved projects: if it stops without being closed (crash, power cut), it offers to recover them at the next start. Closing that question without an answer keeps the copies for next time; only "Ignore" deletes them.

File › Settings... › At start-up, "Reopen the projects that were open when Nuée was closed": at the next start, the saved projects (.nuee) open when Nuée closed come back, with their models and views; a file moved or deleted since is named in the status bar. Without it, the start page offers Reopen last session. After an unexpected stop, the recovery copies are offered instead.

Edit › Undo (Ctrl+Z) takes back the last change to a project's data (edited value, new variable, class, scores as variables, deleted definition...), up to 20 steps back. Edit › Redo (Ctrl+Y or Ctrl+Shift+Z) makes again, as it was, what Undo took back: an update of the data with its source and steps, the models fitted again on its data. Both menu items name the change they act on; any new change empties Redo.

Notes: each model's summary has a notes area, saved with the project and included in the report; a pencil marks it in the explorer.

Removing a model (Model › Delete model) asks for confirmation. Its definition stays in the project; for a model made in the application, a checkbox removes it as well (undoable).

If the R engine stops

Long computations run in the background, in a second R: while a model is fitted, permutations run or a simulation goes on, the rest of the window works — other models' views, other projects, the data, the menus. New model's dialog steps aside when the fit takes more than a moment; the model's views open once it is there, and if the fit fails the dialog comes back with its settings and the error. A change to the project being computed (a variable renamed, a model refitted) waits for the end of the computation, then is made.

A computation that takes more than a second and a half shows in the status bar, with Stop (above a dialog too): a bar with the step under way — “Permutation 420 of 999”, “Cross-validation: group 3 of 7” — and the time left, or, for a computation that doesn't count its rounds (a single fit), a bar going across with the time since it began; a view waiting for it shows the same bar. Stop ends it between two of its rounds, and nothing changes: the model isn't added, the data aren't changed, the view says "Computation stopped". The long loops stop this way: permutations (of a PLS, a PERMANOVA, a dispersion test, Mantel's test and its correlogram, indicator species, an RDA's tests, the variables fitted to an ordination's axes, Moran's I), the AIC selection's models, an NMDS's random starts, the power simulations, the cross-validation rounds (PCA, PLS, OPLS, linear models, GAMs, trees, random forests, boosted trees), boosted trees one tree at a time, a tree's stability draws, TRIM's stepwise selection of change points, iPLS's intervals, One model per response, k-means' choice of k, and the steps replayed by Update the data. A computation that doesn't stop between two rounds — a single fit in compiled code (a mixed model, a GAM, a random forest's trees, distance sampling, TRIM's estimation) or an R-code model's code — is stopped all the same a second and a half later: its R is stopped, another takes its place, and the project is as it was. The R console's code runs in the window's R and stops only at its end; Stop then says so, and Help › Restart the R engine remains. During Update the data, its own Stop stops the model being fitted too. The application says when the engine stops and offers to restart it; you can also do it yourself (Help › Restart the R engine) if a computation doesn't finish. Projects reopen with their models and views, from their recovery copy if they had changes, otherwise from the file they save to; changes made since the last recovery copy (two minutes at most) are lost. Closing Nuée when the engine no longer answers keeps the recovery copies, offered at the next start. After a minute of computing, the status bar says so.

Help › What's new: the changes in each version (shown once after an update). The installed copy (Nuee-Setup, the macOS application or the Linux packages) looks for a new version at start-up (a single request to GitHub, nothing else is sent) and mentions it in the status bar; on macOS and Linux, a click opens the version's page. On Windows, one click offers to update: the installer is downloaded and checked (its SHA-256 checksum must be the one GitHub gives), then Nuée closes (offering to save the projects you changed), installs it and starts again. For an installation for all users, Windows asks for permission. Help › Check for updates does the same at any time, even with the start-up check off; Help › Look for a new version at start-up turns the check off.

R used by Nuée

File › Settings...: Nuée computes with its own R (on Windows and macOS, R 4.6.2 with every package it needs), the recommended choice, or with an R already installed on the computer, R 4.3 or newer. The list shows those that R's installers put in the usual places: on Windows, those the registry knows and those in Program Files or in your own Programs folder; on macOS, CRAN's and Homebrew's; on Linux, where Nuée's default is the computer's R found on the PATH, those in /opt/R. Browse... adds any other, by its folder.

Nuée runs the R chosen once to check it: its version, and the packages the engine needs (httpuv, jsonlite, openxlsx, haven, readxl, RSQLite and ranger, and R's recommended mgcv, nlme, MASS, rpart, cluster and foreign). "Install them" installs those missing from CRAN into that R's user library, made if needed, and shows what R says meanwhile; or copy the line shown and run it in that R (R or RStudio). With an R older than 4.4, .rds and .RData files don't open; older than 4.5, data files are fingerprinted with MD5 rather than SHA-256 (see Data steps and updating the data).

"Use this R" restarts the engine with it, and open projects reopen with their models, views and changes ("At the next start" waits). That R's packages and .Renviron apply, not your .Rprofile, so that it can't change the results. If the R chosen doesn't start (removed, broken), Nuée computes with its own R and says so once. An organisation can set everyone's R; Settings then shows it, and doesn't change it. Help › Diagnostic information and Help › About say which R is in use.

The explorer (on the left)

Projects, data, models imported from a .usp file, fitted models and their views.

Double-click: open. Right-click: every action (fit, edit, add or remove a component, export, delete...). Double-clicking an imported model refits it in R; the Summary marks each value: "=" the same as the value stored in the file, "≈" close (less than 0.01), "≠" different. Q2 usually differs: an imported model is validated like the others (see "Cross-validation"); "Full model's centres and weights" gives back the file's.

The explorer follows the work: a project opened, or a model fitted, comes into view at its top, and opening a project folds the other projects' fitted models to a line each (their arrow unfolds them).

Menus and toolbar

File, Edit, Model, Plots, Predict, Window, View, Help. Shortcuts:

Ctrl+O open              Ctrl+S save                Ctrl+E export the results
Ctrl+V paste a table     Ctrl+Z undo                Ctrl+H find and replace
Ctrl+Y (or Ctrl+Shift+Z) redo
Ctrl+K find a command    Ctrl+J R console           Ctrl+C copy the table
Ctrl+N new model         Ctrl+M edit the model      Ctrl+= / Ctrl+- components
Esc    clear the selection       Ctrl+Del exclude the selection and refit
Ctrl+Shift+N new window          Ctrl+Shift+D detach the panel    Ctrl+W close the panel
Ctrl+B explorer          F1 guide
Ctrl+Tab / Ctrl+Shift+Tab next / previous tab      F6 / Shift+F6 next / previous area

View: dark theme, French / English, text size.

The toolbar's views follow the model in front: a PCA, PLS or OPLS has SIMCA's (Summary, Scores, Loadings, DModX, T², Contrib., VIP, Coeff., Obs/pred, HCA, as always); a regression or another analysis has its own (a regression's Coefficients, Effects, Residuals, AIC selection...; TRIM's Indices and Totals; distance sampling's Detection and Density). The Plots menu starts with the active model's views; those it doesn't have are under Plots › Other plots.

Help › User guide (F1): this guide, in a panel at the window's right, beside the work, at the section of what is in front: the model's type, the view (F1 on a TRIM model opens TRIM's section, on Plots › AIC selection its paragraph). Its contents, the sections before and after, and a search through every section (accents and capitals don't matter, the words found are marked); the sections it refers to ("see Cross-validation") and web addresses are links. It stays open while you work, like another panel (Ctrl+W closes it, F1 again goes to what is in front); its buttons open the guide online and as a text file.

Keyboard and screen readers: Alt (or F10) goes to the menu bar, the arrows through its menus, Enter runs a command, Esc goes back; Alt with a menu's underlined letter opens it (Alt+F File...). F6 goes from area to area (toolbar, explorer, each group of panels, status bar), Ctrl+Tab from tab to tab; on a tab, the arrows and Delete. The explorer is a tree (arrows;

Enter opens, Space chooses), a table a grid (arrows; Enter or F2 edits a cell, Space chooses a row, Enter on a header sorts). Shift+F10 or the menu key gives the menu of what has the keyboard (a node, a row, a column, a tab, a plot). A plot is named by what it shows for screen readers, and Ctrl+C copies its numbers as a table. Dialogs keep the keyboard until they close. Both themes meet WCAG AA contrast and follow the system's "reduce motion" setting; Format plot › Colours "colour-blind safe" (Okabe-Ito) is made for colour-vision deficiencies, and the default colours stay apart for them too.

Windows

In the centre, one tab per model ("M1 · PLS"), and a tab for each view of the project (Data, Variable statistics, History). With several projects open, a model's tab, and the status bar, start with its project's name ("skylark_counts · M1 · TRIM"). A model's tab is its page: its summary on the left, its scores and loadings on the right; its other views (VIP, DModX...) join it as tabs. Choosing a model in the explorer shows its page; closing a page's last view closes the page.

In a page as in the centre, views move by their tab (drag and drop), split and stack; dragging a model's tab next to another one compares two models. Right-click on a tab, or the icon at the top right of a group: detach into its own window (on a second screen, for example), maximise, close, close the others, close all the tabs of its project, close all views. Window › Close all views closes every tab of the centre, models' pages and project views (the explorer and the R console stay).

Window › New window opens a second full window. A selection of observations (box or lasso in a plot, click on a point or a list row) shows in every view and every window of the same model. A window's title, which its taskbar button and the Window menu show, names the project in front: the one the menus act on.

Plots: mouse wheel to zoom; right-click to copy or save the image (PNG, SVG), see the selection's contributions or make it a class.

Ctrl+C in a view that shows a table (summary, lists, statistics...) copies the table as tab-separated text, to paste into Excel (a list: all its rows, at full precision); with text selected, Ctrl+C copies the text as usual.

View › Find a command (Ctrl+K): type part of the name of a command or of its menu ("vip", "export r"), or of an analysis, in English or French, or its code ("trim", "glm", "nmds", "random forest"), then Enter: the command runs, or New model opens with that type.

Help › Diagnostic information: the versions of Nuée, the system, R and its packages, to paste into a report of a problem (github.com/4rtefakt/nuee/issues; no paths, no data).

Help › Tutorials and Help › User guide online open the documentation website in the browser, in the interface's language: six tutorials, from the question to the paper, and this guide in pages. Help › About gives the versions, the website (nuee.io), the source code and Report a problem, and how to cite Nuée: the sentence to copy, with Zenodo's DOI, which stands for every version (Model › Text for the Methods section writes it too).
