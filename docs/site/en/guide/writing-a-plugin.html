Writing a plugin

A plugin is a folder holding its manifest, plugin.json, and its R files: occupancy/plugin.json and occupancy/occupancy.R for the first example (https://github.com/4rtefakt/nuee/tree/main/exemple/plugins/occupancy). Start from an example: copy its folder, then change its manifest and its code. The manifest, in UTF-8, is a JSON object of these fields:

id
the plugin’s name for Nuée and its folder’s: lowercase letters, digits, and “-”, “_” or “.” between them (occupancy, mann-kendall); the same for all its versions.
version
X.Y.Z (1.0.0); each version you share gets a greater one.
nuee
the oldest Nuée it works with (1.1.0).
name
{"en": "…", "fr": "…"}: English required, French optional (the English shows in French without it); description likewise, a sentence or two.
authors
[{"name": "…", "orcid": "0000-0002-1825-0097"}], one at least; the ORCID optional (checked: its last digit).
license
its licence (GPL-3.0-or-later, MIT…).
citation
what its users cite: {"text": "…", "bibtex": "@article{…}"}, or a list of them; optional.
packages
the R packages it needs beyond R’s own (["unmarked"]); optional.
files
its R files, read in this order (["occupancy.R"], or ["R/model.R", "R/methods.R"]).
function
the name of its function (occupancy_fit), defined at the top level of one of them.
inputs
the project’s variables its dialog asks for, a list of {"id": "detections", "type": "variables", "accepts": "quantitative", "min": 2, "max": 20, "label": {"en": "…", "fr": "…"}, "help": {…}}: type "variable" (one; "optional": true lets it be left empty) or "variables" (several: min, 1 by default, and max, none by default); accepts "quantitative", "qualitative" or "any".
options
its settings, a list of {"id": "maxit", "type": "number", "default": 1000, "min": 10, "max": 100000, "integer": true, "label": {…}, "help": {…}}: type "number" (default required; min, max and integer optional), "choice" ("values": [{"value": "BFGS", "label": {…}}], default required, one of the values), "checkbox" (default false or true) or "text" (default "").

Nuée checks the manifest strictly as it reads it: a field it doesn’t know, a field of the wrong kind, a file that isn’t there, a function the files don’t define at their top level are refused, saying where and what (“inputs[2].accepts: "quantitative", "qualitative" or "any"”); a plugin with an error doesn’t install. It reads the code without running it.

The function: Nuée calls it f(donnees, entrees, options).

  • donnees: a data.frame of the model’s observations (those of the Observations tab), one column per variable of the project under its name (qualitative variables as factors, their categories in the project’s order), then the observations’ IDs, as text: what an R-code model’s code sees.
  • entrees: the names of the variables chosen, by input id: a text (NULL when an optional input is left empty) for a "variable" input, a vector of texts (character(0) when none) for a "variables" one; donnees[entrees$detections] are their columns.
  • options: the value of each option, by its id: a number (an integer when "integer" is true), a text for a choice or a text, TRUE or FALSE for a box.
  • It returns what an R-code model’s code returns: the fitted model, or list(modele = fit, valeurs = c(psi = 0.54, p = 0.37), tableaux = list(sites = d)). Nuée takes from the model print(summary()), coef(summary()) (or coef() and vcov()), logLik(), nobs(), AIC(), fitted(), residuals() and predict() when they work. For a class of your own, define its methods in your files (summary.myclass, print.summary.myclass, vcov.myclass, logLik.myclass, nobs.myclass…): Nuée registers those of the generics it calls, so that it finds them; give the class a name your plugin owns (nuee_occupancy).
  • Write it for R alone: call another package as package::function (or library() inside the function) and list it in "packages"; don’t use Nuée’s own functions: Export to R runs your code outside Nuée. stop() with a sentence says what is wrong (Nuée shows it with the plugin’s file and line). getOption("nuee.langue") is "fr" or "en", the interface’s language, for messages in both languages; outside Nuée it is NULL.

Testing it in Nuée: File › Plugins…, Install from file…, then the plugin.json of your folder (no need to package it): Nuée checks it, shows it and installs it. After a change, install it again (each change makes another fingerprint, approved again), then fit again (Model › Edit model). An error gives the plugin’s file and line; Export to R gives a script that calls your function on the same data, to work on it in R or RStudio. The examples’ check, moteur/tests/verifier_greffons.R, tests their numbers against references worked out independently (the likelihood by enumerating the sites’ states, a closed form, cor.test, a hand calculation): a model for testing yours.

Packaging: put the folder in a zip archive (plugin.json at its root, or in its one folder: Windows’ Send to › Compressed (zipped) folder does it), then rename the .zip to .nueeplugin. Only plugin.json and the R files it lists go into an installation and into the projects that use it. Give each new version a greater "version": the projects made with an older one keep it, and say a newer one is installed.
