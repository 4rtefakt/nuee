NUÉE — PCA, PLS, community ecology, models and maps, computed in R
==================================================================
(Guide en français : LISEZ-MOI-APPLICATION.txt)

Getting started
---------------
To install Nuée, double-click "Nuee-Setup-<version>.exe" and follow the steps: for you alone
(no administrator rights needed) or for every user of the computer. R is included. Nuée
appears in Settings › Apps › Installed apps, where it can be uninstalled; projects and
settings are kept.
If Windows shows "Windows protected your PC" (unknown publisher), click "More info", then
"Run anyway".
For IT departments installing Nuée on many computers (silent installation, Intune,
Configuration Manager, Group Policy, turning the update check off): the deployment guide,
https://github.com/4rtefakt/nuee/blob/main/docs/deploiement.md

On macOS, R is included too: open Nuee-<version>-arm64.dmg (Apple silicon, macOS 14 or later)
or Nuee-<version>-x64.dmg (Intel, macOS 13 or later) and drag Nuée into Applications. The
first time, macOS says it couldn't check the application (it isn't signed by Apple): click
"Done", then "Open Anyway" in System Settings › Privacy & Security, and confirm. Settings are
in ~/Library/Application Support/Nuee.

On Linux, Nuée uses the computer's R.
- Debian, Ubuntu and their derivatives: sudo apt install ./Nuee-<version>-amd64.deb also
  installs R and the R packages needed. Nuée appears in the applications menu.
- Other distributions: Nuee-<version>-x86_64.AppImage (make it executable, then run it) or
  Nuee-<version>-x64.tar.gz (unpack it, then run ./nuee). Install R first, then in R:
  install.packages(c("httpuv", "jsonlite", "openxlsx", "haven", "readxl", "foreign", "nlme",
  "mgcv", "MASS", "rpart", "cluster", "RSQLite", "ranger")).
.usp projects need python3. For another R than the PATH's: start Nuée with
RSCRIPT=/path/to/Rscript. Settings are in ~/.config/Nuee.

Opening
-------
File › Open (Ctrl+O):
  - a .usp project: the data, models and results stored in the file;
  - a project saved by the application (.nuee; .json for versions before 0.9.1);
  - a table, one row per observation:
      Excel .xlsx, .xlsm, .xls        text .csv, .txt, .tsv (separator, decimal comma and
      R .rds, .RData                    encoding detected, Excel's "Unicode text" included)
      SPSS .sav, .zsav, .por          SAS .sas7bdat, .xpt
      Stata .dta                      dBase .dbf, Weka .arff
      jamovi .omv                     spectra: JCAMP-DX .jdx, .dx, .jcm and SPC .spc (see Spectra)
      GeoPackage .gpkg (a layer of QGIS: see Maps and spatial data)
    An export of KoboToolbox or ODK Central (.xlsx, .csv, or ODK's .zip) is recognised by its
    columns and opens through its import (see Field data from KoboToolbox or ODK).
    The first column names the observations if it holds text, or if it is called "ID", "Obs",
    "Name"... (for an R file, the row names). Other text columns whose values all differ (one
    code per observation) become secondary identifiers: they serve as labels but don't enter
    the models. The remaining text columns, R factors and labelled SPSS or Stata variables are
    qualitative variables (in the order of their categories). For a workbook with several
    sheets, or an R file with several tables, the application asks which one to open.
    A column of measurements with a few text cells (<0.5, <LOD, nd, n.d., #N/A...) stays a
    quantitative variable: those cells are read as missing, and the status bar says how many,
    in which variables (and which are below the detection limit). Excel dates and times stay
    dates (2024-05-03), as text, like those of a text file (as written: 14/05/2019) or of R: a
    column of dates is a qualitative variable when dates repeat (sectors counted the same day),
    a secondary identifier when they all differ, the observation names when it is the first
    column (move it further to make it a time); variable or identifier, it can be the time (see
    Dates as time). An Excel number without a date format (43599) stays a number. A text file
    with a line holding more values than the header is refused, with the line number, rather
    than shifting the columns. An R file must hold tables; any other object is refused. R files
    open only with R 4.4 or newer (included on Windows): with an older R, such as that of
    Ubuntu 22.04 or 24.04 or Debian 12, a .rds or .RData file could run code as soon as it is
    read (CVE-2024-27322), so Nuée refuses it; save the table as CSV or Excel instead.
File › Paste a table (Ctrl+V): cells copied from Excel, LibreOffice, Google Sheets or jamovi
become a project (the first row gives the variable names). The project has no file yet: save
it (Ctrl+S).
File › Import from KoboToolbox or ODK...: the phone surveys exported by KoboToolbox or ODK
Central (see Field data from KoboToolbox or ODK).
File › Import spectra: files of spectra made into one project (see Spectra).
Dropping files on the window (drag and drop from Explorer) opens them the same way: JCAMP-DX or
SPC spectra together make one project, as Import spectra; other files each open as with File ›
Open. Double-clicking a .nuee project in Windows Explorer opens it in Nuée (in the window
already open, if there is one).
The last files opened are in File › Open recent.
To try it: Help › Example project opens 120 made-up apples (four varieties, organic or
conventional growing, a dozen measurements and a tasting score) with four ready models: a
PCA, a PLS of the score, a PLS-DA of the varieties and an OPLS-DA of the growing method. The
original table, orchards.csv, is next to it (resources\exemple), to try opening a table.

Field data from KoboToolbox or ODK
----------------------------------
Forms filled in on phones (KoboCollect, ODK Collect, Enketo) are exported by their server:
KoboToolbox as an Excel workbook (a sheet for the submissions, one per repeat group) or a CSV
file (semicolons), ODK Central as a .zip archive (one CSV per table) or its submissions CSV
alone. File › Open recognises them by their columns (_id, _uuid, _submission_time, _index...;
SubmissionDate, KEY, meta-instanceID...), as does dropping one on the window; File › Import
from KoboToolbox or ODK... asks for the import, and refuses any other file. A dialog says in
sentences what the import will do before doing it, and says it again at each setting changed:
  - the table to analyse: the submissions, or a repeat group (one row per species observed, per
    plant measured), with the columns of its parent tables joined to each row, all ticked by
    default (the site's habitat and coordinates; a repeat within a repeat goes up both levels);
  - the metadata dropped, listed (internal IDs, device, form version, the columns that link the
    tables...); the submission date and time, the submitter, the submission ID, the start, end
    and day of the survey and the validation status can be kept;
  - group prefixes removed from names (group_site/altitude, group_site-altitude, or with the
    separator chosen for a KoboToolbox export, group_site.altitude: altitude); two questions
    with the same name in different groups keep their group (group_site_notes,
    group_end_notes), with the form even when an ODK export leaves out the groups;
  - a single choice (select_one) becomes a qualitative variable, a multiple choice
    (select_multiple) one 0/1 column per choice named question_code (weather_rain): 1 chosen,
    0 not, empty when the question wasn't answered (even where ODK writes 0); the export's own
    0/1 columns are used when it has them, never twice, and with the form a choice they lack
    (ODK writes columns only for the choices picked at least once) gets its column too;
  - a GPS point (geopoint), as text ("lat lon alt acc") or in columns, becomes gps_longitude,
    gps_latitude, gps_altitude and gps_precision; the table's first point (or its parent's,
    joined) becomes the project's coordinates, in WGS 84 (see Maps and spatial data);
  - dates and times lose their fractions of a second and their time zone
    (2024-05-03T08:12:45.123+02:00 becomes 2024-05-03 08:12:45, the phone's clock), so that
    Nuée reads them as dates (see Dates as time).
The XLSForm form (the workbook with the survey and choices sheets, downloaded from KoboToolbox
or ODK Central), if given, tells each question's type, the choices' labels in the language
chosen (label::English (en), label::Français (fr) or label; by default the interface's) and
their order, which becomes the order of the categories; the columns then take the questions'
names, whatever the export's headers (names or labels), and a multiple choice exported as one
column of labels gets its 0/1 columns from them. Without the form, answers stay as the export
writes them (codes, or labels for an export in labels), categories in alphabetical order, and a
multiple choice without its 0/1 columns stays text. "Open as is" opens the chosen table unchanged
(the sheet, or the CSV of the archive). The import is a project like any table opened, to save
(Ctrl+S); the Methods text says the data were collected with KoboToolbox or ODK (and the form's
title).

Saving and getting your work back
---------------------------------
File › Save project (Ctrl+S) writes the project (.nuee) with its data, its models and the current
session: fitted models, open panels and their layout, plot settings (axes, colours, labels,
titles), selections, VIP choices, dendrogram groups. When the project is opened again, the
models are refitted and everything comes back in place.
The project is written to a file next to the old one, which then takes its place: a network
cut or a full disk during the save leaves the old file intact. If another program keeps the
file open (a sync client, an antivirus), Nuée tries again for five seconds, then leaves it as
it was and says so: save again, or Save as.... If the file was changed elsewhere since you
opened or saved it (a colleague, on a shared folder; another window), Nuée says so and offers
Save as..., Overwrite or Cancel, also for a project recovered after a crash. The file also
records which versions of Nuée and R wrote it; a project saved by a newer Nuée is pointed out
when it opens.
Opening a file that is already open (a recent file, a double-click in Explorer) shows the open
project instead of opening a second copy.
Closing the application with unsaved changes offers "Save and close". Every two minutes it
also keeps a recovery copy of unsaved projects: if it stops without being closed (crash,
power cut), it offers to recover them at the next start. Closing that question without an
answer keeps the copies for next time; only "Ignore" deletes them.
Edit › Undo (Ctrl+Z) takes back the last change to a project's data (edited value, new
variable, class, scores as variables, deleted definition...), up to 20 steps back.
Notes: each model's summary has a notes area, saved with the project and included in the
report; a pencil marks it in the explorer.
Removing a model (Model › Delete model) asks for confirmation. Its definition stays in the
project; for a model made in the application, a checkbox removes it as well (undoable).

If the R engine stops
---------------------
The application says so and offers to restart it; you can also do it yourself (Help ›
Restart the R engine) if a computation doesn't finish. Projects reopen with their models and
views, from their recovery copy if they had changes, otherwise from the file they save to;
changes made since the last recovery copy (two minutes at most) are lost. Closing Nuée when
the engine no longer answers keeps the recovery copies, offered at the next start. After a
minute of computing, the status bar says so.
Help › What's new: the changes in each version (shown once after an update). The installed
copy (Nuee-Setup, the macOS application or the Linux packages) looks for a new version at
start-up (a single request to GitHub, nothing else is sent) and mentions it in the status bar;
on macOS and Linux, a click opens the version's page. On Windows, one click offers to update: the
installer is downloaded and checked (its SHA-256 checksum must be the one GitHub gives), then
Nuée closes (offering to save the projects you changed), installs it and starts again. For an
installation for all users, Windows asks for permission. Help › Check for updates does the
same at any time, even with the start-up check off; Help › Look for a new version at
start-up turns the check off.

The explorer (on the left)
--------------------------
Projects, data, models imported from a .usp file, fitted models and their views.
Double-click: open. Right-click: every action (fit, edit, add or remove a component,
export, delete...). Double-clicking an imported model refits it in R; the Summary marks each
value: "=" the same as the value stored in the file, "≈" close (less than 0.01), "≠"
different. Q2 usually differs: an imported model is validated like the others (see
"Cross-validation"); "Full model's centres and weights (like SIMCA)" gives back the file's.

New model (Model › New model)
-----------------------------
General tab: type (PCA, PLS, PLS-DA, OPLS, OPLS-DA, class models, linear regression, linear
mixed model, generalized linear model, additive model: see Linear, generalized and mixed
models; RDA and CA: see Redundancy analysis and correspondence analysis; decision tree, LDA
and k-means: see Decision trees, linear discriminant analysis and k-means), name, number of
components
(automatic by default, by cross-validation), cross-validation groups (in turn, G groups; or
one group per value of an observation ID or of a variable, see Cross-validation), default
scaling.
Variables tab: role (X, Y, class), scaling, block, modifier and transformation of each
variable: square root, fourth root, log10, or custom... (log10, ln or -log10 of C1*x + C2,
exp(C1*x + C2), C1*x + C2, the logit ln((x - C1) / (C2 - x)) between two bounds, or the power
(C1*x + C2)^C3; a value outside the domain becomes missing); the filter sets every variable shown at once (a block:
type it in "Block..." above the list, then Enter). Block scaling: the terms of a block have
their weight divided by the square root of their number, so that a block of 20 variables
doesn't weigh 20 times more than a variable alone; a qualitative variable counts by its
categories. Modifier: multiplies the variable's weight after its scaling. The "Proposed
transformations" button applies the suggested log10 to the variables shown (see Variable
statistics).
Cross terms tab: products of two or three X variables (A × B, A × B × C), squares (A × A) and
cubes (A × A × A); a qualitative variable enters through each of its categories, once at most.
Each cross term has its own scaling, block and modifier, as in the Variables tab. In a
regression, a factor can also be a variable without a role (listed under "Not X: no main
effect"): it then enters only through the cross term (see Cross terms with a qualitative
variable).
Observations tab: tick / untick the model's observations, and the test set (see Test set);
"Keep only the observations where..." chooses them by a condition (see Observations chosen by
a condition).
"Edit model" (Ctrl+M) opens this window set like an existing model (imported models
included) and makes a new model.
Before fitting, the application checks the data: variables or observations with more than
50 % missing values, constant variables. If there are any, it lists them and offers "Exclude
them and fit" or "Fit anyway".

Which analysis? (Model › Which analysis?)
-----------------------------------------
Model › Which analysis? (also a button of the start page, next to New model, and Ctrl+K): a few
questions in plain words, then the analysis that answers them, already set up.
  - Your question: compare groups or periods; the effect of variables on one response; many
    species at once (how the composition changes, one model per species, the species that
    characterize each group); a trend over time or a monitoring index; a density or an
    abundance (distance sampling); where (maps, spatial autocorrelation); explore or summarise a
    table; predict or classify; diversity and species richness; before-after with controls
    (BACI).
  - The response: the variable measured, and its kind: a measurement, a count (with many zeros
    or not), a presence-absence (0 or 1), a proportion between 0 and 1, a class (a qualitative
    variable), a table of species (one column per species), or the distances to the animals
    detected (one row per detection).
  - The design: the same sites or plots measured several times (the site), years or dates (the
    time), a BACI design (the unit), spatial coordinates, lines or points (distance sampling).
  - The variables: the explanatory variables (X), or the groups.
Nuée proposes the answers from the project's variables (as Variable statistics reads them): a
response of whole numbers from 0 is a count, of 0 and 1 a presence-absence, between 0 and 1 a
proportion; "many zeros" when at least a quarter of the values are 0, and 15 points more than a
Poisson distribution of the same mean would give (the sentence under the response gives both);
the site is a qualitative variable named like one (site, station, plot, transect...) whose
categories repeat; the time a variable named like a year or a date, or whole numbers between
1900 and 2100; the species the columns of numbers zero or more that have zeros (four at least);
the coordinates the project's, or those its variables' names propose; the distances a variable
named like them, and the other columns of distance sampling by the names New model proposes
them from (Distance's Sample.Label, Effort, Region.Label, Area, size, or transect, longueur,
région, aire, taille); points rather than lines when the transect's column is named like a point
or a station. Every answer can be changed.
On the right: the recommended analysis, why, its main conditions and notes for the answers given
(the random effect by site, the residual autocorrelation of successive years, the adjusted means
after comparing groups, a proportion that reaches 0 or 1...), what will be filled in, what is
left to complete, and a button. It opens New model already filled in (type, distribution, roles,
transformation, curves, random effect, cross-validation groups, and the analysis's own settings,
such as an RDA's Hellinger transformation, TRIM's site and time, or the transect, effort,
stratum, area and group size of distance sampling), or the right view
(Statistical tests in the right mode, Series with its trends, Map, Spatial autocorrelation,
Rarefaction, Variable statistics), or New variable with a diversity index. One model per species
opens New model for the first species, then One model per response with the others ticked. The
alternatives below open the same way. The answers are kept until Nuée closes: cancel New model
and come back to try another.
The main choices:
  - a count: the negative binomial when it varies more than a Poisson distribution allows (a
    variance beyond 1.5 times the mean) or has many zeros (many zeros don't always mean zero
    inflation, Warton 2005: compare with the zero-inflated Poisson by AIC), otherwise Poisson; a
    presence-absence: logistic regression; a proportion: beta regression; a positive, skewed
    measurement: gamma (or its log); a measurement with zeros: Tweedie; otherwise the linear
    model; with the same sites measured several times, a random effect by site and
    cross-validation by site;
  - groups compared: the test between two variables (the one their types call for), paired by
    site when each site comes once in each group (no more observations than sites × groups),
    otherwise the mixed model and its adjusted means; for counts, presences and proportions,
    their GLM;
  - many species: RDA after the Hellinger transformation with quantitative X, PERMANOVA with
    groups, NMDS without X; indicator species; one model per species;
  - a trend: TRIM for counts by site and year (one row per site and year: no more observations
    than sites × years; otherwise a GLM, and TRIM after Edit › Summarize by group); a
    measurement on several sites: the mixed model with the year as X; a single series: Series
    and its trends;
  - predict: PLS or PLS-DA with many X (20 or more, or half as many as the observations), the
    random forest otherwise, boosted trees for counts and presences;
  - a density or an abundance: distance sampling, the distances as Y, lines or points, its
    columns pre-filled from their names; the units (m, km and km² until changed) are left to
    check, and a missing transect or effort to complete; without the strata's areas (or with
    areas of 0), the density only;
  - where: the map, then Moran's I and a GAM's spatial smooth; the Mantel test for species;
  - explore: PCA, NMDS for species; diversity: rarefaction.
Advice, not a rule: the conditions are checked after the fit (Summary › Model conditions).

Plots: colours and labels
-------------------------
Scores, DModX, T², observed / predicted: the "Colour" list colours the points by class
(PLS-DA), by dendrogram group, or by any variable of the project (a gradient for a numeric
variable). The "Labels" list writes next to each point its name, a secondary identifier or the
value of a variable.
Right-click on a plot after a selection: "Make a class from the selection…" puts these
observations in a class of a qualitative variable (new or existing), to colour by or to use as
the classes of a PLS-DA.
Edit › Same selection in all the project's models (ticked by default): observations chosen in
one model are chosen in the project's other models too.
Highlighted variables: a click on a variable (a bar of the VIP, the coefficients or the
loadings, a point of the loadings, the biplot or the S-plot, a line of a profile, a row of the
variable list) highlights it in red on all the model's plots; a box picks several in the
scatter plots of variables. Esc clears the selection and the highlighted variables.

Other plots
-----------
Biplot: scores and loadings in one plot, scaled as correlations (t(corr) and p(corr), or
pc(corr) with the Y of a PLS), all inside the circle of radius 1.
3D scores: three components, turned with the mouse; a click picks a point.
S-plot (OPLS): p[1] against p(corr)[1]; the variables at both ends are those that carry the
link with Y (or that separate the two classes).

Formatting plots (for a paper, a report)
----------------------------------------
Right-click on a plot › Format plot, or Edit › Format plot: this plot's title and axis
titles; for every plot: font, text size, point size, colours (including a palette readable by
colour-blind people, and greys), grid, legend; and "Export image" at the size wanted (in
pixels, resolution ×1 to ×6) as PNG, SVG or JPEG. These settings are kept from one session to
the next.

Contributions
-------------
Plots › Contributions, or right-click on a selection: for an observation (or the mean of
several), each variable's share in its distance from the model's average observation. To
choose: contribution to DModX (why the observation is poorly modelled), to the score of a
component, or to T² (why it is far from the centre); weighted or not by the modelling power.

Predicting
----------
Predict › Predict observations: the project's observations left out of the model, or a prediction set
stored in the .usp file.
Predict › Predict a file: a table (in one of the formats above) whose columns carry the
names of the model's variables (ignoring capitals and spaces at the start and end; categories
by their name). The result gives the scores, DModX, T² and predicted Y; observations outside
the model's domain (DModX > DCrit or T² > T²Crit 95 %) are flagged; it exports to every export
format. X variables missing from the file are listed and treated as missing.
The plot above the table shows the scores, or DModXPS: each predicted observation's distance
to the model, compared with DCrit (the model's observations in grey).

Hierarchical models
-------------------
Model › Scores as variables: a model's scores become variables of the project ($M1.t1(title),
$M1.t2(title)...), which can be the X of a higher-level model. After changing the base model,
do this step again, then refit the models that use them (the application names them). To
predict a file with a hierarchical model, the base models are predicted first, automatically.

Exporting to other software
---------------------------
File › Export data: the project's table (observation names, identifiers, variables). File ›
Export model results (Ctrl+E): the model's tables (observations: scores, T², DModX, fitted
values; variables: loadings, VIP, intervals; components; coefficients; Y variables). Formats:
Excel (one sheet per table), CSV, tab-separated text, R (.rds: a list of tables; .RData), SPSS
(.sav), Stata (.dta), SAS transport (.xpt), jamovi (.omv), dBase (.dbf) and Weka (.arff); for
the last ones, one file per table ("M1.sav", "M1 - variables.sav"...). Qualitative variables
stay qualitative (R factors, SPSS and Stata value labels, jamovi nominal variables). For SPSS,
Stata, SAS and dBase, variable names are made valid (unaccented letters, digits, "_"); the
original name becomes the variable label. The variables' units and descriptions (Edit › Units
and descriptions) go into a "Variables" sheet of an Excel workbook, read back when Nuée opens
it, a "Variables" table of a GeoPackage, the descriptions of a jamovi file and the attributes
of an R table (see Cleaning the data).
SAS: transport format version 5, which SAS reads with libname xport (names of 8 characters,
labels of 40, text of 200 at most). dBase: text in Windows-1252; in LibreOffice, choose the
"Western Europe (Windows-1252)" character set when opening. The files written were opened in
jamovi, PSPP (for SPSS), Weka, LibreOffice and pandas.

Spectra
-------
File › Import spectra: choose one or more files (Ctrl+A in a folder takes them all); they
become one project, one row per spectrum, one column per wavelength (named by its value:
"1450", "3999.69"). Files read:
  JCAMP-DX (.jdx, .dx, .jcm)  every form (plain or compressed numbers: AFFN, PAC, SQZ, DIF,
             DUP), several spectra per file; not peak tables, nor NTUPLES (complex NMR, mass
             spectrometry);
  SPC (.spc)  Galactic (GRAMS, Thermo), new and old format, one or more spectra;
  text (.csv, .txt...)  a column of x values, then one column per spectrum, with or without a
             header row; the lines an instrument writes before the numbers are skipped.
A spectrum is named after its file (and the block's title or its number when a file holds
several). If the spectra don't all have the same x values, they are interpolated (linearly)
onto those of the first one, in the range they all share; the status bar says so. Different
units (nm and cm-1, absorbance and transmittance) are refused.
Information (optional): a table (Excel, CSV...) whose first column gives the name of each
file, with or without its extension, and the other columns information to join to the spectra
(contents, classes, batches); they come before the spectra. The status bar says how many
spectra didn't find their row. A single JCAMP-DX or SPC file also opens with File › Open, and
a file of new spectra on the same grid is predicted with Predict › Predict a file.

New model › General › Spectral preprocessing: each observation is a spectrum (its
quantitative X variables, in the order of the table), corrected before scaling by one to
three steps, in order:
  SNV        each spectrum centred on its mean and divided by its standard deviation;
  MSC        each spectrum fitted to the mean spectrum of the model's observations
             (x = a + b r), then replaced by (x - a) / b; a prediction uses that mean spectrum;
  Detrend    a degree-2 polynomial of the wavelength, fitted to the spectrum, is removed from
             it (Barnes et al., 1989; often after SNV);
  Baseline   the spectrum's lower convex hull (the segments joining its lowest points, from
             one end to the other) is removed from it; the corrected spectrum is zero or
             positive;
  Savitzky–Golay: smoothing, first or second derivative, in a window of n variables (odd)
             with a polynomial of degree d. Each range of neighbouring variables in the table
             is treated on its own: a window never reaches across a range left out.
The wavelength (for Detrend and Baseline) is the number read in the variables' names when
each has one, all different; otherwise their place in the table.
For spectra, one often centres without scaling ("Centring only" scaling). Only MSC depends on
the other observations (the mean spectrum): in cross-validation, each group is corrected with
the mean spectrum of the other observations. Plots › Profiles (spectra): loadings, coefficients, VIP,
or the spectra themselves (before or after preprocessing) as lines; the horizontal axis is the
number read in the variables' names ("1450 nm") when each has one; the lines break where
variables are out of the model. A click on a spectrum selects its observation.
Wavelength ranges: tick "Choose ranges", then drag across the plot (one or more ranges, in
orange); "New model without these ranges" (the water bands, for example) or "New model with
these ranges only" opens New model with the model's settings and those X variables, to check
before fitting. The model's other X variables (qualitative) stay.
Plots › iPLS (spectrum intervals), for a model with Y: the spectrum (the model's quantitative
X variables, in their order) is preprocessed once, whole, as for the model (with MSC, also
for each cross-validation group, with the mean spectrum of the other observations), then cut
into n intervals of the same width; each one is a PLS on its range (with the model's scaling
and its other X variables), with 1 to A components. A bar per interval gives its smallest RMSEcv (in
the units of Y, as in the summary), with that number of components written on it; in green,
the intervals that predict better than the whole spectrum (red dashes); the grey line is the
mean spectrum after preprocessing. Click bars to choose intervals, then "New model with these
intervals" or "without these intervals". Such a model preprocesses its own variables: with
SNV, MSC, detrend or baseline, its RMSEcv can differ from the bar's. Method: Nørgaard et al.
(2000), Applied Spectroscopy 54, 413–419.

Export to R (script, R Markdown, Quarto)
----------------------------------------
File › Export to R: a file that refits the model without Nuée, with R alone, to send to a
colleague or attach to a paper. The calculation is written for that model alone, in plain R
with no package (a regression: lm, or nlme and mgcv, which come with R; an NMDS: MASS, which
comes with R too; TRIM and distance sampling, and boosted trees with rpart: the functions of
Nuée's engine, copied into the script; a random forest, the one exception: the ranger package,
which Nuée installs with itself), commented in the export's language, in four parts:
  1. the functions: the NIPALS algorithm, the cross-validation, and only what this model
     uses (missing values, spectral preprocessing, OPLS...);
  2. the data, in the script or in a CSV file next to it ("M1 - donnees.csv"), numbers
     written without loss and categories in their order;
  3. the model: its X and Y terms (transformations, categories, cross terms), their
     scaling, the fit, then R2 and Q2, T2 and DModX with their limits, VIP, coefficients
     (a PLS's with their 95% jackknife interval), RMSEE and RMSEcv, CV-ANOVA, classification
     for a PLS-DA, test set;
  4. the results: the tables, the permutation test (commented out) and the plots (scores,
     loadings, VIP, observed / fitted, T2 and DModX).
Format: R script (.R); or an R Markdown (.Rmd) or Quarto (.qmd) report, which adds the
Methods text, tables and plots (scores, loadings, VIP, observed / predicted, T2, DModX) and
the references; it compiles in RStudio (Knit button) or with quarto render, and needs the
knitr package. Extra files, as you choose: renv.lock (versions of R and packages, for
renv::restore()), the data and fitted model as .RData (load() gives them back without
refitting), an RStudio project (.Rproj, best in a folder of its own).
Models: this one, or all the models of the session (the latest fit of each) in one .R
script: the functions and the data once, then a block per model under its name (M1,
M2...).
Before writing, the application refits the script's models and checks they give the same
results; otherwise it says so.

Dates as time
-------------
Wherever a time is asked for (Series, BACI, Residual autocorrelation, a mixed model's CAR1
autocorrelation, previous() and following() in New variable), it can be numbers (the year;
2019.5) or dates: 2019-05-14 (ISO, with the time of day if needed: 2019-05-14 10:30) or
14/05/2019, also 14-05-2019 and 14.05.2019, with a four-digit year. The day always comes
first, as in France: 05/04/2019 is 5 April, never 4 May. A date becomes a decimal year: the
year + (the day of the year − 1 + the fraction of the day) / the number of days in the year
(366 in leap years); 1 January 2019 is 2019, 14 May 2019 is 2019.364. Years and dates thus read
alike: a Sen slope or the CAR1 φ is per year. A time is made of numbers or of dates, not both:
a value of the other kind, or a date that doesn't exist (31/02/2019), is refused, naming it. A
number stays a number: an Excel day number (43599) can't be told from a year. previous() and
following() keep their rule, the time exactly one step before: they go with regular times
(years); with dates that time rarely exists, and no nearby date is taken instead. The export to
R reads the dates the same way.

Series
------
Plots › Series (or in the explorer, under the project): a variable over time, like figures of
series by sector, one page per site. Choose the variable, the time (a variable or an ID made of
numbers, like the year, or of dates: see Dates as time), the lines (a qualitative variable or
an ID: the sector) and, optionally, the panels (the site): one small plot per panel, in a grid
with shared axes. Within a line, times that follow each other at its own step (its smallest
gap) are joined, so a sector counted every other year stays one line; a missing time breaks
the line, so a year without a count shows. Dates, rarely evenly spaced, go on a date axis, and
a line joins all its points. Colours go by line within each panel and the legend is grouped by
panel (a click on an entry hides its line): it stays readable with 30 sectors. Optionally: the
mean of each panel's lines, time by time (a thick line), a log scale (values ≤ 0 aren't shown
on it) and events, times typed as "2015; 2019" (with dates, also 2019-05-14 or 14/05/2019),
drawn as dashed lines in every panel. Hovering gives the observation's name, the time and the
value; a click or a box selects observations, also in the project's models when the selection
is shared with them. Observations without a time, a value, a line or a panel are left out and
counted; a line with the same time twice (sectors chosen without their site) is flagged and
shown as points. Right-click: copy or save the image.
Trends (the toolbar's box): under the plot, a table gives for each line of each panel, marked
with its colour, n (its times with a value), its first and last time; Sen's slope (Sen, 1968:
the median of the slopes between all pairs of its times, per time unit, per year with dates)
and its 95 % interval (Gilbert, 1987: the ranked slopes, taken around the median from the
variance of S; no bounds when there are too few times); Kendall's τ (tau-b), the Mann–Kendall
S and its two-sided p by the normal approximation (variance corrected for ties, continuity
correction, as trend::mk.test and Kendall::MannKendall do); and the p corrected over the lines
(Benjamini–Hochberg, or Holm as a choice). A line with fewer than 4 times, the same time twice
or the same value at every time isn't tested, and the table says why; Ctrl+C copies it. The
test takes the times as independent: positive autocorrelation (years that resemble each other)
makes p too small. For a trend that accounts for it: Plots › Residual autocorrelation, then a
mixed model with a CAR1 autocorrelation, the year as an X.
In the table's toolbar, two options change the test. Allow for autocorrelation: Hamed and
Rao's (1998) modified Mann–Kendall test, computed as modifiedmk::mmkh computes it: the line
detrended by its Sen slope (over its actual times), the ranks of what remains, their
autocorrelation at each lag (counted from one time to the next: the time after a missing year
is one lag away), those beyond ±1.96/√n kept (the others count 0), and Var(S) multiplied by
n/n* = 1 + 2/(n(n − 1)(n − 2)) Σ (n − k)(n − k − 1)(n − k − 2) ρ(k); p and the slope's interval
come from that variance, and the n/n* column gives the factor (1: no autocorrelation kept; a
factor that isn't positive, from a strong negative autocorrelation, leaves the line untested).
It needs a long series: an autocorrelation is poorly estimated from few times (Box and Jenkins,
1976, ask for about 50), and with 15 times only one beyond ±0.51 counts; even with 60 to 90
times the corrected test still rejects a true absence of trend too often when the
autocorrelation is strong (Blain, 2013). It corrects each line on its own: it is no substitute
for a mixed model with a CAR1 autocorrelation, which estimates the trend shared by the sites
and their sectors, with the autocorrelation within each.
Seasons: the seasonal Kendall test (Hirsch, Slack and Smith, 1982), for samples taken several
times a year, the season given by the month of a time made of dates, or by a qualitative
variable or an ID (season, month). The year of a value is the whole part of its time (the
calendar year of a date); several values in a season of the same year count as one, their
median (as some implementations do; EnvStats would keep them all, as ties in time), and a note
says how many. In each season seen in at least 2 years: the Mann–Kendall S between its years
and its variance with ties; S and Var(S) are summed over the seasons, taken as independent, and
p comes from the normal approximation with the continuity correction, as trend::smk.test and
EnvStats::kendallSeasonalTrendTest compute them. The seasonal Sen slope is the median of the
slopes between years within each season (per year, or per time unit), its 95 % interval taken
from Var(S) as Gilbert (1987) does (the ranks rounded, as for the Sen slope above; EnvStats
interpolates between them); τ is EnvStats': the seasons' τ averaged, weighted by their years.
A season seen in a single year doesn't count; a line with fewer than 4 values in the seasons
that count, or with the same value every year in each season, isn't tested; observations
without a season are left out of the test, and counted. The seasonal test takes the seasons as
independent: autocorrelation from one month to the next makes p too small, and Allow for
autocorrelation doesn't apply to it (Hirsch and Slack, 1984, give a correction, not done here).
The Test column gives each line's test; the correction over the lines stays the same.

One model per response
----------------------
Model › One model per response (for a regression: LM, LMM, GLM or GAM): the same model, its
terms, random effects, distribution, curves, observations and the transformation of its
response, fitted to each response ticked, one species after another (a filter and All / None
help pick them). For each term, the p-values are corrected over the responses: Benjamini–
Hochberg (FDR) by default, or Holm, or Bonferroni. The view shows, for the term chosen: each
response's coefficient with its 95 % interval as a forest plot, in red where the corrected p is
at most 0.05 (a curve: its edf); the term's effect in small multiples, one small plot per
response (36 at most); and a table with each model's N, AIC, R² and Q². A response that can't be
fitted is named with the reason, and the others are kept. "Also keep each model in the project"
adds them all, each with its own views.

Maps and spatial data
---------------------
Plots › Map (or in the explorer, under the project): the observations on a map. The first time,
choose the project's coordinates: two of its variables, X (east, or the longitude) and Y (north,
or the latitude), and their coordinate system: longitudes and latitudes in degrees (WGS 84),
Lambert-93, the CC zones, Lambert II étendu (NTF), a UTM zone (another EPSG code: 326xx north,
327xx south), LAEA Europe, web Mercator, or plane coordinates in metres of another system
(distances stay right, without a background map). Nuée proposes them from the variables' names
(lon/lat, X_L93/Y_L93, X/Y...). They are saved with the project, and Ctrl+Z takes them back.
The map draws the points with the same scale on both axes. Colour: a variable of the project, or
a column of a fitted model's results (scores, residuals, fitted values, clusters...); Size: a
quantitative variable or column; Labels: the observations' names. Background: none by default,
so nothing leaves the computer; OpenStreetMap, the IGN map or IGN's aerial photographs (France)
are downloaded when chosen, and their servers then receive the area shown. A box, lasso or click
selects observations, shared with the project's models as in the other plots.
Conversions between systems are written in Nuée (Lambert, transverse Mercator, LAEA formulas;
NTF moved to WGS 84 by IGN's three translations, to about a metre; RGF93 and ETRS89 taken as
WGS 84): they match PROJ, the library QGIS uses, to the micrometre.

GeoPackage (.gpkg), the format of QGIS: File › Open reads one of its layers (Nuée asks which when
there are several) as a table; points give two coordinate columns (X and Y, or longitude and
latitude), lines and polygons their centre (the centroid of a polygon's area), and the project's
coordinates are set. File › Export data and a model's Export write a GeoPackage when the project
has coordinates: one point per observation with all its columns, a model's other result tables
beside it; QGIS opens it with its coordinate system.

Raster values (Edit › Add raster values…, or the button on the map): an elevation, a slope, a
land cover, a climate layer… read from raster files at each observation's position, and added
to the project as new variables, one per band. Choose one or several files: GeoTIFF (.tif, as
QGIS, IGN's BD ALTI and RGE ALTI, Copernicus, CORINE, WorldClim or CHELSA write it) or ESRI
ASCII grids (.asc, with their .prj). In the browser version, type each file's full path
(several: separated by ";"): the engine reads the files where they are. Before adding, each
file shows its size, format, compression, cells and their size, bands and their type,
coordinate system, no-data value, and how many observations fall in it; a file that can't be
read says why. For each file, choose the value: the cell holding the observation (classes,
land cover; proposed for 8-bit integers and palettes), the bilinear interpolation of the four
nearest cells (continuous values; proposed for reals), or the mean, or the majority class, of
the cells whose centre is within a radius in metres (a tie goes to the class of the
observation's own cell, then to the smallest; with no centre within the radius, the
observation's own cell). The values are those of terra::extract. An observation without
coordinates, outside the raster or on a cell without a value gets a missing value, and the
result counts each case. Each band gets a name (its description in the file, or the file's
name), which you can change; a name already taken becomes "name (2)". Files side by side with
the same bands, type, system and cells (the tiles of a DEM) are proposed as one raster: one
variable per band, each observation taking the value of the tile that holds it (a circle
takes the cells of every tile). Edit › Undo (Ctrl+Z) removes the variables. They are saved
with the project like any other, and remember where they come from: the Methods text of a
model that uses them says which files, cell size, system and method gave them. The R console
shows the call, ajouter_valeurs_rasters(...), and what it gave.
The files are read in Nuée, without GDAL, and only the strips or tiles that hold observations:
a national DEM stays quick (a fraction of a second for a hundred observations in an
uncompressed or Deflate file, one to three seconds with LZW, decoded in R). Read: classic TIFF
and BigTIFF, in strips or tiles, bands interleaved or separate; uncompressed, LZW, Deflate,
PackBits, LZMA and ZSTD (ZSTD with R 4.4 and later), with predictors 2 and 3; integers of 8, 16
and 32 bits, reals of 32 and 64 bits; GDAL's no-data value, scale, offset and band names; the
georeferencing (ModelPixelScale and ModelTiepoint, ModelTransformation, or a .tfw file), pixels
as areas or as points. The raster's coordinate system comes from its EPSG code, or its
parameters, and must be one Nuée converts (WGS 84, ETRS89, RGF93, Lambert-93, CC42 to CC50,
Lambert II étendu, UTM, LAEA Europe, web Mercator): another one is refused with its code;
reproject the raster in QGIS (Raster › Projections › Warp) or with gdalwarp. A raster without a
coordinate system is taken in the project's. Refused, with a message: JPEG, WebP, LERC, JPEG
2000 and CCITT compression, values of 1, 2, 4, 12 or 24 bits, 16-bit reals, complex numbers,
YCbCr colours, ground control points (GCPs). Read without their colours: palettes (the class
numbers are read). Left aside: overviews (the values come from the full resolution), the other
images of a file, masks and .aux.xml files.

Plots › Spatial autocorrelation (from the map, or for a regression from its model): Moran's I of
a variable or of a regression's residuals (or, for counts, presence-absence and positive values,
its quantile residuals), with its expectation without autocorrelation, z and the one-sided p
(positive autocorrelation) under randomisation, and p by permutations (999 by default). For a
linear model without random effects, a second line gives the test that accounts for the fit
(Cliff and Ord 1981, as spdep::lm.morantest). Neighbourhood: the k nearest neighbours of each
observation (made mutual), the observations within a distance (empty: the smallest distance that
gives each observation a neighbour), or the inverse of the distance; rows summing to 1 (spdep's
"W" style) or the weights as they are. Under it, the correlogram (Moran's I in classes of
distance up to half the largest one, two-sided p corrected by Holm over the classes, in red at
0.05) and the semivariogram (half the mean squared difference between the values of the pairs of
each class, as gstat::variogram, up to a third of the area's diagonal), with the variance as a
dashed line. Distances are along great circles for longitudes and latitudes, straight lines for
plane coordinates. Observations at the same place (a plot surveyed several years) are each
other's nearest neighbours: "Mean by place" replaces their values by their mean.

Statistical tests
-----------------
Plots › Statistical tests (or in the explorer, under the project), in four modes chosen at the
top left.

Between classes, variable by variable: each quantitative variable compared between the classes
of a qualitative variable.
  Two classes (A, the reference, and B): Welch's t test (the default, unequal variances),
  Student's t or Mann–Whitney (on ranks). Effect: log2 of the ratio of the means B / A (when
  both means are positive) or Cohen's d. Volcano plot: the effect against -log10(p).
  Two classes paired by a key ("Pair by": a variable or an observation ID, the year for two
  sectors followed over the same years): for each variable, the rows of A and B that share a
  key, and have a value, make the pairs, and the differences B − A go through the paired t
  test (the default) or Wilcoxon's signed-rank test. The table gives each variable's number of
  pairs and the means of A and B over those pairs; the effect is log2 of the ratio of those
  means (when both are positive) or Cohen's d_z (the mean difference over the standard
  deviation of the differences). A variable with fewer than three pairs is not tested. A key
  may appear only once per class: one repeated within A or B is refused, as in "Two
  variables".
  All classes: one-way ANOVA or Kruskal–Wallis; the variables ranked by p.
p values are corrected for multiple comparisons: Benjamini–Hochberg (false discovery rate, the
default), Bonferroni, or none. In colour: the variables whose corrected p passes the threshold
(and, for two classes, whose effect does too).

Two variables: the test their types call for, its conditions checked, on the observations where
both are known. An observation ID (site, sector, year...) can make the groups, like a
qualitative variable.
  Two qualitative variables: the contingency table and Pearson's chi-square test of
  independence, with Cramér's V. In red and in blue, the cells more or less frequent than if the
  two variables were independent (adjusted residual beyond ±1.96). When the expected counts are
  too small for the chi-square test (one below 1, or more than 20 % below 5: Cochran's rule),
  Fisher's exact test is recommended; for a 2 × 2 table it is always given, with the odds
  ratio. Beyond 2 × 2 and 200 observations, its p value is simulated (100,000 tables).
  A measurement and a qualitative variable: the measurement compared between the groups, in box
  plots. Two groups: Welch's t test and Mann–Whitney (exact below 50 values on each side with
  no ties; otherwise by the normal approximation with continuity correction: the same
  calculation on every R version). More: one-way ANOVA, Welch's ANOVA and Kruskal–Wallis, each
  with its pairwise comparisons (Tukey, Games–Howell, Dunn with Holm's correction; up to 50
  groups): a click on a test shows them. The rank test is recommended when normality is
  doubtful in a group (Shapiro–Wilk p < 0.05, or fewer than three observations), Welch's ANOVA
  when the variances differ (Brown–Forsythe p < 0.05).
  A measurement and a qualitative variable, paired by a third variable or ID ("Pair by": the
  year, for two sectors of a site followed over the same years): the data stay in long format,
  one row per sector and year. Two levels A and B are compared on the keys both have: the
  differences B − A by the paired t-test (mean difference, its 95 % interval, Cohen's d_z) and
  by Wilcoxon's signed-rank test, the rank test recommended when the normality of the
  differences is doubtful (Shapiro–Wilk p < 0.05; not tested beyond 5,000 pairs, nor with
  constant differences, which leave Wilcoxon alone). Wilcoxon's p is exact below 50 pairs
  when no difference is zero or tied; otherwise the zero differences are dropped and p comes
  from the normal approximation with continuity correction, the same on every R version. At
  least three pairs are needed, and a key may appear only once per level. The rows left
  without a partner, and those without a value, are counted and listed; the plot joins each
  pair. With three levels or more, the table below can also list every pair of levels, each
  on its own shared keys, with Holm's correction over the pairs tested, for the test chosen
  above (a click on a test): when all the levels share the same keys, those of
  pairwise.t.test() and pairwise.wilcox.test() with paired = TRUE. A pair not tested (fewer
  than three shared keys, a key twice in a level, the same value in every pair) says why, and
  a click on a pair compares it; when A and B can't be compared, the table stays, under their
  reason. "Pairs of levels within each" (a qualitative variable or an ID: the site) keeps to
  the pairs of levels of the same group, the sectors of each site compared two by two. Holm's
  correction covers the pairs tested, all groups together; the raw p reads one site at a
  time. A level belongs to the group its rows carry: one with rows in several groups is
  refused, and those without a group are listed. Above the pairs comes the omnibus test, for
  both paired tests: Friedman's test on the keys where every level has a value (complete
  blocks; the keys left out for a missing level are counted), its χ², degrees of freedom and
  p, with Kendall's W = χ² / (n (k − 1)) as effect size (0: no agreement from one key to the
  next, 1: the same ranking of the levels at every key), as a sentence. Within each group,
  one Friedman test per group, on its own levels and complete keys, its p corrected by Holm
  over the groups tested; a group with fewer than three levels or fewer than two complete keys
  gets no test, and the reason is given.
  Two measurements: Pearson's and Spearman's correlations; Spearman is recommended when
  normality is doubtful for either. Paired by "the observation (same row)", two measurements
  of the same rows (before and after, say) are compared instead: the differences
  Variable 2 − Variable 1, on the observations where both are known, by the same two paired
  tests.
The recommended test's result comes as a sentence ready for a report (copy it with the button
next to it), with its effect size: Cramér's V, odds ratio, Cohen's d or d_z, rank-biserial
correlation, η², ε², r or ρ. Mann–Whitney's names both groups with their medians.

Correlation matrix: the Pearson or Spearman correlations of all the quantitative variables (300
at most), each pair on the observations where both are known, p values corrected for the number
of pairs. A click on a pair, in the table or the plot, tests it in "Two variables".

Before/after (BACI): a change of management on some units (the impact) compared with units
left as they were (the controls), as in a before-after control-impact design. Choose a
quantitative response, a time (a variable or an observation ID: the year, or dates) and a unit
(a qualitative variable or an ID: the sector), then tick the impact unit(s) and the control
unit(s). At each time, the gap d_t is the mean of the impact rows minus the mean of the
control rows, at the times where both have a value (one row per unit and time gives the mean
of the units; the times with one side only are listed and left out): with dates, the impact
and the controls counted on the same day; to compare years, take the year. The event is the
first time counted as "after" (a number for a time made of numbers; a date for a time made of
dates, where a year is its 1 January): for a spring density that responds to the previous
year's management, the year after the change. The times before it are "before"; "after" runs to
an optional end, of the time's kind too (with dates, 31/12/2012 for the end of 2012: a year
alone is refused, as is a date for a time made of numbers), the later times shown in grey, out
of the test. With at least two times in each period, the gaps after are compared
with those before: Welch's t test (the default), Student's t (equal variances: a linear model
of the gap on the period) or Mann–Whitney (on ranks); the effect is the change in the mean
gap, after minus before, with its 95 % interval,
and the result comes as a sentence ready for a report. The plot shows the gaps over time, the
event and each period's mean; until an event is entered, the gaps alone. The times are treated
as independent: successive gaps that resemble each other (autocorrelation) make the p value
too small. "Fit the mixed model" accounts for it: it adds to the project two variables worth
0 or 1, "BACI period (2007)" (1 from the event on, 0 before) and "BACI impact (S1 vs S2, S3)"
(1 for the impact units, 0 for the controls, missing for the other units), then the linear
mixed model y ~ period × impact + (1 | unit) on the rows of the impact and control units with
a known time, up to the end if there is one: a random intercept per unit and, with "with CAR1
in time" (ticked by default when every unit has at least three times; impossible when a unit
has several rows at the same time), a CAR1 autocorrelation along the time within each unit.
A variable of that name, or of that name followed by (2), (3)..., or of its name in the other
language, that already has these values is used as it is; otherwise the variable takes the
first of these names that is free (a name held by other values: other units beyond the three
named, another time, a time corrected since); Ctrl+Z removes them, as for a new variable. The model
joins the project (named "BACI <response>"; the same settings refit the same model) and its
views open. Back in the BACI view, its BACI effect, the period × impact coefficient with its
95 % interval and p value, comes as a sentence under the test's, saying that this model
accounts for the units and, with CAR1, for the autocorrelation. Its Methods text says it is
the BACI model and what its two variables are worth.

Linear, generalized and mixed models
------------------------------------
New model › type "Linear regression" or "Linear mixed model": one quantitative Y, the X
variables of the Variables tab (transformations and cross terms included; a qualitative
variable through its categories, one of them the reference). Without X: the null model, useful
to compare AICs. The default scaling keeps the variables' units (coefficients per unit); UV
gives coefficients per standard deviation.
A mixed model (nlme) adds nested random effects, the widest first: a random intercept for each
site, then for each sector within its site (an observation ID or a qualitative variable). It
can add an autocorrelation in time (CAR1, continuous time: missing years are fine; the time is
an ID or a variable, of numbers or of dates, and φ is then from one year to the next: see Dates
as time) within the last level or, through "within each", within a finer one that has no
random effect of its own: the sector within its site, when only the site has a random effect.
Coefficients and variances are
estimated by REML; the log-likelihood, AIC, AICc and BIC come from the ML fit, the only one
that compares models with different fixed effects. Cross-validation defaults to the first
random effect: each site is predicted by the fixed effects of the model fitted without it, as a
site never seen.
Random slopes: under each random effect chosen, "Random slopes by site" ticks the quantitative
X variables whose slope changes from one site to another, most often the year: each site has
its own trend, which varies around the model's fixed slope; it is (1 + year | site) in an R
formula. The variable must also be an X term of the model, quantitative and on its own
(transformed or not), not a curve: otherwise the model is refused, naming it. With nlme (a
mixed model, or a GLM or GAM with the normal distribution and CAR1, fitted by mgcv::gamm), each
level has nlme's general covariance matrix (random = ~ year | site; with nested levels, the
list list(site = ~ year, sector = ~ 1)): the variance of its intercept, that of each slope and
their correlation. A slope's standard deviation, in units of Y per unit of X, says how much the
sites' trends differ from the mean trend: about 95 % of the sites are within ±2 standard
deviations of the fixed slope. The correlation says whether the high sites have steeper slopes
(above 0) or shallower ones (below); it is that of the intercept taken at x = 0. The Summary
gives the variance and standard deviation of each intercept and each slope, and each slope's
correlation with its level's intercept (with several slopes at one level, their correlations
with each other are estimated but not in this table: summary(m) in the script of Export to R
gives them). With a slope, a level's variance changes with x and its share of the random
variance has no single value: the Summary gives each level's share of its mean variance over
the observations, and the marginal and conditional R2 take it too, as Johnson (2014) extends
those of Nakagawa and Schielzeth: the mean over the observations of zᵢᵀΣzᵢ, Σ the level's
matrix and zᵢ = (1, the values of its slopes).
Centring: a variable far from 0, such as the year (≈ 2010), puts the random intercept far from
the data (at year 0), where its correlation with the slope is near ±1; the fit often stops
short there, on a slope whose standard deviation is nearly 0. Nuée doesn't centre without
saying so: the Summary flags a singular fit (a correlation beyond ±0.99, or a slope's standard
deviation, times that of its variable over the observations, below 1 % of the residual standard
deviation) and, when the variable is far from 0 (its mean beyond its standard deviation),
advises centring it, scaling Ctr or UV in the Variables tab: it is the same model, which nlme
then usually finds, the intercept taken at the variable's mean. A centred variable and a
singular fit: the data can't estimate this slope or this correlation; compare by AIC with the
model without it. A failed fit still reads "The model could not be fitted".
In a GLM or GAM fitted by mgcv::gam (another distribution than the normal, or without CAR1), a
random slope is a term s(site, year, bs = "re") (Wood, 2017): independent of the random
intercept, with no correlation, as mgcv can't correlate them. That model depends on where x is
0: with x centred, the random intercept is each site's level at the mean of x; the year left
uncentred leaves little room for the slope's variance. The Summary says so. Refitted with CAR1
(mgcv::gamm), such a model has its slopes correlated, as in nlme.
With random slopes: cross-validation predicts a site never seen by the fixed effects; the AIC
selection chooses only the fixed effects, and the group of a variable with a random slope stays
in every model (a random slope goes around its variable's fixed slope); in Block contributions,
without that variable, only its fixed slope is removed and its random slope stays (the test of
the mean slope, with the same random effects); two models with different random slopes don't
have the same random effects: no likelihood-ratio test between them, they compare by AIC on the
same observations; Fit with CAR1 keeps the slopes; predictions are those of the fixed effects.
Not covered: in nlme, a slope uncorrelated with the intercept ((0 + year | site),
(1 | site) + (0 + year | site), ||), refused in the R formula; the random slope of a
qualitative variable, a cross term or a curve.
Type "Generalized linear model (GLM)" or "Additive model (GAM)" (mgcv), for a Y that isn't
normal. Distribution of Y: Poisson for counts; negative binomial for counts that vary more than
a Poisson allows (its θ estimated); zero-inflated Poisson for counts with more zeros than a
Poisson gives (its θ₁ and θ₂ estimated); binomial for presence-absence (0 or 1); gamma for
positive values; Tweedie for densities with zeros (its power p estimated); beta for proportions
strictly between 0 and 1 (its precision φ estimated); or normal. The link is log (counts, gamma,
Tweedie; for the zero-inflated Poisson, that of its Poisson parameter μ), logit (binomial, beta)
or identity (normal). Effort (offset): a variable
such as an area, a duration or a number of visits, whose log enters the model with a
coefficient of 1, which then describes a density (an effort of 0 or less is refused). Random
effects as above make a GLMM or a GAMM. With the normal distribution and at least one random
effect, a GLM or GAM can take the autocorrelation in time too: it is then fitted by
mgcv::gamm, as an nlme mixed model whose curves are random effects (coefficients, curves,
variances and φ by REML; logLik, AIC, AICc and BIC from an ML fit, comparable only with other
models fitted that way). With another distribution it is refused: mgcv::gamm would use
penalized quasi-likelihood (PQL), with no true likelihood nor AIC. In an additive model, the X
variables ticked in the Curve column of the Variables tab enter through a smooth curve (a
spline) instead of a straight line, for an effect that rises then falls, or a threshold; the
data decide how curved it is (its edf; 1 is a straight line). Its basis dimension k bounds how
curved it can be: 10 at most, less when the variable has few values; type another one (3 to
100) in the box beside the tick, as s(x, k = 5) does in R. A curve per category: the list
beside k offers the model's qualitative X variables ("one per sector"), as s(year, by = sector)
does in mgcv: each sector has its own curve, each of dimension k, with its edf, test,
concurvity, effect and thresholds. Each is centred on its category's observations (mgcv's
identifiability constraint): the qualitative variable must stay in X, its main effect giving the
difference in level between the categories; without it every category would have the same
mean, and Nuée then refuses the model rather than add that term without saying so. The factor
mgcv sees comes from the model's 0/1 category columns (its levels, the categories observed, in
their order); a category added to the data after the model was defined has no column, hence no
curve: its rows are left out of the model with the incomplete observations, and in a test set
they stay without a prediction. A variable with a curve per category can't also be in a cross
term with a qualitative variable (each category already has its curve). Curves and random
effects are estimated by REML, and the AIC comes from an ML fit; a GLM without them is fitted
by maximum likelihood, as glm() and MASS::glm.nb() do. The Summary of a Poisson model warns
when the counts are overdispersed (Pearson's chi-square above 1.5 times its degrees of
freedom): its p values are then too small, and the negative binomial suits the counts better.
Zero-inflated Poisson and beta (mgcv's ziP and betar families; Wood, Pya & Säfken 2016). In the
zero-inflated Poisson, a hurdle model, a count is zero with probability 1 − p and otherwise
follows a Poisson distribution of parameter μ truncated at zero; the linear predictor is log(μ)
(mgcv calls this link "identity"; exp(coefficient) multiplies μ, and so does the effort), and p
is tied to it by log(−log(1 − p)) = θ₁ + θ₂ log(μ), θ₁ and θ₂ estimated with the model; θ₁ = 0
and θ₂ = 1 give back the Poisson distribution, so its AIC compares with those of the Poisson and
negative binomial models of the same counts. Its fitted values, predictions, cross-validation and
test set are expected counts, p μ / (1 − e^(−μ)); it has no adjusted R², only the deviance
explained. It needs counts with at least one zero. Many zeros don't make zero inflation (too many
zeros given the model's mean may): compare the models by AIC and look at the quantile residuals;
when X variables explain the zeros themselves, the model may be poorly identified. The beta
distribution is for proportions strictly between 0 and 1 (a cover, a share of time), of mean μ
with the logit link and variance μ (1 − μ) / (1 + φ), its precision φ estimated (Ferrari &
Cribari-Neto 2004); its AIC compares with that of a normal model of the same proportions. A
response at 0 or 1 is refused, with the number of such values: mgcv would move them just inside
(its eps), which isn't harmless for the fit; bring them inside yourself, saying so (Edit › New
variable, for example (y * (n - 1) + 0.5) / n for n observations; Smithson & Verkuilen 2006),
or take the binomial for presence-absence. Both take random effects, curves and the spatial
smooth (no CAR1 autocorrelation); only the zero-inflated Poisson takes an effort. θ₁, θ₂ and φ
show in the Summary, the report and the coefficients side by side. Without a curve or random
effect, mgcv's ML fit of these two families sometimes stops on a LAPACK error: Nuée then finds
the distribution's parameters that maximize the likelihood itself (each fit at fixed parameters
by mgcv), and its exported script does the same.
Spatial smooth (General tab, for a GAM of a project with coordinates, see Maps and spatial
data): a surface of the observations' coordinates, s(x, y), a thin plate regression spline on
plane coordinates (Wood 2003) or a spline on the sphere for longitudes and latitudes (s(lat,
lon, bs = "sos")), of basis dimension k (empty: 30 at most, fewer with few places). It takes up
the spatial structure the terms don't explain: check with Plots › Spatial autocorrelation of the
model's residuals, and compare the models by AIC. Observations without coordinates are left out
of the model. Its edf and test are in the Summary's curves table, and its value at each
observation is a column of the model's results that the map can show. The R formula writes it
s(x, y), s(x, y, k = 40) or s(lat, lon, bs = "sos"). Export to R redoes it: the script puts the
coordinates in the columns sx and sy of the model's table and the term in the formula (with its
k, thin plate or on the sphere), its row in the curves table and a map of its value at each
observation.
Model conditions (a regression's Summary): pointers in words, each ✓ or ⚠ with what to do: the
residuals' distribution (Shapiro–Wilk, on the quantile residuals for counts, presence-absence and
positive values), a spread of the residuals that changes with the fitted values, influential
observations (Cook's distance beyond 4/n, linear model), overdispersion and an excess of zeros
(counts), collinear quantitative terms (VIF > 5), curves confounded with the other terms, and the
residuals' spatial autocorrelation when the project has coordinates. With many observations a
test sees harmless departures, with few it sees none: the residual plots remain the reference.
R formula (General tab): the model written as in R, for instance
  y ~ a * b + log10(c) + I(a^2) + s(d) + offset(log(effort)) + (1 | site/sector).
Edit it, then Apply (Ctrl+Enter): it sets the variables and their transformations (log,
log10, log1p, exp, sqrt, I(x^p), I(a * x + b), the logit log((x - a) / (b - x))), the cross
terms (a:b; a*b for a, b and a:b; a:b without a: a enters without a main effect; I(a^2) when
a is in the model too, else the square of a), the
curves s(x), s(x, k = 5) and s(x, by = f) (one per category of f, which must also be a term;
s(x, by = f, k = 5)), the effort offset(log(x)) and the nested random intercepts
(1 | site/sector), the widest first, with their random slopes as lme4 writes them:
(1 + year | site) or (year | site); (1 + year | site/sector), a slope at each level; one term
per level, (1 + year | site) + (1 | site:sector).
A curve makes the model additive, random effects make it mixed. R reads the formula without
ever running it: anything else (another function, code) is refused with the reason, and the
formula isn't kept, only the settings it gives.
Views: Summary (R2, or marginal and conditional R2 for a mixed model, Nakagawa and Schielzeth;
adjusted R2 and deviance explained for a GLM or GAM (marginal and conditional R2 when fitted by
mgcv::gamm, the curves in the fixed part), with each curve's edf, test and concurvity (the
share of the curve the other terms reproduce; above 0.8, in red, it is confounded with them; a
row per category for a curve per category);
Q2 and RMSEcv; AIC; the variance of each random effect and its share (with random slopes, see
above); φ of the
autocorrelation), Coefficients (each term's effect with its 95 % interval, red when p ≤ 0.05;
with a log link, exp(estimate) is the multiplicative effect of one unit more, with the logit
the odds ratio),
Effects (each quantitative term's effect as its variable varies, the others fixed, with its
95 % band and the observed values below it: a GAM's curves, straight lines otherwise, one per
category for a term crossed with a qualitative variable or a curve per category, with the
categories' legend; on the
scale of the link, log or logit, when there is one; for a curve, Thresholds: the effect and its
slope with 95 % simultaneous bands from 2000 draws of the coefficients, the ranges where the
slope's band excludes 0, clearly rising or falling, shaded and listed, and the edf, below 1.5
nearly a straight line, as Simpson (2018) reads thresholds; a curve with one per category (a
curve per category, or a curve crossed with a qualitative variable) has the thresholds of the
category chosen in the list beside the box, over the variable's percentiles in that category),
Observed / predicted, Residuals
(standardized, against the fitted values, normal Q-Q plot, by group of a random effect; Cook's
distance for a linear regression; the quantile residuals too for counts, presence-absence and
positive values, below), Block contributions (AIC): each block of the Block column
(or each variable) removed and the model refitted by ML, a main effect with the cross terms
that contain it and the curves per category it makes (the With column names them); ΔAIC above
2 means the block clearly
improves the model, a likelihood-ratio test gives its p. Observations with a missing value in
Y, X, a random effect, the time or the effort are left out (the summary counts them).
Residuals of a GLM or GAM with the Poisson, negative binomial, binomial, gamma, zero-inflated
Poisson or beta distribution: beside the standardized deviance residuals (the default), the
randomized quantile residuals of Dunn and Smyth (1996), r = Φ⁻¹(u), F the model's distribution at
each observation's fitted value (its random effects and effort included; the negative binomial
with its fitted θ, the binomial with one trial, the gamma with the shape 1 / its estimated scale,
the zero-inflated Poisson as mgcv defines it with its θ₁ and θ₂, the beta of shapes μ φ and
(1 − μ) φ): u = F(y) for the gamma and the beta, and for counts or 0/1 u drawn uniformly between
F(y − 1) and F(y), with a fixed seed, so
that the plot doesn't change from one look to the next (the session's random numbers are left
as they were). The Pearson or deviance residuals of counts are far from normal even when the
model is right; these residuals are normal when it is. Not offered for Tweedie (no distribution
function in the packages that come with R) nor for the normal distribution, where they would
be the standardized residuals.
Plots › Residual autocorrelation: the autocorrelation of a regression's residuals in time
within each group, the groups pooled, as nlme::ACF computes it: at lag k, observations k steps
apart in their group's time order (a missing year is skipped), lags 0 to 10 at most, with the
band ±1.96/√n of each lag (n: its pairs), as nlme draws it. A model with CAR1 keeps its time
and groups and shows two series: its residuals without the autocorrelation, and its normalized
residuals, which show none left when CAR1 is enough (the note reads lag 1). For another model,
choose the time (an ID or a variable, of numbers or of dates: the year) and the groups: by
default those of its random effects (the sector within its site), otherwise an ID or a
qualitative variable; either can take a finer level within it (the sector within the site of a
random effect, or a sector whose names repeat from one site to another). Beyond the band at lag
1, the note suggests a CAR1 autocorrelation, to compare by AIC. For a GLM or a GAM, Pearson
residuals ((y − fitted) / √variance) or deviance residuals (each observation's signed share of
the deviance), the same for the normal distribution; a mixed model's residuals are those within
its groups (given the random effects), as in nlme::ACF. Nuée computes the normalized residuals
in each group's time order: nlme's own are right only on rows sorted by group, then by time.
Within the groups of its random effects, with or without a finer level, Fit with CAR1 makes it
a new model: the same settings with a CAR1 autocorrelation along that time within those groups
(an LMM, or a GLM or GAM with the normal distribution, then fitted by mgcv::gamm; the button is
offered only then, and a refusal of the engine is shown), named like a refit (M1 (1)) and
selected with its default views open. An LMM on the same observations stays in the AIC set of
the model without CAR1: the two compare by AIC in Prediction › Compare models (the
likelihood-ratio test doesn't test an autocorrelation). The note says when they don't:
observations without a time or a group stay out of the new model, and mgcv::gamm's likelihood
doesn't compare with mgcv::gam's. File › Model report can include the plot.
Plots › AIC selection (also under each regression in the explorer): which variables to keep.
Each combination of the model's groups of terms (the blocks of the Block column, otherwise the
variables), from the null model to the full model, is fitted by ML on the same observations and
ranked by AICc; a cross term or a square enters only with its main effects (a qualitative
variable through all its categories) and the cross terms of part of its factors, a curve per
category only with its qualitative variable's main effect. Only the fixed
effects are chosen: the random effects, the autocorrelation, the effort and the curves'
settings stay those of the model, and the group of a variable with a random slope stays in
every model, out of the groups to choose. Up to 8 groups (256 combinations), every combination
is fitted (a mixed model with CAR1 on 240 rows takes about 10 s); beyond, a backward elimination
from the full model removes, step by step, the group whose removal lowers AICc the most. The
view suggests the best model (lowest AICc) and, when it differs, the most parsimonious within
ΔAICc ≤ 2 (fewest parameters; Burnham and Anderson, 2002); it plots each group's importance
(the sum of the Akaike weights of the models that contain it) and lists the 20 best models, or
those within ΔAICc < 10, with a column per group, k, logLik, AICc, ΔAICc, the weight and the
cumulative weight. Fit this model, on the suggestion or on any row (click the row first), makes
it a new model: the same settings with only those groups' variables (a cross term keeps its
factors), on the same observations, fitted as usual (REML for the estimates) and named like a
refit (M1 (1)). Once the selection has run, the Methods text describes it, the model report can
include it, and Export to R redoes it.
Plots › Trend power (also under each linear regression or linear mixed model in the explorer):
with this many sites counted every year, how many years until a trend is detected? Choose the
time (a quantitative X, untransformed: the year), the trend to detect (a change per year in the
units of the model's Y; with a log10 or ln response, also in % per year, converted to the slope
log(1 + %/100) on that scale, an approximation with log10(x + 1), close only where x is large
against 1), α (a two-sided test), the numbers of years (from, to) and the numbers of units of the
first random effect (the sites; the data's own number is always among them). Every unit is
counted once a year, its nested levels as in the data, their mean numbers rounded (2.75 sectors
per site: 3); a linear regression counts observations per year. The variances are the model's
REML estimates (random effects, residual variance, CAR1 φ), and the model's other terms stay out
of the designs (their effects held constant). For each design, the variance of the generalized
least squares estimator of the slope with these variances known, (X'V⁻¹X)⁻¹ with V the design's
covariance (Diggle et al., 2002), gives the power Φ(|β|/se − z) + Φ(−|β|/se − z): power against
the number of years, a line per number of units, the 80 % line, a sentence ready for a report
("With 12 units of “site”, each counted every year, a decline of 3% per year in “densite” is
detected with 80% power after 11 years"), and the table. Every unit being counted every year,
the random intercepts change nothing in the slope's variance: the residual variance, φ, the years
and the number of series counted decide it. A simulation checks the formula at one design (by
default the data's own): N data sets (200 by default) drawn from the model with the trend, each
refitted by nlme with the same structure (REML), the power being the share of slopes with p ≤ α
(Johnson et al., 2015), with its Monte Carlo error. Its seed is fixed (the same data sets every
time; the session's random numbers are left as they were), and the view says first how long it
will take: the R engine fits one model at a time and does nothing else meanwhile (a simulation
that would take more than 15 minutes, or of more than 20,000 observations per data set, is
refused). The two may differ: the simulation estimates the variances and φ in each data set
(from few units or years they are uncertain) and tests the slope with nlme's t, where the
formula takes them as known and uses the normal distribution. Not covered, and refused with the
reason: GLMs and GAMs, random slopes, a model without a quantitative X that can be the time, a
CAR1 along a time in other units than the trend's. Once computed, the Methods text describes it,
the model report can include it, and Export to R redoes it (the simulation with the same draws).
Plots › Adjusted means (also under each regression that has a qualitative variable, in the
explorer): the mean of each category of a qualitative X adjusted for the model's other terms,
as R's emmeans package computes it (Lenth; its default conventions, without the package): the
estimated marginal means of Searle, Speed and Milliken (1980). Choose the variable (a main
effect or a factor of a cross term). Each mean is the model's prediction on a reference grid,
averaged: the grid has every combination of the observed categories of the model's qualitative
variables; each quantitative variable is at its mean over the model's observations (a
transformed variable at the transform of its mean, as emmeans: log10 of the mean of x, not the
mean of log10(x)), the cross terms and squares evaluated at these values (the product of the
means), a curve (GAM) at the mean of its variable, the effort at 1 (densities, as emmeans'
offset = 0); the mean of a category averages the grid's rows that have it, with equal weights
over the categories of the other qualitative variables. Its standard error is √(L V Lᵀ), V the
covariance of the coefficients (nlme's for a mixed model, mgcv's Bayesian one for a GLM or GAM,
as emmeans), with its 95 % interval. Below, every pair of categories: the difference with its
interval and p, adjusted by Tukey's method (the default: the studentized range for the number
of means compared; Tukey 1953, Kramer 1956), by Holm's (the p-values; the intervals by
Bonferroni's, as emmeans, Holm's method giving none) or unadjusted. "Within each level of"
another qualitative variable crossed with the first (the treatment within each habitat): the
first's categories compared within each category of the other, the adjustment within each. "For
each category › the slope of x", for a quantitative variable crossed with it (year × sector):
the slope of x in each category (per unit of the term, transformed if it is), the derivative of
the predictions as emtrends takes it (a forward difference of a thousandth of x's range), and
the pairs of slopes; for a straight line, the slopes of the Effects view. The degrees of
freedom are those emmeans takes by default: the residual ones for a linear regression, and for
a GLM or GAM whose scale is estimated (normal, gamma, Tweedie); nlme's containment rule for a
mixed model (the smallest of those of the coefficients a mean or a pair involves in R's default
coding, the first category as reference, as emmeans on R's own fit; the intercept counting for
the number of groups of the first random effect minus one: typically, the mean of a sector has
the number of sites minus one, a pair of sectors within sites the inner df; for a habitat that
varies only between sites, the mean of the first habitat has the number of sites minus one, the
others and the pairs the habitat's df, the sites minus one minus its coefficients); z
(asymptotic) for a Poisson, binomial, negative binomial, zero-inflated Poisson or beta
distribution, as emmeans for glm() and as the model's Coefficients (on an mgcv::gam object,
emmeans uses the residual df whatever the distribution). With a log or logit link, the means are
on the response scale (exp; inverse logit: probabilities, or mean proportions for the beta
distribution), their intervals transformed from the link scale, and the pairs are ratios of
means or odds ratios, tested on the link scale, as emmeans' type = "response"; the link scale on
demand. With the zero-inflated Poisson, the means are expected counts, p μ / (1 − e^(−μ)) at
each category's linear predictor log(μ) (θ₁ and θ₂ taken as known; their standard errors by the
delta method, their intervals transformed, that value increasing with log(μ)), and the pairs
ratios of expected counts, tested on their log by the delta method, as emmeans'
regrid(transform = "log"); on the link scale, log(μ). A transformed Y (log10, ln…) stays on
its scale, as the view says:
back-transformed, a mean of logarithms is a median (a geometric mean), not a mean. A
combination of categories that no observation has is not estimable (emmeans: nonEst): its mean
and its pairs are left out, and named. A click on a pair in the table gives its sentence ready
for a report (copy button); Ctrl+C copies both tables. Once computed, the Methods text
describes it (Searle et al. 1980, Lenth's emmeans, Tukey 1953 and Kramer 1956, or Holm 1979),
the model report can include it, and Export to R redoes it in base R (the grid, the model's
rows L, the covariance and the degrees of freedom: the same numbers). Not covered: weights
other than equal (emmeans' weights = "proportional"…), contrasts other than pairs (against a
control), a quantitative variable at another value than its mean.
Prediction › Predict observations, Predict a file: Y predicted by the fixed effects (for a
mixed model, a group never seen), on the model's scale of Y (its transformation included), next
to Y observed when it is known. A file's columns are matched to the model's variables by name,
the effort included (without it, the predictions are for an effort of 1, and the note says
so). ⚠ marks a value outside the range of the model's observations: an extrapolation.
Prediction › Compare models: Q2 and RMSEcv for every model; AIC, ΔAIC and Akaike weights (the
probability that each model is the best of its set) between the regressions of the same
response on the same observations only (an "AIC set", lettered A, B...), and only those whose
likelihoods compare: Poisson, negative binomial and zero-inflated Poisson models of the same
counts, but not a normal model of them; normal, gamma or beta models of the same values;
Tweedie models with each other; GLMMs and GAMMs (mgcv's conditional likelihood)
with each other.
Under the AIC table, Nested models: the likelihood-ratio test between each pair of nested
regressions of the same AIC set, as anova(m1, m2) on ML fits. The smaller model's fixed terms
are among the bigger one's (its columns lie within the bigger one's), with the same
distribution, effort, random effects (their slopes included) and autocorrelation;
χ² = 2 × (logLik of the bigger − logLik of the smaller) on Δdf, the difference in their numbers
of parameters, and its p. For
linear regressions and GLMs it is the difference of their logLik (of their deviances for a
Poisson or binomial GLM, as anova(glm1, glm2, test = "Chisq")). Random effects and
autocorrelation aren't tested this way: a zero variance is on the boundary of its range,
where the χ² distribution no longer holds; compare them by AIC. With curves or mgcv random
effects, the df are edf and the test is approximate, as the table says. Every nested pair is
listed (2000 at most); the table's search box finds those of a model.
Prediction › Compare models › Coefficients side by side (the choice at the top of the view):
several regressions as papers present them, a row per term and a column per model. Tick the
project's regressions to show (all of them at first). Each cell is the estimate with its 95 %
interval, or with its standard error, from the model's Coefficients table (its decimals those of
two significant digits of the standard error), in red when p ≤ 0.05, empty when the model lacks
the term. The rows are the intercept and the first model's terms, then the others' terms in
their order: two models share a row when they have a term of the same name. Below: n, AIC and
AICc (ML fit), R² (a linear regression), the marginal and conditional R² (a mixed model) or the
share of the deviance explained (a GLM or GAM), the standard deviation σ of each random effect
(and the residual one of an nlme model), CAR1's φ and each curve's edf. A model with a log or
logit link keeps its estimates on the link's scale, as in its Coefficients view, and the note
says so. Ctrl+C (or the copy button) puts the table on the clipboard as text and as a table,
which Excel and Word paste as a table, with stars for p (* ≤ 0.05, ** ≤ 0.01, *** ≤ 0.001) and
their legend; File › Export model results (Ctrl+E), from this view, writes it, with each model's
coefficients in numbers beside it.
File › Export: the observations (observed, fitted, predicted in cross-validation, residuals),
the coefficients, the fit statistics, the random effects (each random intercept and slope, and
their correlation) and the curves, a table each. File ›
Model report: the summary and the coefficients, each term's effect, each curve's thresholds,
observed / predicted and the residuals (the quantile residuals too, for counts, presence-absence
and positive values).
File › Export to R: a script or report for a regression too, with lm, nlme::lme, mgcv::gam or
mgcv::gamm: its rows and terms, the fits (REML and ML; its random slopes included), the
cross-validation by its groups, then the coefficients, AIC, R2, variances, curves with their
concurvity and thresholds (the same draws as the Thresholds view), the quantile residuals (the
same draws as the Residuals view), test set and plots, checked against Nuée's results before it
is written.
Cross terms with a qualitative variable (Cross terms tab, or a * b and a:b in the R formula): a
qualitative variable enters a cross term through each of its categories, once at most (neither
squared nor cubed). year × sector lets the slope of the year differ from one sector to
another: its coefficients are, for each sector but the reference one, the difference between
the year's slope in that sector and its slope in the reference sector, which is the
coefficient of the year. The reference category is the one the fit leaves out (the last
category observed), the same in the main effect and in the cross term. For a density monitored
by sector, a coefficient of 0.2 for year*sector(S2), the year's being 0.05, reads: the density
rises by 0.25 a year in S2, 0.2 more than in the reference sector. Without the year in X (a
factor without a role in the Cross terms tab, or y ~ sector + sector:year), each coefficient of
year × sector is the year's slope in that sector; without the sector in X (y ~ year +
year:sector), the slopes differ but the sectors share one intercept. habitat × treatment: each
coefficient is the difference between a treatment's effect (compared with the reference
treatment) in a habitat and the same effect in the reference habitat; three variables (year ×
sector × habitat) give differences of differences. A category's own coefficient (sector(S2)) is
then its difference from the reference category where the terms crossed with it are 0: where
the year is 0 (with the years in their units, year 0, far outside the data; at the mean year
when the year is centred, Ctr or UV), in the reference habitat for habitat × treatment. The
columns are ordered as R orders its terms, the main effects first, so that the results are
those of lm(), nlme::lme() and mgcv with factors whose first level is Nuée's reference. A
combination of categories no observation has (a treatment never given in a habitat) can't be
estimated: it is left out, and the Summary names it among the terms never observed. Effects: a
quantitative term crossed with categories has one line per category (a curve when the term is a
GAM's curve), its slope being its coefficient plus that of its product with the category, with
its 95 % band from the coefficients' covariance and, under the plot, each slope per unit with
its interval. For a curve, Thresholds are those of the category chosen: the shared curve plus
that category's slope; a curve per category (s(x, by = f), above) gives each category its own
shape, not the same curve tilted. In the AIC selection and the contributions table, a cross
term enters and leaves whole (all its categories), only with its main effects and its
lower-order cross terms. The Methods text names each reference category and says what a
category's coefficient and the cross terms' coefficients are. Prediction: a category the model
has seen gets its own prediction; a category, or a combination of categories, it hasn't seen
(absent from the model's observations, from the other groups in cross-validation, or unknown to
the project in a file) gets none: the model would predict it as the reference category, or
without its slope, and R likewise refuses a level it hasn't seen. This is the rule for every
qualitative variable of a regression (main effects, cross terms, curves per category; LM, LMM,
GLM, GAM, mgcv::gamm), not for the other models (PLS...). Such observations are counted and
named: in cross-validation, the Summary gives how many stayed without a prediction and of which
variable, Q2 and RMSEcv being computed on the others; when none is left (sectors proper to each
site, cross-validated by site), Q2 is missing, and the Summary says the model can't be
cross-validated by these groups with that variable as a fixed X: make it a random effect, or
choose other cross-validation groups. The test set counts them apart from its RMSEP, bias and
external Q2; Prediction › Predict marks them ⊘ (column Unseen category, in the exported table
too). The Methods text and the script of Export to R do the same.

Class models and the Coomans plot
---------------------------------
New model › type "Class models": one PCA per category of the class variable, on the
observations of that category only ("M5.Gala", "M5.Golden"...), each with its own centres,
scaling and number of components. An observation belongs to a class when its distance to the
class's model (DModX) doesn't exceed the 5 % DCrit limit: to one class, to several, or to
none (an observation of another kind than all the known classes). Plots › Coomans plot: each
observation's distances to two of the models, with their limits in red; the table gives, for
each class, the share of its observations each model accepts (expected: about 95 % for its
own class, 0 % for the others), then each observation's distances and classes.

Redundancy analysis and correspondence analysis
-----------------------------------------------
New model › type "RDA (redundancy analysis)": how much of a table of responses Y (species
abundances, measurements) the explanatory variables X explain, and how. Y: quantitative
variables; X: the explanatory variables (a qualitative one through its categories, cross terms
included); Z (covariate, in the Role list of the Variables tab): variables whose effect is
removed first (partial RDA: the site, a known gradient...). General tab: the transformation of
the responses (Hellinger or chord for abundances, Legendre and Gallagher 2001; log(x + 1); or
none); the responses centred (covariance RDA, for responses in the same units) or standardized
(correlation RDA); the number of permutations of the tests (999; 0: no test), the groups they
stay within (an observation ID or a qualitative variable: a site followed over several years is
permuted only with itself) and their seed (the same seed gives the same permutations, hence the
same p values). An observation with a missing value, or with no abundance under Hellinger or
chord, is left out.

Views: Summary (the total inertia, the covariates' share, the X's share and what is left; R2
and adjusted R2; the pseudo-F and its permutation p); Ordination, the triplot (the observations
by their wa scores, weighted sums of the responses, or lc scores, linear combinations of the X;
the responses; an arrow per quantitative X, lengthened to fill the plot by the factor shown in
the legend, and a triangle at the centroid of each category; scaling 1 keeps the distances
between observations, scaling 2 the correlations between responses); Eigenvalues (constrained
axes in blue, unconstrained ones in grey); Permutation tests (each constrained axis after the
previous ones, each term after all the others; Forward selection keeps a term that raises the
adjusted R2 without going beyond that of all the terms and whose test gives p ≤ 0.05, Blanchet
et al. 2008; Variation partitioning splits the adjusted R2 between two or three blocks of X,
from the Block column of the Variables tab); the lists of observations and variables. The
results are those of the vegan package (rda, anova.cca, RsquareAdj, ordiR2step, varpart): the
same eigenvalues, scores and pseudo-F, and for the same permutations the same p values.

Type "Correspondence analysis (CA)": a table of counts or abundances (the X variables, one
observation per row, positive or zero values); observations and variables without any value are
left out. Views: Summary (the total inertia: the table's chi-square divided by its grand
total); Ordination (rows and columns in scaling 1, 2 or 3: chi-square distances between
observations, between variables, or symmetric); Eigenvalues; Contributions and cos² (each row's
and column's share of an axis's inertia, in blue above the mean, and the quality of its
representation); the lists.

Both export their tables (File › Export), write their Methods text with its references and make
a report. File › Export to R writes a script, or an R Markdown or Quarto report, that redoes
them with R alone, their tests with the same permutations. They don't predict new observations.

Canonical correspondence analysis (CCA)
---------------------------------------
New model › type "CCA (canonical correspondence analysis)" (ter Braak 1986): the RDA's
counterpart for species counts or abundances whose responses along the gradients are unimodal
rather than linear. Y: the species (counts or abundances, positive or zero), the columns of the
table; X: the explanatory variables; Z: covariates removed first (partial CCA). The table is
turned into its departures from independence, as in a correspondence analysis, and the X are
weighted by the observations' masses (their shares of the grand total). General tab: the number
of permutations (999; 0: no test), the groups they stay within and their seed; in each
permutation the masses go with the observations. Observations with a missing value or without
any abundance, and species absent from all the others, are left out.

Views, as the RDA's: Summary (inertia; R2 and the adjusted R2, estimated with the test's
permutations, Peres-Neto et al. 2006, none without permutations; pseudo-F and p); Ordination,
the triplot in scaling 1 (chi-square distances between observations), 2 (between species) or 3
(symmetric); Eigenvalues; Permutation tests (each constrained axis after the previous ones, the
terms one after another in the order of the model, each term after all the others; forward
selection, with adjusted R2 from the same permutations). Variation partitioning is an RDA's.
The results are those of vegan (cca, anova.cca by axis, by terms and by margin, RsquareAdj,
ordiR2step), and for the same permutations the same p values. Methods text, export, report and
Export to R as for the RDA.

Indicator species
-----------------
New model › type "Indicator species (IndVal)": which species characterize each group of
observations (habitats, site types...). Y: the species, abundances or presences; Class: the
qualitative variable of the groups. For each species and each group, A (specificity: the share
of its abundance in the group) and B (fidelity: the share of the group's observations where it
is), and the indicator value √(A·B): IndVal.g by default, which compares the groups' mean
abundances so that groups of different sizes count alike (De Cáceres and Legendre 2009), or
IndVal, which compares their totals (Dufrêne and Legendre 1997). Combinations of groups
(De Cáceres et al. 2010): by default every combination, up to all the groups (a species tied to
all of them isn't tested), or single groups, or up to an order. Each species goes to the group
or combination of its largest value, tested by permuting the observations' groups (999 times;
within strata, an ID or a qualitative variable; a seed); its p corrected over the species
(Benjamini–Hochberg or Holm) stands beside the raw p. "Presences only" uses 0/1 values.
Views: Indicator species (the sortable table, p ≤ 0.05 in red, "corrected p ≤ 0.05 only"; a
click highlights the species in the plot), Indicator values (each species' value for its group,
coloured by the group and pale when not significant; or one species' A and B in each group),
Summary (the number of species retained at 0.05, raw and corrected, and per group). The
statistics are those of indicspecies::multipatt, and for the same permutations the same p values.
Methods text, export and report as for the other models; Export to R redoes the analysis with R
alone, the engine's own functions and the same permutations.

Rarefaction and species accumulation
------------------------------------
Plots › Rarefaction (or in the explorer, under the project): how many species the observations
hold, compared on an equal footing. The species: columns of counts, a range from one column to
another in the table's order (as the diversity indices of New variable read them) or ticked in
the list. Rarefaction (by observation): each observation's expected richness in m individuals
drawn without replacement (Hurlbert 1971) with its standard deviation (Heck et al. 1975), the
curve from 1 to all its individuals, and its richness at a common size (by default the smallest
observation's: the dashed line); in the table, Chao1 (bias-corrected) and ACE estimate each
observation's richness. These need integer counts of individuals: with covers or densities the
view says so and gives the accumulation alone. Accumulation (over the observations): the
richness expected in k observations drawn among all (exact method, Ugland et al. 2003), ±2
standard deviations, and the estimators of the total richness from the presences: Chao2, the
first- and second-order jackknifes and the bootstrap. By group (a qualitative variable or an
ID): a curve and estimators per group. A click or a box selects observations, as in Series. The
values are those of vegan (rarefy, rarecurve, specaccum, estimateR, specpool), except ACE's
standard deviation, from the delta method with ACE's own gradient (vegan uses another).
PCoA, NMDS, PERMANOVA and Mantel test
-------------------------------------
Four analyses built on a distance between observations, computed on the table Y (Role Y: the
species, or any quantitative variables); an observation with a missing Y value is left out and
counted. General tab: the distance, as the vegan package defines it (Bray-Curtis, Jaccard
2B/(1 + B), Gower, Euclidean, Manhattan, Canberra, Kulczynski, Hellinger, chord), optionally on
presence-absence (Bray-Curtis then becomes the Sørensen index); a transformation before it
(square or fourth root, log(x + 1), presence-absence, relative abundances, Wisconsin double
standardization, square root then Wisconsin as metaMDS does); the number of permutations of the
tests (999; 0: none), the groups they stay within and their seed. A distance that has no meaning
for negative values (Bray-Curtis, Jaccard, Kulczynski, Canberra, Hellinger) refuses them, and
one that isn't defined for an observation without any value (only zeros) names it.

Type "PCoA (principal coordinates analysis)": the axes that best show, on a few dimensions, the
distances between observations (Gower 1966). A distance that isn't Euclidean (Bray-Curtis,
usually) has negative eigenvalues: they are kept and reported, and the Lingoes or Cailliez
correction (General tab) adds the constant that removes them. X variables (optional): fitted
onto the first two axes as vegan::envfit, an arrow per quantitative variable (its direction and
R2), a centroid per category of a qualitative one (and its R2), each tested by permutations;
observations without an X value are left out of this fit only. Views: Summary; Ordination (the
observations, coloured and labelled like the other plots, the species at the weighted average
of their observations, the arrows, grey when p > 0.05, and the centroids, on equal scales);
Eigenvalues (the share of the total inertia, the sum of all the eigenvalues; negative ones in
red); Fitted variables; the lists of observations and variables.

Type "NMDS (non-metric multidimensional scaling)": a configuration in k dimensions (2 by
default, 1 to 4) whose distances keep the order of the dissimilarities (Kruskal 1964), by
MASS::isoMDS as vegan::metaMDS does it: from the PCoA, then from 20 random starts (fixed seed);
the lowest stress is kept, and the Summary says whether another start found it again
(Procrustes): when none did, raise the starts. A zero dissimilarity between two observations
is replaced by half the smallest non-zero one. The configuration is centred, rotated to its
principal axes and scaled to the largest dissimilarity. Views: Summary (the stress: below 0.1
good, beyond 0.2 to be read with care); Ordination, as for the PCoA; Shepard diagram (each
pair's dissimilarity and ordination distance, the monotone regression, the stress of each
start); Fitted variables; the lists (each observation's share of the stress).

Type "PERMANOVA (permutational analysis of variance)": the effect of the X terms (qualitative or
quantitative, cross terms included) on the distance (Anderson 2001), as vegan::adonis2: each term
after those before it, in their order (sequential), each after all the others (marginal: a term
inside a cross term isn't tested alone) or the whole model; degrees of freedom, sum of squares,
R2, pseudo-F and its permutation p. With it, the multivariate dispersion (Anderson 2006, as
vegan::betadisper) of the categories of each qualitative X variable and of the class variable
(Role Class, one more grouping): each observation's distance to the centroid (or the spatial
median) of its group in the PCoA space, compared by an ANOVA, its residuals permuted, and
Tukey's pairs. A dispersion that differs between groups makes the PERMANOVA harder to read: its
differences may come from the spread of the groups as much as from their position. Views:
Summary; PERMANOVA table; Multivariate dispersion (box plots or the PCoA plane, with its tests);
the list of observations (each one's distance to its centre).

Type "Mantel test": the correlation (Pearson, or Spearman on ranks) between the distance of Y and
the Euclidean distance of the X variables, scaled as the Variables tab says (UV by default), and
its one-sided permutation p (vegan::mantel); with covariates Z (Role Z), the partial Mantel test
(vegan::mantel.partial); and the Mantel correlogram (vegan::mantel.correlog): the X distance cut
into classes of equal width (Sturges' rule, or the number given), the Mantel r of each class
(positive: close observations more alike), the classes beyond half tested only if every
observation has a pair in them, the p values corrected progressively by Holm's method. Views:
Summary; Mantel test (each pair of observations); Mantel correlogram; the list. "X distance:
Geographic" compares the distance of Y with the distance between the observations in kilometres,
from the project's coordinates (see Maps and spatial data), no X needed: whether nearby samples
are more alike (distance decay), and with the correlogram, up to what distance.

The four export their tables (File › Export), write their Methods text with its references and
make a report; they don't predict new observations. The results are those of vegan (vegdist,
wcmdscale, envfit, metaMDS with isoMDS, adonis2, betadisper, mantel, mantel.correlog): the same
values, and for the same permutations the same p values. File › Export to R writes a script, or
an R Markdown or Quarto report, that redoes them with R alone (and MASS, which comes with R, for
the NMDS): its functions are those of Nuée's engine, copied as the engine writes them; then the
model's data (the coordinates for a geographic Mantel test), its transformation, distance and
options, the same permutations and the same starts, so the same p values and the same NMDS.

Decision trees, linear discriminant analysis and k-means
--------------------------------------------------------
New model › type "Decision tree" (rpart): a quantitative Y variable (regression tree) or a
class variable (classification tree), and X variables by their raw values, so that the
thresholds read in their units; missing X values are handled by surrogate variables.
General tab: at least 20 observations per leaf, but at most a sixth of the observations, so
that the tree can split (a node is split only if it holds three times as many), at most 5
levels, cp = 0.001, 5 surrogates, pruning by the 1-SE rule (the smallest tree within one
standard error of the minimum error) or at the minimum error. The pruning comes from an
internal cross-validation by the cross-validation groups (for sites followed over several
years, choose the site), and Q2 from an external cross-validation: each group is predicted by
a tree entirely rebuilt without it. Views: Tree (a click on a node selects its
observations), Pruning, Leaf rules, Variable importance, First-split stability (200
bootstrap draws of the groups: the share of the draws where each variable makes the first
split, and its median threshold), Observed / predicted and Residuals, or Classification
for a classification tree. Test set and Predict: a new observation follows the tree,
surrogates included.

Type "Linear discriminant analysis (LDA)" (MASS::lda): a class variable and X variables by
their raw values; prior probabilities proportional to the class sizes or equal. Each
observation goes to the class of largest posterior probability; cross-validated, each
group is classified by the model fitted without it. Views: Discriminant scores,
Discriminant coefficients (structure correlations, coefficients in the variables' units
or for variables of standard deviation 1), Classification, Posterior probabilities. Test
set and Predict.

Type "k-means": X variables scaled as the Variables tab says (UV by default), k clusters
(Hartigan and Wong algorithm, 25 starts, seed 1), numbered from the largest to the
smallest; an observation with a missing value is left out. Views: Clusters (on the first
two principal components), Silhouettes, Choice of k (2 to 10: within-cluster sum of
squares and mean silhouette), Cluster centres. "Clusters → variable" adds the clusters to
the project as a qualitative variable (Edit › Undo removes it); Predict assigns a new
observation to the cluster of the nearest centre.

For all three: Methods text with its references, Export, PDF or Word report, Export to R
(a script or an R Markdown / Quarto report that redoes the analysis with rpart, MASS or
cluster, which come with R). Compare models shows a regression tree's Q2 and RMSEcv beside
the other models.

TRIM: indices and trends of counts
----------------------------------
New model › type "TRIM (indices and trends of counts)": the yearly indices and the trend of
counts of animals surveyed on sites year after year, as Statistics Netherlands' TRIM 3 software
and the rtrim package compute them (the standard of European bird monitoring), with missing
counts: the model imputes them. The data: the long table, one row per site and year; Y: the
counts (whole numbers, positive or zero; an empty cell is a missing count); X: optional
qualitative covariates (a site's habitat, or a value per site and year) that make the time
effects vary. General tab:
  - the site (an ID or a variable) and the time (the year: a variable or an ID made of evenly
    spaced numbers; a year without any row is added, all its counts imputed), proposed from the
    columns' names;
  - the model: 3, an effect of each year (ln μ = site + year); 2, a linear trend on the log scale
    whose slope changes at the changepoints given (years; empty: a single slope), at every year,
    or chosen stepwise as rtrim does (a point leaves when the Wald test of its change in slope
    exceeds p = 0.2, comes back when its score test falls below p = 0.15); 1, no time effect;
  - overdispersion (σ²) and serial correlation (ρ, between two successive years of a site),
    ticked by default as the TRIM manual recommends: the parameters are then estimated by
    generalized estimating equations that allow for them; without them, by Poisson maximum
    likelihood;
  - weights (a variable: over- or under-represented sites), and the base time of the indices
    (the first by default).
Two rows for the same site and year are refused, the site, the year and the observations named;
a site without any positive count is left out, and counted; a cell without a row takes the
weight and the covariate category of its site's previous year.

Views: Summary (the model, σ² and ρ, the overall slope of the imputed totals: multiplicative, per
time step, with its standard error, its 95% interval and its class by TRIM, strong increase,
moderate increase, stable, uncertain, moderate decline or steep decline, from the interval
compared with 1 and with 0.95 / 1.05; the Pearson chi-square, the likelihood ratio and the AIC);
Indices (the imputed indices, from the observed counts and the model's for the missing ones, and
the model's, with their 95% band, the base time, and optionally the overall slope's line); Time
totals (observed, imputed, model); Slopes, parameters and tests (the Wald tests of the slope, the
changes in slope, the deviations from the linear trend and the covariates; model 3 as a line and
its deviations; the stepwise steps); Counts by site (a site's counts and the model's, or every
count against its expected value). The results are those of the rtrim package. Methods text
with its references, Export and report as for the other models, and Export to R: a script or
report that redoes the model with R alone, TRIM's functions of Nuée's engine copied into it (the
same indices, totals, slopes and tests as Nuée). No prediction.

Distance sampling: density and abundance
----------------------------------------
New model › type "Distance sampling (density, abundance)": the density and abundance of a
population from the distances of the animals detected from lines (line transects) or from
points (point transects, point counts), as the ds() and dht2() functions of the Distance package
compute them (Buckland et al. 2001; Miller et al. 2019). The data: the flat table, one row per
detection, as Distance reads it:
  - the distance (Y): the perpendicular distance from the line, or the distance from the point;
  - the transect (the line or the point: an ID or a variable) and its effort, the same on all
    its rows: the length of the line, or for points the number of visits (no column: one visit
    per point);
  - optional: the stratum (the region: an ID or a variable) and its area, the same on all its
    rows (without an area, or areas all 0, the density only); the size of each detected group;
  - a transect without any detection stays a row, its distance empty, so that its effort
    counts; rows without a transect and a distance are left out.
For example, with Distance's column names (the dialog proposes them from the names):
    Region.Label  Area  Sample.Label  Effort  distance  size
    North         630   N-01          2.4     35        2
    North         630   N-01          2.4     120       1
    North         630   N-02          1.8               (no detection)
General tab:
  - line or point transects;
  - the truncation: the largest distance (ds's default), a distance, or a percentage of the
    largest distances (5 to 10% is usual); a left truncation if needed. Detections beyond it
    leave the model, their transect stays;
  - intervals, for distances recorded in classes (as ds(cutpoints = )): their bounds, e.g.
    "0 10 25 50 100"; each distance of the table (the true one, or its class's midpoint) counts
    in its interval, the first bound is the left truncation and the last w; the likelihood is
    then that of the counts of the classes, and the goodness of fit the chi-square on them;
  - the key of the detection function g(x): half-normal exp(−x²/2σ²), hazard-rate
    1 − exp(−(x/σ)^−b) (b ≥ 1, as mrds) or uniform;
  - covariates (multiple-covariate distance sampling, as ds(formula = ~ x1 + x2); Marques and
    Buckland 2003, Marques et al. 2007): the variables whose Role is Z in the Variables tab, or
    added from the Covariates list of the General tab (the same thing). The scale σ of the
    half-normal or hazard-rate key depends on them, ln σ = β0 + β1 x1 + …: a quantitative
    covariate as it is, a qualitative one through an indicator of each of its categories but the
    first present among the detections, its reference (R's treatment contrasts); the group size
    can be one. Each detection then has its own detection function and its own probability of
    detection pi. As ds: no adjustment terms unless a number is given, no monotonicity
    constraint, no uniform key; the covariates are taken as they are (no transformation), known
    for every detection within the truncation;
  - the adjustment terms: cosine (the default), Hermite polynomials or simple polynomials, their
    number chosen by AIC as ds() does (the key alone, then one more term at a time while the AIC
    falls, five at most; orders 2, 3, 4… for cosines, 4, 6, 8… for Hermite and polynomials, 1,
    2, 3… and 2, 4, 6… with the uniform key) or fixed; the distances in the terms divided by the
    truncation w (ds's default) or by σ;
  - monotonicity: mrds's constraint on a function with adjustment terms, checked at 10
    distances from 0 to w: strict (the default: g decreases), weak (g stays below g(0)), or
    none; g stays positive there;
  - the units of the distances, of the effort (lines) and of the areas, or a conversion factor
    (Distance's convert_units): the density is per unit of area, and the results say it.
The detection function is fitted by maximum likelihood on the exact distances; its parameters'
variance comes from the outer product of the distances' scores, as mrds; p, the average
probability of detection within the truncation, and its standard error by the delta method; the
effective strip half-width ESW = p w (lines) or the effective detection radius EDR = w √p
(points). The density of each stratum is D = n / (a p), a the covered area (2 w L, or 2 (w − L)
L with a left truncation, for lines; π w² K for points); its variance combines the encounter
rate's between transects (the R2 estimator for lines, P2 for points, Fewster et al. 2009), that
of p, and that of the mean group size; its 95% interval is log-normal with Satterthwaite degrees
of freedom, as dht2. The total over the strata adds their abundances (with areas) or weights
their densities by their covered areas (without). Without areas, each stratum's encounter rate
and group size variances enter the total's with the square of its weight, and the total's
degrees of freedom are those of Satterthwaite's formula with these weights. dht2 leaves the
weights out of the group size variance, which gives a larger standard error with groups, and out
of its degrees of freedom's denominator, which gives fewer degrees of freedom, and a wider total
interval, sometimes absurdly so: on Distance's amakihi data (7 strata, hn ~ OBs + MAS), 0.6
instead of 871, and an interval of 0.09 to 434 birds per hectare instead of 5.85 to 6.89. The
strata's intervals don't depend on it. The Summary, the Density and abundance view and the
Methods text give dht2's numbers as well. Refused, and named: a negative distance, a missing or
zero effort, two efforts for one transect, two areas for one stratum, an area of zero beside
others, a distance without a transect.
With covariates, the likelihood is that of each detection's distance given its covariates
(mrds's flpt.lnl, or the counts of the classes); the coefficients are fitted on the quantitative
covariates centred and scaled, then returned in their units. The same settings without
covariates are fitted too, first in the list of models, to compare the AICs (as Distance's
summarize_ds_models). p̄ = n / Σ 1/pi is the average probability of detection, with its standard
error as mrds's summary.ds, and ESW = p̄ (w − L) or EDR = w √p̄; the density of each stratum is
dht2's Horvitz–Thompson-like estimator D = Σ si / pi / a (si the group size, 1 without groups),
its detection variance by the delta method on all the parameters; the goodness of fit compares
each distance with the detection function of its covariates (Cramér–von Mises on their fitted
distributions, the chi-square's expected counts summed over the detections). Refused, and named:
a covariate missing for a detection, a qualitative covariate with a single category among the
detections, a quantitative one with a single value, covariates that follow from one another, and
a combination of covariates whose scale σ runs off to infinity (its distances don't fall off up
to w: group the categories, or choose others).

Views: Summary (the model retained and the AIC of each model fitted on the way, p and ESW or EDR
with their standard errors, the parameters, the goodness of fit, the overall density and
abundance with their intervals; what was left out; with covariates, the covariates and their
reference categories, and the coefficients on ln σ with exp(β), the factor on σ of a category
against its reference or of one unit of a quantitative covariate); Detection function (the
histogram of the distances, each bar its count over the count it would have if every animal were
detected, as mrds's plot.ds, under the fitted g; each detection on the curve, a click selects
its row; for points, the density of the distances f(r) = 2r g(r) / (w² p) too; below, the
chi-square's classes; with covariates, the average detection function, each detection's g given
its covariates weighted by 1/pi as plot.ds, each detection at its own g, and "by" a qualitative
covariate one curve per category, the average over its detections as plot.ds(subset = )); QQ
plot (the fitted distribution of each distance against the empirical one, with the Cramér–von
Mises test; not for distances in intervals); Density and abundance (by stratum and overall:
area, covered area, effort, transects, detections, encounter rate and its CV, D, its standard
error, CV, 95% interval and df, N and its interval, the share of the variance due to the
encounter rate, to detection and to group size; with groups, the density of groups too). The
observation list gives each detection's g and, with covariates, its probability of detection pi.
Methods and Results texts with their references, Export and report as for the other models, and
Export to R: a script or report that redoes the analysis with R alone, without Distance or mrds,
the distance sampling functions of Nuée's engine copied into it (the same candidates and AICs,
parameters and their covariance, p or p̄ and each detection's pi, ESW or EDR, goodness-of-fit
tests, density and abundance as Nuée; the detection function over the histogram, one curve per
category of each qualitative covariate, and the QQ plot in base R). No prediction.

The results are those of Distance 2.0 (moteur/tests/verifier_distance.R compares them, with
covariates on Distance's amakihi, ETP_Dolphin, ClusterExercise, unimak and golftees data), with
these known differences: Nuée integrates the hazard-rate key exactly where mrds approximates its
integral by a smoothing spline (lines, the key without adjustment terms, with or without
covariates: parameters and p differ by about 1e-4); with a left truncation of line transects the
covered area is 2 (w − L) L, where dht2 keeps 2 w L; without stratum areas, the strata's weights
enter the total's group size variance (squared) and its Satterthwaite degrees of freedom, where
dht2 leaves them out of both: a larger standard error with groups, and fewer degrees of freedom;
mrds's optimizer under the monotonicity constraint stops within 1e-6 of the likelihood, so its
estimates can differ from Nuée's in the fourth digit, or, on rare data, settle on another local
optimum. With covariates: ds can stop short of the maximum on poorly conditioned covariates (on
unimak, hn ~ MSTDO + Hour, on a plateau where σ is e^9 or more, thousands of times w, 21.9
log-likelihood units below the maximum Nuée finds; started from Nuée's estimates, ds stays
there); a combination of covariates whose σ runs off to infinity is refused, where ds returns
the point where its optimizer stopped; when the group size is a covariate, dht2 recomputes each
detection's probability with a size of 1 for the variance of its density of groups, where Nuée
keeps the detection's own (the densities of individuals agree); for points, the density of the
distances drawn is the mean of the detections' f(r | z), the density the histogram estimates,
where plot.ds weights them by 1/pi. And dht2 keeps a transect without detection within the
truncation only if its Sample.Label has no detection in any stratum (amakihi repeats its labels
across strata): Nuée keeps every transect's effort.

Random forests and boosted trees
--------------------------------
New model › type "Random forest" (the ranger package, Wright and Ziegler 2017): a quantitative
Y variable (regression forest) or a class variable (classification forest), and X variables by
their raw values. Each tree is grown on a bootstrap draw of the observations (with
replacement), each split chosen among mtry randomly drawn variables; the forest predicts the
mean of its trees, or the class most of them vote for (Breiman 2001). General tab: 500 trees,
ranger's mtry and node size by default (the square root of the number of X rounded down; nodes
of 5 observations for a regression, 1 for a classification), the share drawn, the permutation
importance unscaled or divided by its standard error. Seed 1 and a single thread: the same
forest every time. ranger takes no missing values: an observation with a missing X value is
left out (the summary counts them). The out-of-bag error: each observation predicted by the
trees whose draw doesn't hold it (MSE and R², or the share misclassified); the
cross-validation: each cross-validation group (the site) predicted by a forest rebuilt without
it (Q2 and RMSEcv, or the share correctly classified). Views: Variable importance (by
permutation, how much the out-of-bag error rises when the variable's values are permuted; or by
impurity), Partial dependence (computed on request, Friedman 2001: the forest's mean prediction
when a variable takes each value of a grid, the other X unchanged; all the variables side by
side, or one, the observed values under the curve; for a classification, the share of a class's
votes), Error against the number of trees, Observed / predicted (out of bag, cross-validated or
fitted) or Classification (with ROC curves from the votes). Test set and Predict.

Type "Boosted trees (BRT)": gradient boosting of regression trees (Friedman 2001, 2002), as the
gbm package computes it and as Elith, Leathwick and Hastie (2008) describe it for ecologists,
written in R on rpart. A quantitative Y: a measurement (normal distribution), a presence-absence
0/1 (binomial) or counts (Poisson), chosen as a GLM's. The trees are added one by one, each
fitted to what the model still misses (the gradient of the deviance) on a draw without
replacement of a share of the observations, its leaves re-estimated for the deviance, and added
with a small weight (the learning rate). General tab: at most 2000 trees, a learning rate of
0.01, 3 splits per tree (the interaction depth: 1 gives an additive model), at least 10
observations per leaf, draws of 50%. The number of trees is the one where the cross-validated
deviance is smallest (each cross-validation group predicted after each tree by the boosting
redone without it): the more groups and trees, the longer the fit. Observations with a missing
X value are left out. Views: Relative influence (the error reductions of each variable's splits,
in %), Partial dependence (on the link scale, logit or log, or on the response's), Error against
the number of trees (the deviance of the fit and the cross-validated one, the number of trees
retained), Observed / predicted, and Classification (at a probability of 0.5, with the ROC
curve) for a 0/1 response. Test set and Predict.

For both: Methods text with its references, Export, PDF or Word report. Compare models shows
the Q2 and RMSEcv of a regression forest, or of boosted trees of a measurement, beside the other
models. Export to R: boosted trees with R and rpart alone (the boosting of Nuée's engine copied
into the script: with the same seed, the same draws and the same trees, which are gbm's); a
random forest with R and the ranger package, the one exception to "no package": Nuée depends on
it and installs it with itself (elsewhere, install.packages("ranger")), and the script loads it
with the same seed, one thread and the same settings, so its forest is Nuée's, tree for tree,
with the same version of ranger. The test set and the partial dependence, when it was computed,
are in it too.

Cleaning the data: find and replace, categories, units
------------------------------------------------------
What one used to do in Excel before opening the table, in Nuée, each change undone by a single
Ctrl+Z (Edit › Undo) like the other changes of the data; models already fitted keep their
results until you fit them again. In the Edit menu, in the Data view's toolbar, and in the
right-click on a column's header in the Data view (a header shows the variable's unit, its
number of empty cells and of distinct values, "Column summary"; its tooltip, the description)
or on a variable of Plots › Variable statistics.
Edit › Find and replace (Ctrl+H): in one variable, several or all, the cells that hold a text
or a number, or the empty cells ("empty cells": replace empty by 0), get what you type, or
become empty when you type nothing (replace -9999 by nothing). A qualitative variable is
compared as text: the whole cell, or part of the text (a "," in "3,5"), capitals counting or
not; a quantitative variable as numbers ("3,5" finds 3.5), on the whole cell, and it takes only
a number or nothing (its cells stay otherwise, and the dialog says so). Before you replace,
the dialog says how many cells will change in each variable, the first changes ("foret" →
"forêt" (3)) and what each variable becomes: a text variable whose values all become numbers
(",", "<0.5" replaced by 0.25, "abs" by 0) becomes quantitative, unless you untick it. A
category replaced by another one that exists merges into it; one emptied of its cells leaves.
Note that a column of measurements is read as numbers when you open the table: a few "<0.5"
or "nd" in it are read as missing values then (File › Open says so), and are no longer there
to replace; a column with more text stays text, where you can.
Edit › Categories (or right-click on a qualitative variable's header): a qualitative variable's
categories with their number of observations, to rename (a name another category has merges
them), merge (the ticked ones, into the most frequent), move up and down, and choose the
reference. Their order is that of the plots and tables (colours, bars, adjusted means). In a
regression the last category observed is the reference category: each other category's
coefficient is its difference from it, and "Reference" moves a category last. The project's
model definitions follow the categories (refitted, a regression takes the new reference); a
fitted model whose categories were renamed or merged can't be refitted from its own page (fewer
observations, a component more) nor predict: fit it again (Model › Modify model, or double-click
its definition in the explorer). A new order only doesn't stop it.
Edit › Units and descriptions (or right-click on a header › Unit and description): each
variable's unit (ind./ha, m, °C) and description. The unit goes into the axis titles
("density (ind./ha)": Effects, Observed / predicted, Variable statistics, Series, the Map's
legend, adjusted means, statistical tests, a forest's partial dependence; not on an axis that
shows it transformed), the Data view's headers, the Methods text ("the response is "density"
(ind./ha)") and the Results text (a coefficient "per m" when the variable is in its own units).
Both are saved in the project, kept by File › Export data where the format has room (a
"Variables" sheet of an Excel workbook and a "Variables" table of a GeoPackage, which Nuée
reads back when it opens them; the description of a jamovi column; the label and units
attributes of an R column, as Hmisc reads them; not in CSV or text), and written as comments
before the data in Export to R.
In the Data view, a click on a cell, then Ctrl+V, pastes a block of cells copied from a
spreadsheet from that cell on, in the rows and columns as the view shows them (sorted,
filtered): each cell as when you edit it by hand (empty: missing; a new category is added; a
text in a quantitative variable is refused, naming the observation, and nothing changes); cells
beyond the table are left out. One Ctrl+Z undoes the whole block.

Adding columns from another table
---------------------------------
Edit › Add columns from a table (or right-click on the project's data in the explorer): the
columns of another table added to the observations by a key, as one would do in a spreadsheet:
the habitat and altitude of each site from a table of sites, the weather of each year, or of
each site and each year. The table: a file in any format File › Open reads (with its sheet or
table for a workbook or an R file; a Nuée project gives its data), or cells copied from a
spreadsheet (Paste cells).
The key: one or more columns of the project (variables, IDs or the observation names), each
beside the matching column of the table. The application proposes columns with the same names
(ignoring capitals and the spaces at the ends, as Predict a file does): those with which each
key comes once in the table and the most observations find theirs, from the table's first
columns, as few as possible: the site for a table of sites, the site and the year for weather
by site and year; change them as needed. Each key must come only once in the table: a key that
comes twice is refused, named, rather than one of its rows taken at random.
Keys are compared as numbers when the project's column is a quantitative variable: 2019 and
2019.0 are the same year (the table's values read as numbers, as File › Open reads them).
Otherwise they are compared as text, as written in the table and in the project, without the
spaces at the ends, capitals counting: "S1" isn't "s1", nor "01" "1" (a key column of "01",
"02" isn't read as numbers here); a number of the table is then written as R writes it (2019).
A key with a missing part matches nothing.
Columns to add: every column of the table but the key, ticked by default. A column of numbers
gives a quantitative variable; text, an R factor or a labelled SPSS or Stata variable gives a
qualitative one (a factor's categories in their order, otherwise the texts sorted), as when a
table is opened. A name already taken in the project, by a variable or an ID, becomes
"name (2)", "name (3)"...: nothing is overwritten.
Each observation takes the values of the table's row that has its key, and the observations
keep their order: as k <- match(key of the project, key of the table), then table[k, columns]
(merge() would sort the rows). An observation with no such row gets missing values. The result
says what was added and counts the observations without a match and the table's keys that
match no observation, naming the first five of each; rows of the table without a key are
counted too. If no observation finds its key, nothing is added, and the message shows keys of
both sides. Edit › Undo (Ctrl+Z) removes the added columns; models already fitted don't
change. The R console's "Application actions" shows the call, and the same computation written
with match() on the project's data table.

Summarizing by group
--------------------
Edit › Summarize by group (or right-click on the project's data): a new project with one row per
group, beside the project, which doesn't change: the mean density of each sector and each year
from several plots, before BACI or Series. The groups: one or more variables or IDs (the
sector and the year; the site, the sector and the year). Each group becomes an observation
named from its values ("S1 2019"); the groups come in the order of these columns (a
qualitative variable's categories in their order, numbers in theirs), and the columns stay
variables or IDs, as in the project. An observation without a value in one of them is left
out, and counted.
The quantitative variables to summarize (all but those of the groups, ticked by default) and
the statistics, one or several, for each of them: mean (by default), sum, median, minimum,
maximum, standard deviation (n − 1, as sd() computes it), number of values (n), in columns
"density (mean)", "density (n)"... (named in the interface's language). Missing values are
ignored and n counts the known values; a group with no known value has missing statistics, and
n = 0. As aggregate(d[variables], d[groups], FUN) on the project's data table: the R console's
"Application actions" shows it with the call.
A qualitative variable or an ID whose known values are the same within every group (the habitat
of a sector, the site of a sector) is kept, with that value; the others are left out, and the
status bar names them. The new project has no file yet: save it (Ctrl+S).

Editing the data, making variables
----------------------------------
In the Data view, double-click a cell to edit it (Enter to keep, Esc to cancel; empty =
missing value; for a qualitative variable, the category's name). Models already fitted don't
change: refit them.
Edit › New variable: from an R formula on the other variables and the observation IDs, for
example log10(polyphenols), sugar / acidity, ifelse(weight >= 170, "large", "small") (a text
result gives a qualitative variable); by group, group_mean(x, sector), the mean of x in each
observation's group (missing values ignored; an observation without a group gets none), and
group_deviation(x, sector), the deviation from it (moyenne_groupe and ecart_groupe in
French): a sector mean as a covariate, or a response centred by sector. Or classes from the
values of a variable, at given limits (10 ; 20 gives "≤ 10", "]10 ; 20]", "> 20") or in
classes of equal size. Or Imputation (PCA): the chosen quantitative variables' missing values
filled from each other by regularized iterative PCA, as missMDA::imputePCA does, with the
number of components chosen by generalized cross-validation of the standardized variables,
from 0 to 5, as missMDA::estim_ncpPCA does on them (0: each variable's mean), unless you give
it; observed values unchanged, an observation missing more than half of them left missing,
imputed values kept within each variable's observed range unless unticked; as new variables
"x (imputed)" or in the variables themselves (Ctrl+Z undoes it). Remember to save the project.
In a New variable formula, from one year to the next: previous(x, year, sector), the value of x
the year before in the same sector, and following(x, year, sector), that of the year after
(pas = 2: two years before or after). The year sought must exist: a missing year gives a
missing value, never that of an older year, as does an observation without a sector or a year.
The time is made of numbers (an ID made of numbers, like the year, will do); dates too, but
these functions go with regular times (see Dates as time); the group, a qualitative variable,
an ID or interaction(site, sector) for a sector within a site; the same sector twice in one
year is refused, naming it. growth_rate(x, year, sector) gives the growth rate log(x / x of
the year before), missing unless both values are positive: for density dependence, the growth
rate against previous(density, year, sector). In French: precedent, suivant and croissance.
In a New variable formula, the diversity of each survey, over several species columns of its
row (counts, densities, covers: numbers ≥ 0), as vegan::specnumber and vegan::diversity compute
it: richness(...), S, the number of columns > 0; shannon(...), H′ = −Σ p ln p (natural log, p
each species' share of the row's total); simpson(...), 1 − Σ p² (the Gini–Simpson index, vegan's
"simpson"); pielou(...), Pielou's evenness J = H′ / ln S, missing when S ≤ 1. The columns are
listed (shannon(Ablette, Brochet, Gardon)), or a range in the table's column order, from one
column to another, both included (shannon(Ablette:Vandoise), as dplyr reads it), or both; a
column named twice counts once, and any other expression counts as a column of its values. A
survey of zeros has S = 0, H′ = 0 and a Simpson of 0 (vegan gives 1: one minus an empty sum),
and no J; a missing value in any of the columns makes the index missing for that survey (a
missing value isn't read as an absence); a negative value is refused, naming its variable. In
French: richesse.

File history
------------
For a project from a .usp file, the explorer shows "File history": the log stored in the
file (creation, working-set changes, number of components, deleted models...), with the
date, the software version and the user. Right-click on an imported model › Model history:
only what concerns it.

OPLS and OPLS-DA
----------------
Predictive components, which carry what in X is related to Y, and orthogonal components,
which describe the rest of X's variation: scores and loadings are easier to read (t[1]
against to[1], S-plot). One predictive component per Y variable, or one fewer than the
classes for OPLS-DA (t[1], t[2]... then to[1], to[2]...); with just one, the predicted values
are those of a PLS with the same number of components. With several Y (or more than two
classes), each orthogonal weight is made orthogonal to the weights X'y of every column of Y,
so the orthogonal components are not related to Y at all (since 0.9.0; version 0.8.0 left a
slight link: the OPLS models with several predictive components it made change a little when
refitted). Q2 by cross-validation, as for the other models (see below). None
of the .usp projects available had an OPLS model: this computation follows Trygg and Wold's
paper (2002), with no stored values to compare with; it is checked against a second writing
of the paper's algorithm.

VIP
---
The cut-off is placed automatically at the largest step in the sorted VIPs around 0.8. You
can type another cut-off or drag the red line, and Ctrl+click a bar to keep or drop a
variable (a plain click highlights it on the model's other plots).
"Refit with VIP variables" makes the model again with the variables kept.

Cross-validation
----------------
The model's observations are assigned in turn to G groups (7 by default: the 1st, 8th, 15th...
in group 1), or one group per value of an observation ID or of a variable (New model ›
Cross-validation groups): with "site", all the years of a site are in the same group, and each
site is predicted by a model that has never seen it; observations without a value make a group
of their own. Models from .usp files keep their groups: by an ID when the file groups the
observations with the same value, or else the file's groups as they are (shown "groups from the
file").
Three ways to validate a PCA, PLS or OPLS (New model › Cross-validation):
- Centres recomputed, full model's weights (the default, for every model, imported ones
  included): each group is predicted by a model fitted without it, like new observations; its
  centres (and MSC's mean spectrum, the cross terms) are computed again on the other
  observations, with the same number of components. The model knows nothing of the Y of the
  group it predicts. Its weights stay the full model's: the standard deviations of X don't
  depend on Y (a single Y: its weight doesn't change the predictions), and nothing is rescaled
  on fewer observations, so no prediction blows up.
- Centres and weights recomputed without the held-out group (the validation of 0.9.0 to
  0.9.7): likewise, but the weights are computed again on the other observations too.
  Stricter: a term that varies little without the held-out group gets a large weight there,
  and the group's predictions stray. A guard: a term whose standard deviation on the other
  observations falls under 10 % of the full model's (a variable that varies at one site only,
  validated by site) keeps the full model's weight; otherwise its weight, 1 / standard
  deviation, would be multiplied as much, and the held-out group's predictions would blow up
  (Q2 of -8e11 on a real project). The Summary says which ones, without which group.
- Full model's centres and weights (like SIMCA): the full model's centring and scaling; each
  component is validated on what the full model's previous components leave, one component
  fitted without each group. A component's Q2: 1 - PRESS / SS of the residuals before it;
  Q2(cum): 1 - the product of the components' (1 - Q2), each counted as -0.1 at worst. It is
  the validation of .usp files: it gives back their Q2, their Q2 per variable and their
  coefficients' confidence intervals. The Y predicted in cross-validation (RMSEcv, CV-ANOVA,
  classification) comes from sub-models fitted without each group on the full model's
  matrices. More optimistic, especially with few observations or groups by site: Y's centre and
  the previous components already know the held-out group (on pure noise, 6 observations and 20
  variables, it gave Q2 = 0.98 for an OPLS-DA; the other two, less than 0). An OPLS has its
  sub-models fitted on the full model's matrices.
The first two: PRESS, the sum of squared prediction errors; Q2(cum) = 1 - PRESS / SS (SS: the
variation of Y, or of X for a PCA); a component's Q2, 1 - PRESS / PRESS of the previous one.
PCA: each value is predicted by the scores of its observation computed without the variables of
its group of variables (also assigned to G groups). RMSEcv, CV-ANOVA, the cross-validated
classification, the confidence intervals (jack-knife, over the G sub-models), the permutation
test and autofit follow the validation chosen.
Gain over the empty model (the first two, PLS and OPLS): the Summary also gives the Q2 of the
empty model, where each held-out group is predicted by the mean of Y over the other
observations, and the model's gain over it, (Q2(cum) - Q2 of the empty model) / (1 - Q2 of the
empty model) = 1 - PRESS / PRESS of the empty model: the share of the empty model's prediction
error that the model avoids. With groups that differ (sites, departments), the empty model's
Q2 is below 0, and so is a model's Q2 that predicts a little better than it: the gain says how
much better. 0: no better than the mean of the other groups. With the full model's centres and
weights, the empty model predicts the mean of all the observations, held-out group included
(its Q2 is 0): no gain is given. Also in the Methods text, the model report and Export to R.
Hierarchical model (a PLS whose X include scores of other models of the project, $M1.t1...):
its Q2 takes these scores as they are, though they were computed with the held-out group's Y.
Its Summary also gives an honest Q2(cum): in each round, its base models are refitted without
the held-out group (the whole site when the groups are by site), then their scores, with the
model's validation (centres recomputed when it is the full model's); a base model with no
variation left without that group gives scores of zero. The honest Q2 has its gain over the
empty model too.

Validation (PLS and PLS-DA)
---------------------------
Permutation test: the values of Y (for a PLS-DA, the classes) are shuffled among the
observations 20 times (or more) and the whole model refitted, cross-validation included; the
intercepts of R2 and Q2 measure overfitting (a valid model if Q2 < 0.05 and R2 < 0.3 to 0.4,
the usual rule).
CV-ANOVA: the model's p (cross-validation residuals against the mean); also in the Summary.
Classification (PLS-DA): table of the observations correctly and wrongly classified, with
the fitted or cross-validated values, and ROC curves with their area (AUC).

Test set
--------
New model › Observations › Test set: observations left out of the model and of the
cross-validation, then predicted by it, to judge its predictions on data it hasn't seen.
"Test" column: by hand; "Selection to test set": the active model's selection; "Choose": a
share of the observations (25 % by default), at random or by Kennard–Stone (which keeps for the
model the observations furthest apart, so that it covers the whole range of the data, and
leaves the others for the test); by class for a PLS-DA, so that each class is in both. After
fitting, the Summary gives, for each Y:
  RMSEP    root mean square of the prediction errors (predicted - observed);
  bias     mean of these errors; SEP their standard deviation;
  Q2ext    1 - sum (observed - predicted)² / sum (observed - the model's mean)²;
for a PLS-DA, the share of the test set correctly classified; for all, the number of test
observations outside the model's domain. Observed / predicted shows them as red diamonds. The
test set is saved with the model, and kept by Export to R and by the Methods text.

Observations chosen by a condition
----------------------------------
New model › Observations › "Keep only the observations where...": a condition written in R like
a New variable formula, on the variables and the observation IDs by their names (a name with
spaces between `backticks`), for example site == "S1" & year >= 2010, !is.na(density),
habitat %in% c("marsh", "meadow") or year != 2015. Under the field, how many of the ticked
observations meet it ("312 of 480 observations"), or why it doesn't read: an unknown name, a
function that isn't allowed, a result that isn't TRUE or FALSE (or 1 and 0) for each
observation. It is evaluated on all the project's observations, as a New variable formula is:
density > median(density, na.rm = TRUE) compares with the median of every observation, not of
the ticked ones. The model takes the ticked observations where it is TRUE; a missing result
(density > 5 for an observation without a density) counts as FALSE.
The condition is saved with the model and evaluated again on the project's current data each
time the model is fitted or refitted: reopening the project, automatic fitting, a component
added or removed, Exclude the selection and refit, Refit with the VIP variables, the AIC
selection's Fit this model, Fit with CAR1. After a change to the data, a refit can take other
observations. The ticks don't change: clearing the condition brings back the observations it
set aside. The test set keeps its own ticks: the condition doesn't apply to it. The
observations the condition sets aside are out of the model, as unticked ones, so Predict
observations predicts them. A model imported from a .usp file keeps its file's observations;
Edit model on it makes a new model, which can take a condition. Two models with different
observations are never compared by their AIC.
The Methods text says "the 312 observations where site == "S1" & year >= 2010", the model's
summary and report give the condition, and Export to R writes it in R with the script's own
names for the variables: the ticked rows, the condition evaluated on every row of the table
with with(), then the ticked rows where it is TRUE, exactly Nuée's rows (a New variable function
it calls is written in the script).
Allowed in a condition: comparisons, &, |, !, xor(), %in%, :, arithmetic (+ - * / ^ %% %/%),
c(), is.na(), ifelse(), abs(), sqrt(), exp(), log(), log10(), log2(), log1p(), round(), floor(),
ceiling(), trunc(), signif(), as.numeric(), as.character(), nchar(), substr(), substring(),
startsWith(), endsWith(), tolower(), toupper(), trimws(), paste(), paste0(), mean(), median(),
min(), max(), sum(), quantile(), pmin(), pmax(), interaction(), and the New variable functions
group_mean(), group_deviation(), previous(), following() and growth_rate() (and their French
names). Nothing else: a condition is kept in the project file and run again at each fit, so a
project received from someone can't run other code through it (a New variable formula, typed
and computed once, is not kept and has no such limit). To keep that run quick and bounded, ":"
goes only between two whole numbers (year %in% 2005:2010) and over a range of at most 100000
values, and interaction() drops the empty combinations: a short condition can't build a huge
vector that would tie up a fit. For a diversity index (shannon()...), make it a New variable
first, then use that variable in the condition.

Windows
-------
In the centre, one tab per model ("M1 · PLS"), and a tab for each view of the project (Data,
Variable statistics, History). A model's tab is its page: its summary on the left, its scores
and loadings on the right; its other views (VIP, DModX...) join it as tabs. Choosing a model
in the explorer shows its page; closing a page's last view closes the page.
In a page as in the centre, views move by their tab (drag and drop), split and stack;
dragging a model's tab next to another one compares two models. Right-click on a tab, or the
icon at the top right of a group: detach into its own window (on a second screen, for
example), maximise, close.
Window › New window opens a second full window. A selection of observations (box or lasso in
a plot, click on a point or a list row) shows in every view and every window of the same
model.
Plots: mouse wheel to zoom; right-click to copy or save the image (PNG, SVG), see the
selection's contributions or make it a class.
Ctrl+C in a view that shows a table (summary, lists, statistics...) copies the table as
tab-separated text, to paste into Excel (a list: all its rows, at full precision); with text
selected, Ctrl+C copies the text as usual.
View › Find a command (Ctrl+K): type part of the name of a command or of its menu ("vip",
"export r"), then Enter.
Help › Diagnostic information: the versions of Nuée, the system, R and its packages, to paste
into a report of a problem (github.com/4rtefakt/nuee/issues; no paths, no data).

What matches the stored values (checked on 944 models from 133 .usp projects)
-----------------------------------------------------------------------------
Scaling, R2X, R2Y, scores, loadings, eigenvalues, T2 and its limit, DModX (plain and weighted)
and DCrit, VIP, coefficients, RMSEE.
The models of a file are fitted as the software that wrote it fits them: with missing values,
NIPALS sometimes converges very slowly, doesn't converge or has several solutions, and it stops
there as that software does (a relative change of 1e-5, 200 iterations at most), starts from the
same column and validates each component starting from the full model. So 805 PLS models out of
809 of the test corpus, and the 403 PLS models of the 2003 projects, give back their fit and
their Q2; the models Nuée fits itself keep its precision (1e-10).

What differs
------------
- Q2 (and what comes from the cross-validation: Q2 per variable, RMSEcv, CV-ANOVA, the
  cross-validated classification, confidence intervals): by default, Nuée predicts each group
  by a model fitted without it, its centres recomputed (see "Cross-validation"); the stored
  values come from a validation done with the centring and scaling of all the observations.
  Median difference from the stored Q2(cum), over the test corpus: 0.003 for PLS models with
  over 200 observations, 0.01 from 50 to 200, 0.10 from 20 to 50, 0.22 below, Nuée's Q2 being
  nearly always lower; 0.04 for PCA. With groups by an ID (a site, a sector), the difference is
  larger: the model fitted without a site doesn't know that site's mean level either. Validated
  with "Full model's centres and weights (like SIMCA)", the stored Q2 comes back exactly, groups
  by ID included: 805 PLS models out of 809 of the test corpus (220 out of 220 without missing
  data; the other four are those of a project whose fit differs, below), 441 out of 443 of four
  real projects (moteur/tests/verifier_references.R), where the other two have a round without
  any variation, whose stored value comes from rounding errors. For a PCA, it is off by 0.02 in
  median: the details of the files' validation aren't published.

- A version 11 project: its four PLS models, whose single Y has missing values. Their software
  counts the observations without y in the X weights, as if their Y residuals were ±0.99, which
  no rule found explains; R2 and Q2 are up to 0.04 off.
- Sign of the components of new models: arbitrary (imported models are oriented as in the
  file).
- Dendrograms: exact Ward method; the merges at the top of the tree may differ from those of
  the stored tree.
- Automatic fitting: the published rules, applied to Nuée's Q2, may choose another number of
  components; for PCA, the exact limit used in the files isn't published.
- VIP cut-off (step around 0.8): the application's own method.
- Confidence intervals of the VIPs of a model with two components or more (the VIPs themselves
  are the same): those of the program that wrote the file weight the components of each
  cross-validation round in a way that isn't published; with one component, they are the same.
- OPLS / OPLS-DA: no stored model to compare with (see above).
- Suggested transformation: the published rule doesn't say whether both skewness and Min/Max
  are needed; the application requires both.

--------

  regression.R           regression models (lm, nlme, mgcv), AIC, block contributions
  statistiques.R         T2, DModX, VIP, coefficients, intervals, limits
  validation.R           permutations, CV-ANOVA, PLS-DA classification and ROC curves
  opls.R                 OPLS and OPLS-DA
  diagnostic.R           contributions, data checks, variable statistics
  variables.R            scores as variables, classes, edited values, computed variables
  projet.R               reading projects, file history

  script.R               export of a model as a standalone R script or report
  methodes.R             Methods text and references

  modeles_classe.R       class models (one PCA per class), Coomans plot
