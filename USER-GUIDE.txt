NUÉE — PCA, PLS, PLS-DA and OPLS, computed in R
===============================================
(Guide en français : LISEZ-MOI-APPLICATION.txt)

Getting started
---------------
Two ways to install Nuée, without administrator rights; R is included in both.
- From the network share: double-click "Lancer Nuee.cmd". Windows can't start the
  application straight from a network share, so this launcher copies it to the computer (into
  %LOCALAPPDATA%\Nuee) and starts it there. The first copy takes one or two minutes; after
  that only the files changed on the share are copied again, and the application starts right
  away. On the first start, "Nuée" shortcuts are made on the desktop and in the Start menu:
  they start the application the same way (always up to date with the share).
- With the installer: double-click "Nuee-Setup-<version>.exe" and follow the steps (for you
  alone, or for every user of the computer).
Either way, Nuée appears in Settings › Apps › Installed apps, where it can be uninstalled;
projects and settings are kept.
If Windows shows "Windows protected your PC" (unknown publisher), click "More info", then
"Run anyway".

On Linux, Nuée uses the computer's R.
- Debian, Ubuntu and their derivatives: sudo apt install ./Nuee-<version>-amd64.deb also
  installs R and the R packages needed. Nuée appears in the applications menu.
- Other distributions: Nuee-<version>-x86_64.AppImage (make it executable, then run it) or
  Nuee-<version>-x64.tar.gz (unpack it, then run ./nuee). Install R first, then in R:
  install.packages(c("httpuv", "jsonlite", "openxlsx", "haven", "readxl", "foreign", "nlme",
  "mgcv", "MASS", "rpart", "cluster")).
.usp projects need python3. For another R than the PATH's: start Nuée with
RSCRIPT=/path/to/Rscript. Settings are in ~/.config/Nuee.

Opening
-------
File › Open (Ctrl+O):
  - a .usp project: the data, models and results stored in the file;
  - a project saved by the application (.nuee; .json for versions before 0.9.1);
  - a table, one row per observation:
      Excel .xlsx, .xlsm, .xls        text .csv, .txt, .tsv (separator, decimal comma and
      R .rds, .RData                    encoding detected, Excel's "Unicode text" included)
      SPSS .sav, .zsav, .por          SAS .sas7bdat, .xpt
      Stata .dta                      dBase .dbf, Weka .arff
      jamovi .omv                     spectra: JCAMP-DX .jdx, .dx, .jcm and SPC .spc (see Spectra)
    The first column names the observations if it holds text, or if it is called "ID", "Obs",
    "Name"... (for an R file, the row names). Other text columns whose values all differ (one
    code per observation) become secondary identifiers: they serve as labels but don't enter
    the models. The remaining text columns, R factors and labelled SPSS or Stata variables are
    qualitative variables (in the order of their categories). For a workbook with several
    sheets, or an R file with several tables, the application asks which one to open.
    A column of measurements with a few text cells (<0.5, <LOD, nd, n.d., #N/A...) stays a
    quantitative variable: those cells are read as missing, and the status bar says how many,
    in which variables (and which are below the detection limit). Excel dates and times stay
    dates (2024-05-03). A text file with a line holding more values than the header is refused,
    with the line number, rather than shifting the columns. An R file must hold tables; any
    other object is refused. R files open only with R 4.4 or newer (included on Windows): with
    an older R, such as that of Ubuntu 22.04 or 24.04 or Debian 12, a .rds or .RData file could
    run code as soon as it is read (CVE-2024-27322), so Nuée refuses it; save the table as CSV
    or Excel instead.
File › Paste a table (Ctrl+V): cells copied from Excel, LibreOffice, Google Sheets or jamovi
become a project (the first row gives the variable names). The project has no file yet: save
it (Ctrl+S).
File › Import spectra: files of spectra made into one project (see Spectra).
Dropping files on the window (drag and drop from Explorer) opens them the same way: JCAMP-DX or
SPC spectra together make one project, as Import spectra; other files each open as with File ›
Open. Double-clicking a .nuee project in Windows Explorer opens it in Nuée (in the window
already open, if there is one).
The last files opened are in File › Open recent.
To try it: Help › Example project opens 120 made-up apples (four varieties, organic or
conventional growing, a dozen measurements and a tasting score) with four ready models: a
PCA, a PLS of the score, a PLS-DA of the varieties and an OPLS-DA of the growing method. The
original table, vergers.csv, is next to it (resources\exemple), to try opening a table.

Saving and getting your work back
---------------------------------
File › Save project (Ctrl+S) writes the project (.nuee) with its data, its models and the current
session: fitted models, open panels and their layout, plot settings (axes, colours, labels,
titles), selections, VIP choices, dendrogram groups. When the project is opened again, the
models are refitted and everything comes back in place.
The project is written to a file next to the old one, which then takes its place: a network
cut or a full disk during the save leaves the old file intact. If another program keeps the
file open (a sync client, an antivirus), Nuée tries again for five seconds, then leaves it as
it was and says so: save again, or Save as.... If the file was changed elsewhere since you
opened or saved it (a colleague, on a shared folder; another window), Nuée says so and offers
Save as..., Overwrite or Cancel, also for a project recovered after a crash. The file also
records which versions of Nuée and R wrote it; a project saved by a newer Nuée is pointed out
when it opens.
Opening a file that is already open (a recent file, a double-click in Explorer) shows the open
project instead of opening a second copy.
Closing the application with unsaved changes offers "Save and close". Every two minutes it
also keeps a recovery copy of unsaved projects: if it stops without being closed (crash,
power cut), it offers to recover them at the next start. Closing that question without an
answer keeps the copies for next time; only "Ignore" deletes them.
Edit › Undo (Ctrl+Z) takes back the last change to a project's data (edited value, new
variable, class, scores as variables, deleted definition...), up to 20 steps back.
Notes: each model's summary has a notes area, saved with the project and included in the
report; a pencil marks it in the explorer.
Removing a model (Model › Delete model) asks for confirmation. Its definition stays in the
project; for a model made in the application, a checkbox removes it as well (undoable).

If the R engine stops
---------------------
The application says so and offers to restart it; you can also do it yourself (Help ›
Restart the R engine) if a computation doesn't finish. Projects reopen with their models and
views, from their recovery copy if they had changes, otherwise from the file they save to;
changes made since the last recovery copy (two minutes at most) are lost. Closing Nuée when
the engine no longer answers keeps the recovery copies, offered at the next start. After a
minute of computing, the status bar says so.
Help › What's new: the changes in each version (shown once after an update). The installed
copy (Nuee-Setup, or the Linux packages) looks for a new version at start-up (a single request
to GitHub, nothing else is sent) and mentions it in the status bar; on Linux, a click opens the
version's page. On Windows, one click offers to update: the
installer is downloaded and checked (its SHA-256 checksum must be the one GitHub gives), then
Nuée closes (offering to save the projects you changed), installs it and starts again. For an
installation for all users, Windows asks for permission. Help › Check for updates does the
same at any time, even with the start-up check off; Help › Look for a new version at
start-up turns the check off. The copy started from the network share doesn't look: it is
updated with the share.

The explorer (on the left)
--------------------------
Projects, data, models imported from a .usp file, fitted models and their views.
Double-click: open. Right-click: every action (fit, edit, add or remove a component,
export, delete...). Double-clicking an imported model refits it in R; the Summary marks each
value: "=" the same as the value stored in the file, "≈" close (less than 0.01), "≠"
different. Q2 nearly always differs: Nuée doesn't cross-validate the way the software that
wrote the file did (see "What differs").

New model (Model › New model)
-----------------------------
General tab: type (PCA, PLS, PLS-DA, OPLS, OPLS-DA, class models, linear regression, linear
mixed model, generalized linear model, additive model: see Linear, generalized and mixed
models; RDA and CA: see Redundancy analysis and correspondence analysis; decision tree, LDA
and k-means: see Decision trees, linear discriminant analysis and k-means), name, number of
components
(automatic by default, by cross-validation), cross-validation groups (in turn, G groups; or
one group per value of an observation ID or of a variable, see Cross-validation), default
scaling.
Variables tab: role (X, Y, class), scaling, block, modifier and transformation of each
variable: square root, fourth root, log10, or custom... (log10, ln or -log10 of C1*x + C2,
exp(C1*x + C2), C1*x + C2, the logit ln((x - C1) / (C2 - x)) between two bounds, or the power
(C1*x + C2)^C3; a value outside the domain becomes missing); the filter sets every variable shown at once (a block:
type it in "Block..." above the list, then Enter). Block scaling: the terms of a block have
their weight divided by the square root of their number, so that a block of 20 variables
doesn't weigh 20 times more than a variable alone; a qualitative variable counts by its
categories. Modifier: multiplies the variable's weight after its scaling. The "Proposed
transformations" button applies the suggested log10 to the variables shown (see Variable
statistics).
Cross terms tab: products of two or three X variables (A × B, A × B × C), squares (A × A) and
cubes (A × A × A); a qualitative variable enters through each of its categories, once at most.
Each cross term has its own scaling, block and modifier, as in the Variables tab.
Observations tab: tick / untick the model's observations, and the test set (see Test set).
"Edit model" (Ctrl+M) opens this window set like an existing model (imported models
included) and makes a new model.
Before fitting, the application checks the data: variables or observations with more than
50 % missing values, constant variables. If there are any, it lists them and offers "Exclude
them and fit" or "Fit anyway".

Plots: colours and labels
-------------------------
Scores, DModX, T², observed / predicted: the "Colour" list colours the points by class
(PLS-DA), by dendrogram group, or by any variable of the project (a gradient for a numeric
variable). The "Labels" list writes next to each point its name, a secondary identifier or the
value of a variable.
Right-click on a plot after a selection: "Make a class from the selection…" puts these
observations in a class of a qualitative variable (new or existing), to colour by or to use as
the classes of a PLS-DA.
Edit › Same selection in all the project's models (ticked by default): observations chosen in
one model are chosen in the project's other models too.
Highlighted variables: a click on a variable (a bar of the VIP, the coefficients or the
loadings, a point of the loadings, the biplot or the S-plot, a line of a profile, a row of the
variable list) highlights it in red on all the model's plots; a box picks several in the
scatter plots of variables. Esc clears the selection and the highlighted variables.

Other plots
-----------
Biplot: scores and loadings in one plot, scaled as correlations (t(corr) and p(corr), or
pc(corr) with the Y of a PLS), all inside the circle of radius 1.
3D scores: three components, turned with the mouse; a click picks a point.
S-plot (OPLS): p[1] against p(corr)[1]; the variables at both ends are those that carry the
link with Y (or that separate the two classes).

Formatting plots (for a paper, a report)
----------------------------------------
Right-click on a plot › Format plot, or Edit › Format plot: this plot's title and axis
titles; for every plot: font, text size, point size, colours (including a palette readable by
colour-blind people, and greys), grid, legend; and "Export image" at the size wanted (in
pixels, resolution ×1 to ×6) as PNG, SVG or JPEG. These settings are kept from one session to
the next.

Contributions
-------------
Plots › Contributions, or right-click on a selection: for an observation (or the mean of
several), each variable's share in its distance from the model's average observation. To
choose: contribution to DModX (why the observation is poorly modelled), to the score of a
component, or to T² (why it is far from the centre); weighted or not by the modelling power.

Predicting
----------
Predict › Predict observations: the project's observations left out of the model, or a prediction set
stored in the .usp file.
Predict › Predict a file: a table (in one of the formats above) whose columns carry the
names of the model's variables (ignoring capitals and spaces at the start and end; categories
by their name). The result gives the scores, DModX, T² and predicted Y; observations outside
the model's domain (DModX > DCrit or T² > T²Crit 95 %) are flagged; it exports to every export
format. X variables missing from the file are listed and treated as missing.
The plot above the table shows the scores, or DModXPS: each predicted observation's distance
to the model, compared with DCrit (the model's observations in grey).

Hierarchical models
-------------------
Model › Scores as variables: a model's scores become variables of the project ($M1.t1(title),
$M1.t2(title)...), which can be the X of a higher-level model. After changing the base model,
do this step again, then refit the models that use them (the application names them). To
predict a file with a hierarchical model, the base models are predicted first, automatically.

Exporting to other software
---------------------------
File › Export data: the project's table (observation names, identifiers, variables). File ›
Export model results (Ctrl+E): the model's tables (observations: scores, T², DModX, fitted
values; variables: loadings, VIP, intervals; components; coefficients; Y variables). Formats:
Excel (one sheet per table), CSV, tab-separated text, R (.rds: a list of tables; .RData), SPSS
(.sav), Stata (.dta), SAS transport (.xpt), jamovi (.omv), dBase (.dbf) and Weka (.arff); for
the last ones, one file per table ("M1.sav", "M1 - variables.sav"...). Qualitative variables
stay qualitative (R factors, SPSS and Stata value labels, jamovi nominal variables). For SPSS,
Stata, SAS and dBase, variable names are made valid (unaccented letters, digits, "_"); the
original name becomes the variable label.
SAS: transport format version 5, which SAS reads with libname xport (names of 8 characters,
labels of 40, text of 200 at most). dBase: text in Windows-1252; in LibreOffice, choose the
"Western Europe (Windows-1252)" character set when opening. The files written were opened in
jamovi, PSPP (for SPSS), Weka, LibreOffice and pandas.

Spectra
-------
File › Import spectra: choose one or more files (Ctrl+A in a folder takes them all); they
become one project, one row per spectrum, one column per wavelength (named by its value:
"1450", "3999.69"). Files read:
  JCAMP-DX (.jdx, .dx, .jcm)  every form (plain or compressed numbers: AFFN, PAC, SQZ, DIF,
             DUP), several spectra per file; not peak tables, nor NTUPLES (complex NMR, mass
             spectrometry);
  SPC (.spc)  Galactic (GRAMS, Thermo), new and old format, one or more spectra;
  text (.csv, .txt...)  a column of x values, then one column per spectrum, with or without a
             header row; the lines an instrument writes before the numbers are skipped.
A spectrum is named after its file (and the block's title or its number when a file holds
several). If the spectra don't all have the same x values, they are interpolated (linearly)
onto those of the first one, in the range they all share; the status bar says so. Different
units (nm and cm-1, absorbance and transmittance) are refused.
Information (optional): a table (Excel, CSV...) whose first column gives the name of each
file, with or without its extension, and the other columns information to join to the spectra
(contents, classes, batches); they come before the spectra. The status bar says how many
spectra didn't find their row. A single JCAMP-DX or SPC file also opens with File › Open, and
a file of new spectra on the same grid is predicted with Predict › Predict a file.

New model › General › Spectral preprocessing: each observation is a spectrum (its
quantitative X variables, in the order of the table), corrected before scaling by one to
three steps, in order:
  SNV        each spectrum centred on its mean and divided by its standard deviation;
  MSC        each spectrum fitted to the mean spectrum of the model's observations
             (x = a + b r), then replaced by (x - a) / b; a prediction uses that mean spectrum;
  Detrend    a degree-2 polynomial of the wavelength, fitted to the spectrum, is removed from
             it (Barnes et al., 1989; often after SNV);
  Baseline   the spectrum's lower convex hull (the segments joining its lowest points, from
             one end to the other) is removed from it; the corrected spectrum is zero or
             positive;
  Savitzky–Golay: smoothing, first or second derivative, in a window of n variables (odd)
             with a polynomial of degree d. Each range of neighbouring variables in the table
             is treated on its own: a window never reaches across a range left out.
The wavelength (for Detrend and Baseline) is the number read in the variables' names when
each has one, all different; otherwise their place in the table.
For spectra, one often centres without scaling ("Centring only" scaling). Only MSC depends on
the other observations (the mean spectrum): in cross-validation, each group is corrected with
the mean spectrum of the other observations. Plots › Profiles (spectra): loadings, coefficients, VIP,
or the spectra themselves (before or after preprocessing) as lines; the horizontal axis is the
number read in the variables' names ("1450 nm") when each has one; the lines break where
variables are out of the model. A click on a spectrum selects its observation.
Wavelength ranges: tick "Choose ranges", then drag across the plot (one or more ranges, in
orange); "New model without these ranges" (the water bands, for example) or "New model with
these ranges only" opens New model with the model's settings and those X variables, to check
before fitting. The model's other X variables (qualitative) stay.
Plots › iPLS (spectrum intervals), for a model with Y: the spectrum (the model's quantitative
X variables, in their order) is preprocessed once, whole, as for the model (with MSC, also
for each cross-validation group, with the mean spectrum of the other observations), then cut
into n intervals of the same width; each one is a PLS on its range (with the model's scaling
and its other X variables), with 1 to A components. A bar per interval gives its smallest RMSEcv (in
the units of Y, as in the summary), with that number of components written on it; in green,
the intervals that predict better than the whole spectrum (red dashes); the grey line is the
mean spectrum after preprocessing. Click bars to choose intervals, then "New model with these
intervals" or "without these intervals". Such a model preprocesses its own variables: with
SNV, MSC, detrend or baseline, its RMSEcv can differ from the bar's. Method: Nørgaard et al.
(2000), Applied Spectroscopy 54, 413–419.

Export to R (script, R Markdown, Quarto)
----------------------------------------
File › Export to R: a file that refits the model without Nuée, with R alone, to send to a
colleague or attach to a paper. The calculation is written for that model alone, in plain R
with no package (a regression: lm, or nlme and mgcv, which come with R), commented in the
export's language, in four parts:
  1. the functions: the NIPALS algorithm, the cross-validation, and only what this model
     uses (missing values, spectral preprocessing, OPLS...);
  2. the data, in the script or in a CSV file next to it ("M1 - donnees.csv"), numbers
     written without loss and categories in their order;
  3. the model: its X and Y terms (transformations, categories, cross terms), their
     scaling, the fit, then R2 and Q2, T2 and DModX with their limits, VIP, coefficients,
     CV-ANOVA, classification for a PLS-DA, test set;
  4. the results: the tables, the permutation test (commented out) and the plots (scores,
     loadings, VIP, observed / fitted, T2 and DModX).
Format: R script (.R); or an R Markdown (.Rmd) or Quarto (.qmd) report, which adds the
Methods text, tables and plots (scores, loadings, VIP, observed / predicted, T2, DModX) and
the references; it compiles in RStudio (Knit button) or with quarto render, and needs the
knitr package. Extra files, as you choose: renv.lock (versions of R and packages, for
renv::restore()), the data and fitted model as .RData (load() gives them back without
refitting), an RStudio project (.Rproj, best in a folder of its own).
Models: this one, or all the models of the session (the latest fit of each) in one .R
script: the functions and the data once, then a block per model under its name (M1,
M2...).
Before writing, the application refits the script's models and checks they give the same
results; otherwise it says so.

Methods text
------------
Model › Text for the Methods section: a paragraph written from the model, in French or
English (data, transformations, scaling, spectral preprocessing, method, cross-validation, R²,
Q², CV-ANOVA, classification, software and R version), with its references. "Copy the text"
button. Read it over and complete it (experimental design, sampling...) before publishing.

R console
---------
View › R console (Ctrl+J): a panel below the tabs, with
  - the log: for each action of the application, the call it made to the engine, written in
    R (P1 <- lire_projet(...), d <- modele_du_projet(P1, 5), M4 <- ajuster(P1, d)...), to copy
    into a script (Copy button), and for each fitted model what R prints of it (components,
    Y, limits, variables, observations; print(M4) does the same); the "Application actions"
    box hides or shows them;
  - a prompt to type R, run in the application's R session. m is the model shown, p its
    project; P1, M4... the open projects and models, by their names in the log. For example:
    m$statistiques$variables, summary(p$donnees), plot(m$T[, 1], m$T[, 2]) (the plot shows in
    the console), modeles(), projets(), definition("M4").
    Enter runs the command, Shift+Enter starts a new line, ↑ and ↓ recall commands.
    Tab completes the name begun: objects, m$... and p$... (the names they hold), the
    arguments of the function whose parenthesis is open; when several fit, a list opens
    (arrows, then Tab or Enter). The application's shortcuts (Ctrl+S, Ctrl+K...) also work
    while typing.
Changing a project in the console (p$donnees[...] <- ...) changes it in the application.
Correcting the engine: dossier_moteur() gives the folder of the application's R files; after
a correction, recharger_moteur() reads them again, then refit the model. For the copy started
from the network share, this folder is the copy made on the computer: at the next start, the
share's copy replaces it; to keep a correction, make it in the same file on the share
(application\resources\moteur\R).
A long command blocks the application until the computation ends.
Checking the engine: verifier_moteur() refits the imported models of the open projects and
compares them with the values stored in their files (R2X, R2Y, Q2); verifier_moteur("folder")
does the same for the .usp and .json files of a folder. To do after a correction of the
engine. Q2 is shown but left out of the verdict: Nuée's cross-validation isn't the files' (see
"What differs").

Model report
------------
File › Model report (or right-click on the model): a PDF or Word (.docx) document with a
title, a comment and the parts ticked (summary, scores, loadings, DModX, VIP, coefficients,
CV-ANOVA, classification, list of variables...). Plots are formatted as in their open panels.
The document opens once written.

Variable statistics
-------------------
Plots › Variable statistics (or in the explorer, under the project): for each variable N,
missing values, min, max, Min/Max, mean, median, standard deviation, standard deviation /
mean, skewness, skewness test and kurtosis. In red: Min/Max < 0.1 and a skewness test beyond
2; the "Suggested" column gives the log10 advised (with the constant C2 if there are zeros).
A click on a row shows the variable's histogram, next to that of the transformed variable.
The other view is the map of missing values (observations × variables).

Series
------
Plots › Series (or in the explorer, under the project): a variable over time, like figures of
series by sector, one page per site. Choose the variable, the time (a numeric variable, or an
ID made of numbers like the year), the lines (a qualitative variable or an ID: the sector)
and, optionally, the panels (the site): one small plot per panel, in a grid with shared axes.
Within a line, times that follow each other at its own step (its smallest gap) are joined, so a
sector counted every other year stays one line; a missing time breaks the line, so a year
without a count shows. Colours go by line within each panel and the legend is grouped by panel
(a click on an entry hides its line): it stays readable with 30 sectors. Optionally: the mean
of each panel's lines, time by time (a thick line), a log scale (values ≤ 0 aren't shown on it)
and events, times typed as "2015; 2019", drawn as dashed lines in every panel. Hovering gives
the observation's name, the time and the value; a click or a box selects observations, also in
the project's models when the selection is shared with them. Observations without a time, a
value, a line or a panel are left out and counted; a line with the same time twice (sectors
chosen without their site) is flagged and shown as points. Right-click: copy or save the image.

Statistical tests
-----------------
Plots › Statistical tests (or in the explorer, under the project), in four modes chosen at the
top left.

Between classes, variable by variable: each quantitative variable compared between the classes
of a qualitative variable.
  Two classes (A, the reference, and B): Welch's t test (the default, unequal variances),
  Student's t or Mann–Whitney (on ranks). Effect: log2 of the ratio of the means B / A (when
  both means are positive) or Cohen's d. Volcano plot: the effect against -log10(p).
  Two classes paired by a key ("Pair by": a variable or an observation ID, the year for two
  sectors followed over the same years): for each variable, the rows of A and B that share a
  key, and have a value, make the pairs, and the differences B − A go through the paired t
  test (the default) or Wilcoxon's signed-rank test. The table gives each variable's number of
  pairs and the means of A and B over those pairs; the effect is log2 of the ratio of those
  means (when both are positive) or Cohen's d_z (the mean difference over the standard
  deviation of the differences). A variable with fewer than three pairs is not tested. A key
  may appear only once per class: one repeated within A or B is refused, as in "Two
  variables".
  All classes: one-way ANOVA or Kruskal–Wallis; the variables ranked by p.
p values are corrected for multiple comparisons: Benjamini–Hochberg (false discovery rate, the
default), Bonferroni, or none. In colour: the variables whose corrected p passes the threshold
(and, for two classes, whose effect does too).

Two variables: the test their types call for, its conditions checked, on the observations where
both are known. An observation ID (site, sector, year...) can make the groups, like a
qualitative variable.
  Two qualitative variables: the contingency table and Pearson's chi-square test of
  independence, with Cramér's V. In red and in blue, the cells more or less frequent than if the
  two variables were independent (adjusted residual beyond ±1.96). When the expected counts are
  too small for the chi-square test (one below 1, or more than 20 % below 5: Cochran's rule),
  Fisher's exact test is recommended; for a 2 × 2 table it is always given, with the odds
  ratio. Beyond 2 × 2 and 200 observations, its p value is simulated (100,000 tables).
  A measurement and a qualitative variable: the measurement compared between the groups, in box
  plots. Two groups: Welch's t test and Mann–Whitney (exact below 50 values on each side with
  no ties; otherwise by the normal approximation with continuity correction: the same
  calculation on every R version). More: one-way ANOVA, Welch's ANOVA and Kruskal–Wallis, each
  with its pairwise comparisons (Tukey, Games–Howell, Dunn with Holm's correction; up to 50
  groups): a click on a test shows them. The rank test is recommended when normality is
  doubtful in a group (Shapiro–Wilk p < 0.05, or fewer than three observations), Welch's ANOVA
  when the variances differ (Brown–Forsythe p < 0.05).
  A measurement and a qualitative variable, paired by a third variable or ID ("Pair by": the
  year, for two sectors of a site followed over the same years): the data stay in long format,
  one row per sector and year. Two levels A and B are compared on the keys both have: the
  differences B − A by the paired t-test (mean difference, its 95 % interval, Cohen's d_z) and
  by Wilcoxon's signed-rank test, the rank test recommended when the normality of the
  differences is doubtful (Shapiro–Wilk p < 0.05; not tested beyond 5,000 pairs, nor with
  constant differences, which leave Wilcoxon alone). Wilcoxon's p is exact below 50 pairs
  when no difference is zero or tied; otherwise the zero differences are dropped and p comes
  from the normal approximation with continuity correction, the same on every R version. At
  least three pairs are needed, and a key may appear only once per level. The rows left
  without a partner, and those without a value, are counted and listed; the plot joins each
  pair. With three levels or more, the table below can also list every pair of levels, each
  on its own shared keys, with Holm's correction over the pairs tested, for the test chosen
  above (a click on a test): when all the levels share the same keys, those of
  pairwise.t.test() and pairwise.wilcox.test() with paired = TRUE. A pair not tested (fewer
  than three shared keys, a key twice in a level, the same value in every pair) says why, and
  a click on a pair compares it; when A and B can't be compared, the table stays, under their
  reason. "Pairs of levels within each" (a qualitative variable or an ID: the site) keeps to
  the pairs of levels of the same group, the sectors of each site compared two by two. Holm's
  correction covers the pairs tested, all groups together; the raw p reads one site at a
  time. A level belongs to the group its rows carry: one with rows in several groups is
  refused, and those without a group are listed.
  Two measurements: Pearson's and Spearman's correlations; Spearman is recommended when
  normality is doubtful for either. Paired by "the observation (same row)", two measurements
  of the same rows (before and after, say) are compared instead: the differences
  Variable 2 − Variable 1, on the observations where both are known, by the same two paired
  tests.
The recommended test's result comes as a sentence ready for a report (copy it with the button
next to it), with its effect size: Cramér's V, odds ratio, Cohen's d or d_z, rank-biserial
correlation, η², ε², r or ρ. Mann–Whitney's names both groups with their medians.

Correlation matrix: the Pearson or Spearman correlations of all the quantitative variables (300
at most), each pair on the observations where both are known, p values corrected for the number
of pairs. A click on a pair, in the table or the plot, tests it in "Two variables".

Before/after (BACI): a change of management on some units (the impact) compared with units
left as they were (the controls), as in a before-after control-impact design. Choose a
quantitative response, a time (a quantitative variable or an observation ID: the year) and a
unit (a qualitative variable or an ID: the sector), then tick the impact unit(s) and the
control unit(s). At each time, the gap d_t is the mean of the impact rows minus the mean of
the control rows, at the times where both have a value (one row per unit and time gives the
mean of the units; the times with one side only are listed and left out). The event is the
first time counted as "after": for a spring density that responds to the previous year's
management, the year after the change. The times before it are "before"; "after" runs to an
optional end, the later times shown in grey, out of the test. With at least two times in each
period, the gaps after are compared with those before: Welch's t test (the default),
Student's t (equal variances: a linear model of the gap on the period) or Mann–Whitney (on
ranks); the effect is the change in the mean gap, after minus before, with its 95 % interval,
and the result comes as a sentence ready for a report. The plot shows the gaps over time, the
event and each period's mean; until an event is entered, the gaps alone. The times are treated
as independent: successive gaps that resemble each other (autocorrelation) make the p value
too small. A mixed model accounts for it: y ~ period × impact + (1 | unit), with CAR1 in time
if needed (New model › Linear mixed model). Make the period and the impact as new variables
worth 0 or 1, ifelse(year >= 2007, 1, 0) and ifelse(sector %in% c("S1", "S2"), 1, 0): a
regression doesn't take a cross term with a qualitative variable yet.

Linear, generalized and mixed models
------------------------------------
New model › type "Linear regression" or "Linear mixed model": one quantitative Y, the X
variables of the Variables tab (transformations and cross terms included; a qualitative
variable through its categories, one of them the reference). Without X: the null model, useful
to compare AICs. The default scaling keeps the variables' units (coefficients per unit); UV
gives coefficients per standard deviation.
A mixed model (nlme) adds nested random effects, the widest first: a random intercept for each
site, then for each sector within its site (an observation ID or a qualitative variable). It
can add an autocorrelation in time (CAR1, continuous time: missing years are fine; the time is
a numeric ID or a quantitative variable) within the last level or, through "within each",
within a finer one that has no random effect of its own: the sector within its site, when only
the site has a random effect. Coefficients and variances are
estimated by REML; the log-likelihood, AIC, AICc and BIC come from the ML fit, the only one
that compares models with different fixed effects. Cross-validation defaults to the first
random effect: each site is predicted by the fixed effects of the model fitted without it, as a
site never seen.
Type "Generalized linear model (GLM)" or "Additive model (GAM)" (mgcv), for a Y that isn't
normal. Distribution of Y: Poisson for counts; negative binomial for counts that vary more than
a Poisson allows (its θ estimated); binomial for presence-absence (0 or 1); gamma for positive
values; Tweedie for densities with zeros (its power p estimated); or normal. The link is log
(counts, gamma, Tweedie), logit (binomial) or identity (normal). Effort (offset): a variable
such as an area, a duration or a number of visits, whose log enters the model with a
coefficient of 1, which then describes a density (an effort of 0 or less is refused). Random
effects as above make a GLMM or a GAMM. With the normal distribution and at least one random
effect, a GLM or GAM can take the autocorrelation in time too: it is then fitted by
mgcv::gamm, as an nlme mixed model whose curves are random effects (coefficients, curves,
variances and φ by REML; logLik, AIC, AICc and BIC from an ML fit, comparable only with other
models fitted that way). With another distribution it is refused: mgcv::gamm would use
penalized quasi-likelihood (PQL), with no true likelihood nor AIC. In an additive model, the X
variables ticked in the Curve column of the Variables tab enter through a smooth curve (a
spline) instead of a straight line, for an effect that rises then falls, or a threshold; the
data decide how curved it is (its edf; 1 is a straight line). Its basis dimension k bounds how
curved it can be: 10 at most, less when the variable has few values; type another one (3 to
100) in the box beside the tick, as s(x, k = 5) does in R. Curves and random effects are
estimated by REML, and the AIC comes from an ML fit; a GLM without them is fitted by maximum
likelihood, as glm() and MASS::glm.nb() do. The Summary of a Poisson model warns when the
counts are overdispersed (Pearson's chi-square above 1.5 times its degrees of freedom): its p
values are then too small, and the negative binomial suits the counts better.
R formula (General tab): the model written as in R, for instance
  y ~ a * b + log10(c) + I(a^2) + s(d) + offset(log(effort)) + (1 | site/sector).
Edit it, then Apply (Ctrl+Enter): it sets the variables and their transformations (log,
log10, log1p, exp, sqrt, I(x^p), I(a * x + b), the logit log((x - a) / (b - x))), the cross
terms (a:b; a*b for a, b and a:b; I(a^2) when a is in the model too, else the square of a), the
curves s(x) or s(x, k = 5), the effort offset(log(x)) and the nested random intercepts
(1 | site/sector), the widest first.
A curve makes the model additive, random effects make it mixed. R reads the formula without
ever running it: anything else (another function, code) is refused with the reason, and the
formula isn't kept, only the settings it gives.
Views: Summary (R2, or marginal and conditional R2 for a mixed model, Nakagawa and Schielzeth;
adjusted R2 and deviance explained for a GLM or GAM (marginal and conditional R2 when fitted by
mgcv::gamm, the curves in the fixed part), with each curve's edf, test and concurvity (the
share of the curve the other terms reproduce; above 0.8, in red, it is confounded with them);
Q2 and RMSEcv; AIC; the variance of each random effect and its share; φ of the
autocorrelation), Coefficients (each term's effect with its 95 % interval, red when p ≤ 0.05;
with a log link, exp(estimate) is the multiplicative effect of one unit more, with the logit
the odds ratio),
Effects (each quantitative term's effect as its variable varies, the others fixed, with its
95 % band and the observed values below it: a GAM's curves, straight lines otherwise; on the
scale of the link, log or logit, when there is one; for a curve, Thresholds: the effect and its
slope with 95 % simultaneous bands from 2000 draws of the coefficients, the ranges where the
slope's band excludes 0, clearly rising or falling, shaded and listed, and the edf, below 1.5
nearly a straight line, as Simpson (2018) reads thresholds), Observed / predicted, Residuals
(standardized, against the fitted values, normal Q-Q plot, by group of a random effect; Cook's
distance for a linear regression; the quantile residuals too for counts, presence-absence and
positive values, below), Block contributions (AIC): each block of the Block column
(or each variable) removed and the model refitted by ML; ΔAIC above 2 means the block clearly
improves the model, a likelihood-ratio test gives its p. Observations with a missing value in
Y, X, a random effect, the time or the effort are left out (the summary counts them).
Residuals of a GLM or GAM with the Poisson, negative binomial, binomial or gamma distribution:
beside the standardized deviance residuals (the default), the randomized quantile residuals of
Dunn and Smyth (1996), r = Φ⁻¹(u), F the model's distribution at each observation's fitted
value (its random effects and effort included; the negative binomial with its fitted θ, the
binomial with one trial, the gamma with the shape 1 / its estimated scale): u = F(y) for the
gamma, and for counts or 0/1 u drawn uniformly between F(y − 1) and F(y), with a fixed seed, so
that the plot doesn't change from one look to the next (the session's random numbers are left
as they were). The Pearson or deviance residuals of counts are far from normal even when the
model is right; these residuals are normal when it is. Not offered for Tweedie (no distribution
function in the packages that come with R) nor for the normal distribution, where they would
be the standardized residuals.
Plots › Residual autocorrelation: the autocorrelation of a regression's residuals in time
within each group, the groups pooled, as nlme::ACF computes it: at lag k, observations k steps
apart in their group's time order (a missing year is skipped), lags 0 to 10 at most, with the
band ±1.96/√n of each lag (n: its pairs), as nlme draws it. A model with CAR1 keeps its time
and groups and shows two series: its residuals without the autocorrelation, and its normalized
residuals, which show none left when CAR1 is enough (the note reads lag 1). For another model,
choose the time (an ID or a quantitative variable: the year) and the groups: by default those
of its random effects (the sector within its site), otherwise an ID or a qualitative variable;
either can take a finer level within it (the sector within the site of a random effect, or a
sector whose names repeat from one site to another). Beyond the band at lag 1, the note
suggests a CAR1 autocorrelation, to compare by AIC. For a GLM or a GAM, Pearson residuals
((y − fitted) / √variance) or deviance residuals (each observation's signed share of the
deviance), the same for the normal distribution; a mixed model's residuals are those within its
groups (given the random effects), as in nlme::ACF. Nuée computes the normalized residuals in
each group's time order: nlme's own are right only on rows sorted by group, then by time.
Within the groups of its random effects, with or without a finer level, Fit with CAR1 makes it
a new model: the same settings with a CAR1 autocorrelation along that time within those groups
(an LMM, or a GLM or GAM with the normal distribution, then fitted by mgcv::gamm; the button is
offered only then, and a refusal of the engine is shown), named like a refit (M1 (1)) and
selected with its default views open. An LMM on the same observations stays in the AIC set of
the model without CAR1: the two compare by AIC in Prediction › Compare models (the
likelihood-ratio test doesn't test an autocorrelation). The note says when they don't:
observations without a time or a group stay out of the new model, and mgcv::gamm's likelihood
doesn't compare with mgcv::gam's.
File › Model report can include the plot.
Plots › AIC selection (also under each regression in the explorer): which variables to keep.
Each combination of the model's groups of terms (the blocks of the Block column, otherwise the
variables), from the null model to the full model, is fitted by ML on the same observations and
ranked by AICc; a cross term or a square enters only with its main effects. Only the fixed
effects are chosen: the random effects, the autocorrelation, the effort and the curves'
settings stay those of the model. Up to 8 groups (256 combinations), every combination is
fitted (a mixed model with CAR1 on 240 rows takes about 10 s); beyond, a backward elimination
from the full model removes, step by step, the group whose removal lowers AICc the most. The
view suggests the best model (lowest AICc) and, when it differs, the most parsimonious within
ΔAICc ≤ 2 (fewest parameters; Burnham and Anderson, 2002); it plots each group's importance
(the sum of the Akaike weights of the models that contain it) and lists the 20 best models, or
those within ΔAICc < 10, with a column per group, k, logLik, AICc, ΔAICc, the weight and the
cumulative weight. Fit this model, on the suggestion or on any row (click the row first), makes
it a new model: the same settings with only those groups' variables (a cross term keeps its
factors), on the same observations, fitted as usual (REML for the estimates) and named like a
refit (M1 (1)). Once the selection has run, the Methods text describes it, the model report can
include it, and Export to R redoes it.
Prediction › Predict observations, Predict a file: Y predicted by the fixed effects (for a
mixed model, a group never seen), on the model's scale of Y (its transformation included), next
to Y observed when it is known. A file's columns are matched to the model's variables by name,
the effort included (without it, the predictions are for an effort of 1, and the note says
so). ⚠ marks a value outside the range of the model's observations: an extrapolation.
Prediction › Compare models: Q2 and RMSEcv for every model; AIC, ΔAIC and Akaike weights (the
probability that each model is the best of its set) between the regressions of the same
response on the same observations only (an "AIC set", lettered A, B...), and only those whose
likelihoods compare: Poisson and negative binomial models of the same counts, but not a normal
model of them; Tweedie models with each other; GLMMs and GAMMs (mgcv's conditional likelihood)
with each other.
Under the AIC table, Nested models: the likelihood-ratio test between each pair of nested
regressions of the same AIC set, as anova(m1, m2) on ML fits. The smaller model's fixed terms
are among the bigger one's (its columns lie within the bigger one's), with the same
distribution, effort, random effects and autocorrelation; χ² = 2 × (logLik of the bigger −
logLik of the smaller) on Δdf, the difference in their numbers of parameters, and its p. For
linear regressions and GLMs it is the difference of their logLik (of their deviances for a
Poisson or binomial GLM, as anova(glm1, glm2, test = "Chisq")). Random effects and
autocorrelation aren't tested this way: a zero variance is on the boundary of its range,
where the χ² distribution no longer holds; compare them by AIC. With curves or mgcv random
effects, the df are edf and the test is approximate, as the table says. Every nested pair is
listed (2000 at most); the table's search box finds those of a model.
File › Export: the observations (observed, fitted, predicted in cross-validation, residuals),
the coefficients, the fit statistics, the random effects and the curves, a table each. File ›
Model report: the summary and the coefficients, each term's effect, each curve's thresholds,
observed / predicted and the residuals (the quantile residuals too, for counts, presence-absence
and positive values).
File › Export to R: a script or report for a regression too, with lm, nlme::lme, mgcv::gam
or mgcv::gamm: its rows and terms, the fits (REML and ML), the cross-validation by its groups,
then the coefficients, AIC, R2, variances, curves with their concurvity and thresholds (the
same draws as the Thresholds view), the quantile residuals (the same draws as the Residuals
view), test set and plots, checked against Nuée's results before it is written.

Class models and the Coomans plot
---------------------------------
New model › type "Class models": one PCA per category of the class variable, on the
observations of that category only ("M5.Gala", "M5.Golden"...), each with its own centres,
scaling and number of components. An observation belongs to a class when its distance to the
class's model (DModX) doesn't exceed the 5 % DCrit limit: to one class, to several, or to
none (an observation of another kind than all the known classes). Plots › Coomans plot: each
observation's distances to two of the models, with their limits in red; the table gives, for
each class, the share of its observations each model accepts (expected: about 95 % for its
own class, 0 % for the others), then each observation's distances and classes.

Redundancy analysis and correspondence analysis
-----------------------------------------------
New model › type "RDA (redundancy analysis)": how much of a table of responses Y (species
abundances, measurements) the explanatory variables X explain, and how. Y: quantitative
variables; X: the explanatory variables (a qualitative one through its categories, cross terms
included); Z (covariate, in the Role list of the Variables tab): variables whose effect is
removed first (partial RDA: the site, a known gradient...). General tab: the transformation of
the responses (Hellinger or chord for abundances, Legendre and Gallagher 2001; log(x + 1); or
none); the responses centred (covariance RDA, for responses in the same units) or standardized
(correlation RDA); the number of permutations of the tests (999; 0: no test), the groups they
stay within (an observation ID or a qualitative variable: a site followed over several years is
permuted only with itself) and their seed (the same seed gives the same permutations, hence the
same p values). An observation with a missing value, or with no abundance under Hellinger or
chord, is left out.

Views: Summary (the total inertia, the covariates' share, the X's share and what is left; R2
and adjusted R2; the pseudo-F and its permutation p); Ordination, the triplot (the observations
by their wa scores, weighted sums of the responses, or lc scores, linear combinations of the X;
the responses; an arrow per quantitative X, lengthened to fill the plot by the factor shown in
the legend, and a triangle at the centroid of each category; scaling 1 keeps the distances
between observations, scaling 2 the correlations between responses); Eigenvalues (constrained
axes in blue, unconstrained ones in grey); Permutation tests (each constrained axis after the
previous ones, each term after all the others; Forward selection keeps a term that raises the
adjusted R2 without going beyond that of all the terms and whose test gives p ≤ 0.05, Blanchet
et al. 2008; Variation partitioning splits the adjusted R2 between two or three blocks of X,
from the Block column of the Variables tab); the lists of observations and variables. The
results are those of the vegan package (rda, anova.cca, RsquareAdj, ordiR2step, varpart): the
same eigenvalues, scores and pseudo-F, and for the same permutations the same p values.

Type "Correspondence analysis (CA)": a table of counts or abundances (the X variables, one
observation per row, positive or zero values); observations and variables without any value are
left out. Views: Summary (the total inertia: the table's chi-square divided by its grand
total); Ordination (rows and columns in scaling 1, 2 or 3: chi-square distances between
observations, between variables, or symmetric); Eigenvalues; Contributions and cos² (each row's
and column's share of an axis's inertia, in blue above the mean, and the quality of its
representation); the lists.

Both export their tables (File › Export), write their Methods text with its references and make
a report. File › Export to R writes a script, or an R Markdown or Quarto report, that redoes
them with R alone, their tests with the same permutations. They don't predict new observations.

Decision trees, linear discriminant analysis and k-means
--------------------------------------------------------
New model › type "Decision tree" (rpart): a quantitative Y variable (regression tree) or a
class variable (classification tree), and X variables by their raw values, so that the
thresholds read in their units; missing X values are handled by surrogate variables.
General tab: at least 20 observations per leaf, but at most a sixth of the observations, so
that the tree can split (a node is split only if it holds three times as many), at most 5
levels, cp = 0.001, 5 surrogates, pruning by the 1-SE rule (the smallest tree within one
standard error of the minimum error) or at the minimum error. The pruning comes from an
internal cross-validation by the cross-validation groups (for sites followed over several
years, choose the site), and Q2 from an external cross-validation: each group is predicted by
a tree entirely rebuilt without it. Views: Tree (a click on a node selects its
observations), Pruning, Leaf rules, Variable importance, First-split stability (200
bootstrap draws of the groups: the share of the draws where each variable makes the first
split, and its median threshold), Observed / predicted and Residuals, or Classification
for a classification tree. Test set and Predict: a new observation follows the tree,
surrogates included.

Type "Linear discriminant analysis (LDA)" (MASS::lda): a class variable and X variables by
their raw values; prior probabilities proportional to the class sizes or equal. Each
observation goes to the class of largest posterior probability; cross-validated, each
group is classified by the model fitted without it. Views: Discriminant scores,
Discriminant coefficients (structure correlations, coefficients in the variables' units
or for variables of standard deviation 1), Classification, Posterior probabilities. Test
set and Predict.

Type "k-means": X variables scaled as the Variables tab says (UV by default), k clusters
(Hartigan and Wong algorithm, 25 starts, seed 1), numbered from the largest to the
smallest; an observation with a missing value is left out. Views: Clusters (on the first
two principal components), Silhouettes, Choice of k (2 to 10: within-cluster sum of
squares and mean silhouette), Cluster centres. "Clusters → variable" adds the clusters to
the project as a qualitative variable (Edit › Undo removes it); Predict assigns a new
observation to the cluster of the nearest centre.

For all three: Methods text with its references, Export, PDF or Word report, Export to R
(a script or an R Markdown / Quarto report that redoes the analysis with rpart, MASS or
cluster, which come with R). Compare models shows a regression tree's Q2 and RMSEcv beside
the other models.

Editing the data, making variables
----------------------------------
In the Data view, double-click a cell to edit it (Enter to keep, Esc to cancel; empty =
missing value; for a qualitative variable, the category's name). Models already fitted don't
change: refit them.
Edit › New variable: from an R formula on the other variables and the observation IDs, for
example log10(polyphenols), sucre / acidite, ifelse(poids >= 170, "gros", "petit") (a text
result gives a qualitative variable); by group, group_mean(x, sector), the mean of x in each
observation's group (missing values ignored; an observation without a group gets none), and
group_deviation(x, sector), the deviation from it (moyenne_groupe and ecart_groupe in
French): a sector mean as a covariate, or a response centred by sector. Or classes from the
values of a variable, at given limits (10 ; 20 gives "≤ 10", "]10 ; 20]", "> 20") or in
classes of equal size. Or Imputation (PCA): the chosen quantitative variables' missing values
filled from each other by regularized iterative PCA, as missMDA::imputePCA does, with the
number of components chosen by generalized cross-validation of the standardized variables,
from 0 to 5, as missMDA::estim_ncpPCA does on them (0: each variable's mean), unless you give
it; observed values unchanged, an observation missing more than half of them left missing,
imputed values kept within each variable's observed range unless unticked; as new variables
"x (imputed)" or in the variables themselves (Ctrl+Z undoes it). Remember to save the project.
In a New variable formula, from one year to the next: previous(x, year, sector), the value of x
the year before in the same sector, and following(x, year, sector), that of the year after
(pas = 2: two years before or after). The year sought must exist: a missing year gives a
missing value, never that of an older year, as does an observation without a sector or a year.
The time is numeric (an ID made of numbers, like the year, will do); the group, a qualitative
variable, an ID or interaction(site, sector) for a sector within a site; the same sector twice
in one year is refused, naming it. growth_rate(x, year, sector) gives the growth rate log(x / x
of the year before), missing unless both values are positive: for density dependence, the
growth rate against previous(density, year, sector). In French: precedent, suivant and
croissance.

File history
------------
For a project from a .usp file, the explorer shows "File history": the log stored in the
file (creation, working-set changes, number of components, deleted models...), with the
date, the software version and the user. Right-click on an imported model › Model history:

OPLS and OPLS-DA
----------------
Predictive components, which carry what in X is related to Y, and orthogonal components,
which describe the rest of X's variation: scores and loadings are easier to read (t[1]
against to[1], S-plot). One predictive component per Y variable, or one fewer than the
classes for OPLS-DA (t[1], t[2]... then to[1], to[2]...); with just one, the predicted values
are those of a PLS with the same number of components. With several Y (or more than two
classes), each orthogonal weight is made orthogonal to the weights X'y of every column of Y,
so the orthogonal components are not related to Y at all (since 0.9.0; version 0.8.0 left a
slight link: the OPLS models with several predictive components it made change a little when
refitted). Q2 by cross-validation, as for the other models (see below). None
of the .usp projects available had an OPLS model: this computation follows Trygg and Wold's
paper (2002), with no stored values to compare with; it is checked against a second writing
of the paper's algorithm.

VIP
---
The cut-off is placed automatically at the largest step in the sorted VIPs around 0.8. You
can type another cut-off or drag the red line, and Ctrl+click a bar to keep or drop a
variable (a plain click highlights it on the model's other plots).
"Refit with VIP variables" makes the model again with the variables kept.

Cross-validation
----------------
The model's observations are assigned in turn to G groups (7 by default: the 1st, 8th, 15th...
in group 1), or one group per value of an observation ID or of a variable (New model ›
Cross-validation groups): with "site", all the years of a site are in the same group, and each
site is predicted by a model that has never seen it; observations without a value make a group
of their own. Models from .usp files keep their groups: by an ID when the file groups the
observations with the same value, or else the file's groups as they are (shown "groups from the
file"). Each group is predicted by a model fitted without it, like new observations: the
centring, the scaling (and MSC's mean spectrum, the cross terms) are computed again on the
other observations, with the same number of components. PRESS: the sum of squared prediction
errors; Q2(cum) = 1 - PRESS / SS (SS: the variation of Y, or of X for a PCA); a component's Q2,
1 - PRESS / PRESS of the previous one. PCA: each value is predicted by the scores of its
observation computed without the variables of its group of variables (also assigned to G
groups). This Q2 sees nothing of the observations it predicts: with few observations, it is
much lower than a validation done with the scaling of all the observations (on pure noise, 6
observations and 20 variables, the latter gave Q2 = 0.98 for an OPLS-DA; Nuée now gives less
than 0). RMSEcv, CV-ANOVA, the cross-validated classification and the confidence intervals
(jack-knife, over the G sub-models) come from it.

Validation (PLS and PLS-DA)
---------------------------
Permutation test: the values of Y (for a PLS-DA, the classes) are shuffled among the
observations 20 times (or more) and the whole model refitted, cross-validation included; the
intercepts of R2 and Q2 measure overfitting (a valid model if Q2 < 0.05 and R2 < 0.3 to 0.4,
the usual rule).
CV-ANOVA: the model's p (cross-validation residuals against the mean); also in the Summary.
Classification (PLS-DA): table of the observations correctly and wrongly classified, with
the fitted or cross-validated values, and ROC curves with their area (AUC).

Test set
--------
New model › Observations › Test set: observations left out of the model and of the
cross-validation, then predicted by it, to judge its predictions on data it hasn't seen.
"Test" column: by hand; "Selection to test set": the active model's selection; "Choose": a
share of the observations (25 % by default), at random or by Kennard–Stone (which keeps for the
model the observations furthest apart, so that it covers the whole range of the data, and
leaves the others for the test); by class for a PLS-DA, so that each class is in both. After
fitting, the Summary gives, for each Y:
  RMSEP    root mean square of the prediction errors (predicted - observed);
  bias     mean of these errors; SEP their standard deviation;
  Q2ext    1 - sum (observed - predicted)² / sum (observed - the model's mean)²;
for a PLS-DA, the share of the test set correctly classified; for all, the number of test
observations outside the model's domain. Observed / predicted shows them as red diamonds. The
test set is saved with the model, and kept by Export to R and by the Methods text.

Windows
-------
In the centre, one tab per model ("M1 · PLS"), and a tab for each view of the project (Data,
Variable statistics, History). A model's tab is its page: its summary on the left, its scores
and loadings on the right; its other views (VIP, DModX...) join it as tabs. Choosing a model
in the explorer shows its page; closing a page's last view closes the page.
In a page as in the centre, views move by their tab (drag and drop), split and stack;
dragging a model's tab next to another one compares two models. Right-click on a tab, or the
icon at the top right of a group: detach into its own window (on a second screen, for
example), maximise, close.
Window › New window opens a second full window. A selection of observations (box or lasso in
a plot, click on a point or a list row) shows in every view and every window of the same
model.
Plots: mouse wheel to zoom; right-click to copy or save the image (PNG, SVG), see the
selection's contributions or make it a class.
Ctrl+C in a view that shows a table (summary, lists, statistics...) copies the table as
tab-separated text, to paste into Excel (a list: all its rows, at full precision); with text
selected, Ctrl+C copies the text as usual.
View › Find a command (Ctrl+K): type part of the name of a command or of its menu ("vip",
"export r"), then Enter.
Help › Diagnostic information: the versions of Nuée, the system, R and its packages, to paste
into a report of a problem (github.com/4rtefakt/nuee/issues; no paths, no data).

What matches the stored values (checked on 944 models from 133 .usp projects)
-----------------------------------------------------------------------------
Scaling, R2X, R2Y, scores, loadings, eigenvalues, T2 and its limit, DModX (plain and weighted)
and DCrit, VIP, coefficients, RMSEE.

What differs
------------
- Q2 (and what comes from the cross-validation: Q2 per variable, RMSEcv, CV-ANOVA, the
  cross-validated classification, confidence intervals): Nuée predicts each group by a model
  fitted without it, centring and scaling included (see "Cross-validation"); the stored values
  come from a validation done with the scaling of all the observations. Median difference from
  the stored Q2(cum): 0.003 for PLS models with over 200 observations, 0.02 from 50 to 200,
  0.11 from 20 to 50, 0.27 up to 20, Nuée's Q2 being nearly always lower; a few hundredths for
  PCA. With groups by an ID (a site, a sector), the difference is larger: the model fitted
  without a site doesn't know that site's mean level either. With the file's own validation
  (the scaling of all the observations), the stored Q2 of .usp models comes back exactly,
  groups by ID included (moteur/tests/verifier_references.R). 18 models out of 944, with a
  variable that varies on almost one observation only, lose much more (without it, its scaling
  enlarges it a lot).

- Sign of the components of new models: arbitrary (imported models are oriented as in the
  file).
- Dendrograms: exact Ward method; the merges at the top of the tree may differ from those of
  the stored tree.
- Automatic fitting: the published rules, applied to Nuée's Q2, may choose another number of
  components; for PCA, the exact limit used in the files isn't published.
- VIP cut-off (step around 0.8): the application's own method.
- OPLS / OPLS-DA: no stored model to compare with (see above).
- Suggested transformation: the published rule doesn't say whether both skewness and Min/Max
  are needed; the application requires both.
