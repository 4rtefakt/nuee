NUÉE — ACP, PLS, écologie des communautés, modèles et cartes, calculés en R
===========================================================================
(English guide: USER-GUIDE.txt)

Démarrer
--------
Pour installer Nuée, double-cliquez sur « Nuee-Setup-<version>.exe » et suivez les étapes :
pour vous seul (sans droits d'administrateur) ou pour tous les utilisateurs de l'ordinateur.
R est inclus. Nuée apparaît dans Paramètres › Applications › Applications installées, d'où on
peut la désinstaller ; les projets et les réglages sont gardés.
Si Windows affiche « Windows a protégé votre ordinateur » (éditeur inconnu), cliquez sur
« Informations complémentaires » puis « Exécuter quand même ».
Pour les services informatiques qui installent Nuée sur de nombreux ordinateurs (installation
silencieuse, Intune, Configuration Manager, stratégies de groupe, recherche de mises à jour
coupée) : le guide de déploiement, en anglais,
https://github.com/4rtefakt/nuee/blob/main/docs/deploiement.md

Sous macOS, R est inclus aussi : ouvrez Nuee-<version>-arm64.dmg (Apple silicon, macOS 14 ou
plus récent) ou Nuee-<version>-x64.dmg (Intel, macOS 13 ou plus récent) et faites glisser Nuée
dans Applications. La première fois, macOS dit qu'il n'a pas pu vérifier l'application (elle
n'est pas signée par Apple) : cliquez sur « OK », puis sur « Ouvrir quand même » dans Réglages
Système › Confidentialité et sécurité, et confirmez. Les réglages sont dans
~/Library/Application Support/Nuee.

Sous Linux, Nuée utilise le R de l'ordinateur.
- Debian, Ubuntu et dérivées : sudo apt install ./Nuee-<version>-amd64.deb installe aussi R
  et les paquets R nécessaires. Nuée apparaît dans le menu des applications.
- Autres distributions : Nuee-<version>-x86_64.AppImage (le rendre exécutable, puis le
  lancer) ou Nuee-<version>-x64.tar.gz (le décompresser, puis lancer ./nuee). Installer
  d'abord R, puis dans R : install.packages(c("httpuv", "jsonlite", "openxlsx", "haven",
  "readxl", "foreign", "nlme", "mgcv", "MASS", "rpart", "cluster", "RSQLite", "ranger")).
Les projets .usp demandent python3. Pour un autre R que celui du PATH : Fichier › Réglages...
(voir Le R utilisé par Nuée), ou lancer Nuée avec RSCRIPT=/chemin/vers/Rscript. Les réglages sont
dans ~/.config/Nuee.

Ouvrir
------
Fichier › Ouvrir (Ctrl+O) :
  - un projet .usp : données, modèles et résultats enregistrés dans le fichier ;
  - un projet enregistré par l'application (.nuee ; .json pour les versions avant 0.9.1) ;
  - un tableau, une ligne par observation :
      Excel .xlsx, .xlsm, .xls        texte .csv, .txt, .tsv (séparateur, virgule décimale et
      R .rds, .RData                    encodage reconnus, y compris le « texte Unicode »
      SPSS .sav, .zsav, .por            d'Excel)
      Stata .dta                      SAS .sas7bdat, .xpt
      jamovi .omv                     dBase .dbf, Weka .arff
      spectres JCAMP-DX .jdx, .dx, .jcm et SPC .spc (voir Spectres)
      GeoPackage .gpkg (une couche de QGIS : voir Cartes et données spatiales)
    Un export de KoboToolbox ou d'ODK Central (.xlsx, .csv, ou le .zip d'ODK) est reconnu à ses
    colonnes et s'ouvre par son import (voir Données de terrain de KoboToolbox ou d'ODK).
    La première colonne sert de nom d'observation si c'est du texte ou si elle s'appelle
    « ID », « Obs », « Nom »... (pour un fichier R, les noms des lignes) ; les autres colonnes
    de texte dont toutes les valeurs diffèrent (un code par observation) deviennent des
    identifiants secondaires : elles servent d'étiquettes mais n'entrent pas dans les modèles ;
    les autres colonnes de texte, les facteurs R et les variables étiquetées de SPSS ou Stata
    sont des variables qualitatives (dans l'ordre de leurs modalités). Pour un classeur à
    plusieurs feuilles ou un fichier R à plusieurs tableaux, l'application demande lequel ouvrir.
    Une colonne de mesures qui a quelques cellules de texte (<0,5, <LOD, nd, n.d., #N/A...)
    reste une variable quantitative : ces cellules sont lues comme manquantes, et la barre d'état
    dit combien, dans quelles variables (dont celles sous la limite de détection). Les dates et
    heures d'Excel restent des dates (2024-05-03), en texte, comme celles d'un fichier texte
    (telles qu'écrites : 14/05/2019) ou de R : une colonne de dates est une variable qualitative
    quand des dates reviennent (des secteurs comptés le même jour), un identifiant secondaire
    quand toutes diffèrent, le nom des observations si c'est la première colonne (la mettre
    alors plus loin pour en faire un temps) ; variable ou identifiant, elle peut être le temps
    (voir Le temps en dates). Un nombre d'Excel sans format de date (43599) reste un nombre. Un
    fichier texte dont une ligne a plus de valeurs que l'en-tête est refusé, avec le numéro de
    la ligne, plutôt que de décaler les colonnes. Un fichier R doit contenir des tableaux ; tout
    autre objet est refusé. Les fichiers R ne s'ouvrent qu'avec R 4.4 ou plus récent (celui de
    Windows) : avec un R plus ancien, comme celui d'Ubuntu 22.04 ou 24.04 ou de Debian 12, un
    .rds ou un .RData pourrait exécuter du code dès sa lecture (CVE-2024-27322) ; Nuée le refuse
    donc : enregistrez le tableau en CSV ou en Excel.
Fichier › Coller un tableau (Ctrl+V) : des cellules copiées dans Excel, LibreOffice, Google
Sheets ou jamovi deviennent un projet (la première ligne donne les noms des variables). Le
projet n'a pas encore de fichier : l'enregistrer (Ctrl+S).
Fichier › Importer depuis KoboToolbox ou ODK... : les relevés sur téléphone exportés par
KoboToolbox ou ODK Central (voir Données de terrain de KoboToolbox ou d'ODK).
Fichier › Importer des spectres : des fichiers de spectres réunis en un projet (voir Spectres).
Déposer des fichiers sur la fenêtre (glisser-déposer depuis l'Explorateur) les ouvre de même :
des spectres JCAMP-DX ou SPC ensemble font un seul projet, comme Importer des spectres ; les
autres fichiers s'ouvrent chacun comme avec Fichier › Ouvrir. Un double-clic sur un projet
.nuee dans l'Explorateur Windows l'ouvre dans Nuée (dans la fenêtre déjà ouverte s'il y en a une).
Les derniers fichiers ouverts sont dans Fichier › Ouvrir un fichier récent.
Pour essayer : Aide › Projet d'exemple ouvre 120 pommes inventées (quatre variétés, culture
bio ou conventionnelle, une douzaine de mesures et une note de dégustation) avec quatre
modèles prêts : une ACP, une PLS de la note, une PLS-DA des variétés et une OPLS-DA de la
culture. Le tableau d'origine, vergers.csv, est à côté (resources\exemple) pour essayer
l'ouverture d'un tableau.

Données de terrain de KoboToolbox ou d'ODK
------------------------------------------
Les formulaires remplis sur téléphone (KoboCollect, ODK Collect, Enketo) sont exportés par leur
serveur : KoboToolbox en classeur Excel (une feuille pour les envois, une par groupe répété) ou
en fichier CSV (points-virgules), ODK Central en archive .zip (un CSV par table) ou en son seul
CSV des envois. Fichier › Ouvrir les reconnaît à leurs colonnes (_id, _uuid, _submission_time,
_index... ; SubmissionDate, KEY, meta-instanceID...), comme un fichier déposé sur la fenêtre ;
Fichier › Importer depuis KoboToolbox ou ODK... demande l'import, et refuse tout autre fichier.
Un dialogue dit en phrases ce que l'import fera avant de le faire, et le redit à chaque réglage
changé :
  - la table à analyser : les envois, ou un groupe répété (une ligne par espèce observée, par
    plante mesurée), avec les colonnes de ses tables parentes jointes à chaque ligne, toutes
    cochées au départ (l'habitat et les coordonnées du site ; une répétition dans une
    répétition remonte les deux niveaux) ;
  - les métadonnées retirées, listées (identifiants internes, appareil, version du formulaire,
    colonnes qui relient les tables...) ; on peut garder la date et l'heure d'envoi, son auteur,
    son identifiant, le début, la fin et le jour du relevé, et le statut de validation ;
  - les préfixes des groupes retirés des noms (group_site/altitude, group_site-altitude, ou
    avec le séparateur choisi pour un export de KoboToolbox, group_site.altitude : altitude) ;
    deux questions au même nom dans deux groupes gardent leur groupe (group_site_remarques,
    group_fin_remarques), avec le formulaire même quand un export d'ODK omet les groupes ;
  - un choix unique (select_one) devient une variable qualitative, un choix multiple
    (select_multiple) une colonne 0/1 par choix nommée question_code (meteo_pluie) : 1 choisi,
    0 non, vide quand la question est restée sans réponse (même là où ODK écrit 0) ; les
    colonnes 0/1 de l'export servent quand il les a, jamais en double, et avec le formulaire
    un choix qui leur manque (ODK n'en écrit que pour les choix pris au moins une fois) a
    aussi la sienne ;
  - un point GPS (geopoint), en texte (« lat lon alt préc ») ou en colonnes, devient
    gps_longitude, gps_latitude, gps_altitude et gps_precision ; le premier point de la table
    (ou de sa table parente, joint) devient les coordonnées du projet, en WGS 84 (voir Cartes
    et données spatiales) ;
  - les dates et heures perdent leurs fractions de seconde et leur fuseau horaire
    (2024-05-03T08:12:45.123+02:00 devient 2024-05-03 08:12:45, l'heure du téléphone), pour
    que Nuée les lise comme des dates (voir Le temps en dates).
Le formulaire XLSForm (le classeur aux feuilles survey et choices, téléchargé depuis KoboToolbox
ou ODK Central), s'il est donné, dit le type de chaque question, les libellés des choix dans la
langue choisie (label::Français (fr), label::English (en) ou label ; par défaut celle de
l'interface) et leur ordre, qui devient celui des catégories ; les colonnes prennent alors les
noms des questions, quels que soient les en-têtes de l'export (noms ou libellés), et un choix
multiple exporté en une colonne de libellés en tire ses colonnes 0/1. Sans le formulaire, les
réponses restent telles que l'export les écrit (des codes, ou des libellés pour un export en
libellés), les catégories dans l'ordre alphabétique, et un choix multiple sans ses colonnes 0/1
reste du texte. « Ouvrir tel quel » ouvre la table choisie sans rien y changer (la feuille, ou le
CSV de l'archive). L'import est un projet comme un tableau ouvert, à enregistrer (Ctrl+S) ; le
texte des Méthodes dit que les données ont été recueillies avec KoboToolbox ou ODK (et le titre
du formulaire).

Enregistrer et retrouver son travail
------------------------------------
Fichier › Enregistrer (Ctrl+S) écrit le projet (.nuee) avec ses données, ses modèles et la
séance en cours : modèles calculés, panneaux ouverts et leur disposition, réglages des
graphiques (axes, couleurs, étiquettes, titres), sélections, choix des VIP, groupes du
dendrogramme. En rouvrant le projet, les modèles sont recalculés et tout revient en place.
Le projet est écrit dans un fichier à côté, qui prend ensuite la place de l'ancien : une coupure
du réseau ou un disque plein pendant l'enregistrement laisse l'ancien intact. Si un autre
programme garde le fichier ouvert (synchronisation, antivirus), Nuée réessaie pendant cinq
secondes, puis le laisse tel quel et le dit : enregistrer de nouveau, ou Enregistrer sous.... Si
le fichier a été modifié ailleurs depuis qu'on l'a ouvert ou enregistré (un collègue, sur un
dossier partagé ; une autre fenêtre), Nuée le dit et propose de réunir ses changements avec les
vôtres (voir Travailler à plusieurs), Écraser, Enregistrer sous... ou Annuler ; pour un projet
repris après un arrêt inattendu, Enregistrer sous..., Écraser ou Annuler. Le fichier dit aussi
quelle version de Nuée et de R l'a écrit, et le nom de qui l'a enregistré ; un projet enregistré
par une version plus récente de Nuée est signalé à l'ouverture. Nuée garde aussi d'elle-même des
versions de chaque projet enregistré, pour y revenir : voir Historique et versions.
Rouvrir un fichier déjà ouvert (fichier récent, double-clic dans l'Explorateur) montre le
projet ouvert au lieu d'en ouvrir une seconde copie.
En fermant l'application avec des changements non enregistrés, elle propose « Enregistrer et
fermer ». Toutes les deux minutes, elle garde aussi une copie de secours des projets non
enregistrés : si elle s'arrête sans avoir été fermée (panne, coupure), elle propose au
lancement suivant de les récupérer. Fermer cette question sans répondre garde les copies pour
la fois suivante ; seul « Ignorer » les efface.
Édition › Annuler (Ctrl+Z) revient sur la dernière modification des données d'un projet
(valeur modifiée, nouvelle variable, classe, scores en variables, définition supprimée...),
jusqu'à 20 en arrière.
Notes : le résumé de chaque modèle a une zone de notes, enregistrée avec le projet et reprise
dans le rapport ; un crayon le signale dans l'explorateur.
Retirer un modèle (Modèle › Supprimer le modèle) demande confirmation. Sa définition reste
dans le projet ; pour un modèle fait dans l'application, une case permet de la supprimer
aussi (annulable).

Si le moteur R s'arrête
-----------------------
L'application le signale et propose de le redémarrer ; on peut aussi le faire soi-même
(Aide › Redémarrer le moteur R) si un calcul ne finit pas. Les projets se rouvrent avec leurs
modèles et leurs vues, depuis leur copie de secours s'ils avaient des changements, sinon
depuis le fichier où ils s'enregistrent ; les changements faits depuis la dernière copie de
secours (deux minutes au plus) sont perdus. Fermer Nuée quand le moteur ne répond plus garde
les copies de secours, proposées au lancement suivant. Au-delà d'une minute de calcul, la
barre d'état le rappelle.
Aide › Quoi de neuf : les nouveautés de chaque version (affichées une fois après une mise à
jour). La version installée (Nuee-Setup, l'application macOS ou les paquets Linux) cherche au
démarrage s'il existe une nouvelle version (une seule demande à GitHub, rien d'autre n'est
envoyé) et la signale dans la barre d'état ; sous macOS et Linux, un clic ouvre la page de la
version. Sous Windows,
un clic propose de mettre à jour : le programme d'installation est téléchargé et
vérifié (son empreinte SHA-256 doit être celle que donne GitHub), puis Nuée se ferme (en
proposant d'enregistrer les projets modifiés), l'installe et redémarre. Pour une installation
pour tous les utilisateurs, Windows demande l'autorisation. Aide › Chercher une mise à jour
fait de même à tout moment, même sans la recherche au démarrage ; Aide › Chercher une nouvelle
version au démarrage arrête la recherche.

Le R utilisé par Nuée
---------------------
Fichier › Réglages... : Nuée calcule avec son propre R (sous Windows et macOS, R 4.6.2 avec tous
les paquets qu'il lui faut), le choix recommandé, ou avec un R déjà installé sur l'ordinateur, en
version 4.3 ou plus récente. La liste montre ceux que les installateurs de R mettent aux endroits
habituels : sous Windows, ceux que connaît le registre et ceux de Program Files ou de votre
propre dossier Programs ; sous macOS, celui du CRAN et celui de Homebrew ; sous Linux, où Nuée
prend par défaut le R de l'ordinateur trouvé dans le PATH, ceux de /opt/R. Parcourir... en ajoute
un autre, par son dossier.
Nuée lance une fois le R choisi pour le vérifier : sa version, et les paquets dont le moteur a
besoin (httpuv, jsonlite, openxlsx, haven, readxl, RSQLite et ranger, et mgcv, nlme, MASS, rpart,
cluster et foreign, parmi les paquets recommandés de R). « Les installer » installe ceux qui
manquent depuis le CRAN, dans la bibliothèque de l'utilisateur de ce R, créée au besoin, en
montrant ce que dit R pendant ce temps ; ou copiez la ligne affichée et lancez-la dans ce R (R ou
RStudio). Avec un R antérieur à 4.4, les fichiers .rds et .RData ne s'ouvrent pas ; antérieur à
4.5, les empreintes des fichiers de données sont des MD5 et non des SHA-256 (voir Étapes des
données et mise à jour).
Le bouton « Utiliser ce R » redémarre le moteur avec lui, et les projets ouverts se rouvrent avec
leurs modèles, leurs vues et leurs changements (« Au prochain démarrage » attend). Les paquets et
le .Renviron de ce R s'appliquent, pas votre .Rprofile, pour qu'il ne change pas les résultats.
Si le R choisi ne démarre pas (supprimé, abîmé), Nuée calcule avec son propre R et le dit une
fois. Une organisation peut choisir le R de tous ; les Réglages le montrent alors, sans le
changer. Aide › Informations de diagnostic et Aide › À propos disent quel R est utilisé.

L'explorateur (à gauche)
------------------------
Projets, données, modèles importés d'un fichier .usp, modèles calculés et leurs vues.
Double-clic : ouvrir. Clic droit : toutes les actions (calculer, modifier, ajouter ou
retirer une composante, exporter, supprimer...). Double-cliquer un modèle importé le
recalcule en R ; le Résumé marque chaque valeur : « = » identique à la valeur enregistrée
dans le fichier, « ≈ » proche (moins de 0,01), « ≠ » différente. Le Q2 diffère en général : un
modèle importé est validé comme les autres (voir « Validation croisée ») ; « Centres et poids du
modèle complet (comme SIMCA) » redonne celui du fichier.

-----------------------
Fichier, Édition, Modèle, Graphiques, Prédiction, Fenêtre, Affichage, Aide. Raccourcis :
  Ctrl+O ouvrir            Ctrl+S enregistrer         Ctrl+E exporter les résultats
  Ctrl+V coller un tableau Ctrl+Z annuler             Ctrl+H chercher et remplacer
  Ctrl+K rechercher une commande    Ctrl+J console R  Ctrl+C copier le tableau
  Ctrl+N nouveau modèle    Ctrl+M modifier le modèle  Ctrl+= / Ctrl+- composantes
  Échap  effacer la sélection    Ctrl+Suppr exclure la sélection et réajuster
  Ctrl+Maj+N nouvelle fenêtre    Ctrl+Maj+D détacher le panneau   Ctrl+W fermer le panneau
  Ctrl+B explorateur       F1 guide
  Ctrl+Tab / Ctrl+Maj+Tab onglet suivant / précédent  F6 / Maj+F6 zone suivante / précédente
Affichage : thème sombre, français / anglais, taille du texte.
Clavier et lecteurs d'écran : Alt (ou F10) mène à la barre de menus, les flèches dans ses
menus, Entrée lance une commande, Échap revient ; Alt et la lettre soulignée d'un menu l'ouvre
(Alt+F Fichier...). F6 va de zone en zone (barre d'outils, explorateur, chaque groupe de
panneaux, barre d'état), Ctrl+Tab d'onglet en onglet ; sur un onglet, les flèches et Suppr.
L'explorateur est un arbre (flèches ; Entrée ouvre, Espace choisit), un tableau une grille
(flèches ; Entrée ou F2 modifie une cellule, Espace choisit une ligne, Entrée sur un en-tête
trie). Maj+F10 ou la touche menu donne le menu de ce qui a le clavier (nœud, ligne, colonne,
onglet, graphique). Un graphique est nommé par ce qu'il montre pour les lecteurs d'écran, et
Ctrl+C copie ses nombres en tableau. Les dialogues gardent le clavier jusqu'à leur fermeture.
Les deux thèmes respectent les contrastes WCAG AA et le réglage « réduire les animations » du
système ; Mise en forme › Couleurs « lisibles par les daltoniens » (Okabe-Ito) est faite pour
les déficiences de la vision des couleurs, et les couleurs par défaut restent distinctes pour
elles aussi.

Nouveau modèle (Modèle › Nouveau modèle)
----------------------------------------
Onglet Général : type (ACP, PLS, PLS-DA, OPLS, OPLS-DA, modèles de classe, régression
linéaire, modèle linéaire mixte, modèle linéaire généralisé, modèle additif : voir Modèles
linéaires, généralisés et mixtes ; RDA et CA : voir Analyse de redondance et analyse des
correspondances ; arbre de décision, LDA et k-moyennes : voir Arbres de décision, analyse
discriminante linéaire et k-moyennes), nom, nombre de composantes
(automatique par défaut, par validation croisée), groupes de validation croisée (à tour de
rôle, G groupes ; ou un groupe par valeur d'un identifiant ou d'une variable, voir Validation
croisée), échelle par défaut.
Onglet Variables : rôle (X, Y, classe), échelle, bloc, modificateur et transformation de
chaque variable : racine carrée, racine quatrième, log10, ou personnalisée... (log10, ln ou
-log10 de C1*x + C2, exp(C1*x + C2), C1*x + C2, le logit ln((x - C1) / (C2 - x)) entre deux
bornes, ou la puissance (C1*x + C2)^C3 ; une valeur hors du domaine devient manquante) ; le filtre permet de régler d'un coup
toutes les variables affichées (un bloc : le taper dans « Bloc... » au-dessus de la liste,
puis Entrée). Pondération par blocs : les termes d'un même bloc ont leur poids divisé par la
racine carrée de leur nombre, pour qu'un bloc de 20 variables ne pèse pas 20 fois plus qu'une
variable seule ; une variable qualitative compte par ses catégories. Modificateur : multiplie
le poids de la variable après sa mise à l'échelle. Le bouton « Transformations proposées »
applique aux variables affichées le log10 proposé (voir Statistiques des variables).
Onglet Termes croisés : produits de deux ou trois variables X (A × B, A × B × C), carrés
(A × A) et cubes (A × A × A) ; une variable qualitative y entre par chacune de ses catégories,
une fois au plus. Chaque terme croisé a sa propre échelle, son bloc et son modificateur, comme
dans l'onglet Variables. Dans une régression, un facteur peut aussi être une variable sans rôle
(sous « Pas en X : sans effet principal ») : elle n'entre alors que par le terme croisé (voir
Termes croisés avec une variable qualitative).
Onglet Observations : cocher / décocher les observations du modèle, et le jeu de test (voir
Jeu de test) ; « Garder seulement les observations où… » les choisit par une condition (voir
Observations choisies par une condition).
« Modifier le modèle » (Ctrl+M) ouvre cette fenêtre réglée comme un modèle existant (y compris
les modèles importés) et crée un nouveau modèle.
Avant le calcul, l'application vérifie les données : variables ou observations avec plus de
50 % de valeurs manquantes, variables constantes. S'il y en a, elle les liste et propose
« Les exclure et ajuster » ou « Ajuster quand même ».

Quelle analyse ? (Modèle › Quelle analyse ?)
--------------------------------------------
Modèle › Quelle analyse ? (aussi un bouton de la page d'accueil, à côté de Nouveau modèle, et en
tapant « quelle » dans Affichage › Rechercher une commande, Ctrl+K) : quelques questions en mots
simples, puis l'analyse qui y répond, déjà réglée.
  - Votre question : comparer des groupes ou des périodes ; l'effet de variables sur une
    réponse ; beaucoup d'espèces à la fois (comment la composition change, un modèle par
    espèce, les espèces qui caractérisent chaque groupe) ; une tendance dans le temps ou un
    indice de suivi ; une densité ou un effectif (échantillonnage par distance) ; où (cartes,
    autocorrélation spatiale) ; explorer ou résumer un tableau ; prédire ou classer ; diversité
    et richesse en espèces ; avant/après avec des témoins (BACI).
  - La réponse : la variable mesurée, et son type : une mesure, un comptage (avec beaucoup de
    zéros ou non), une présence-absence (0 ou 1), une proportion entre 0 et 1, une classe (une
    variable qualitative), un tableau d'espèces (une colonne par espèce), ou les distances aux
    animaux détectés (une ligne par détection).
  - Le dispositif : les mêmes sites ou placettes mesurés plusieurs fois (le site), des années
    ou des dates (le temps), un dispositif BACI (l'unité), des coordonnées spatiales, des lignes
    ou des points (échantillonnage par distance).
  - Les variables : les variables explicatives (X), ou les groupes.
Nuée propose les réponses d'après les variables du projet (comme les lit Statistiques des
variables) : une réponse d'entiers à partir de 0 est un comptage, sauf quand son unité (Édition ›
Unités et descriptions : g, cm, ha, %, °C...) ou son nom (une moyenne, un rapport, une
biomasse...) dit une mesure arrondie à son unité ; des comptages que rien ne confirme (pas
d'unité de comptage, pas de nom comme abondance) ont aussi le modèle linéaire parmi les autres
possibilités ; de 0 et de 1 une présence-absence, entre 0 et 1 une proportion ; « beaucoup de zéros » quand un quart au moins
des valeurs sont nulles, et 15 points de plus que n'en donnerait une loi de Poisson de même
moyenne (la phrase sous la réponse donne les deux) ; le site est une variable qualitative nommée
comme un site (site, station, placette, transect...) dont les catégories se répètent ; le temps
une variable nommée comme une année ou une date, ou des entiers entre 1900 et 2100 ; les espèces
les colonnes de nombres positifs ou nuls qui ont des zéros (quatre au moins) ; les coordonnées
celles du projet, ou celles que proposent les noms de ses variables ; les distances une
variable nommée comme elles, et les autres colonnes de l'échantillonnage par distance par les
noms d'où Nouveau modèle les propose (Sample.Label, Effort, Region.Label, Area, size du paquet
Distance, ou transect, longueur, région, aire, taille) ; des points plutôt que des lignes quand
la colonne du transect est nommée comme un point ou une station. Chaque réponse se change.
À droite : l'analyse conseillée, pourquoi, ses conditions principales et des notes selon les
réponses (l'effet aléatoire par site, l'autocorrélation des résidus d'années qui se suivent, les
moyennes ajustées après la comparaison de groupes, une proportion qui touche 0 ou 1...), ce qui
sera rempli, ce qui reste à compléter, et un bouton. Il ouvre Nouveau modèle déjà rempli (type,
loi, rôles, transformation, courbes, effet aléatoire, groupes de validation croisée, et les
réglages propres de l'analyse, comme la transformation de Hellinger d'une RDA, le site et le
temps de TRIM, ou le transect, l'effort, la strate, l'aire et la taille des groupes de
l'échantillonnage par distance), ou la bonne vue (Tests statistiques dans le bon mode, Séries
avec ses tendances, Carte, Autocorrélation spatiale, Raréfaction, Statistiques des variables),
ou Nouvelle variable avec un indice de diversité. Un modèle par espèce ouvre Nouveau modèle pour
la première espèce, puis Un modèle par réponse, les autres cochées. Les autres possibilités, en
dessous, s'ouvrent de la même façon. Les réponses sont gardées jusqu'à la fermeture de Nuée :
annulez Nouveau modèle et revenez en essayer une autre.
Les choix principaux :
  - un comptage : la binomiale négative quand il varie plus qu'une loi de Poisson ne le permet
    (une variance au-delà de 1,5 fois la moyenne) ou a beaucoup de zéros (beaucoup de zéros ne
    veut pas toujours dire excès de zéros, Warton 2005 : comparez avec la Poisson à excès de
    zéros par l'AIC), sinon Poisson ; une présence-absence : la régression logistique ; une
    proportion : la régression bêta ; une mesure avec des zéros : Tweedie ; sinon le modèle
    linéaire, une mesure positive et asymétrique aussi (ses X peuvent la rendre asymétrique :
    ses résidus le disent après l'ajustement, et gamma ou le logarithme sont proposés) ; avec les
    mêmes sites mesurés plusieurs fois, un effet aléatoire par site et la validation croisée par
    site ;
  - des groupes comparés : le test entre deux variables (celui que leurs types demandent),
    apparié par site quand chaque site vient une fois dans chaque groupe (pas plus
    d'observations que de sites × groupes), sinon le modèle mixte et ses moyennes ajustées ;
    pour des comptages, des présences et des proportions, leur GLM ;
  - beaucoup d'espèces : la RDA après la transformation de Hellinger avec des X quantitatives,
    la PERMANOVA avec des groupes, le NMDS sans X ; les espèces indicatrices ; un modèle par
    espèce ;
  - une tendance : TRIM pour des comptages par site et par année (une ligne par site et par
    année : pas plus d'observations que de sites × années ; sinon un GLM, et TRIM après Édition
    › Résumer par groupe) ; une mesure sur plusieurs sites : le modèle mixte, l'année en X ; une
    seule série : Séries et ses tendances ;
  - prédire : la PLS ou la PLS-DA avec beaucoup de X (20 ou plus, ou moitié moins que
    d'observations), la forêt aléatoire sinon, les arbres boostés pour des comptages et des
    présences ;
  - une densité ou un effectif : l'échantillonnage par distance, les distances en Y, des lignes
    ou des points, ses colonnes préremplies d'après leurs noms ; les unités (m, km et km²
    sinon) restent à vérifier, et un transect ou un effort introuvable à compléter ; sans aire
    des strates (ou des aires nulles), la densité seule ;
  - où : la carte, puis l'I de Moran et le lissage spatial d'un GAM ; le test de Mantel pour
    des espèces ;
  - explorer : l'ACP, le NMDS pour des espèces ; la diversité : la raréfaction.
Un conseil, pas une règle : les conditions se vérifient après l'ajustement (Résumé › Conditions
du modèle).

Spectres
--------
Fichier › Importer des spectres : choisir un ou plusieurs fichiers (Ctrl+A dans un dossier
pour les prendre tous) ; ils deviennent un projet, une ligne par spectre, une colonne par
longueur d'onde (nommée par sa valeur : « 1450 », « 3999.69 »). Fichiers lus :
  JCAMP-DX (.jdx, .dx, .jcm)  toutes les écritures (nombres simples ou compressés : AFFN, PAC,
             SQZ, DIF, DUP), plusieurs spectres par fichier ; pas les tables de pics ni les
             NTUPLES (RMN complexe, spectrométrie de masse) ;
  SPC (.spc)  Galactic (GRAMS, Thermo), nouveau et ancien format, un ou plusieurs spectres ;
  texte (.csv, .txt...)  une colonne d'abscisses, puis une colonne par spectre, avec ou sans
             ligne d'en-tête ; les lignes que l'appareil écrit avant les nombres sont ignorées.
Un spectre est nommé d'après son fichier (et le titre du bloc ou son numéro quand un fichier en
a plusieurs). Si les spectres n'ont pas tous les mêmes abscisses, ils sont interpolés
(linéairement) sur celles du premier, dans la partie commune à tous ; la barre d'état le dit.
Des unités différentes (nm et cm-1, absorbance et transmittance) sont refusées.
Informations (facultatif) : un tableau (Excel, CSV...) dont la première colonne donne le nom de
chaque fichier, avec ou sans son extension, et les autres colonnes des informations à joindre
aux spectres (teneurs, classes, lots) ; elles prennent place avant les spectres. La barre
d'état dit combien de spectres n'ont pas trouvé leur ligne. Un seul fichier JCAMP-DX ou SPC
s'ouvre aussi avec Fichier › Ouvrir, et un fichier de nouveaux spectres sur la même grille se
prédit avec Prédiction › Prédire un fichier.

Nouveau modèle › Général › Prétraitement des spectres : chaque observation est un spectre
(ses variables X quantitatives, dans l'ordre du tableau), corrigé avant la mise à l'échelle
par une à trois étapes, dans l'ordre :
  SNV        chaque spectre centré sur sa moyenne et divisé par son écart-type ;
  MSC        chaque spectre ajusté sur le spectre moyen des observations du modèle (x = a + b r),
             puis remplacé par (x - a) / b ; une prédiction reprend ce spectre moyen ;
  Detrend    un polynôme de degré 2 en fonction de la longueur d'onde, ajusté sur le spectre,
             en est retiré (Barnes et al., 1989 ; souvent après SNV) ;
  Ligne de base  l'enveloppe convexe inférieure du spectre (les segments qui joignent ses points
             les plus bas, d'un bout à l'autre) en est retirée ; le spectre corrigé est positif
             ou nul ;
  Savitzky–Golay : lissage, dérivée première ou seconde, dans une fenêtre de n variables
             (impair) avec un polynôme de degré d. Chaque zone de variables voisines dans le
             tableau est traitée à part : une fenêtre ne passe pas par-dessus une zone retirée.
La longueur d'onde (pour Detrend et la ligne de base) est le nombre lu dans le nom des
variables quand chacune en a un, différent ; sinon leur place dans le tableau.
Pour des spectres, on centre souvent sans réduire (échelle « Centrage seul »). Seul le MSC
dépend des autres observations (le spectre moyen) : en validation croisée, chaque groupe est
corrigé avec le spectre moyen des autres observations. Graphiques › Profils (spectres) :
loadings, coefficients, VIP, ou les spectres eux-mêmes (avant ou après prétraitement) en
lignes ; l'axe horizontal est le nombre lu dans le nom des variables (« 1450 nm ») quand
chacune en a un ; les lignes s'interrompent là où des variables sont hors du modèle. Un clic sur
un spectre sélectionne son observation.
Zones de longueurs d'onde : cocher « Choisir des zones », puis faire glisser sur le graphique
(une ou plusieurs zones, en orange) ; « Nouveau modèle sans ces zones » (par exemple les
bandes de l'eau) ou « Nouveau modèle avec ces zones seules » ouvre Nouveau modèle avec les
réglages du modèle et ces variables X, à vérifier avant d'ajuster. Les autres variables X du
modèle (qualitatives) restent.
Graphiques › iPLS (intervalles du spectre), pour un modèle avec Y : le spectre (les variables X
quantitatives du modèle, dans leur ordre) est prétraité une fois, en entier, comme pour le
modèle (avec un MSC, aussi pour chaque groupe de la validation croisée, avec le spectre moyen
des autres observations), puis coupé en n intervalles de même largeur ; chacun est une PLS sur sa zone (avec la
mise à l'échelle du modèle et ses autres variables X), avec 1 à A composantes. Une barre par
intervalle donne son plus petit RMSEcv (dans les unités de Y, comme dans le résumé), avec ce
nombre de composantes écrit dessus ; en vert, les intervalles qui prédisent mieux que le
spectre entier (tirets rouges) ; la ligne grise est le spectre moyen après prétraitement.
Cliquer des barres pour choisir des intervalles, puis « Nouveau modèle avec ces intervalles »
ou « sans ces intervalles ». Un tel modèle prétraite ses propres variables : avec SNV, MSC,
detrend ou ligne de base, son RMSEcv peut différer de celui de la barre. Méthode : Nørgaard et
al. (2000), Applied Spectroscopy 54, 413–419.

Exporter vers R (script, R Markdown, Quarto)
--------------------------------------------
Fichier › Exporter vers R : un fichier qui refait le modèle sans Nuée, avec R seul, à
envoyer à un collègue ou à joindre à un article. Le calcul y est écrit pour ce modèle seul,
en R sans paquet (une régression : lm, ou nlme et mgcv, livrés avec R ; un NMDS : MASS, livré
avec R lui aussi ; TRIM et l'échantillonnage par distances, et des arbres boostés avec rpart :
les fonctions du moteur de Nuée, recopiées dans le script ; une forêt aléatoire, la seule
exception : le paquet ranger, que Nuée installe avec lui), commenté dans la langue de l'export,
en quatre parties :
  1. les fonctions : l'algorithme NIPALS, la validation croisée, et seulement ce que ce
     modèle utilise (valeurs manquantes, prétraitement des spectres, OPLS...) ;
  2. les données, dans le script ou dans un fichier CSV à côté (« M1 - donnees.csv »),
     les nombres écrits sans perte et les catégories dans leur ordre ;
  3. le modèle : ses termes X et Y (transformations, catégories, termes croisés), leur
     mise à l'échelle, l'ajustement, puis R2 et Q2, T2 et DModX avec leurs limites, VIP,
     coefficients (ceux d'une PLS avec leur intervalle à 95 % par jack-knife), RMSEE et RMSEcv,
     CV-ANOVA, classement pour une PLS-DA, jeu de test ;
  4. les résultats : les tableaux, le test de permutation (en commentaire) et les
     graphiques (scores, loadings, VIP, observé / ajusté, T2 et DModX).
Format : script R (.R) ; ou rapport R Markdown (.Rmd) ou Quarto (.qmd), qui y ajoute le texte
des méthodes, des tableaux et des graphiques (scores, loadings, VIP, observé / prédit, T2,
DModX) et les références ; il se compile dans RStudio (bouton Knit) ou avec quarto render, et
demande le paquet knitr. Fichiers en plus, au choix : renv.lock (versions de R et des paquets,
pour renv::restore()), les données et le modèle ajusté en .RData (load() les rend sans
recalculer), un projet RStudio (.Rproj, à mettre dans un dossier à part).
Modèles : celui-ci, ou tous les modèles de la séance (le dernier ajustement de chacun) dans un
seul script .R : les fonctions et les données une fois, puis un bloc par modèle sous son nom
(M1, M2...).
Avant d'écrire, l'application recalcule les modèles du script et vérifie qu'ils donnent les
mêmes résultats ; sinon elle le signale.

    le fichier ;
  - Zotero sur cet ordinateur (Zotero 7 ou plus récent, en cochant Paramètres › Avancé › « Autoriser
    les autres applications de cet ordinateur à communiquer avec Zotero ») : ses références se
    cherchent en tapant @, ou dans Citer › Insérer une citation, dans Ma bibliothèque ou dans la
    bibliothèque d'un groupe (ceux que Zotero synchronise, sous Ma bibliothèque dans sa fenêtre),
    entière ou dans une de ses collections ; la bibliothèque choisie dans Insérer une citation est
    gardée, et taper @ y cherche. Leurs clés sont celles de Zotero (celles de Better BibTeX quand il
    est installé). Avec l'extension Better BibTeX, Citer › Choisir dans Zotero ouvre le sélecteur de
    Zotero, dans toutes ses bibliothèques, avec la page qu'on y donne. Nuée ne fait que lire les
    bibliothèques. Quand Zotero ne donne pas ses bibliothèques de groupe, Insérer une citation dit
    pourquoi et propose Ma bibliothèque seule ;
  - du BibTeX collé (Citer › Coller des références BibTeX).
Une clé est unique dans une bibliothèque Zotero, pas d'une bibliothèque à l'autre : deux œuvres
différentes peuvent avoir la même clé dans Ma bibliothèque et dans un groupe (bechet2019). Une
référence de Zotero dont le document donne déjà la clé à une autre œuvre (d'une autre bibliothèque, ou
d'un fichier lié) y est citée avec une lettre en plus, @bechet2019a, et la barre d'état le dit ; le
même élément cité de nouveau, ou la même œuvre copiée dans une autre bibliothèque (le même DOI, ou le
même titre, la même année et le même premier auteur), garde la clé que le document lui donne, quelle
que soit celle que Zotero lui donne là. Un fichier lié ensuite qui donne la clé d'une référence gardée
de Zotero à une autre œuvre : c'est celle du fichier qui est citée, et la barre d'état le dit.
Le document garde une copie des références qu'il cite, avec la bibliothèque et l'élément d'où vient
chacune de celles de Zotero : envoyé à quelqu'un qui n'a pas le .bib, il les cite encore (Citer ›
Références du document les montre, et retire celles qui ne sont plus citées). Compilé pour Quarto, le
texte garde ses citations telles quelles, les références citées dans un .bib à côté du .qmd, pour que
Quarto les écrive dans le style d'une revue (csl: style.csl dans l'en-tête ; le fichier est copié à
côté du .qmd).
La langue d'une référence (le champ Langue de Zotero : fr, de...) la suit : les styles qui mettent
les titres anglais en capitales (Title Case), comme celui de Quarto par défaut, laissent alors un
titre français tel qu'il est écrit.
Chaque document s'ouvre dans son propre onglet. Les graphiques des documents et des rapports de modèle
sont dessinés en clair, quel que soit le thème de la fenêtre.
Orthographe, en français et en anglais (et dans la langue du système) : les mots mal
orthographiés sont soulignés ; clic droit pour les corrections proposées (dans tous les champs
de texte de l'application).

Console R
---------
Affichage › Console R (Ctrl+J) : un panneau sous les onglets, avec
  - le journal : pour chaque action de l'application, l'appel au moteur qu'elle a fait, écrit
    en R (P1 <- lire_projet(...), d <- modele_du_projet(P1, 5), M4 <- ajuster(P1, d)...),
    à recopier dans un script (bouton Copier), et pour chaque modèle ajusté ce que R en
    affiche (composantes, Y, limites, variables, observations ; print(M4) fait de même) ; la
    case « Actions de l'application » les masque ou les montre ;
  - une invite où taper du R, exécuté dans la session R de l'application. m est le modèle
    affiché, p son projet ; P1, M4... les projets et modèles ouverts, sous les noms du journal.
    Par exemple : m$statistiques$variables, summary(p$donnees), plot(m$T[, 1], m$T[, 2]) (le
    graphique s'affiche dans la console), modeles(), projets(), definition("M4").
    Entrée lance la commande, Maj+Entrée passe à la ligne, ↑ et ↓ rappellent les commandes.
    Tab complète le nom commencé : objets, m$... et p$... (les noms qu'ils contiennent),
    arguments de la fonction dont la parenthèse est ouverte ; s'il y en a plusieurs, une liste
    s'ouvre (flèches, puis Tab ou Entrée). Les raccourcis de l'application (Ctrl+S, Ctrl+K...)
    fonctionnent aussi pendant qu'on tape.
Modifier un projet dans la console (p$donnees[...] <- ...) le modifie dans l'application.
Corriger le moteur : dossier_moteur() donne le dossier des fichiers R de l'application ; après
une correction, recharger_moteur() les relit, puis réajuster le modèle. Une mise à jour de
Nuée remplace ces fichiers.
Une commande longue bloque l'application jusqu'à la fin du calcul.
Vérifier le moteur : verifier_moteur() recalcule les modèles importés des projets ouverts,
validés comme leurs fichiers, et les compare aux valeurs enregistrées dans leurs fichiers (R2X,
R2Y, Q2) ; verifier_moteur("dossier") fait de même pour les fichiers .usp et .json d'un
dossier. À faire après une correction du moteur. Le Q2 entre dans le verdict, sauf celui d'une
ACP, seulement proche (voir « Ce qui diffère »).

Figures pour publication
------------------------

    moitié), les titres des graphiques (cachés d'abord : la lettre et la légende suffisent) et
    les légendes.
  - Export : PDF (vectoriel, polices incluses, la page juste à la taille de la figure), SVG

    sans marges).
  - Cartes sur fond (OpenStreetMap, IGN) : dans le fichier, les points, la légende et l'échelle
    de couleurs sont des vecteurs sur une image des tuiles de la carte à la résolution de

    niveau de zoom plus proche que celui de l'aperçu : plus de détails, des noms de lieux plus
    petits. Chaque carte demande au plus 200 tuiles à son serveur, d'au plus deux niveaux de zoom
    au-dessus de celui de l'écran et d'aucun au-delà du niveau 19 ; la barre d'état dit quand le
    fond en est moins net que demandé. L'attribution (© OpenStreetMap contributors, © IGN) reste
    dans un coin de la carte.
Chaque graphique est dessiné comme dans sa vue au moment où il a été ajouté (axes, couleurs,
étiquettes, titres de Mise en forme, zoom), dans le thème clair, sans la sélection, sur fond
blanc ; le bouton d'actualisation d'un panneau reprend les réglages de sa vue ouverte. La figure

exporter, renommer, dupliquer, supprimer) ; elle prend toujours le dernier ajustement de chaque
modèle (un modèle pas encore calculé l'est quand la figure est dessinée) : après un
réajustement, on l'exporte de nouveau. Édition › Annuler ne touche pas aux figures.

Le temps en dates
-----------------
Partout où un temps est demandé (Séries, BACI, Autocorrélation des résidus, l'autocorrélation
CAR1 d'un modèle mixte, precedent() et suivant() de Nouvelle variable), il peut être fait de
nombres (l'année ; 2019,5) ou de dates : 2019-05-14 (ISO, au besoin avec l'heure :
2019-05-14 10:30) ou 14/05/2019, aussi 14-05-2019 et 14.05.2019, l'année en quatre chiffres.
Le jour vient toujours d'abord, comme en France : 05/04/2019 est le 5 avril, jamais le 4 mai.
Une date devient une année décimale : l'année + (le jour de l'année − 1 + la fraction du jour)
/ le nombre de jours de l'année (366 les années bissextiles) ; le 1er janvier 2019 est 2019, le
14 mai 2019 est 2019,364. Années et dates se lisent ainsi de la même façon : une pente de Sen
ou le φ de CAR1 sont par an. Un temps est fait de nombres ou de dates, pas des deux : une
valeur de l'autre genre, ou une date qui n'existe pas (31/02/2019), est refusée en la nommant.
Un nombre reste un nombre : un numéro de jour d'Excel (43599) ne se distingue pas d'une année.
precedent() et suivant() gardent leur règle, le temps exactement un pas avant : elles vont
avec des temps réguliers (des années) ; avec des dates, ce temps-là existe rarement, et aucune
date proche n'est prise à sa place. L'export vers R lit les dates de la même façon.

Séries
------
Graphiques › Séries (ou dans l'explorateur, sous le projet) : une variable au fil du temps,
comme des figures de séries par secteur, une page par site. Choisir la variable, le temps (une
variable ou un identifiant fait de nombres, comme l'année, ou de dates : voir Le temps en
dates), les lignes (une variable qualitative ou un identifiant : le secteur) et, au choix, les
panneaux (le site) : un petit graphique par panneau, en grille, aux axes communs. Dans une
ligne, les temps qui se suivent à son propre pas (son plus petit écart) sont reliés, et un
secteur compté une année sur deux reste une ligne ; un temps manquant coupe la ligne, et
l'année sans comptage se voit. Des dates, rarement régulières, vont sur un axe de dates, et une
ligne relie tous ses points. Les couleurs vont par ligne dans chaque panneau, la légende est
rangée par panneau (un clic sur une entrée cache sa ligne) : elle reste lisible avec 30
secteurs. Au choix : la moyenne des lignes de chaque panneau, temps par temps (trait épais),
une échelle log (les valeurs ≤ 0 n'y sont pas montrées) et des événements, des temps tapés
« 2015 ; 2019 » (avec des dates, aussi 2019-05-14 ou 14/05/2019), en tirets dans chaque
panneau. Le survol donne le nom de l'observation, le temps et la valeur ; un clic ou un cadre
sélectionne des observations, qui le sont aussi dans les modèles du projet quand la sélection
leur est commune. Les observations sans temps, sans valeur, sans ligne ou sans panneau sont
laissées de côté et comptées ; une ligne qui a deux fois le même temps (des secteurs choisis
sans leur site) est signalée et montrée en points. Clic droit : copier ou enregistrer l'image.
Tendances (la case de la barre) : sous le graphique, un tableau donne pour chaque ligne de
chaque panneau, marquée de sa couleur, n (ses temps qui ont une valeur), son premier et son
dernier temps ; la pente de Sen (Sen, 1968 : la médiane des pentes entre toutes ses paires de
temps, par unité de temps, par an avec des dates) et son intervalle à 95 % (Gilbert, 1987 : les
pentes rangées, prises autour de la médiane d'après la variance de S ; sans bornes quand il y a
trop peu de temps) ; le τ de Kendall (tau-b), le S de Mann–Kendall et sa valeur p bilatérale
par la loi normale (variance corrigée pour les ex aequo, correction de continuité, comme
trend::mk.test et Kendall::MannKendall) ; et la valeur p corrigée sur les lignes
(Benjamini–Hochberg, ou Holm au choix). Une ligne de moins de 4 temps, qui a un même temps deux
fois ou la même valeur à chaque temps n'est pas testée, et le tableau dit pourquoi ; Ctrl+C le
copie. Le test tient les temps pour indépendants : une autocorrélation positive (des années qui
se ressemblent) rend p trop petite. Pour une tendance qui en tient compte : Graphiques ›
Autocorrélation des résidus, puis un modèle mixte avec une autocorrélation CAR1, l'année en X.
Dans la barre du tableau, deux options changent le test. Tenir compte de l'autocorrélation : le
test de Mann–Kendall modifié de Hamed et Rao (1998), calculé comme le calcule modifiedmk::mmkh :
la ligne privée de sa tendance (sa pente de Sen, sur ses vrais temps), les rangs de ce qui
reste, leur autocorrélation à chaque décalage (compté d'un temps au suivant : le temps qui suit
une année manquante est à un décalage), celles au-delà de ±1,96/√n gardées (les autres
comptent 0), et Var(S) multipliée par
n/n* = 1 + 2/(n(n − 1)(n − 2)) Σ (n − k)(n − k − 1)(n − k − 2) ρ(k) ; p et l'intervalle de la
pente viennent de cette variance, et la colonne n/n* donne le facteur (1 : aucune
autocorrélation gardée ; un facteur qui n'est pas positif, d'une forte autocorrélation négative,
laisse la ligne sans test). Il faut une longue série : une autocorrélation s'estime
mal sur peu de temps (Box et Jenkins, 1976, en demandent une cinquantaine), et avec 15 temps
seule une autocorrélation au-delà de ±0,51 compte ; même sur 60 à 90 temps, le test corrigé
rejette encore trop souvent une absence de tendance quand l'autocorrélation est forte (Blain,
2013). Il corrige chaque ligne seule : il ne remplace pas un modèle mixte avec une
autocorrélation CAR1, qui estime la tendance commune aux sites et à leurs secteurs, avec
l'autocorrélation dans chacun.
Saisons : le test de Kendall saisonnier (Hirsch, Slack et Smith, 1982), pour des relevés faits
plusieurs fois par an, la saison donnée par le mois d'un temps fait de dates, ou par une
variable qualitative ou un identifiant (la saison, le mois). L'année d'une valeur est la partie
entière de son temps (l'année civile d'une date) ; plusieurs valeurs d'une saison la même année
n'en font qu'une, leur médiane (comme le font certaines mises en œuvre ; EnvStats les
garderait toutes, en ex aequo de temps), et une note dit combien. Dans chaque saison vue au
moins 2 années : le S de Mann–Kendall entre ses années et sa variance avec les ex aequo ; S et
Var(S) sont additionnés sur les saisons, tenues pour indépendantes, et p vient de la loi normale
avec la correction de continuité, comme les calculent trend::smk.test et
EnvStats::kendallSeasonalTrendTest. La pente de Sen saisonnière est la médiane des pentes entre
années au sein de chaque saison (par an, ou par unité de temps), son intervalle à 95 % tiré de
Var(S) comme le fait Gilbert (1987) (les rangs arrondis, comme pour la pente de Sen plus haut ;
EnvStats interpole entre eux) ; τ est celui d'EnvStats : les τ des saisons en moyenne, pondérée
par leurs années. Une saison vue une seule année ne compte pas ; une ligne de moins de 4 valeurs
dans les saisons qui comptent, ou de la même valeur chaque année dans chaque saison, n'est pas
testée ; les observations sans saison sont laissées de côté par le test, et comptées. Le test
saisonnier tient les saisons pour indépendantes : une autocorrélation d'un mois au suivant rend
p trop petite, et Tenir compte de l'autocorrélation ne s'y applique pas (Hirsch et Slack, 1984,
donnent une correction, qui n'est pas faite ici). La colonne Test donne le test de chaque
ligne ; la correction sur les lignes reste la même.

Un modèle par réponse
---------------------
Modèle › Un modèle par réponse (pour une régression : LM, LMM, GLM ou GAM) : le même modèle,
ses termes, ses effets aléatoires, sa loi, ses courbes, ses observations et la transformation de
sa réponse, ajusté à chaque réponse cochée, une espèce après l'autre (un filtre et Toutes /
Aucune aident à les choisir). Pour chaque terme, les valeurs p sont corrigées sur les réponses :
Benjamini–Hochberg (FDR) par défaut, ou Holm, ou Bonferroni. La vue montre, pour le terme
choisi : le coefficient de chaque réponse avec son intervalle à 95 % en forêt, en rouge là où la
p corrigée est au plus 0,05 (une courbe : son edf) ; l'effet du terme en petits graphiques, un
par réponse (36 au plus) ; et un tableau avec le N, l'AIC, le R² et le Q² de chaque modèle. Une
réponse qui ne s'ajuste pas est nommée avec la raison, et les autres restent. « Garder aussi
chaque modèle dans le projet » les y ajoute tous, chacun avec ses vues.

Cartes et données spatiales
---------------------------
Graphiques › Carte (ou dans l'explorateur, sous le projet) : les observations sur une carte. La
première fois, choisissez les coordonnées du projet : deux de ses variables, X (l'est, ou la
longitude) et Y (le nord, ou la latitude), et leur système de coordonnées : des longitudes et
latitudes en degrés (WGS 84), du Lambert-93, les zones CC, le Lambert II étendu (NTF), une zone
UTM (un autre code EPSG : 326xx au nord, 327xx au sud), LAEA Europe, la Mercator du web, ou des
coordonnées planes en mètres d'un autre système (les distances restent justes, sans fond de
carte). Nuée les propose d'après le nom des variables (lon/lat, X_L93/Y_L93, X/Y...). Elles sont
enregistrées avec le projet, et Ctrl+Z les retire.
La carte place les points à la même échelle sur les deux axes. Couleur : une variable du projet,
ou une colonne des résultats d'un modèle ajusté (scores, résidus, valeurs ajustées, groupes...) ;
Taille : une variable ou une colonne quantitative ; Étiquettes : le nom des observations. Fond :
aucun par défaut, et rien ne quitte l'ordinateur ; OpenStreetMap, le plan de l'IGN ou ses
photographies aériennes (en France) se téléchargent quand on les choisit, et leurs serveurs
reçoivent alors la zone affichée. Un cadre, un lasso ou un clic sélectionne des observations,
partagées avec les modèles du projet comme dans les autres graphiques.
Les conversions entre systèmes sont écrites dans Nuée (formules de Lambert, de la Mercator
transverse, de LAEA ; la NTF passée en WGS 84 par les trois translations de l'IGN, au mètre près ;
RGF93 et ETRS89 pris pour WGS 84) : elles donnent celles de PROJ, la bibliothèque de QGIS, au
micromètre près.

GeoPackage (.gpkg), le format de QGIS : Fichier › Ouvrir lit l'une de ses couches (Nuée demande
laquelle quand il y en a plusieurs) comme un tableau ; des points donnent deux colonnes de
coordonnées (X et Y, ou longitude et latitude), des lignes et des polygones leur centre (le
centre de gravité de la surface d'un polygone), et les coordonnées du projet sont réglées.
Fichier › Exporter les données et l'export des résultats d'un modèle écrivent un GeoPackage quand
le projet a des coordonnées : un point par observation avec toutes ses colonnes, les autres
tableaux de résultats d'un modèle à côté ; QGIS l'ouvre avec son système de coordonnées.

Valeurs de rasters (Édition › Ajouter des valeurs de rasters…, ou le bouton de la carte) :
l'altitude, la pente, l'occupation du sol, le climat… lus dans des fichiers raster à la position
de chaque observation, et ajoutés au projet comme de nouvelles variables, une par bande.
Choisissez un ou plusieurs fichiers : GeoTIFF (.tif, celui de QGIS, de la BD ALTI et du RGE ALTI
de l'IGN, de Copernicus, de CORINE, de WorldClim ou de CHELSA) ou grilles ASCII d'ESRI (.asc,
avec leur .prj). Dans la version navigateur, tapez le chemin complet de chaque fichier
(plusieurs : séparés par « ; ») : le moteur lit les fichiers là où ils sont. Avant d'ajouter,
chaque fichier montre sa taille, son format, sa compression, ses cellules et leur taille, ses
bandes et leur type, son système de coordonnées, sa valeur manquante, et combien d'observations
y tombent ; un fichier qui ne se lit pas dit pourquoi. Pour chaque fichier, choisissez la
valeur : la cellule qui contient l'observation (des classes, l'occupation du sol ; proposée pour
des entiers de 8 bits et les palettes), l'interpolation bilinéaire des quatre cellules les plus
proches (des valeurs continues ; proposée pour des réels), ou la moyenne, ou la classe
majoritaire, des cellules dont le centre est à moins d'un rayon en mètres (à égalité, la classe
de la cellule de l'observation, puis la plus petite ; sans centre dans le rayon, la cellule de
l'observation). Les valeurs sont celles de terra::extract. Une observation sans coordonnées,
hors du raster ou sur une cellule sans valeur reçoit une valeur manquante, et le résultat compte
chaque cas. Chaque bande reçoit un nom (sa description dans le fichier, ou le nom du fichier),
que vous pouvez changer ; un nom déjà pris devient « nom (2) ». Des fichiers côte à côte, aux
mêmes bandes, type, système et cellules (les dalles d'un MNT), sont proposés comme un seul
raster : une variable par bande, chaque observation prenant la valeur de la dalle qui la
contient (un cercle prend les cellules de toutes les dalles). Édition › Annuler (Ctrl+Z) retire
les variables. Elles sont enregistrées avec le projet comme les autres, et gardent d'où elles
viennent : le texte des Méthodes d'un modèle qui les utilise dit quels fichiers, quelle taille de
cellules, quel système et quelle méthode les ont données. La console R montre l'appel,
ajouter_valeurs_rasters(...), et ce qu'il a donné.
Les fichiers sont lus dans Nuée, sans GDAL, et seulement les blocs de lignes ou les tuiles qui
contiennent des observations : un MNT national reste rapide (une fraction de seconde pour une
centaine d'observations dans un fichier sans compression ou Deflate, une à trois secondes en LZW,
décodé en R). Lus : TIFF classique et BigTIFF, en blocs de lignes ou en tuiles, bandes
entrelacées ou séparées ; sans compression, LZW, Deflate, PackBits, LZMA et ZSTD (ZSTD avec R 4.4
et après), avec les prédicteurs 2 et 3 ; des entiers de 8, 16 et 32 bits, des réels de 32 et 64
bits ; la valeur manquante, l'échelle, le décalage et le nom des bandes de GDAL ; le
géoréférencement (ModelPixelScale et ModelTiepoint, ModelTransformation, ou un fichier .tfw),
les pixels comme surfaces ou comme points. Le système de coordonnées du raster vient de son code
EPSG, ou de ses paramètres, et doit être de ceux que Nuée convertit (WGS 84, ETRS89, RGF93,
Lambert-93, CC42 à CC50, Lambert II étendu, UTM, LAEA Europe, Mercator du web) : un autre est
refusé avec son code ; reprojetez le raster dans QGIS (Raster › Projections › Projection) ou
avec gdalwarp. Un raster sans système de coordonnées est pris dans celui du projet. Refusés,
avec un message : les compressions JPEG, WebP, LERC, JPEG 2000 et CCITT, des valeurs de 1, 2, 4,
12 ou 24 bits, des réels de 16 bits, des nombres complexes, les couleurs YCbCr, les points
d'appui (GCP). Lues sans leurs couleurs : les palettes (les numéros des classes sont lus).
Laissés de côté : les aperçus (overviews : les valeurs viennent de la pleine résolution), les
autres images d'un fichier, les masques et les fichiers .aux.xml.

Graphiques › Autocorrélation spatiale (depuis la carte, ou pour une régression depuis son modèle) :
l'I de Moran d'une variable ou des résidus d'une régression (ou, pour des comptages, des
présences-absences et des valeurs positives, ses résidus quantiles), avec son espérance sans
autocorrélation, z et la valeur p unilatérale (autocorrélation positive) sous la randomisation,
et p par permutations (999 par défaut). Pour un modèle linéaire sans effet aléatoire, une seconde
ligne donne le test qui tient compte de l'ajustement (Cliff et Ord 1981, comme
spdep::lm.morantest). Voisinage : les k plus proches voisins de chaque observation (rendus
réciproques), les observations à moins d'une distance (vide : la plus petite qui donne un
voisin à chacune), ou l'inverse de la distance ; lignes de somme 1 (style « W » de spdep) ou
poids tels quels. Dessous, le corrélogramme (l'I de Moran par classes de distance jusqu'à la
moitié de la plus grande, p bilatérale corrigée par Holm sur les classes, en rouge à 0,05) et le
semi-variogramme (la moitié de la moyenne des carrés des écarts entre les valeurs des paires de
chaque classe, comme gstat::variogram, jusqu'au tiers de la diagonale de la zone), la variance
en tirets. Les distances suivent les grands cercles pour des longitudes et latitudes, des lignes
droites pour des coordonnées planes. Des observations au même endroit (une placette suivie
plusieurs années) sont les plus proches voisines les unes des autres : « Moyenne par lieu »
remplace leurs valeurs par leur moyenne.

Tests statistiques
------------------
Graphiques › Tests statistiques (ou dans l'explorateur, sous le projet), en quatre modes, au
choix en haut à gauche.

Entre classes, variable par variable : chaque variable quantitative comparée entre les classes
d'une variable qualitative.
  Deux classes (A, la référence, et B) : test t de Welch (par défaut, variances inégales), t de
  Student ou Mann–Whitney (sur les rangs). Effet : log2 du rapport des moyennes B / A (quand les
  deux moyennes sont positives) ou d de Cohen. Graphique volcan : l'effet contre -log10(p).
  Deux classes appariées par une clé (« Apparier par » : une variable ou un identifiant des
  observations, l'année pour deux secteurs suivis les mêmes années) : pour chaque variable, les
  lignes de A et de B qui ont la même clé, et une valeur, font les paires, et les différences
  B − A passent par le test t apparié (par défaut) ou par le test des rangs signés de Wilcoxon.
  Le tableau donne le nombre de paires de chaque variable et les moyennes de A et de B sur ces
  paires ; l'effet est le log2 du rapport de ces moyennes (quand les deux sont positives) ou le
  d_z de Cohen (la différence moyenne sur l'écart-type des différences). Une variable de moins
  de trois paires n'est pas testée. Une clé ne revient qu'une fois par classe : une clé en
  double dans A ou dans B est refusée, comme dans « Deux variables ».
  Toutes les classes : ANOVA à un facteur ou Kruskal–Wallis ; les variables rangées par p.
Les valeurs p sont corrigées pour les comparaisons multiples : Benjamini–Hochberg (taux de
fausses découvertes, par défaut), Bonferroni, ou aucune. En couleur : les variables dont le p
corrigé passe le seuil (et, pour deux classes, l'effet aussi).

Deux variables : le test qui convient à leurs types, ses conditions vérifiées, sur les
observations où les deux sont connues. Un identifiant des observations (site, secteur,
année...) peut faire les groupes, comme une variable qualitative.
  Deux variables qualitatives : le tableau de contingence et le khi² d'indépendance de Pearson,
  avec le V de Cramér. En rouge et en bleu, les cases plus ou moins fréquentes que si les deux
  variables étaient indépendantes (résidu ajusté au-delà de ±1,96). Quand les effectifs
  attendus sont trop petits pour le khi² (un sous 1, ou plus de 20 % sous 5 : règle de
  Cochran), le test exact de Fisher est conseillé ; pour un tableau 2 × 2, il est toujours
  donné, avec le rapport des cotes. Au-delà de 2 × 2 et de 200 observations, sa valeur p est
  simulée (100 000 tableaux).
  Une mesure et une variable qualitative : la mesure comparée entre les groupes, en boîtes à
  moustaches. Deux groupes : test t de Welch et Mann–Whitney (exact sous 50 valeurs de chaque
  côté sans ex aequo ; sinon par la loi normale avec la correction de continuité : le même
  calcul sous toutes les versions de R). Plus : ANOVA à un facteur, ANOVA de Welch et
  Kruskal–Wallis, chacun avec ses comparaisons deux à deux (Tukey, Games–Howell, Dunn avec la
  correction de Holm ; jusqu'à 50 groupes) : un clic sur un test les montre. Le test sur les
  rangs est conseillé quand la normalité est douteuse dans un groupe (Shapiro–Wilk p < 0,05, ou
  moins de trois observations), l'ANOVA de Welch quand les variances diffèrent
  (Brown–Forsythe p < 0,05).
  Une mesure et une variable qualitative, appariées par une troisième variable ou un
  identifiant (« Apparier par » : l'année, pour deux secteurs d'un site suivis les mêmes
  années) : les données restent en long, une ligne par secteur et par année. Deux niveaux A et
  B sont comparés sur les clés qu'ils ont tous deux : les différences B − A par le test t
  apparié (différence moyenne, son intervalle à 95 %, d_z de Cohen) et par le test des rangs
  signés de Wilcoxon, le test sur les rangs conseillé quand la normalité des différences est
  douteuse (Shapiro–Wilk p < 0,05 ; pas testée au-delà de 5 000 paires, ni avec des
  différences constantes, qui ne laissent que Wilcoxon). La p de Wilcoxon est exacte sous 50
  paires quand aucune différence n'est nulle ni ex aequo ; sinon, les différences nulles
  retirées, elle vient de la loi normale avec la correction de continuité, la même sous toutes
  les versions de R. Il faut au moins trois paires, et une clé ne revient qu'une fois par
  niveau. Les lignes restées sans partenaire, et celles sans valeur, sont comptées et
  listées ; le graphique relie chaque paire. Avec trois niveaux ou plus, le tableau du bas peut
  aussi lister toutes les paires de niveaux, chacune sur ses propres clés communes, avec la
  correction de Holm sur les paires testées, pour le test choisi au-dessus (un clic sur un
  test) : quand tous les niveaux ont les mêmes clés, celles de pairwise.t.test() et
  pairwise.wilcox.test() avec paired = TRUE. Une paire non testée (moins de trois clés
  communes, une clé deux fois dans un niveau, la même valeur dans chaque paire) dit pourquoi,
  et un clic sur une paire la compare ; quand A et B ne se comparent pas, le tableau reste,
  sous leur raison. « Paires de niveaux dans chaque » (une variable qualitative ou un
  identifiant : le site) garde les paires de niveaux d'un même groupe, les secteurs de chaque
  site comparés deux à deux. La correction de Holm porte sur les paires testées, tous les
  groupes ensemble ; la valeur p brute se lit site par site. Un niveau est du groupe que
  portent ses lignes : un niveau aux lignes de plusieurs groupes est refusé, et ceux sans
  groupe sont listés. Au-dessus des paires vient le test d'ensemble, pour les deux tests
  appariés : le test de Friedman sur les clés où chaque niveau a une valeur (les blocs
  complets ; les clés laissées de côté faute d'un niveau sont comptées), son χ², ses degrés de
  liberté et sa valeur p, avec le W de Kendall = χ² / (n (k − 1)) pour taille de l'effet (0 :
  aucun accord d'une clé à l'autre, 1 : le même classement des niveaux à chaque clé), en une
  phrase. Dans chaque groupe, un test de Friedman par groupe, sur ses propres niveaux et ses
  clés complètes, sa valeur p corrigée par Holm sur les groupes testés ; un groupe de moins de
  trois niveaux ou de moins de deux clés complètes n'a pas de test, et la raison est dite.
  Deux mesures : les corrélations de Pearson et de Spearman ; Spearman est conseillée quand la
  normalité de l'une des deux est douteuse. Appariées par « l'observation (même ligne) », deux
  mesures des mêmes lignes (avant et après, par exemple) sont comparées à la place : les
  différences Variable 2 − Variable 1, sur les observations où les deux sont connues, par les
  deux mêmes tests appariés.
Le résultat du test conseillé est donné en une phrase, prête pour un rapport (le bouton à côté
la copie), avec la taille de l'effet : V de Cramér, rapport des cotes, d ou d_z de Cohen,
corrélation rang-bisériale, η², ε², r ou ρ. Celle de Mann–Whitney nomme les deux groupes avec
leurs médianes.

Matrice des corrélations : les corrélations de Pearson ou de Spearman de toutes les variables
quantitatives (300 au plus), chaque paire sur les observations où les deux sont connues,
valeurs p corrigées pour le nombre de paires. Un clic sur une paire, dans la table ou le
graphique, la teste dans « Deux variables ».

Avant/après (BACI) : un changement de gestion sur certaines unités (l'impact) comparé à des
unités restées comme elles étaient (les témoins), comme dans un plan avant/après avec témoin.
Choisir une réponse quantitative, un temps (une variable ou un identifiant des observations :
l'année, ou des dates) et une unité (une variable qualitative ou un identifiant : le secteur),
puis cocher la ou les unités d'impact et la ou les unités témoins. À chaque temps, l'écart d_t
est la moyenne des lignes de l'impact moins celle des lignes des témoins, aux temps où les deux
ont une valeur (une ligne par unité et par temps donne la moyenne des unités ; les temps d'un
seul côté sont listés et laissés de côté) : avec des dates, l'impact et les témoins comptés le
même jour ; pour comparer des années, prendre l'année. L'événement est le premier temps compté
« après » (un nombre pour un temps fait de nombres ; une date pour un temps fait de dates, où
une année est son 1er janvier) : pour une densité de printemps qui répond à la gestion de
l'année d'avant, l'année qui suit le changement. Les temps qui le précèdent sont « avant » ; «
après » court jusqu'à une fin facultative, elle aussi du genre du temps (avec des dates,
31/12/2012 pour la fin de 2012 : une année seule est refusée, comme une date pour un temps fait
de nombres), les temps suivants en gris, hors du test. Avec au moins deux temps dans chaque
période, les écarts d'après sont comparés à ceux d'avant : test t de Welch (par défaut), t de
Student (variances égales : un modèle linéaire de l'écart sur la période) ou Mann–Whitney (sur
les rangs) ; l'effet est le changement de l'écart moyen, après
moins avant, avec son intervalle à 95 %, et le résultat vient en une phrase prête pour un
rapport. Le graphique montre les écarts dans le temps, l'événement et la moyenne de chaque
période ; tant qu'aucun événement n'est entré, les écarts seuls. Les temps sont tenus pour
indépendants : des écarts successifs qui se ressemblent (autocorrélation) rendent la valeur p
trop petite. « Ajuster le modèle mixte » en tient compte : il ajoute au projet deux variables
valant 0 ou 1, « période BACI (2007) » (1 à partir de l'événement, 0 avant) et « impact BACI
(S1 contre S2, S3) » (1 pour les unités d'impact, 0 pour les témoins, manquante pour les
autres unités), puis le modèle linéaire mixte y ~ période × impact + (1 | unité) sur les
lignes des unités d'impact et témoins dont le temps est connu, jusqu'à la fin s'il y en a
une : une ordonnée à l'origine aléatoire par unité et, avec « avec CAR1 dans le temps »
(cochée d'office quand chaque unité a au moins trois temps ; impossible quand une unité a
plusieurs lignes au même temps), une autocorrélation CAR1 le long du temps dans chaque unité.
Une variable de ce nom, ou de ce nom suivi de (2), (3)…, ou de son nom dans l'autre langue, qui
a déjà ces valeurs sert telle quelle ; sinon la variable prend le premier de ces noms qui est
libre (un nom tenu par d'autres valeurs : d'autres unités au-delà des trois nommées, un autre
temps, un temps corrigé depuis) ; Ctrl+Z les retire, comme une nouvelle
variable. Le modèle rejoint le projet (nommé « BACI <réponse> » ; les mêmes réglages
réajustent le même modèle) et ses vues s'ouvrent. De retour dans la vue BACI, son effet BACI,
le coefficient période × impact avec son intervalle à 95 % et sa valeur p, vient en une phrase
sous celle du test, qui dit que ce modèle tient compte des unités et, avec CAR1, de
l'autocorrélation. Son texte des Méthodes dit que c'est le modèle BACI et ce que valent ses
deux variables.

Modèles linéaires, généralisés et mixtes
----------------------------------------
Nouveau modèle › type « Régression linéaire » ou « Modèle linéaire mixte » : une variable Y
quantitative, les variables X de l'onglet Variables (transformations et termes croisés
compris ; une variable qualitative par ses catégories, l'une d'elles servant de référence).
Sans X : le modèle nul, utile pour comparer les AIC. L'échelle par défaut garde les unités
des variables (coefficients par unité) ; UV donne des coefficients par écart-type.
Un modèle mixte (nlme) ajoute des effets aléatoires emboîtés, du plus large au plus fin : une
ordonnée à l'origine aléatoire par site, puis par secteur dans son site (un identifiant des
observations ou une variable qualitative). Il peut ajouter une autocorrélation dans le temps
(CAR1, en temps continu : des années manquantes ne gênent pas ; le temps est un identifiant ou
une variable, de nombres ou de dates, et φ est alors d'une année à l'autre : voir Le temps en
dates) à l'intérieur du dernier niveau ou, par « dans chaque », d'un niveau plus fin qui n'a
pas d'effet aléatoire à lui : le secteur dans son site, quand seul le site a un effet
aléatoire. Les coefficients et les
variances sont estimés en REML ; la log-vraisemblance, l'AIC, l'AICc et le BIC viennent de
l'ajustement en ML, le seul qui compare des modèles aux effets fixes différents. La validation
croisée se fait par défaut par le premier effet aléatoire : chaque site est prédit par les
effets fixes du modèle ajusté sans lui, comme un site jamais vu.
Pentes aléatoires : sous chaque effet aléatoire choisi, « Pentes aléatoires par site » coche
les variables X quantitatives dont la pente change d'un site à l'autre, le plus souvent
l'année : chaque site a sa propre tendance, qui varie autour de la pente fixe du modèle ; c'est
(1 + annee | site) dans une formule R. La variable doit être aussi un terme X du modèle,
quantitatif et seul (transformé ou non), pas en courbe : sinon le modèle est refusé, en la
nommant. Avec nlme (un modèle mixte, ou un GLM ou un GAM à loi normale avec CAR1, ajusté par
mgcv::gamm), chaque niveau a la matrice de covariance générale de nlme
(random = ~ annee | site ; avec des niveaux emboîtés, la liste list(site = ~ annee,
secteur = ~ 1)) : la variance de son ordonnée à l'origine, celle de chaque pente et leur
corrélation. L'écart-type d'une pente, en unités de Y par unité de X, dit combien les tendances
des sites s'écartent de la tendance moyenne : environ 95 % des sites sont à ±2 écarts-types de
la pente fixe. La corrélation dit si les sites hauts ont des pentes plus fortes (au-dessus de
0) ou plus faibles (au-dessous) ; elle est celle de l'ordonnée à l'origine prise à x = 0. Le
Résumé donne la variance et l'écart-type de chaque ordonnée à l'origine et de chaque pente, et
la corrélation de chaque pente avec l'ordonnée à l'origine de son niveau (avec plusieurs pentes
à un niveau, leurs corrélations entre elles sont estimées mais pas dans ce tableau : summary(m)
du script d'Exporter vers R les donne). Avec une pente, la variance d'un niveau change avec x
et sa part de la variance aléatoire n'a plus une seule valeur : le Résumé donne la part de
chaque niveau, de sa variance moyenne sur les observations, et les R2 marginal et conditionnel
la prennent aussi, comme Johnson (2014) étend ceux de Nakagawa et Schielzeth : la moyenne sur
les observations de zᵢᵀΣzᵢ, Σ la matrice du niveau et zᵢ = (1, les valeurs de ses pentes).
Centrer : une variable loin de 0, comme l'année (≈ 2010), met l'ordonnée à l'origine aléatoire
loin des données (à l'an 0), où sa corrélation avec la pente est près de ±1 ; l'ajustement s'y
arrête souvent trop tôt, sur une pente d'écart-type presque nul. Nuée ne centre pas sans le
dire : le Résumé signale un ajustement singulier (une corrélation au-delà de ±0,99, ou
l'écart-type d'une pente, fois celui de sa variable sur les observations, sous 1 % de
l'écart-type résiduel) et, quand la variable est loin de 0 (sa moyenne au-delà de son
écart-type), conseille de la centrer, échelle Ctr ou UV dans l'onglet Variables : c'est le même
modèle, que nlme trouve alors le plus souvent, l'ordonnée à l'origine prise à la moyenne de la
variable. Une variable centrée et un ajustement singulier : les données ne permettent pas
d'estimer cette pente ou cette corrélation ; comparez par l'AIC le modèle sans elle. Un échec
de l'ajustement reste « Le modèle n'a pas pu être ajusté ».
Dans un GLM ou un GAM ajusté par mgcv::gam (une autre loi que la normale, ou sans CAR1), une
pente aléatoire est un terme s(site, annee, bs = "re") (Wood, 2017) : indépendante de
l'ordonnée à l'origine aléatoire, sans corrélation, mgcv ne sachant pas les corréler. Ce modèle
dépend de l'endroit où x vaut 0 : x centré, l'ordonnée à l'origine aléatoire est le niveau de
chaque site à la moyenne de x ; l'année non centrée ne laisse guère de place à la variance de
la pente. Le Résumé le dit. Refait avec CAR1 (mgcv::gamm), un tel modèle a ses pentes
corrélées, comme nlme.
Avec des pentes aléatoires : la validation croisée prédit un site jamais vu par les effets
fixes ; la sélection par AIC ne choisit que les effets fixes, et le groupe d'une variable qui a
une pente aléatoire reste dans chaque modèle (une pente aléatoire suit la pente fixe de sa
variable) ; dans Apport des blocs, sans cette variable, sa pente fixe seule est retirée et sa
pente aléatoire reste (le test de la pente moyenne, avec les mêmes effets aléatoires) ; deux
modèles aux pentes aléatoires différentes n'ont pas les mêmes effets aléatoires : pas de test
du rapport de vraisemblance entre eux, ils se comparent par l'AIC sur les mêmes observations ;
Ajuster avec CAR1 garde les pentes ; les prédictions sont celles des effets fixes. Non
couvert : dans nlme, une pente non corrélée à l'ordonnée à l'origine ((0 + annee | site),
(1 | site) + (0 + annee | site), ||), refusée dans la formule R ; la pente aléatoire d'une
variable qualitative, d'un terme croisé ou d'une courbe.
Type « Modèle linéaire généralisé (GLM) » ou « Modèle additif (GAM) » (mgcv), pour une
variable Y qui ne suit pas une loi normale. Loi de Y : Poisson pour des comptages ; binomiale
négative pour des comptages qui varient plus qu'une loi de Poisson ne le permet (son θ
estimé) ; Poisson à excès de zéros pour des comptages qui ont plus de zéros qu'une loi de
Poisson n'en donne (ses θ₁ et θ₂ estimés) ; binomiale pour la présence-absence (0 ou 1) ;
gamma pour des valeurs positives ; Tweedie pour des densités avec des zéros (sa puissance p
estimée) ; bêta pour des proportions strictement comprises entre 0 et 1 (sa précision φ
estimée) ; ou normale. Le lien est log (comptages, gamma, Tweedie ; pour le Poisson à excès de
zéros, celui de son paramètre de Poisson μ), logit (binomiale, bêta) ou l'identité (normale). Effort
(décalage) : une variable comme une surface, une durée ou un nombre de passages, dont le log
entre dans le modèle avec un coefficient 1 : il décrit alors une densité (un effort nul ou
négatif est refusé). Des effets aléatoires comme ci-dessus en font un GLMM ou un GAMM. Avec la
loi normale et au moins un effet aléatoire, un GLM ou un GAM peut prendre aussi
l'autocorrélation dans le temps : il est alors ajusté par mgcv::gamm, comme un modèle mixte de
nlme dont les courbes sont des effets aléatoires (coefficients, courbes, variances et φ en
REML ; log-vraisemblance, AIC, AICc et BIC d'un ajustement en ML, comparables seulement à ceux
d'autres modèles ajustés ainsi). Avec une autre loi, elle est refusée : mgcv::gamm passerait
par une quasi-vraisemblance pénalisée (PQL), sans vraie vraisemblance ni AIC. Dans un modèle
additif, les variables X cochées dans la colonne Courbe de l'onglet Variables entrent par une
courbe lissée (une spline) plutôt que par une droite, pour un effet qui monte puis descend, ou
un seuil ; les données décident de sa courbure (son edf ; 1 est une droite). Sa dimension de
base k borne sa courbure : 10 au plus, moins quand la variable a peu de valeurs ; tapez-en une
autre (de 3 à 100) dans la case à côté de la coche, comme s(x, k = 5) dans R. Une courbe par
catégorie : la liste à côté de k offre les variables qualitatives X du modèle (« une par
secteur »), comme s(annee, by = secteur) dans mgcv : chaque secteur a sa courbe, de dimension k
chacune, avec son edf, son test, sa concurvité, son effet et ses seuils. Chacune est centrée sur
les observations de sa catégorie (la contrainte d'identifiabilité de mgcv) : la variable
qualitative doit rester en X, son effet principal donnant l'écart de niveau entre les
catégories ; sans lui, toutes les catégories auraient la même moyenne, et Nuée refuse alors le
modèle plutôt que d'ajouter ce terme sans le dire. Le facteur que mgcv voit vient des colonnes
0/1 des catégories du modèle (ses niveaux, les catégories observées, dans leur ordre) ; une
catégorie ajoutée aux données après la définition du modèle n'y a pas de colonne, donc pas de
courbe : ses lignes restent hors du modèle avec les observations incomplètes, et dans un jeu de
test, sans prédiction. Une variable en courbe par catégorie n'est pas aussi dans un terme
croisé avec une variable qualitative (chaque catégorie a déjà sa courbe). Les courbes et les
effets aléatoires sont estimés en REML, et l'AIC vient d'un ajustement en ML ; un GLM sans eux
est ajusté par maximum de vraisemblance, comme le font glm() et MASS::glm.nb(). Le résumé d'un
modèle de Poisson prévient quand les comptages sont surdispersés (le khi² de Pearson au-delà
de 1,5 fois ses degrés de liberté) : ses valeurs p sont alors trop petites, et la binomiale
négative convient mieux à ces comptages.
Poisson à excès de zéros et loi bêta (les familles ziP et betar de mgcv ; Wood, Pya et Säfken,
2016). Dans le Poisson à excès de zéros, un modèle à obstacle, un comptage est nul avec la
probabilité 1 − p et suit sinon une loi de Poisson de paramètre μ tronquée en zéro ; le
prédicteur linéaire est log(μ) (mgcv nomme ce lien « identity » ; exp(coefficient) multiplie μ,
l'effort aussi), et p lui est lié par log(−log(1 − p)) = θ₁ + θ₂ log(μ), θ₁ et θ₂ estimés avec
le modèle ; θ₁ = 0 et θ₂ = 1 redonnent la loi de Poisson, et son AIC se compare à ceux des
modèles de Poisson et binomiaux négatifs des mêmes comptages. Ses valeurs ajustées, ses
prédictions, sa validation croisée et son jeu de test sont des comptages attendus,
p μ / (1 − e^(−μ)) ; il n'a pas de R² ajusté, seulement la part de déviance expliquée. Il
demande des comptages, dont au moins un zéro. Beaucoup de zéros ne font pas un excès de zéros
(trop de zéros pour la moyenne du modèle, si) : comparez les modèles par l'AIC et regardez les
résidus quantiles ; quand des X expliquent les zéros eux-mêmes, le modèle peut mal s'identifier.
La loi bêta est faite pour des proportions strictement comprises entre 0 et 1 (une couverture,
une part de temps), de moyenne μ par le lien logit et de variance μ (1 − μ) / (1 + φ), sa
précision φ estimée (Ferrari et Cribari-Neto, 2004) ; son AIC se compare à celui d'un modèle de
loi normale des mêmes proportions. Une réponse à 0 ou à 1 est refusée, avec le nombre de ces
valeurs : mgcv les déplacerait juste à l'intérieur (son eps), ce qui n'est pas sans effet sur
l'ajustement ; ramenez-les vous-même dans l'intervalle, en le disant (Édition › Nouvelle

termes du premier modèle, puis ceux des autres dans leur ordre : deux modèles partagent une ligne
quand ils ont un terme du même nom. Dessous : n, AIC et AICc (ajustement en ML), R² (une
régression linéaire), R² marginal et conditionnel (un modèle mixte) ou part de la déviance
expliquée (un GLM ou un GAM), l'écart-type σ de chaque effet aléatoire (et le résiduel d'un
modèle de nlme), φ de CAR1 et l'edf de chaque courbe. Un modèle de lien log ou logit garde ses
estimations sur l'échelle du lien, comme dans sa vue Coefficients, et la note le dit. Ctrl+C (ou
le bouton de copie) met le tableau dans le presse-papiers en texte et en tableau, qu'Excel et
Word collent en tableau, avec des étoiles pour p (* ≤ 0,05, ** ≤ 0,01, *** ≤ 0,001) et leur
légende ; Fichier › Exporter les résultats du modèle (Ctrl+E), depuis cette vue, l'écrit, avec à
côté les coefficients de chaque modèle en nombres.
Fichier › Exporter : les observations (observées, ajustées, prédites en validation croisée,
résidus), les coefficients, la qualité de l'ajustement, les effets aléatoires (chaque
ordonnée à l'origine et pente aléatoire, et leur corrélation) et les courbes, un tableau
chacun. Fichier › Rapport du modèle : le résumé et les coefficients, l'effet de
chaque terme, les seuils de chaque courbe, observé / prédit et les résidus (aussi les résidus
quantiles, pour des comptages, une présence-absence ou des valeurs positives).
Fichier › Exporter vers R : un script ou un rapport pour une régression aussi, avec lm,
nlme::lme, mgcv::gam ou mgcv::gamm : ses lignes et ses termes, les ajustements (REML et ML ;
ses pentes aléatoires comprises), la validation croisée par ses groupes, puis les coefficients,
l'AIC, le R2, les variances, les courbes avec leur concurvité et leurs seuils (les mêmes
tirages que la vue Seuils), les résidus quantiles (les mêmes tirages que la vue Résidus), le
jeu de test et les graphiques, vérifiés contre les résultats de Nuée avant d'être écrits.
Termes croisés avec une variable qualitative (onglet Termes croisés, ou a * b et a:b dans la
formule R) : une variable qualitative entre dans un terme croisé par chacune de ses catégories,
une fois au plus (ni au carré ni au cube). année × secteur laisse la pente de l'année changer
d'un secteur à l'autre : ses coefficients sont, pour chaque secteur sauf celui de référence,
l'écart entre la pente de l'année dans ce secteur et sa pente dans le secteur de référence, qui
est le coefficient de l'année. La catégorie de référence est celle que l'ajustement laisse de
côté (la dernière catégorie observée), la même dans l'effet principal et dans le terme croisé.
Pour une densité suivie par secteur, un coefficient de 0,2 pour annee*secteur(S2), celui de
l'année valant 0,05, se lit : la densité gagne 0,25 par an dans S2, 0,2 de plus que dans le
secteur de référence. Sans l'année en X (un facteur sans rôle dans l'onglet Termes croisés, ou
y ~ secteur + secteur:année), chaque coefficient de année × secteur est la pente de l'année
dans ce secteur ; sans le secteur en X (y ~ année + année:secteur), les pentes diffèrent mais
les secteurs partagent une même ordonnée à l'origine. habitat × traitement : chaque coefficient
est l'écart entre l'effet d'un traitement (par rapport au traitement de référence) dans un
habitat et ce même effet dans l'habitat de référence ; trois variables (année × secteur ×
habitat) donnent des écarts d'écarts. Le coefficient d'une catégorie elle-même (secteur(S2))
est alors son écart à la catégorie de référence là où les termes croisés avec elle valent 0 :
là où l'année vaut 0 (avec les années dans leurs unités, l'an 0, loin des données ; l'année
moyenne quand l'année est centrée, Ctr ou UV), dans l'habitat de référence pour habitat ×
traitement. Les colonnes sont rangées comme R range ses termes, les effets principaux
d'abord : les résultats sont ceux de lm(), nlme::lme() et mgcv avec des facteurs dont le
premier niveau est la référence de Nuée. Une combinaison de catégories qu'aucune observation
n'a (un traitement jamais donné dans un habitat) ne peut pas être estimée : elle est laissée
de côté, et le Résumé la nomme parmi les termes jamais observés. Effets : un terme
quantitatif croisé avec des catégories a une droite par catégorie (une courbe quand le terme
est une courbe d'un GAM), de pente son coefficient plus celui de son produit avec la
catégorie, avec sa bande à 95 % tirée de la covariance des coefficients et, sous le graphique,
chaque pente par unité avec son intervalle. Pour une courbe, les Seuils sont ceux de la
catégorie choisie : la courbe commune plus la pente de cette catégorie ; une courbe par
catégorie (s(x, by = f), plus haut) donne à chaque catégorie sa propre forme, et non la même
courbe inclinée. Dans la sélection par AIC et la table des apports, un terme croisé entre et
sort en entier (toutes ses catégories), seulement avec ses effets principaux et ses termes
croisés d'ordre plus bas. Le texte des Méthodes nomme chaque catégorie de référence et dit ce
que valent le coefficient d'une catégorie et ceux des termes croisés. Prédiction : une
catégorie que le modèle a vue a sa propre prédiction ; une catégorie, ou une combinaison de
catégories, qu'il n'a pas vue (absente de ses observations, des autres groupes en validation
croisée, ou inconnue du projet dans un fichier) n'en a pas : le modèle la prédirait comme la
catégorie de référence, ou sans sa pente, et R refuse de même un niveau qu'il n'a pas vu.
C'est la règle de chaque variable qualitative d'une régression (effets principaux, termes
croisés, courbes par catégorie ; LM, LMM, GLM, GAM, mgcv::gamm), pas des autres modèles
(PLS...). Ces observations sont comptées et nommées : en validation croisée, le Résumé dit
combien sont restées sans prédiction et de quelle variable, Q2 et RMSEcv étant calculés sur
les autres ; quand il n'en reste aucune (des secteurs propres à chaque site, validés par
site), Q2 manque, et le Résumé dit que le modèle ne peut pas être validé par ces groupes avec
cette variable en X fixe : faites-en un effet aléatoire, ou choisissez d'autres groupes de
validation croisée. Le jeu de test les compte à part de son RMSEP, de son biais et de son Q2
externe ; Prédiction › Prédire les marque ⊘ (colonne Catégorie non vue, dans le tableau
exporté aussi). Le texte des Méthodes et le script d'Exporter vers R font de même.

Modèles de classe et graphique de Coomans
-----------------------------------------
Nouveau modèle › type « Modèles de classe » : une ACP par catégorie de la variable de classe,
sur les seules observations de cette catégorie (« M5.Gala », « M5.Golden »...), chacune avec
ses centres, ses échelles et son nombre de composantes. Une observation appartient à une
classe quand sa distance au modèle de la classe (DModX) ne dépasse pas la limite DCrit à 5 % :
à une classe, à plusieurs, ou à aucune (une observation d'un autre type que toutes les
classes connues). Graphiques › Graphique de Coomans : les distances de chaque observation à
deux des modèles, avec leurs limites en rouge ; la table donne, pour chaque classe, la part de
ses observations que chaque modèle accepte (attendu : vers 95 % pour sa propre classe, 0 %
pour les autres), puis les distances et les classes de chaque observation.

Analyse de redondance et analyse des correspondances
----------------------------------------------------
Nouveau modèle › type « RDA (analyse de redondance) » : ce que des variables explicatives X
expliquent d'un tableau de réponses Y (abondances d'espèces, mesures), et comment. Y : des
variables quantitatives ; X : les variables explicatives (une variable qualitative par ses
catégories, termes croisés compris) ; Z (covariable, dans la liste Rôle de l'onglet
Variables) : des variables dont l'effet est retiré d'abord (RDA partielle : le site, un
gradient connu...). Onglet Général : la transformation des réponses (Hellinger ou corde pour
des abondances, Legendre et Gallagher 2001 ; log(x + 1) ; ou aucune) ; les réponses centrées
(RDA sur les covariances, pour des réponses dans les mêmes unités) ou centrées-réduites (sur
les corrélations) ; le nombre de permutations des tests (999 ; 0 : aucun test), les groupes à
l'intérieur desquels elles restent (un identifiant ou une variable qualitative : un site suivi
plusieurs années n'est permuté qu'avec lui-même) et leur graine (la même graine donne les mêmes
permutations, donc les mêmes valeurs p). Une observation où une valeur manque, ou sans aucune
abondance avec Hellinger ou corde, est laissée de côté.

Vues : Résumé (l'inertie totale, la part des covariables, celle des X et ce qui reste ; R2 et
R2 ajusté ; le pseudo-F et sa valeur p par permutation) ; Ordination, le triplot (les
observations par leurs scores wa, sommes pondérées des réponses, ou lc, combinaisons linéaires
des X ; les réponses ; une flèche par X quantitative, allongée pour remplir le graphique du
facteur indiqué dans la légende, et un triangle au centroïde de chaque catégorie ; l'échelle 1
garde les distances entre observations, l'échelle 2 les corrélations entre réponses) ; Valeurs
propres (les axes contraints en bleu, les non contraints en gris) ; Tests par permutation
(chaque axe contraint après les précédents, chaque terme après tous les autres ; Sélection pas
à pas garde un terme qui augmente le R2 ajusté sans dépasser celui de tous les termes et dont
le test donne p ≤ 0,05, Blanchet et al. 2008 ; Partition de la variance partage le R2 ajusté
entre deux ou trois blocs de X, d'après la colonne Bloc de l'onglet Variables) ; les listes des
observations et des variables. Les résultats sont ceux du paquet vegan (rda, anova.cca,
RsquareAdj, ordiR2step, varpart) : mêmes valeurs propres, scores et pseudo-F, et pour les mêmes
permutations, mêmes valeurs p.

Type « Analyse des correspondances (CA) » : un tableau d'effectifs ou d'abondances (les
variables X, une observation par ligne, des valeurs positives ou nulles) ; les observations et
les variables sans aucune valeur sont laissées de côté. Vues : Résumé (l'inertie totale : le
khi² du tableau divisé par son effectif total) ; Ordination (lignes et colonnes en échelle 1, 2
ou 3 : distances du khi² entre observations, entre variables, ou symétrique) ; Valeurs
propres ; Contributions et cos² (la part de chaque ligne et de chaque colonne dans l'inertie
d'un axe, en bleu au-dessus de la moyenne, et la qualité de sa représentation) ; les listes.

L'une et l'autre exportent leurs tableaux (Fichier › Exporter), écrivent leur texte des
méthodes avec ses références et font un rapport. Fichier › Exporter vers R écrit un script, ou
un rapport R Markdown ou Quarto, qui les refait avec R seul, leurs tests avec les mêmes
permutations. Elles ne prédisent pas de nouvelles observations.

Analyse canonique des correspondances (CCA)
-------------------------------------------
Nouveau modèle › type « CCA (analyse canonique des correspondances) » (ter Braak 1986) : la
cousine de la RDA pour des effectifs ou des abondances d'espèces qui répondent aux gradients en
cloche plutôt qu'en ligne droite. Y : les espèces (effectifs ou abondances, positifs ou nuls),
les colonnes du tableau ; X : les variables explicatives ; Z : des covariables retirées d'abord
(CCA partielle). Le tableau est ramené à ses écarts à l'indépendance, comme dans une analyse des
correspondances, et les X pondérés par les masses des observations (leurs parts de l'effectif
total). Onglet Général : le nombre de permutations (999 ; 0 : aucun test), les groupes où elles
restent et leur graine ; à chaque permutation, les masses suivent les observations. Les
observations où une valeur manque ou sans aucune abondance, et les espèces absentes de toutes
les autres, sont laissées de côté.

Les vues, comme celles de la RDA : Résumé (l'inertie ; le R² et le R² ajusté, estimé par les
permutations du test, Peres-Neto et al. 2006, absent sans permutation ; le pseudo-F et p) ;
Ordination, le triplot en échelle 1 (distances du khi² entre observations), 2 (entre espèces)
ou 3 (symétrique) ; Valeurs propres ; Tests par permutation (chaque axe contraint après les
précédents, les termes l'un après l'autre dans l'ordre du modèle, chaque terme après tous les
autres ; la sélection pas à pas, ses R² ajustés par les mêmes permutations). La partition de la
variance est celle d'une RDA. Les résultats sont ceux de vegan (cca, anova.cca par axe, par
terme en séquence et marginal, RsquareAdj, ordiR2step) et, pour les mêmes permutations, les
mêmes valeurs p. Texte des méthodes, export, rapport et export vers R comme pour la RDA.

Espèces indicatrices
--------------------
Nouveau modèle › type « Espèces indicatrices (IndVal) » : quelles espèces caractérisent chaque
groupe d'observations (des milieux, des types de sites...). Y : les espèces, des abondances ou
des présences ; Classe : la variable qualitative des groupes. Pour chaque espèce et chaque
groupe, A (la spécificité : la part de son abondance dans le groupe) et B (la fidélité : la part
des observations du groupe où elle est), et la valeur indicatrice √(A·B) : IndVal.g par défaut,
qui compare les abondances moyennes des groupes, des groupes d'effectifs différents comptant
alors autant (De Cáceres et Legendre 2009), ou IndVal, qui compare leurs totaux (Dufrêne et
Legendre 1997). Les combinaisons de groupes (De Cáceres et al. 2010) : par défaut toutes,
jusqu'à tous les groupes (une espèce rattachée à tous n'est pas testée), ou les groupes seuls,
ou jusqu'à un ordre. Chaque espèce va au groupe ou à la combinaison de sa plus grande valeur,
testée en permutant les groupes des observations (999 fois ; à l'intérieur de strates, un
identifiant ou une variable qualitative ; une graine) ; sa valeur p corrigée sur les espèces
(Benjamini–Hochberg ou Holm) est donnée à côté de la p brute. « Présences seules » prend des 0/1.
Les vues : Espèces indicatrices (le tableau, qui se trie ; p ≤ 0,05 en rouge ; « p corrigée
≤ 0,05 seulement » ; un clic met l'espèce en évidence dans le graphique), Valeurs indicatrices
(la valeur de chaque espèce pour son groupe, de la couleur du groupe, pâle quand elle n'est pas
significative ; ou A et B d'une espèce dans chaque groupe), Résumé (le nombre d'espèces retenues
à 0,05, p brutes et corrigées, et par groupe). Les statistiques sont celles de
indicspecies::multipatt et, pour les mêmes permutations, les mêmes valeurs p. Texte des
méthodes, export et rapport comme pour les autres modèles ; Exporter vers R refait l'analyse
avec R seul, les fonctions du moteur lui-même et les mêmes permutations.

Raréfaction et accumulation des espèces
---------------------------------------
Graphiques › Raréfaction (ou dans l'explorateur, sous le projet) : combien d'espèces portent les
observations, comparées à effort égal. Les espèces : des colonnes d'effectifs, une plage d'une
colonne à une autre dans l'ordre du tableau (comme les indices de diversité de Nouvelle variable
les lisent) ou cochées dans la liste. Raréfaction (par observation) : la richesse attendue de
chaque observation dans m individus tirés sans remise (Hurlbert 1971) et son écart-type (Heck et
al. 1975), la courbe de 1 à tous ses individus, et sa richesse à une taille commune (par défaut
celle de la plus petite observation : la ligne en pointillés) ; dans le tableau, Chao1 (corrigé
du biais) et ACE estiment la richesse de chaque observation. Ils demandent des effectifs
entiers d'individus : avec des recouvrements ou des densités, la vue le dit et ne donne que
l'accumulation. Accumulation (sur les observations) : la richesse attendue dans k observations
tirées parmi toutes (méthode exacte, Ugland et al. 2003), ±2 écarts-types, et les estimateurs de
la richesse totale d'après les présences : Chao2, les jackknifes d'ordre 1 et 2 et le bootstrap.
Par groupe (une variable qualitative ou un identifiant) : une courbe et des estimateurs par
groupe. Un clic ou un cadre sélectionne des observations, comme dans Séries. Les valeurs sont
celles de vegan (rarefy, rarecurve, specaccum, estimateR, specpool), sauf l'écart-type d'ACE,
calculé par la méthode delta avec le gradient d'ACE lui-même (vegan en prend un autre).
PCoA, NMDS, PERMANOVA et test de Mantel
---------------------------------------
Quatre analyses fondées sur une distance entre observations, calculée sur le tableau Y (rôle Y :
les espèces, ou toutes variables quantitatives) ; une observation où une valeur Y manque est
laissée de côté, et comptée. Onglet Général : la distance, comme le paquet vegan la définit
(Bray-Curtis, Jaccard 2B/(1 + B), Gower, euclidienne, Manhattan, Canberra, Kulczynski,
Hellinger, corde), au choix sur les présences-absences (Bray-Curtis devient alors l'indice de
Sørensen) ; une transformation avant elle (racine carrée ou quatrième, log(x + 1),
présences-absences, abondances relatives, double standardisation de Wisconsin, racine carrée
puis Wisconsin comme le fait metaMDS) ; le nombre de permutations des tests (999 ; 0 : aucune),
les groupes à l'intérieur desquels elles restent et leur graine. Une distance qui n'a pas de
sens pour des valeurs négatives (Bray-Curtis, Jaccard, Kulczynski, Canberra, Hellinger) les
refuse, et une distance qui n'est pas définie pour une observation sans aucune valeur (que des
zéros) la nomme.

Type « PCoA (analyse en coordonnées principales) » : les axes qui montrent au mieux, sur peu de
dimensions, les distances entre observations (Gower 1966). Une distance qui n'est pas
euclidienne (Bray-Curtis, le plus souvent) a des valeurs propres négatives : elles sont gardées
et signalées, et la correction de Lingoes ou de Cailliez (onglet Général) ajoute la constante
qui les supprime. Variables X (facultatives) : ajustées sur les deux premiers axes comme
vegan::envfit, une flèche par variable quantitative (sa direction et son R2), un centroïde par
catégorie d'une qualitative (et son R2), chacune testée par permutations ; les observations
sans valeur X ne sont laissées de côté que de cet ajustement. Vues : Résumé ; Ordination (les
observations, colorées et étiquetées comme dans les autres graphiques, les espèces à la
moyenne pondérée de leurs observations, les flèches, en gris quand p > 0,05, et les
centroïdes, à la même échelle sur les deux axes) ; Valeurs propres (la part de l'inertie
totale, la somme de toutes les valeurs propres ; les négatives en rouge) ; Variables ajustées ;
les listes des observations et des variables.

Type « NMDS (positionnement multidimensionnel non métrique) » : une configuration en k
dimensions (2 par défaut, de 1 à 4) dont les distances respectent l'ordre des dissimilarités
(Kruskal 1964), par MASS::isoMDS comme le fait vegan::metaMDS : depuis la PCoA, puis depuis 20
départs au hasard (graine fixe) ; le plus faible stress est gardé, et le Résumé dit si un autre
départ l'a retrouvé (Procrustes) : si aucun ne l'a fait, augmentez les départs. Une
dissimilarité nulle entre deux observations est remplacée par la moitié de la plus petite non
nulle. La configuration est centrée, tournée sur ses axes principaux et mise à l'échelle de la
plus grande dissimilarité. Vues : Résumé (le stress : sous 0,1 bon, au-delà de 0,2 à lire avec
prudence) ; Ordination, comme pour la PCoA ; Diagramme de Shepard (la dissimilarité et la
distance dans l'ordination de chaque paire, la régression monotone, le stress de chaque
départ) ; Variables ajustées ; les listes (la part du stress de chaque observation).

Type « PERMANOVA (analyse de variance par permutation) » : l'effet des termes X (qualitatifs ou
quantitatifs, termes croisés compris) sur la distance (Anderson 2001), comme vegan::adonis2 :
chaque terme après ceux qui le précèdent, dans leur ordre (séquentiels), chacun après tous les
autres (marginaux : un terme contenu dans un terme croisé n'est pas testé seul) ou le modèle
entier ; degrés de liberté, somme des carrés, R2, pseudo-F et sa valeur p par permutation. Avec
elle, la dispersion multivariée (Anderson 2006, comme vegan::betadisper) des catégories de
chaque variable X qualitative et de la variable de classe (rôle Classe, un groupement de plus) :
la distance de chaque observation au centroïde (ou à la médiane spatiale) de son groupe dans
l'espace de la PCoA, comparée par une ANOVA, ses résidus permutés, et les paires de Tukey. Une
dispersion qui diffère d'un groupe à l'autre rend la PERMANOVA plus difficile à lire : ses
différences peuvent venir de l'étalement des groupes autant que de leur position. Vues :
Résumé ; Table de la PERMANOVA ; Dispersion multivariée (en boîtes ou sur le plan de la PCoA,
avec ses tests) ; la liste des observations (la distance de chacune à son centre).

Type « Test de Mantel » : la corrélation (de Pearson, ou de Spearman sur les rangs) entre la
distance de Y et la distance euclidienne des variables X, mises à l'échelle comme le dit
l'onglet Variables (UV par défaut), et sa valeur p unilatérale par permutation (vegan::mantel) ;
avec des covariables Z (rôle Z), le test de Mantel partiel (vegan::mantel.partial) ; et le
corrélogramme de Mantel (vegan::mantel.correlog) : la distance X découpée en classes d'égale
largeur (règle de Sturges, ou le nombre donné), le r de Mantel de chaque classe (positif : des
observations proches plus semblables), les classes au-delà de la moitié testées seulement si
chaque observation y a une paire, les valeurs p corrigées progressivement par la méthode de
Holm. Vues : Résumé ; Test de Mantel (chaque paire d'observations) ; Corrélogramme de Mantel ; la
liste. « Distance X : Géographique » compare la distance de Y à la distance entre les
observations en kilomètres, d'après les coordonnées du projet (voir Cartes et données
spatiales), sans variable X : des relevés proches se ressemblent-ils plus (la décroissance avec
la distance), et avec le corrélogramme, jusqu'à quelle distance.

Les quatre exportent leurs tableaux (Fichier › Exporter), écrivent leur texte des méthodes avec
ses références et font un rapport ; elles ne prédisent pas de nouvelles observations. Les
résultats sont ceux de vegan (vegdist, wcmdscale, envfit, metaMDS avec isoMDS, adonis2,
betadisper, mantel, mantel.correlog) : les mêmes valeurs, et pour les mêmes permutations, les
mêmes valeurs p. Fichier › Exporter vers R écrit un script, ou un rapport R Markdown ou Quarto,
qui les refait avec R seul (et MASS, livré avec R, pour le NMDS) : ses fonctions sont celles du
moteur de Nuée, recopiées telles qu'il les écrit ; puis les données du modèle (les coordonnées
pour un test de Mantel géographique), sa transformation, sa distance et ses réglages, les mêmes
permutations et les mêmes départs, donc les mêmes valeurs p et le même NMDS.

Arbres de décision, analyse discriminante linéaire et k-moyennes
----------------------------------------------------------------
Nouveau modèle › type « Arbre de décision » (rpart) : une variable Y quantitative (arbre de
régression) ou une variable de classe (arbre de classement), et des X par leurs valeurs
brutes, pour que les seuils se lisent dans leurs unités ; les valeurs manquantes des X sont
prises en charge par des variables de substitution. Onglet Général : au moins 20
observations par feuille, mais au plus le sixième des observations, pour que l'arbre puisse
se couper (un nœud n'est coupé que s'il en compte trois fois plus), au plus 5 niveaux,
cp = 0,001, 5 substitutions,
élagage par la règle 1-ET (le plus petit arbre à une erreur-type de l'erreur minimale) ou à
l'erreur minimale. L'élagage vient d'une validation croisée interne par les groupes de
validation croisée (pour des sites suivis plusieurs années, choisir le site), et le Q2 d'une
validation croisée externe : chaque groupe est prédit par un arbre refait entièrement sans
lui. Vues : Arbre (un clic sur un nœud choisit ses observations), Élagage, Règles des
feuilles, Importance des variables, Stabilité de la première coupure (200 tirages
bootstrap des groupes : la part des tirages où chaque variable fait la première coupure,
et son seuil médian), Observé / prédit et Résidus, ou Classement pour un arbre de
classement. Jeu de test et Prédire : une nouvelle observation suit l'arbre, substitutions
comprises.

Type « Analyse discriminante linéaire (LDA) » (MASS::lda) : une variable de classe et des X
par leurs valeurs brutes ; probabilités a priori proportionnelles aux effectifs ou égales.
Chaque observation va dans la classe de plus grande probabilité a posteriori ; en
validation croisée, chaque groupe est classé par le modèle ajusté sans lui. Vues : Scores
discriminants, Coefficients discriminants (corrélations de structure, coefficients dans
les unités des variables ou pour des variables d'écart-type 1), Classement, Probabilités a
posteriori. Jeu de test et Prédire.

Type « k-moyennes » : des X mis à l'échelle comme le dit l'onglet Variables (UV par
défaut), k groupes (algorithme de Hartigan et Wong, 25 départs, graine 1), numérotés du
plus grand au plus petit ; une observation où une valeur manque est laissée de côté.
Vues : Groupes (sur les deux premières composantes principales), Silhouettes, Choix de k
(de 2 à 10 : somme des carrés intra-groupes et silhouette moyenne), Centres des groupes.
« Groupes → variable » ajoute les groupes au projet comme une variable qualitative
(Édition › Annuler la retire) ; Prédire range une nouvelle observation dans le groupe du
centre le plus proche.

Pour les trois : texte des méthodes avec ses références, Exporter, rapport PDF ou Word,
Exporter vers R (un script ou un rapport R Markdown / Quarto qui refait l'analyse avec
rpart, MASS ou cluster, livrés avec R). Comparer les modèles donne le Q2 et le RMSEcv d'un

TRIM : indices et tendances de comptages
----------------------------------------
Nouveau modèle › type « TRIM (indices et tendances de comptages) » : les indices annuels et la
tendance de comptages d'animaux suivis sur des sites année après année, comme le logiciel TRIM 3
de Statistics Netherlands et le paquet rtrim (le standard des suivis d'oiseaux européens), avec
des comptages manquants : le modèle les impute. Les données : le tableau long, une ligne par site
et par année ; Y : les comptages (des entiers positifs ou nuls ; une case vide est un comptage
manquant) ; X : des covariables qualitatives, facultatives (l'habitat d'un site, ou une valeur
par site et par année), qui font varier les effets du temps. Onglet Général :
  - le site (un identifiant ou une variable) et le temps (l'année : une variable ou un
    identifiant fait de nombres régulièrement espacés ; une année sans aucune ligne est ajoutée,
    tous ses comptages imputés), proposés d'après les noms des colonnes ;
  - le modèle : 3, un effet de chaque année (ln μ = site + année) ; 2, une tendance linéaire sur
    l'échelle log, dont la pente change aux points de changement donnés (des années ; vide : une
    seule pente), à chaque année, ou choisis pas à pas comme rtrim (un point sort quand le test de
    Wald de son changement de pente dépasse p = 0,2, revient quand son test du score passe sous
    p = 0,15) ; 1, sans effet du temps ;
  - la surdispersion (σ²) et la corrélation sérielle (ρ, entre deux années successives d'un même
    site), cochées par défaut comme le recommande le manuel de TRIM : les paramètres sont alors
    estimés par des équations d'estimation généralisées qui en tiennent compte ; sans elles, par
    le maximum de vraisemblance de Poisson ;
  - des poids (une variable : des sites sur- ou sous-représentés), et le temps de base des
    indices (le premier par défaut).
Deux lignes pour le même site et la même année sont refusées, le site, l'année et les
observations nommés ; un site sans aucun comptage positif est laissé de côté, et compté ; une
case sans ligne prend le poids et la catégorie de covariable de l'année d'avant de son site.

Vues : Résumé (le modèle, σ² et ρ, la pente globale des totaux imputés : multiplicative, par pas
de temps, avec son erreur-type, son intervalle à 95 % et sa classe selon TRIM, forte
augmentation, augmentation modérée, stable, incertaine, déclin modéré ou fort déclin, d'après
l'intervalle comparé à 1 et à 0,95 / 1,05 ; le khi² de Pearson, le rapport de vraisemblance et
l'AIC) ; Indices (les indices imputés, d'après les comptages observés et ceux du modèle pour les
manquants, et ceux du modèle, avec leur bande à 95 %, le temps de base, et au choix la droite de
la pente globale) ; Totaux de chaque temps (observés, imputés, du modèle) ; Pentes, paramètres et
tests (les tests de Wald de la pente, des changements de pente, des écarts à la tendance
linéaire et des covariables ; la droite et ses écarts pour le modèle 3 ; les étapes du pas à
pas) ; Comptages par site (les comptages d'un site et ceux du modèle, ou tous les comptages
contre leur valeur attendue). Les résultats sont ceux du paquet rtrim. Texte des méthodes avec
ses références, Exporter et rapport comme pour les autres modèles, et Exporter vers R : un script
ou un rapport qui refait le modèle avec R seul, les fonctions de TRIM du moteur de Nuée recopiées
dedans (les mêmes indices, totaux, pentes et tests que Nuée). Pas de prédiction.

Échantillonnage par distances : densité et effectif
---------------------------------------------------
Nouveau modèle › type « Échantillonnage par distances (densité, effectif) » : la densité et
l'effectif d'une population d'après les distances des animaux détectés depuis des lignes
(transects linéaires) ou des points (points d'écoute), comme les fonctions ds() et dht2() du
paquet Distance les calculent (Buckland et al. 2001 ; Miller et al. 2019). Les données : le
tableau à plat, une ligne par détection, comme Distance le lit :
  - la distance (Y) : la distance perpendiculaire à la ligne, ou la distance au point ;
  - le transect (la ligne ou le point : un identifiant ou une variable) et son effort, le même
    sur toutes ses lignes : la longueur de la ligne, ou pour des points le nombre de passages
    (sans colonne : un passage par point) ;
  - facultatifs : la strate (la région : un identifiant ou une variable) et son aire, la même
    sur toutes ses lignes (sans aire, ou des aires toutes nulles, la densité seulement) ; la
    taille de chaque groupe détecté ;
  - un transect sans aucune détection reste une ligne, sa distance vide, pour que son effort
    compte ; une ligne sans transect ni distance est laissée de côté.
Par exemple, avec les noms de colonnes de Distance (la fenêtre les propose d'après les noms) :
    Region.Label  Area  Sample.Label  Effort  distance  size
    Nord          630   N-01          2.4     35        2
    Nord          630   N-01          2.4     120       1
    Nord          630   N-02          1.8               (aucune détection)
Onglet Général :
  - des transects linéaires ou des points ;
  - la troncature : la plus grande distance (le défaut de ds), une distance, ou un pourcentage
    des plus grandes distances (5 à 10 % est l'usage) ; une troncature à gauche au besoin. Les
    détections au-delà sortent du modèle, leur transect reste ;
  - des intervalles, pour des distances relevées par classes (comme ds(cutpoints = )) : leurs
    bornes, par exemple « 0 10 25 50 100 » ; chaque distance du tableau (la vraie, ou le milieu
    de sa classe) compte dans son intervalle, la première borne est la troncature à gauche et la
    dernière w ; la vraisemblance est alors celle des comptes des classes, et l'adéquation le
    khi² sur elles ;
  - la clé de la fonction de détection g(x) : demi-normale exp(−x²/2σ²), hasard (hazard-rate)
    1 − exp(−(x/σ)^−b) (b ≥ 1, comme mrds) ou uniforme ;
  - des covariables (l'échantillonnage par distances à covariables multiples, comme ds(formula =
    ~ x1 + x2) ; Marques et Buckland 2003, Marques et al. 2007) : les variables au rôle Z de
    l'onglet Variables, ou ajoutées depuis la liste Covariables de l'onglet Général (c'est la
    même chose). L'échelle σ de la clé demi-normale ou hasard en dépend, ln σ = β0 + β1 x1 + … :
    une covariable quantitative telle quelle, une qualitative par une indicatrice de chacune de
    ses catégories sauf la première présente parmi les détections, sa référence (les contrastes
    de traitement de R) ; la taille des groupes peut en être une. Chaque détection a alors sa
    fonction de détection et sa probabilité de détection pi. Comme ds : pas de terme d'ajustement
    sauf un nombre donné, pas de contrainte de monotonie, pas de clé uniforme ; les covariables
    sont prises telles qu'elles sont (sans transformation), connues pour chaque détection dans la
    troncature ;
  - les termes d'ajustement : cosinus (le défaut), polynômes d'Hermite ou polynômes simples, leur
    nombre choisi par l'AIC comme ds() le fait (la clé seule, puis un terme de plus tant que
    l'AIC baisse, cinq au plus ; ordres 2, 3, 4… des cosinus, 4, 6, 8… d'Hermite et des
    polynômes, 1, 2, 3… et 2, 4, 6… avec la clé uniforme) ou fixé ; les distances des termes
    divisées par la troncature w (le défaut de ds) ou par σ ;
  - la monotonie : la contrainte de mrds sur une fonction à termes d'ajustement, en 10 distances
    de 0 à w : stricte (le défaut : g décroît), faible (g reste sous g(0)) ou aucune ; g y reste
    positive ;
  - les unités des distances, de l'effort (des lignes) et des aires, ou un facteur de conversion
    (convert_units de Distance) : la densité est par unité d'aire, et les résultats le disent.
La fonction de détection est ajustée par le maximum de vraisemblance des distances exactes ; la
variance de ses paramètres vient de la somme des produits des scores des distances, comme mrds ;
p, la probabilité moyenne de détection dans la troncature, et son erreur-type par la méthode
delta ; la demi-largeur effective de bande ESW = p w (lignes) ou le rayon effectif de détection
EDR = w √p (points). La densité de chaque strate est D = n / (a p), a l'aire couverte (2 w L, ou
2 (w − L) L avec une troncature à gauche, pour des lignes ; π w² K pour des points) ; sa variance
réunit celle du taux de rencontre entre les transects (l'estimateur R2 pour des lignes, P2 pour
des points, Fewster et al. 2009), celle de p et celle de la taille moyenne des groupes ; son
intervalle à 95 % est log-normal avec les degrés de liberté de Satterthwaite, comme dht2. Le
total sur les strates additionne leurs effectifs (avec des aires) ou pondère leurs densités par
leurs aires couvertes (sans). Sans aire, les variances du taux de rencontre et de la taille des
groupes de chaque strate entrent dans celle du total avec le carré de son poids, et les degrés de
liberté du total sont ceux de la formule de Satterthwaite avec ces poids. dht2 laisse les poids
hors de la variance de la taille des groupes, ce qui donne une erreur-type plus grande avec des
groupes, et hors du dénominateur de ses degrés de liberté, ce qui en donne moins, et un
intervalle du total plus large, parfois absurdement : sur les données amakihi de Distance (7
strates, hn ~ OBs + MAS), 0,6 au lieu de 871, et un intervalle de 0,09 à 434 oiseaux par hectare
au lieu de 5,85 à 6,89. Les intervalles des strates n'en dépendent pas. Le Résumé, la vue Densité
et effectif et le texte des méthodes donnent aussi ceux de dht2. Refusés, et nommés : une
distance négative, un effort manquant ou nul, deux efforts pour un transect, deux aires pour une
strate, une aire nulle parmi d'autres, une distance sans transect.
Avec des covariables, la vraisemblance est celle de la distance de chaque détection sachant ses
covariables (flpt.lnl de mrds, ou les comptes des classes) ; les coefficients sont ajustés sur
les covariables quantitatives centrées et réduites, puis rendus dans leurs unités. Les mêmes
réglages sans covariables sont ajustés aussi, en tête de la liste des modèles, pour comparer les
AIC (comme summarize_ds_models de Distance). p̄ = n / Σ 1/pi est la probabilité moyenne de
détection, avec son erreur-type comme summary.ds de mrds, et ESW = p̄ (w − L) ou EDR = w √p̄ ; la
densité de chaque strate est celle de type Horvitz–Thompson de dht2, D = Σ si / pi / a (si la
taille du groupe, 1 sans groupes), sa variance de détection par la méthode delta sur tous les
paramètres ; l'adéquation rapporte chaque distance à la fonction de détection de ses covariables
(Cramér–von Mises sur leurs répartitions ajustées, les comptes attendus du khi² sommés sur les
détections). Refusées, et nommées : une covariable manquante pour une détection, une covariable
qualitative d'une seule catégorie parmi les détections, une quantitative d'une seule valeur,
des covariables qui se déduisent l'une de l'autre, et une combinaison de covariables dont
l'échelle σ part à l'infini (ses distances ne décroissent pas jusqu'à w : regroupez les
catégories, ou choisissez-en d'autres).

Vues : Résumé (le modèle retenu et l'AIC de chaque modèle ajusté en chemin, p et ESW ou EDR avec
leurs erreurs-types, les paramètres, l'adéquation, la densité et l'effectif d'ensemble avec leurs
intervalles ; ce qui a été laissé de côté ; avec des covariables, les covariables et leurs
catégories de référence, et les coefficients sur ln σ avec exp(β), le facteur sur σ d'une
catégorie par rapport à sa référence ou d'une unité d'une covariable quantitative) ; Fonction de
détection (l'histogramme des distances, chaque barre son compte sur celui qu'elle aurait si tous
les animaux étaient détectés, comme plot.ds de mrds, sous la fonction g ajustée ; chaque
détection sur la courbe, un clic choisit sa ligne ; pour des points, la densité des distances
f(r) = 2r g(r) / (w² p) aussi ; dessous, les classes du khi² ; avec des covariables, la fonction
de détection moyenne, le g de chaque détection sachant ses covariables pondéré par 1/pi comme
plot.ds, chaque détection à son propre g, et « par » une covariable qualitative une courbe par
catégorie, la moyenne sur ses détections comme plot.ds(subset = )) ; Diagramme quantile-quantile
(la répartition ajustée de chaque distance contre la répartition empirique, avec le test de
Cramér–von Mises ; pas pour des distances par intervalles) ; Densité et effectif (par strate et
au total : aire, aire couverte, effort, transects, détections, taux de rencontre et son CV, D,
son erreur-type, son CV, son intervalle à 95 % et ses ddl, N et son intervalle, la part de la
variance due au taux de rencontre, à la détection et à la taille des groupes ; avec des groupes,
la densité des groupes aussi). La liste des observations donne le g de chaque détection et, avec
des covariables, sa probabilité de détection pi. Textes des méthodes et des résultats avec leurs
références, Exporter et rapport comme pour les autres modèles, et Exporter vers R : un script ou
un rapport qui refait l'analyse avec R seul, sans Distance ni mrds, les fonctions de
l'échantillonnage par distances du moteur de Nuée recopiées dedans (les mêmes modèles candidats
et AIC, paramètres et leur covariance, p ou p̄ et le pi de chaque détection, ESW ou EDR, tests
d'adéquation, densité et effectif que Nuée ; la fonction de détection sur l'histogramme, une
courbe par catégorie de chaque covariable qualitative, et le diagramme quantile-quantile en R de
base). Pas de prédiction.

Les résultats sont ceux de Distance 2.0 (moteur/tests/verifier_distance.R les compare, avec des
covariables sur les données amakihi, ETP_Dolphin, ClusterExercise, unimak et golftees de
Distance), à ces différences connues près : Nuée intègre la clé hasard exactement là où mrds
approche son intégrale par un spline de lissage (des lignes, la clé sans terme d'ajustement, avec
ou sans covariables : les paramètres et p diffèrent d'environ 1e-4) ; avec une troncature à
gauche de transects linéaires, l'aire couverte est 2 (w − L) L, là où dht2 garde 2 w L ; sans
aire de strate, les poids des strates entrent dans la variance de la taille des groupes du total
(au carré) et dans ses degrés de liberté de Satterthwaite, là où dht2 les laisse hors des deux :
une erreur-type plus grande avec des groupes, et moins de degrés de liberté ; l'optimiseur de
mrds sous la contrainte de monotonie s'arrête à 1e-6 près de la vraisemblance, si bien que ses
estimations peuvent différer de celles de Nuée au quatrième chiffre, ou, sur de rares données,
s'arrêter à un autre optimum local. Avec des covariables : ds peut s'arrêter avant le maximum sur
des covariables mal conditionnées (sur unimak, hn ~ MSTDO + Hour, sur un plateau où σ vaut e^9 ou
plus, des milliers de fois w, 21,9 de log-vraisemblance sous le maximum que trouve Nuée ; parti
des estimations de Nuée, ds y reste) ; une combinaison de covariables dont σ part à l'infini est
refusée, là où ds rend le point où son optimiseur s'est arrêté ; quand la taille des groupes est
une covariable, dht2 recalcule la probabilité de chaque détection avec une taille de 1 pour la
variance de sa densité des groupes, là où Nuée garde celle de la détection (les densités des
individus concordent) ; pour des points, la densité des distances tracée est la moyenne des
f(r | z) des détections, celle qu'estime l'histogramme, là où plot.ds les pondère par 1/pi. Et
dht2 ne garde un transect sans détection dans la troncature que si son Sample.Label n'a de
détection dans aucune strate (amakihi répète ses étiquettes d'une strate à l'autre) : Nuée garde
l'effort de chaque transect.

Forêts aléatoires et arbres boostés
-----------------------------------
Nouveau modèle › type « Forêt aléatoire » (le paquet ranger, Wright et Ziegler 2017) : une
variable Y quantitative (forêt de régression) ou une variable de classe (forêt de classement),
et des X par leurs valeurs brutes. Chaque arbre est grandi sur un tirage bootstrap des
observations (avec remise), chaque coupure choisie parmi mtry variables tirées au hasard ; la
forêt prédit la moyenne de ses arbres, ou la classe que le plus d'arbres votent (Breiman 2001).
Onglet Général : 500 arbres, mtry et la taille des nœuds de ranger par défaut (la racine du
nombre de X arrondie en dessous ; des nœuds de 5 observations en régression, 1 en classement),
la part tirée, l'importance par permutation non mise à l'échelle ou divisée par son
erreur-type. Graine 1 et un seul fil de calcul : la même forêt à chaque fois. ranger ne prend
pas de valeurs manquantes : une observation où une valeur X manque est laissée de côté (le
résumé les compte). L'erreur hors sac : chaque observation prédite par les arbres dont le
tirage ne la contient pas (MSE et R², ou la part mal classée) ; la validation croisée : chaque
groupe de validation croisée (le site) prédit par une forêt refaite sans lui (Q2 et RMSEcv, ou
la part bien classée). Vues : Importance des variables (par permutation, la hausse de l'erreur
hors sac quand les valeurs de la variable sont permutées ; ou par l'impureté), Dépendance
partielle (calculée à la demande, Friedman 2001 : la prédiction moyenne de la forêt quand une
variable prend chaque valeur d'une grille, les autres X inchangés ; toutes les variables côte à
côte, ou une seule, les valeurs observées sous la courbe ; en classement, la part des votes
d'une classe), Erreur selon le nombre d'arbres, Observé / prédit (hors sac, en validation
croisée ou ajusté) ou Classement (avec les courbes ROC des votes). Jeu de test et Prédire.

Type « Arbres boostés (BRT) » : le gradient boosting d'arbres de régression (Friedman 2001,
2002), comme le calcule le paquet gbm et comme Elith, Leathwick et Hastie (2008) le présentent
aux écologues, écrit en R sur rpart. Une Y quantitative : une mesure (loi normale), une
présence-absence 0/1 (binomiale) ou des comptages (Poisson), choisie comme celle d'un GLM. Les
arbres sont ajoutés un à un, chacun ajusté à ce que le modèle manque encore (le gradient de la
déviance) sur un tirage sans remise d'une part des observations, ses feuilles réestimées pour
la déviance, puis ajouté avec un petit poids (le taux d'apprentissage). Onglet Général : au plus
2000 arbres, un taux d'apprentissage de 0,01, 3 coupures par arbre (la profondeur
d'interaction : 1 donne un modèle additif), au moins 10 observations par feuille, des tirages de
50 %. Le nombre d'arbres est celui où la déviance de validation croisée est la plus petite
(chaque groupe de validation croisée prédit après chaque arbre par le boosting refait sans lui) :
plus il y a de groupes et d'arbres, plus l'ajustement est long. Les observations où une valeur X
manque sont laissées de côté. Vues : Influence relative (les réductions d'erreur des coupures de
chaque variable, en %), Dépendance partielle (à l'échelle du lien, logit ou log, ou à celle de la
réponse), Erreur selon le nombre d'arbres (la déviance de l'ajustement et celle de la validation
croisée, le nombre d'arbres retenu), Observé / prédit, et Classement (à une probabilité de 0,5,
avec la courbe ROC) pour une réponse 0/1. Jeu de test et Prédire.

Pour les deux : texte des méthodes avec ses références, Exporter, rapport PDF ou Word. Comparer
les modèles donne le Q2 et le RMSEcv d'une forêt de régression, ou d'arbres boostés d'une
mesure, à côté des autres modèles. Exporter vers R : des arbres boostés avec R et rpart seuls (le
boosting du moteur de Nuée recopié dans le script : avec la même graine, les mêmes tirages et les
mêmes arbres, ceux de gbm) ; une forêt aléatoire avec R et le paquet ranger, la seule exception à
« sans paquet » : Nuée en dépend et l'installe avec lui (ailleurs, install.packages("ranger")), et
le script le charge avec la même graine, un seul fil et les mêmes réglages, si bien que sa forêt
est celle de Nuée, arbre pour arbre, avec la même version de ranger. Le jeu de test et la
dépendance partielle, si elle a été calculée, y sont aussi.

Votre propre modèle en code R
-----------------------------
Nouveau modèle › type « Code R (votre propre modèle) » : un modèle que vous écrivez en R, pour ce
que Nuée n'ajuste pas lui-même : tout ce que R sait ajuster (lm, glm, nls, mgcv, nlme, glmmTMB,
unmarked, brms…), avec les paquets installés pour le R que Nuée utilise (library() et paquet::
marchent comme dans R). Nuée donne au code ses données, tire du modèle ce qu'il peut, et le
traite comme ses autres modèles.
  - Onglet Général : l'éditeur du code (R en couleurs, les numéros de ligne ; Ctrl+Entrée
    ajuste) et son aide, avec un exemple fait des variables du projet ; onglet Observations :
    les observations du modèle, comme pour les autres (cochées, une condition).
  - Les données : `donnees`, un data.frame des observations du modèle, une colonne par variable
    du projet sous son nom (les variables qualitatives en facteurs, leurs catégories dans l'ordre
    du projet), puis les identifiants des observations, en texte.
  - Le modèle : la dernière valeur du code (lm(...), fit…), n'importe quel objet R. Ou une liste
    dont Nuée reconnaît les éléments : list(modele = fit, valeurs = c(densite = 3.2, pente =
    -0.4), tableaux = list(effectifs = d)) ; `valeurs`, des nombres nommés, des résultats clés
    que les documents citent ({{M1.valeurs.densite}}) et que Ce qui a changé suit ; `tableaux`,
    des data.frame nommés, montrés et exportés.
  - Le code s'exécute dans un environnement à lui, chaque expression à son tour, comme dans la
    console R : une valeur visible est affichée (un graphique ggplot ou lattice dessiné), sauf la
    dernière, le modèle. Ce qu'il affiche, ses messages, ses avertissements et ses graphiques sont
    gardés. Une erreur donne le message de R et sa ligne (l'éditeur y va) ; un paquet qui n'est
    pas installé est nommé, avec comment l'installer ; le modèle reste dans le dialogue, non
    ajusté.
Du modèle, chaque partie quand l'objet le permet : print(summary()) ; les coefficients
(coef(summary()) quand c'est un tableau de nombres, ou plusieurs, comme cond, zi et disp de
glmmTMB ; sinon coef() avec les erreurs-types de vcov()) et leur intervalle à 95 % (la loi t à
leurs degrés de liberté quand leur test est un t, sinon la loi normale) ; nobs(), logLik() et ses
degrés de liberté, AIC(), BIC() ; fitted() et residuals() ; predict(fit, newdata) quand il marche.

Vues : Résumé (la classe, N, logLik, AIC, BIC, les versions de R et des paquets, les
avertissements, ce que le code a affiché, summary(), Modifier le code), Coefficients (un graphique
et le tableau), Résidus (contre les valeurs ajustées, et la droite de Henry), Graphiques du code,
Valeurs et tableaux, Le code ; Prédictions. Modèle › Modifier le modèle (ou Modifier le code)
ouvre l'éditeur avec le code : ajusté de nouveau, le modèle garde son nom et sa place. Ce qui a
changé, les documents ({{M1.coef.x}}, {{M1.AIC}}, {{M1.N}}), Exporter, le rapport et Mettre à jour
les données comme pour les autres modèles. Comparer les modèles compare son AIC aux régressions
et aux modèles de code R de la même réponse, telle quelle, sur les mêmes observations, quand Nuée
peut vérifier que leurs vraisemblances se comparent (lm, glm, glm.nb, nls, et lme et gls de nlme
ajustés par maximum de vraisemblance) ; sinon son AIC est donné avec la raison pour laquelle il
n'est pas comparé (un modèle ajusté par REML, une réponse transformée…). Le texte des méthodes dit
que le modèle a été ajusté par le code R de ses auteurs, avec la version de R et les paquets que
le code a chargés, leurs versions et leurs citations (citation()), qui rejoignent les références
d'un document. Exporter vers R : les données comme les autres scripts les ont, le code tel qu'il
est écrit, puis ce que Nuée montre du modèle (résumé, coefficients, vraisemblance, graphiques des
résidus) ; Nuée exécute le script avant de l'écrire et dit s'il ne donne pas les mêmes nombres.

Confiance : ouvrir un fichier n'exécute jamais son code. Le code écrit, ou approuvé, sur cet
ordinateur par vous s'exécute ; celui d'un projet venu d'ailleurs (d'un collègue, d'un dossier
partagé, une version de GitHub ou de GitLab) que vous n'avez pas approuvé, non : ses modèles
restent non ajustés, sous une barre « Ce projet a du code R écrit par quelqu'un d'autre (M7) —
Montrer le code / Exécuter ». Exécuter approuve ce code (Nuée garde son empreinte, un SHA-256,
dans vos réglages) et ajuste les modèles ; changé de nouveau ailleurs, il redemande. Le moteur R
lui-même refuse un code que personne n'a approuvé, quel que soit le chemin (l'ouverture, Mettre à
jour les données, une fusion, les versions). Une organisation peut retirer ce type de modèle (la
politique DisableCustomCode).

Nettoyer les données : chercher et remplacer, catégories, unités
--------------------------------------------------------------
Ce qu'on faisait dans Excel avant d'ouvrir le tableau, dans Nuée, chaque changement annulé par
un seul Ctrl+Z (Édition › Annuler) comme les autres changements des données ; les modèles déjà
ajustés gardent leurs résultats jusqu'à ce que vous les ajustiez à nouveau. Dans le menu
Édition, dans la barre de la vue Données, et par un clic droit sur l'en-tête d'une colonne de la
vue Données (un en-tête montre l'unité de la variable, son nombre de cases vides et de valeurs
distinctes, « Résumé des colonnes » ; sa bulle, la description) ou sur une variable de
Graphiques › Statistiques des variables.
Édition › Chercher et remplacer (Ctrl+H) : dans une variable, plusieurs ou toutes, les cases qui
valent un texte ou un nombre, ou les cases vides (« les cellules vides » : remplacer vide par
0), prennent ce que vous tapez, ou deviennent vides si vous ne tapez rien (remplacer -9999 par
rien). Une variable qualitative se compare en texte : la case entière, ou une partie du texte
(la « , » de « 3,5 »), les majuscules comptant ou non ; une variable quantitative en nombres
(« 3,5 » trouve 3,5), sur la case entière, et ne prend qu'un nombre ou rien (sinon ses cases
restent, et le dialogue le dit). Avant de remplacer, le dialogue dit combien de cases changeront
dans chaque variable, les premiers changements (« foret » → « forêt » (3)) et ce que devient
chaque variable : une variable de texte dont toutes les valeurs deviennent des nombres (« , »,
« <0,5 » remplacé par 0,25, « abs » par 0) devient quantitative, sauf si vous décochez la case.
Une catégorie remplacée par une autre qui existe s'y fond ; une catégorie vidée de ses cases
disparaît. Une colonne de mesures est lue en nombres à l'ouverture du tableau : quelques
« <0,5 » ou « nd » y sont alors lus comme des valeurs manquantes (Fichier › Ouvrir le dit), et
ne sont plus là pour être remplacés ; une colonne avec plus de texte reste du texte, où on peut.
Édition › Catégories (ou clic droit sur l'en-tête d'une variable qualitative) : les catégories
d'une variable qualitative avec leur nombre d'observations, à renommer (le nom d'une autre
catégorie les fusionne), fusionner (celles cochées, dans la plus nombreuse), monter et
descendre, et la référence à choisir. Leur ordre est celui des graphiques et des tableaux
(couleurs, barres, moyennes ajustées). Dans une régression, la dernière catégorie observée est
la catégorie de référence : le coefficient de chacune des autres est son écart à elle, et
« Référence » met une catégorie en dernier. Les définitions des modèles du projet suivent les
catégories (ajustée à nouveau, une régression prend la nouvelle référence) ; un modèle ajusté
dont des catégories ont été renommées ou fusionnées ne se réajuste plus depuis sa page (moins
d'observations, une composante de plus) et ne prédit plus : ajustez-le à nouveau (Modèle ›
Modifier le modèle, ou double-clic sur sa définition dans l'explorateur). Un nouvel ordre seul
ne l'en empêche pas.
Édition › Unités et descriptions (ou clic droit sur un en-tête › Unité et description) :
l'unité (ind./ha, m, °C) et la description de chaque variable. L'unité vient dans les titres des
axes (« densité (ind./ha) » : Effets, Observé / prédit, Statistiques des variables, Séries, la
légende de la Carte, moyennes ajustées, tests statistiques, dépendance partielle d'une forêt ;
pas sur un axe qui la montre transformée), les en-têtes de la vue Données, le texte des Méthodes
(« la réponse est « densité » (ind./ha) ») et celui des résultats (un coefficient « par m »
quand la variable est dans ses unités). Les deux sont enregistrées dans le projet, gardées par
Fichier › Exporter les données là où le format a leur place (une feuille « Variables » d'un
classeur Excel et une table « Variables » d'un GeoPackage, que Nuée relit en les ouvrant ; la
description d'une colonne de jamovi ; les attributs label et units d'une colonne de R, comme
Hmisc les lit ; pas en CSV ni en texte), et écrites en commentaire avant les données dans
l'export vers R.
Dans la vue Données, un clic sur une case, puis Ctrl+V, colle à partir de cette case un bloc de
cellules copiées dans un tableur, dans les lignes et les colonnes telles que la vue les montre
(triées, filtrées) : chaque case comme quand on la modifie à la main (vide : manquante ; une
nouvelle catégorie s'ajoute ; un texte dans une variable quantitative est refusé, en nommant
l'observation, et rien ne change) ; les cases au-delà du tableau sont laissées. Un seul Ctrl+Z
annule tout le bloc.

Ajouter des colonnes d'un autre tableau
---------------------------------------
Édition › Ajouter des colonnes d'un tableau (ou clic droit sur les données du projet dans
l'explorateur) : les colonnes d'un autre tableau ajoutées aux observations par une clé, comme on
le ferait dans un tableur : l'habitat et l'altitude de chaque site d'un tableau des sites, la
météo de chaque année, ou de chaque site et de chaque année. Le tableau : un fichier dans tout
format que lit Fichier › Ouvrir (avec sa feuille ou son tableau pour un classeur ou un fichier
R ; un projet Nuée donne ses données), ou des cellules copiées dans un tableur (Coller des
cellules).
La clé : une ou plusieurs colonnes du projet (des variables, des identifiants ou le nom des
observations), chacune à côté de la colonne du tableau qui lui répond. L'application propose
des colonnes de même nom (sans tenir compte des majuscules ni des espaces autour, comme Prédire
un fichier) : celles avec lesquelles chaque clé ne vient qu'une fois dans le tableau et le plus
d'observations trouvent la leur, parmi les premières colonnes du tableau, le moins possible : le
site pour un tableau des sites, le site et l'année pour la météo par site et par année ; les
changer au besoin. Chaque clé ne doit venir qu'une fois dans le tableau : une clé qui revient
est refusée, en la nommant, plutôt que de prendre l'une de ses lignes au hasard.
Les clés se comparent en nombres quand la colonne du projet est une variable quantitative :
2019 et 2019,0 sont la même année (les valeurs du tableau lues en nombres comme les lit
Fichier › Ouvrir). Sinon, elles se comparent en texte, tel qu'écrit dans le tableau et dans le
projet, sans les espaces autour, les majuscules comptant : « S1 » n'est pas « s1 », ni « 01 »
« 1 » (une colonne de clé faite de « 01 », « 02 » n'est pas lue ici en nombres) ; un nombre du
tableau s'écrit alors comme R l'écrit (2019). Une clé dont une partie manque ne répond à rien.
Les colonnes à ajouter : toutes celles du tableau sauf la clé, cochées par défaut. Une colonne
de nombres donne une variable quantitative ; du texte, un facteur R ou une variable étiquetée
de SPSS ou Stata, une variable qualitative (les catégories d'un facteur dans leur ordre, sinon
les textes triés), comme à l'ouverture d'un tableau. Un nom déjà pris dans le projet, par une
variable ou un identifiant, devient « nom (2) », « nom (3) »... : rien n'est écrasé.
Chaque observation prend les valeurs de la ligne du tableau qui a sa clé, et les observations
gardent leur ordre : comme k <- match(clé du projet, clé du tableau), puis tableau[k, colonnes]
(merge() rangerait les lignes autrement). Une observation sans ligne qui lui réponde a des
valeurs manquantes. Le résultat dit ce qui a été ajouté et compte les observations sans
correspondance et les clés du tableau qui ne répondent à aucune observation, en nommant les
cinq premières de chacune ; les lignes du tableau sans clé sont comptées aussi. Si aucune
observation ne trouve sa clé, rien n'est ajouté, et le message montre des clés de chaque côté.
Édition › Annuler (Ctrl+Z) retire les colonnes ajoutées ; les modèles déjà ajustés ne changent
pas. Les « Actions de l'application » de la console R montrent l'appel, et le même calcul écrit
avec match() sur le tableau des données du projet.

Résumer par groupe
------------------
Édition › Résumer par groupe (ou clic droit sur les données du projet) : un nouveau projet d'une
ligne par groupe, à côté du projet, qui ne change pas : la densité moyenne de chaque secteur et
de chaque année d'après plusieurs placettes, avant BACI ou les séries. Les groupes : une ou
plusieurs variables ou identifiants (le secteur et l'année ; le site, le secteur et l'année).
Chaque groupe devient une observation nommée par ses valeurs (« S1 2019 ») ; les groupes
viennent dans l'ordre de ces colonnes (les catégories d'une variable qualitative dans leur
ordre, les nombres dans le leur), et ces colonnes restent des variables ou des identifiants,
comme dans le projet. Une observation sans valeur dans l'une d'elles est laissée de côté, et
comptée.
Les variables quantitatives à résumer (toutes sauf celles des groupes, cochées par défaut) et
les statistiques, une ou plusieurs, pour chacune d'elles : moyenne (par défaut), somme,
médiane, minimum, maximum, écart-type (n − 1, comme le calcule sd()), nombre de valeurs (n), en
colonnes « densite (moyenne) », « densite (n) »... (nommées dans la langue de l'interface). Les
valeurs manquantes sont ignorées et n compte les valeurs connues ; un groupe sans valeur connue
a des statistiques manquantes, et n = 0. Comme aggregate(d[variables], d[groupes], FUN) sur le
tableau des données du projet : les « Actions de l'application » de la console R le montrent
avec l'appel.
Une variable qualitative ou un identifiant dont les valeurs connues sont les mêmes dans chaque
groupe (l'habitat d'un secteur, le site d'un secteur) est gardé, avec cette valeur ; les autres
sont laissés de côté, et la barre d'état les nomme. Le nouveau projet n'a pas encore de
fichier : l'enregistrer (Ctrl+S).

Étapes des données et mise à jour
---------------------------------
Un projet fait d'un fichier de données garde ce fichier, sa source : où il est (et son chemin
depuis le dossier du projet, si bien qu'un dossier déplacé avec ses données les retrouve), sa
table ou sa feuille, les choix de l'import sur ses colonnes, et sa taille, sa date et son
empreinte quand il a été lu. Chaque changement fait à ses données dans Nuée est gardé en étape,
écrite avec les noms des variables et les identifiants des observations : une valeur modifiée,
Chercher et remplacer, les catégories, une Nouvelle variable, des colonnes d'un tableau (avec le
fichier de ce tableau), des valeurs de rasters, des cellules collées, les unités et
descriptions, les coordonnées, une classe d'une sélection, des scores ou des groupes de
k-moyennes en variables.
Édition › Étapes des données (ou clic droit sur les données du projet) : la source (trouvée,
modifiée depuis sa lecture, ou introuvable) et les étapes, chacune avec sa date et les fichiers
qu'elle a lus. Retirer montre d'abord ce que ferait le retrait d'une étape (la source relue,
les autres étapes rejouées dessus), puis, comme une mise à jour, remplace les données en un seul
changement qu'annule Ctrl+Z, ajuste à nouveau chaque modèle et montre Ce qui a changé ; quand la
source a changé depuis sa lecture, mettez d'abord les données à jour. Quand les données ont
changé hors des étapes (dans la console R, ou avec une version de Nuée d'avant la 1.1), le
dialogue le dit : les mettre à jour reprendrait celles que la source et les étapes donnent.
Édition › Mettre à jour les données : la source relue, ou un autre fichier, celui de l'année
suivante, dont les colonnes peuvent venir dans un autre ordre ou avec de nouvelles. Les étapes y
sont rejouées, puis ses lignes rapportées aux observations du projet par leurs identifiants et
ses colonnes aux variables par leurs noms, si bien que chaque modèle garde sa définition. Une
nouvelle catégorie se place juste avant la dernière, pour que chaque régression garde sa
catégorie de référence (la dernière), et chaque modèle prend son terme avec les réglages des
autres (une PLS-DA garde ses classes, et ne prend aucune observation d'une nouvelle). Avant que
rien ne change, le dialogue montre ce qui changera : les nouvelles observations, variables et
catégories, celles qui ne sont plus dans le fichier (elles quittent le projet et ses modèles),
les cellules changées, les variables calculées de nouveau d'après leur formule, chaque étape
rejouée, sautée (une observation ou une variable qu'elle nomme n'est plus là) ou en erreur, avec
sa raison, les modèles qui ne peuvent plus être ajustés et ce qui leur manque, ceux qui prennent
une nouvelle catégorie, un modèle dont la catégorie de référence n'a plus d'observation, et
comment le fichier a été lu (sans colonne qui nomme les observations, elles se retrouvent par
leur numéro de ligne). Un modèle qui laisse de côté des observations demande s'il prend les
nouvelles (coché). Mettre à jour remplace les données en un seul changement (Ctrl+Z l'annule, la
source et les étapes comprises, et ajuste à nouveau chaque modèle sur les données d'avant) ; avec
les versions, une version est enregistrée d'abord. Puis chaque modèle du projet est ajusté à
nouveau, avec une barre de progression et Arrêter, et Ce qui a changé compare leurs résultats
clés avant et après (voir Ce qui a changé). Il montre aussi ce que la mise à jour a fait aux
données, et les valeurs citées dans les documents qui ont changé, l'ancienne → la nouvelle,
chacune avec sa phrase (un clic ouvre le document à cet endroit) ; dans l'aperçu de chaque
document, elles sont marquées, celle d'avant au survol, jusqu'à Cacher les changements.
Quand le fichier source d'un projet change (une nouvelle année ajoutée), la barre d'état le dit,
à l'ouverture du projet et quand Nuée revient au premier plan ; son lien ouvre Mettre à jour les
données.

Modifier les données, créer des variables
-----------------------------------------
Dans la vue Données, double-cliquer une case pour la modifier (Entrée pour garder, Échap pour
annuler ; vide = valeur manquante ; pour une variable qualitative, le nom de la catégorie).
Les modèles déjà ajustés ne changent pas : les réajuster.
Édition › Nouvelle variable : par une formule R sur les autres variables et les identifiants
des observations, par exemple log10(polyphenols), sucre / acidite, ifelse(poids >= 170,
"gros", "petit") (un résultat en texte donne une variable qualitative) ; par groupe,
moyenne_groupe(x, secteur), la moyenne de x dans le groupe de chaque observation (valeurs
manquantes ignorées ; une observation sans groupe n'en a pas), et ecart_groupe(x, secteur),
l'écart à cette moyenne : la moyenne d'un secteur comme covariable, ou une réponse centrée par
secteur. Ou des classes d'après les valeurs d'une variable, à des bornes données (10 ; 20
donne « ≤ 10 », « ]10 ; 20] », « > 20 ») ou en classes d'effectifs égaux. Ou Imputation
(ACP) : les valeurs manquantes des variables quantitatives choisies remplies les unes par les
autres par ACP itérative régularisée, comme le fait missMDA::imputePCA, avec le nombre de
composantes choisi par validation croisée généralisée des variables réduites, de 0 à 5, comme
le fait missMDA::estim_ncpPCA sur elles (0 : la moyenne de chaque variable), sauf si vous le
donnez ; les valeurs observées inchangées, une observation à qui manquent plus de la moitié
d'entre elles laissée manquante, les valeurs imputées gardées dans l'étendue observée de chaque
variable sauf si on décoche ; en nouvelles variables « x (imputée) » ou dans les variables
elles-mêmes (Ctrl+Z annule). Penser à enregistrer le projet.
Dans une formule de Nouvelle variable, d'une année à l'autre : precedent(x, annee, secteur), la
valeur de x l'année d'avant dans le même secteur, et suivant(x, annee, secteur), celle de
l'année d'après (pas = 2 : deux ans avant ou après). L'année cherchée doit exister : une année
manquante donne une valeur manquante, jamais celle d'une année plus ancienne, comme une
observation sans secteur ou sans année. Le temps est fait de nombres (un identifiant fait de
nombres, comme l'année, convient) ; des dates aussi, mais ces fonctions vont avec des temps
réguliers (voir Le temps en dates) ; le groupe, une variable qualitative, un identifiant ou
interaction(site, secteur) pour un secteur dans un site ; un même secteur deux fois la même
année est refusé, en le nommant. croissance(x, annee, secteur) donne le taux de croissance
log(x / x de l'année d'avant), manquant sauf si les deux valeurs sont positives : pour la
dépendance à la densité, la croissance contre precedent(densite, annee, secteur). En anglais :
previous, following et growth_rate.
Dans une formule de Nouvelle variable, la diversité de chaque relevé, sur plusieurs colonnes
d'espèces de sa ligne (comptages, densités, recouvrements : des nombres ≥ 0), comme la calculent
vegan::specnumber et vegan::diversity : richesse(...), S, le nombre de colonnes > 0 ;
shannon(...), H′ = −Σ p ln p (logarithme népérien, p la part de chaque espèce dans le total de
la ligne) ; simpson(...), 1 − Σ p² (l'indice de Gini–Simpson, le « simpson » de vegan) ;
pielou(...), l'équitabilité de Pielou J = H′ / ln S, manquante quand S ≤ 1. Les colonnes sont
nommées (shannon(Ablette, Brochet, Gardon)), ou une plage dans l'ordre des colonnes du tableau,
de l'une à l'autre, les deux comprises (shannon(Ablette:Vandoise), comme dplyr la lit), ou les
deux ; une colonne nommée deux fois compte une fois, et toute autre expression compte comme une
colonne de ses valeurs. Un relevé de zéros a S = 0, H′ = 0 et un Simpson de 0 (vegan donne 1 :
1 moins une somme vide), et pas de J ; une valeur manquante dans l'une des colonnes rend
l'indice manquant pour ce relevé (une valeur manquante n'est pas lue comme une absence) ; une
valeur négative est refusée, en nommant sa variable. En anglais : richness.

Historique du fichier
---------------------
Pour un projet venant d'un fichier .usp, l'explorateur montre « Historique du fichier » :
le journal enregistré dans le fichier (création, changements de jeu de travail, nombre de
composantes, modèles supprimés...), avec la date, la version du logiciel et l'utilisateur.
Clic droit sur un modèle importé › Historique du modèle : seulement ce qui le concerne.
Les versions que Nuée garde de chaque projet, dans Fichier › Historique, sont autre chose : voir
Historique et versions.

Historique et versions (Fichier › Historique)
---------------------------------------------
Nuée garde d'elle-même des versions de chaque projet enregistré dans son format (.nuee), sans
rien à installer : quand le projet est enregistré et que sa dernière version a une heure ou plus,
quand il est fermé (ou que Nuée se ferme) et qu'il a changé depuis, et avant que ses données
soient mises à jour (« Enregistrer d'abord une version » de Mettre à jour les données, coché).
Chacune dit ce qui a changé depuis la précédente : lignes et variables, modèles par leur nom,
documents et figures par leur titre, étapes des données, source des données. Rien ne quitte
l'ordinateur si le projet n'est pas partagé (voir Partager sur GitHub ou GitLab).
Fichier › Historique (ou l'horloge de la barre d'état) : les versions jour par jour (le clic
droit sur le projet les donne aussi), chacune avec son heure, ce qui a changé, ses noms, son
auteur, « automatique » pour une version que Nuée a gardée d'elle-même, et « envoyée » une fois
dans un dépôt partagé. Sur chacune : Ouvrir (à côté du projet, en lecture seule : un cadenas dans
l'explorateur et sur ses onglets ; Enregistrer sous... en garde une copie ailleurs), Comparer
(avec le projet tel qu'il est : voir Ce qui a changé), Nommer... (« soumis à la revue »,
« chapitre 2 de la thèse »), Restaurer... (le projet redevient cette version, ses données, ses
modèles, ses documents et ses figures ; son état actuel reste dans l'historique, gardé d'abord
dans une version). Enregistrer une version... en garde une tout de suite, avec quelques mots ; un
projet qui a des changements non enregistrés est d'abord enregistré, et celui qui n'a pas changé
depuis sa dernière version le dit.
Les versions automatiques jamais envoyées s'espacent avec le temps, une fois par jour au plus :
une par jour après 30 jours, une par mois après un an. Les versions nommées, celles enregistrées
à la main et celles envoyées sont toutes gardées. Garder des versions de ce projet (en haut de
l'Historique) les arrête pour un projet, celles déjà gardées restant lisibles ; Réglages... les
arrête pour tous les projets (Garder des versions de mes projets : aucun nouvel historique ne
commence, ceux qui existent restent), et donne le nom, et l'adresse électronique, écrits avec
chaque version.
Les versions sont gardées à côté du projet, dans un dossier caché nommé .nuee-versions : un
historique par projet de ce dossier (un dépôt git à vous autour du dossier l'ignore). Le haut de
l'Historique donne sa taille ; chaque version contient le fichier du projet entier, compressé. Un
projet renommé hors de Nuée est retrouvé par son contenu, et Enregistrer sous... emmène son
historique. Supprimer le dossier .nuee-versions supprime l'historique des projets de ce dossier,
et rien d'autre : les projets ne changent pas, et un nouvel historique commence à leur prochain
enregistrement, sauf si les versions sont arrêtées (un projet dont les versions étaient arrêtées
suit de nouveau les Réglages). Un projet partagé sur GitHub ou GitLab perd aussi son lien avec le
dépôt : ses versions y restent, et Fichier › Ouvrir depuis GitHub ou GitLab, dans un autre
dossier, reprend le projet avec elles. La version navigateur n'a pas d'Historique : l'application
de bureau garde les versions.

Ce qui a changé
---------------
Ce qui a changé compare deux états d'un projet, modèle par modèle, les modèles appariés par leur
nom, sur leurs résultats clés : l'ajustement (N, R², Q², AIC, déviance expliquée), chaque
estimation avec son intervalle à 95 % et sa valeur p (coefficients, pentes, indices), les tests,
les effets aléatoires, les composantes, le VIP, les coefficients ou les loadings de chaque
variable, la valeur indicatrice de chaque espèce, les moyennes ajustées et la puissance d'une
tendance gardées avec le modèle, un jeu de test. Il s'ouvre après une mise à jour des données ou
le retrait d'une étape (voir Étapes des données et mise à jour), depuis l'Historique (Comparer :
une version avec le projet actuel) et quand arrive la version d'un collègue (Ce qui a changé,
dans le message de la barre d'état). Les modèles des deux états sont d'abord ajustés, avec une
barre de progression.
Chaque modèle commence par ses changements notables, en phrases écrites comme le texte des
résultats : Le coefficient de « annee » passe de -0,0210 à -0,0260 (IC 95 % [-0,0310 ; -0,0210]),
toujours significatif (p < 0,001). Puis le tableau de ses résultats qui ont changé : avant, après
(avec leur intervalle et leur p), l'écart (en points pour un pourcentage) et ce qu'il a franchi :
nouveau ou disparu ; signe (de l'autre côté de 0, ou de 1 pour un rapport ou un indice) ; seuil
de 5 % (significatif d'un côté seulement) ; hors de l'ancien IC (la nouvelle valeur sort de
l'ancien intervalle à 95 %) ; catégorie (la classe d'une tendance, le groupe d'une espèce
indicatrice) ; composante retournée (le signe d'une composante, qui est arbitraire, a changé :
remis dans le même sens avant de comparer). Plus de huit variables ou espèces qui changent sont
résumées en une phrase par marque. Les modèles d'un seul côté viennent à la fin.

Partager sur GitHub ou GitLab
-----------------------------
Fichier › Partager sur GitHub ou GitLab (aussi dans l'Historique) : les versions du projet sont
envoyées dans un dépôt sur GitHub, GitLab ou le GitLab de votre institution, et celles de vos
collègues en reviennent ; chacun travaille sur sa copie, et Nuée les garde au même point.
Choisissez le serveur et connectez-vous-y (voir Se connecter à GitHub ou GitLab) : Nuée crée au
projet un dépôt de votre compte, à son nom (un autre nom est proposé quand celui-là est pris),
privé sauf si vous le décochez : vous seul et les collègues que vous invitez le voyez. La
première fois, elle demande votre nom et votre adresse électronique, écrits avec chaque version
(GitHub et GitLab montrent par l'adresse qui a fait quoi).
Inviter un collègue... : son nom d'utilisateur sur le serveur, tel qu'il est dans l'adresse de
son profil (le bouton est dans Partager une fois le partage fait, puis dans l'Historique, à côté
de votre compte). GitHub lui envoie une invitation, qu'il accepte depuis son courriel ou ses
notifications ; GitLab en fait un membre du projet, avec le rôle Developer. Il l'ouvre ensuite
avec Fichier › Ouvrir depuis GitHub ou GitLab : l'adresse du dépôt (connecté à son serveur, pour
un dépôt privé ; ou un jeton), le projet quand le dépôt en a plusieurs, et le dossier où le
mettre. Il s'ouvre avec ses versions, partagé avec ce dépôt.
Utiliser un dépôt existant, ou un autre serveur : son adresse, telle que la donne son bouton Code
(https://...). Connecté à GitHub ou GitLab, il ne faut rien d'autre ; sinon, un jeton qui peut y
écrire (sur GitHub, un jeton à accès précis, « fine-grained », avec Contents en lecture et
écriture sur ce dépôt ; sur GitLab, un jeton avec write_repository). Le dépôt peut être vide ou
avoir d'autres fichiers : le projet va à sa racine sous son nom, ou sous un autre quand un
fichier l'y a déjà, et les autres fichiers restent tels qu'ils sont.
Une fois le projet partagé, ses versions vont d'elles-mêmes : chacune est envoyée, et le dépôt
est interrogé sur les plus récentes quand le projet s'ouvre, après chaque version et quand Nuée
revient au premier plan (toutes les cinq minutes au plus). Une version plus récente met à jour le
projet ouvert quand il n'a pas de changement non enregistré, et la barre d'état le dit, avec Ce
qui a changé ; avec des changements non enregistrés, elle attend qu'ils soient enregistrés. La
partie partage de l'Historique donne l'état (à jour, envoi, à envoyer, plus récente, en attente,
à choisir, ou l'erreur, avec Réessayer), le compte connecté, avec Inviter un collègue... et Se
déconnecter (ou Se connecter...), et Envoyer maintenant, Recevoir maintenant, Vérifier, Changer
l'adresse ou le jeton... et Arrêter le partage (les versions restent ici et dans le dépôt).
L'horloge de la barre d'état montre le même état. Quand un collègue et vous avez changé le projet
tous les deux : voir Travailler à plusieurs.

Se connecter à GitHub ou GitLab
-------------------------------
Nuée se connecte à GitHub, à GitLab et au GitLab de votre institution sans mot de passe tapé dans
Nuée. Partager, Se connecter... dans l'Historique, ou un dépôt privé dans Ouvrir depuis GitHub ou
GitLab montrent un code court : Ouvrir la page (elle s'ouvre dans votre navigateur, le code
copié), y coller ou taper le code (la page de GitLab l'a déjà) et autoriser Nuée. Le dialogue
attend cet accord (il dit jusqu'à quand le code vaut ; refusé ou expiré, Obtenir un nouveau
code), puis montre le compte, avec sa photo, son nom et son nom d'utilisateur. La connexion est
gardée dans le trousseau de l'ordinateur (sous Linux sans trousseau, jusqu'à la fermeture de
Nuée) et se renouvelle d'elle-même.
Le GitLab de votre institution : tapez le nom de son serveur (gitlab.example.org). Nuée s'y
connecte une fois que son administrateur l'y a enregistré comme application de ce GitLab (17.3 ou
plus récent) : il vous donne son identifiant d'application, que vous tapez une fois. Avant GitLab
17.3, ou tant que Nuée n'y est pas enregistré, utilisez un jeton.
Autres façons de se connecter : Utiliser la connexion git de cet ordinateur, quand git est
installé (une fenêtre de Git Credential Manager peut s'ouvrir) ; Utiliser plutôt un jeton, un
jeton créé sur le site du serveur (En créer un sur GitHub, portée « repo » ; sur GitLab, portées
api, read_user et write_repository), vérifié, puis gardé dans le trousseau et plus jamais montré.
Une connexion qui ne peut qu'envoyer et recevoir des versions ne peut ni créer de dépôt ni
inviter : le dialogue le dit, et se connecter par la page du serveur le permet.
Se déconnecter (dans l'Historique, à côté du compte) : Nuée oublie sa connexion à ce serveur sur
cet ordinateur, et les projets partagés là-bas n'envoient ni ne reçoivent plus leurs versions
jusqu'à ce que vous vous reconnectiez. Le compte et ses dépôts restent tels qu'ils sont.

Travailler à plusieurs
----------------------
Deux personnes peuvent travailler sur un projet, chacune sur son ordinateur : partagé par GitHub
ou GitLab, ou ouvert depuis un dossier réseau partagé. Quand les deux l'ont changé, Nuée réunit
les deux d'après ce qui a changé, pas comme du texte. Chaque modèle par son nom, réglage par
réglage (variables, termes, observations, options) ; deux nouveaux modèles du même nom sont
gardés tous les deux, le leur renommé. Les documents ligne par ligne, leurs références suivant un
modèle renommé, et les figures. Les données par leurs étapes, quand les deux côtés n'ont fait
qu'ajouter des étapes sur la même source : la source du côté qui l'a mise à jour, puis les étapes
des deux côtés rejouées dessus (voir Étapes des données et mise à jour) ; sinon cellule par
cellule, une variable ou une observation ajoutée d'un côté gardée, une retirée d'un côté et
inchangée de l'autre retirée.
Ce qui s'oppose, c'est ce que les deux côtés ont changé autrement : la même cellule, un passage
d'un document, un réglage d'un modèle, une variable retirée d'un côté et changée de l'autre. Si
rien ne s'oppose, le dialogue dit ce que chaque côté a apporté, et Réunir les deux les réunit.
Sinon chaque conflit montre les deux côtés, ses passages ou ses cellules (les vingt premières)
côte à côte, avec Garder la mienne ou Prendre la leur (la mienne pour commencer), et Réunir avec
ces choix les réunit.
Partagé par GitHub ou GitLab : quand votre version et celle d'un collègue ont changé le projet
toutes les deux, la barre d'état le dit (Choisir...), et l'Historique aussi. Réunir les deux, ou,
pour tout le projet, Garder la mienne ou Prendre la leur (le projet devient le leur, le vôtre
restant dans l'historique), après Comparer si vous le voulez (Ce qui a changé du vôtre au leur).
Le projet réuni est la version suivante, envoyée au dépôt ; les deux historiques sont gardés.
Sans version commune (un projet partagé dans un dépôt qui l'avait déjà), Nuée peut ne proposer
que Garder la mienne et Prendre la leur.
Sur un dossier réseau partagé : quand un projet est ouvert depuis un partage ou un NAS, Nuée
regarde toutes les 30 secondes si son fichier a été enregistré par quelqu'un d'autre depuis sa
lecture ; elle dit alors qui (le nom donné dans Historique › Réglages...) et propose de réunir
ses changements avec les vôtres, avec Réunir les deux, ou les choix de chaque conflit, ou Pas
maintenant. La réunion est un seul changement du projet, qu'annule Ctrl+Z : enregistrez le projet
pour la garder. Enregistrer trouve aussi le fichier changé : Réunir les deux (puis le projet
réuni est enregistré), Écraser (ses changements sont perdus), Enregistrer sous... ou Annuler. Un
projet ouvert avant que Nuée ou son moteur R redémarre, ou repris après un arrêt inattendu, ne
peut pas être réuni : Enregistrer demande alors s'il faut écraser ses changements. L'historique
du projet, dans le .nuee-versions du dossier, est commun aux deux, chaque version avec le nom de
qui l'a enregistrée. Un projet partagé par GitHub ou GitLab est tenu au même point par son dépôt.

OPLS et OPLS-DA
---------------
Des composantes prédictives, qui portent ce qui dans X est lié à Y, et des composantes
orthogonales, qui décrivent le reste de la variation de X : scores et loadings se lisent plus
facilement (t[1] contre to[1], S-plot). Une composante prédictive par variable Y, ou une de
moins que de classes pour l'OPLS-DA (t[1], t[2]... puis to[1], to[2]...) ; avec une seule,
les valeurs prédites sont celles d'une PLS au même nombre de composantes. Avec plusieurs Y
(ou plus de deux classes), chaque poids orthogonal est rendu orthogonal aux poids X'y de
toutes les colonnes de Y, si bien que les composantes orthogonales n'ont aucun lien avec Y
(depuis 0.9.0 ; la version 0.8.0 laissait un léger lien : les modèles OPLS à plusieurs
composantes prédictives qu'elle a faits changent un peu quand on les réajuste). Q2 par
validation croisée, comme pour les autres modèles (voir plus bas). Aucun des
projets .usp disponibles n'avait de modèle OPLS : ce calcul suit l'article de Trygg et Wold
(2002), sans comparaison possible avec des valeurs enregistrées ; il est vérifié contre une
seconde écriture de l'algorithme de l'article.

VIP
---
Le seuil est placé automatiquement à la plus grande marche des VIP triés autour de 0,8. On
peut taper un autre seuil ou faire glisser la ligne rouge, et faire Ctrl+clic sur une barre
pour garder ou écarter une variable (un simple clic la met en évidence sur les autres
graphiques du modèle). « Réajuster avec les variables VIP » refait le modèle avec les
variables retenues.

Validation croisée
------------------
Les observations du modèle sont réparties à tour de rôle en G groupes (7 par défaut : la 1re,
la 8e, la 15e... dans le groupe 1), ou bien un groupe par valeur d'un identifiant ou d'une
variable (Nouveau modèle › Groupes de validation croisée) : avec « site », toutes les années
d'un site sont dans le même groupe, et chaque site est prédit par un modèle qui ne l'a jamais
vu ; les observations sans valeur forment un groupe à part. Les modèles des fichiers .usp
gardent leurs groupes : par identifiant quand le fichier groupe les observations de même
valeur, sinon les groupes du fichier tels quels (« groupes du fichier »).
Trois façons de valider une ACP, une PLS ou une OPLS (Nouveau modèle › Validation croisée) :
- Centres recalculés, poids du modèle complet (par défaut, pour tous les modèles, importés
  compris) : chaque groupe est prédit par un modèle ajusté sans lui, comme de nouvelles
  observations ; ses centres (et le spectre moyen du MSC, les termes croisés) sont recalculés
  sur les autres observations, avec le même nombre de composantes. Le modèle ne sait rien du Y
  du groupe qu'il prédit. Ses poids restent ceux du modèle complet : les écarts-types de X ne
  dépendent pas de Y (une seule variable Y : son poids ne change pas les prédictions), et rien
  n'est remis à l'échelle sur moins d'observations, si bien qu'aucune prédiction n'explose.
- Centres et poids recalculés sans le groupe caché (la validation de 0.9.0 à 0.9.7) : de même,
  mais les poids aussi sont recalculés sur les autres observations. Plus sévère : un terme qui
  varie peu sans le groupe caché y prend un grand poids, et les prédictions du groupe s'en
  écartent. Garde-fou : un terme dont l'écart-type sur les autres observations tombe sous 10 %
  de celui du modèle complet (une variable qui ne varie que sur un site, validée par site)
  garde le poids du modèle complet ; sinon son poids, 1 / écart-type, serait multiplié
  d'autant, et les prédictions du groupe caché exploseraient (des Q2 de -8e11 sur un projet
  réel). Le Résumé dit lesquels, sans quel groupe.
- Centres et poids du modèle complet (comme SIMCA) : le centrage et la mise à l'échelle du
  modèle complet ; chaque composante est validée sur ce que laissent les précédentes du modèle
  complet, une composante ajustée sans chaque groupe. Q2 d'une composante : 1 - PRESS / SS des
  résidus avant elle ; Q2(cum) : 1 - le produit des (1 - Q2) des composantes, chacun compté
  pour -0,1 au plus bas. C'est la validation des fichiers .usp : elle redonne leurs Q2, leurs Q2
  par variable et les intervalles de confiance de leurs coefficients. Le Y prédit en
  validation croisée (RMSEcv, CV-ANOVA, classement) vient de sous-modèles ajustés sans chaque
  groupe sur les matrices du modèle complet. Plus optimiste, surtout avec peu d'observations ou
  des groupes par site : le centre de Y et les composantes précédentes connaissent déjà le
  groupe caché (sur du bruit pur, 6 observations et 20 variables, elle donnait Q2 = 0,98 pour
  une OPLS-DA ; les deux autres, moins de 0). Une OPLS a ses sous-modèles ajustés sur les
  matrices du modèle complet.
Les deux premières : PRESS, la somme des carrés des erreurs de prédiction ; Q2(cum) = 1 - PRESS
/ SS (SS : la variation de Y, ou de X pour une ACP) ; le Q2 d'une composante, 1 - PRESS / PRESS
de la précédente. ACP : chaque valeur est prédite par les scores de son observation calculés
sans les variables de son groupe de variables (réparties elles aussi en G groupes). Le RMSEcv,
la CV-ANOVA, le classement en validation croisée, les intervalles de confiance (jack-knife,
sur les G sous-modèles), le test de permutation et l'ajustement automatique suivent la
validation choisie.
Gain sur le modèle vide (les deux premières, PLS et OPLS) : le Résumé donne aussi le Q2 du
modèle vide, où chaque groupe caché est prédit par la moyenne de Y des autres observations, et
le gain du modèle sur lui, (Q2(cum) - Q2 du modèle vide) / (1 - Q2 du modèle vide) = 1 - PRESS
/ PRESS du modèle vide : la part de l'erreur de prédiction du modèle vide que le modèle évite.
Avec des groupes qui diffèrent (sites, départements), le Q2 du modèle vide est sous 0, et celui
d'un modèle qui prédit un peu mieux que lui aussi : le gain dit de combien il fait mieux. 0 :
pas mieux que la moyenne des autres groupes. Avec les centres et poids du modèle complet, le
modèle vide prédit la moyenne de toutes les observations, groupe caché compris (son Q2 vaut
0) : pas de gain. Aussi dans le texte des Méthodes, le rapport du modèle et l'export vers R.
Modèle hiérarchique (une PLS dont des X sont les scores d'autres modèles du projet,
$M1.t1...) : son Q2 prend ces scores tels quels, alors qu'ils ont été calculés avec le Y du
groupe caché. Son Résumé donne aussi un Q2(cum) honnête : à chaque tour, ses modèles de base
sont refaits sans le groupe caché (le site entier quand les groupes sont par site), puis leurs
scores, avec la validation du modèle (centres recalculés quand elle est celle du modèle
complet) ; un modèle de base qui n'a plus de variation sans ce groupe donne des scores nuls.
Le Q2 honnête a lui aussi son gain sur le modèle vide.

Validation (PLS et PLS-DA)
--------------------------
Test de permutation : les valeurs du Y (d'une PLS-DA : les classes) sont mélangées entre les
observations 20 fois (ou plus) et tout le modèle est réajusté, validation croisée comprise ;
les ordonnées à l'origine de R2 et Q2 mesurent le surajustement (modèle valide si Q2 < 0,05 et
R2 < 0,3 à 0,4, règle usuelle).
CV-ANOVA : p du modèle (résidus de validation croisée contre la moyenne) ; aussi dans le Résumé.
Classification (PLS-DA) : table des observations bien et mal classées, avec les valeurs
ajustées ou en validation croisée, et courbes ROC avec leur aire (AUC).

Jeu de test
-----------
Nouveau modèle › Observations › Jeu de test : des observations laissées hors du modèle et de la
validation croisée, puis prédites par lui, pour juger ses prédictions sur des données qu'il n'a
pas vues. Colonne « Test » : à la main ; « Sélection en test » : la sélection du modèle actif ;
« Choisir » : une part des observations (25 % par défaut), au hasard ou par Kennard–Stone (qui
garde pour le modèle les observations les plus éloignées les unes des autres, pour qu'il couvre
toute l'étendue des données, et laisse les autres en test) ; par classe pour une PLS-DA, pour
que chaque classe soit dans les deux. Après l'ajustement, le Résumé donne, pour chaque Y :
  RMSEP    racine de la moyenne des carrés des erreurs de prédiction (prédit - observé) ;
  biais    moyenne de ces erreurs ; SEP leur écart-type ;
  Q2ext    1 - somme (observé - prédit)² / somme (observé - moyenne du modèle)² ;
pour une PLS-DA, la part du jeu de test bien classée ; pour tous, le nombre d'observations du
test hors du domaine du modèle. Observé / prédit les montre en losanges rouges. Le jeu de test
est enregistré avec le modèle, repris par Exporter vers R et par le texte des méthodes.

Observations choisies par une condition
---------------------------------------
Nouveau modèle › Observations › « Garder seulement les observations où… » : une condition écrite
en R comme une formule de Nouvelle variable, sur les variables et les identifiants des
observations par leur nom (un nom avec des espaces entre `accents graves`), par exemple
site == "S1" & annee >= 2010, !is.na(densite), habitat %in% c("marais", "prairie") ou
annee != 2015. Sous le champ, combien des observations cochées la remplissent (« 312
observations sur 480 »), ou pourquoi elle ne se lit pas : un nom inconnu, une fonction qui n'est
pas permise, un résultat qui n'est pas TRUE ou FALSE (ou 1 et 0) pour chaque observation. Elle
est évaluée sur toutes les observations du projet, comme une formule de Nouvelle variable :
densite > median(densite, na.rm = TRUE) compare à la médiane de toutes les observations, pas à
celle des cochées. Le modèle prend les observations cochées où elle est vraie ; un résultat
manquant (densite > 5 pour une observation sans densité) compte pour faux.
La condition est enregistrée avec le modèle et refaite sur les données du projet à chaque
ajustement ou réajustement : à la réouverture du projet, à l'ajustement automatique, en ajoutant
ou en retirant une composante, Exclure la sélection et réajuster, Réajuster avec les variables
VIP, Ajuster ce modèle de la sélection par AIC, Ajuster avec CAR1. Après un changement des
données, un réajustement peut prendre d'autres observations. Les cases cochées ne changent pas :
vider la condition rend les observations qu'elle écartait. Le jeu de test garde ses propres
cases : la condition ne s'y applique pas. Les observations qu'elle écarte sont hors du modèle,
comme des décochées : Prédire les observations les prédit. Un modèle importé d'un fichier .usp
garde les observations de son fichier ; Modifier le modèle en fait un nouveau modèle, qui peut
prendre une condition. Deux modèles aux observations différentes ne sont jamais comparés par
leur AIC.
Le texte des méthodes dit « les 312 observations où site == "S1" & annee >= 2010 », le résumé
et le rapport du modèle donnent la condition, et Exporter vers R l'écrit en R avec les noms des
variables du script : les lignes cochées, la condition évaluée sur toutes les lignes du tableau
par with(), puis les lignes cochées où elle est vraie, exactement celles de Nuée (une fonction
de Nouvelle variable qu'elle appelle est écrite dans le script).
Permis dans une condition : les comparaisons, &, |, !, xor(), %in%, :, les calculs
(+ - * / ^ %% %/%), c(), is.na(), ifelse(), abs(), sqrt(), exp(), log(), log10(), log2(),
log1p(), round(), floor(), ceiling(), trunc(), signif(), as.numeric(), as.character(), nchar(),
substr(), substring(), startsWith(), endsWith(), tolower(), toupper(), trimws(), paste(),
paste0(), mean(), median(), min(), max(), sum(), quantile(), pmin(), pmax(), interaction(), et
les fonctions de Nouvelle variable moyenne_groupe(), ecart_groupe(), precedent(), suivant() et
croissance() (et leurs noms anglais). Rien d'autre : une condition est gardée dans le fichier du
projet et refaite à chaque ajustement, un projet reçu ne peut donc rien exécuter d'autre par
elle (une formule de Nouvelle variable, tapée et calculée une fois, n'est pas gardée et n'a pas
cette limite). Pour que cet ajustement reste rapide et borné, « : » ne va qu'entre deux nombres
entiers (annee %in% 2005:2010) et sur une plage d'au plus 100000 valeurs, et interaction() laisse
de côté les combinaisons vides : une condition courte ne peut pas construire un vecteur énorme qui
figerait un ajustement. Pour un indice de diversité (shannon()...), en faire d'abord une Nouvelle
variable, puis employer cette variable dans la condition.

Fenêtres
--------
Au centre, un onglet par modèle (« M1 · PLS »), et un onglet pour chaque vue du projet
(Données, Statistiques des variables, Historique). L'onglet d'un modèle est sa page : son
résumé à gauche, ses scores et ses loadings à droite ; ses autres vues (VIP, DModX...)
s'y ajoutent en onglets. Choisir un modèle dans l'explorateur affiche sa page ; fermer la
dernière vue d'une page ferme la page.
Dans une page comme au centre, les vues se déplacent par leur onglet (glisser-déposer),
se divisent et s'empilent ; glisser l'onglet d'un modèle à côté d'un autre permet de
comparer deux modèles. Clic droit sur un onglet, ou l'icône en haut à droite d'un groupe :
détacher dans sa propre fenêtre (par exemple sur un second écran), agrandir, fermer.
Fenêtre › Nouvelle fenêtre ouvre une deuxième fenêtre complète. Une sélection d'observations (cadre ou lasso dans un
graphique, clic sur un point ou une ligne de liste) apparaît dans toutes les vues et toutes
les fenêtres du même modèle. Le titre d'une fenêtre, que montrent son bouton dans la barre
des tâches et le menu Fenêtre, nomme le projet qui est devant : celui sur lequel agissent
les menus.
Graphiques : molette pour zoomer ; clic droit pour copier l'image ou l'enregistrer (PNG, SVG),
voir les contributions de la sélection ou en faire une classe.
Ctrl+C dans une vue qui montre un tableau (résumé, listes, statistiques...) copie le tableau en
texte séparé par des tabulations, à coller dans Excel (une liste : toutes ses lignes, en pleine
précision) ; avec du texte sélectionné, Ctrl+C copie le texte comme d'habitude.
Affichage › Rechercher une commande (Ctrl+K) : taper une partie du nom d'une commande ou de son
menu (« vip », « exporter r »), puis Entrée.
Aide › Informations de diagnostic : les versions de Nuée, du système, de R et de ses paquets, à
coller dans un signalement de problème (github.com/4rtefakt/nuee/issues ; ni chemins ni
données).

Ce qui est identique aux valeurs enregistrées (vérifié sur 944 modèles de 133 projets .usp)
-------------------------------------------------------------------------------------------
Mise à l'échelle, R2X, R2Y, scores, loadings, valeurs propres, T2 et sa limite, DModX
(normal et pondéré) et DCrit, VIP, coefficients, RMSEE.
Les modèles d'un fichier sont ajustés comme le logiciel qui l'a écrit : avec des valeurs
manquantes, NIPALS converge parfois très lentement, ne converge pas ou a plusieurs solutions,
et il s'y arrête comme ce logiciel (un écart relatif de 1e-5, 200 itérations au plus), part de
la même colonne et valide chaque composante en partant du modèle complet. Ainsi 805 PLS sur 809
du corpus d'essai, et les 403 PLS des projets de 2003, redonnent leur ajustement et leur Q2 ;
les modèles que Nuée ajuste lui-même gardent sa précision (1e-10).

Ce qui diffère
--------------
- Q2 (et ce qui vient de la validation croisée : Q2 par variable, RMSEcv, CV-ANOVA, classement
  en validation croisée, intervalles de confiance) : par défaut, Nuée prédit chaque groupe par
  un modèle ajusté sans lui, ses centres recalculés (voir « Validation croisée ») ; les valeurs
  enregistrées viennent d'une validation faite avec le centrage et la mise à l'échelle de toutes
  les observations. Écart au Q2(cum) enregistré, en médiane, sur le corpus d'essai : 0,003 pour
  les PLS de plus de 200 observations, 0,01 de 50 à 200, 0,10 de 20 à 50, 0,22 en dessous, le
  Q2 de Nuée étant presque toujours plus bas ; 0,04 pour les ACP. Avec des groupes par
  identifiant (un site, un secteur), l'écart est plus grand : le modèle ajusté sans un site ne
  connaît pas non plus le niveau moyen de ce site. Validé avec « Centres et poids du modèle
  complet (comme SIMCA) », le Q2 enregistré revient exactement, groupes par identifiant
  compris : 805 PLS sur 809 du corpus d'essai (220 sur 220 sans données manquantes ; les quatre
  autres sont celles d'un projet dont l'ajustement diffère, ci-dessous), 441 sur 443 de quatre
  projets réels (moteur/tests/verifier_references.R), où les deux autres ont un tour sans aucune
  variation, dont la valeur enregistrée vient d'erreurs d'arrondi. Pour une ACP, il s'en écarte
  de 0,02 en médiane : le détail de la validation des fichiers n'est pas publié.

- Un projet de la version 11 : ses quatre PLS, dont le seul Y a des valeurs manquantes. Leur
  logiciel compte les observations sans y dans les poids des X, comme si leurs résidus de Y
  valaient ±0,99, ce qu'aucune règle trouvée n'explique ; R2 et Q2 s'en écartent jusqu'à 0,04.
- Signe des composantes de nouveaux modèles : arbitraire (les modèles importés sont
  orientés comme dans le fichier).
- Dendrogrammes : méthode de Ward exacte ; les fusions du haut de l'arbre peuvent
  différer de celles de l'arbre enregistré.
- Ajustement automatique : les règles publiées, appliquées au Q2 de Nuée, peuvent choisir un
  autre nombre de composantes ; pour les ACP, la limite exacte utilisée dans les fichiers
  n'est pas publiée.
- Seuil VIP (marche autour de 0,8) : méthode propre à l'application.
- Intervalles de confiance des VIP d'un modèle à deux composantes ou plus (les VIP elles-mêmes
  sont les mêmes) : ceux du logiciel qui a écrit le fichier pondèrent les composantes de chaque
  tour de la validation croisée d'une façon qui n'est pas publiée ; à une composante, ce sont
  les mêmes.
- OPLS / OPLS-DA : pas de modèle enregistré pour comparer (voir plus haut).
- Transformation proposée : la règle publiée ne dit pas s'il faut l'asymétrie et Min/Max à
  la fois ; l'application les exige tous les deux.

Le code
-------
Tous les calculs sont dans resources\moteur\R (R, commenté en français) :
  pretraitement.R        transformations, centrage, mise à l'échelle
  nipals.R               ACP et PLS (algorithme NIPALS, données manquantes)
  validation_croisee.R   validation croisée (trois façons), Q2
  hierarchique.R         modèles hiérarchiques : Q2 honnête (modèles de base refaits)
  regression.R           modèles de régression (lm, nlme, mgcv), AIC, apport des blocs
  statistiques.R         T2, DModX, VIP, coefficients, intervalles, limites
  validation.R           permutations, CV-ANOVA, classement PLS-DA et courbes ROC
  opls.R                 OPLS et OPLS-DA
  diagnostic.R           contributions, vérification des données, statistiques des variables
  variables.R            scores en variables, classes, valeurs modifiées, variables calculées
  projet.R               lecture des projets, historique du fichier
  verification.R         comparaison avec les résultats enregistrés dans les fichiers .usp
  script.R               export d'un modèle en script ou rapport R autonome
  methodes.R             texte des méthodes et références
  comparaisons.R         tests statistiques
  modeles_classe.R       modèles de classe (une ACP par classe), graphique de Coomans
  formats.R              lecture et écriture des tableaux (Excel, texte, R, SPSS, Stata, SAS, jamovi...)
  spectres.R             prétraitement des spectres (SNV, MSC, detrend, ligne de base, Savitzky–Golay)
  fichiers_spectres.R    lecture des spectres (JCAMP-DX, SPC, texte), informations jointes
  jeu_test.R             jeu de test : prédiction, RMSEP, Q2 externe, Kennard–Stone
  condition.R            les observations d'un modèle choisies par une condition
  langue.R               langue des messages (traduire("français", "English"))
  modele.R, prediction.R, classification.R (HCA), nouveau.R (tableaux, autoajustement)
Dans R : source("resources/moteur/charger.R"), puis par exemple
  p <- importer_tableau("mes_donnees.csv")
  d <- definir_modele(p, "PLS", x = 3:20, y = 2)
  m <- ajuster(p, d)
  m$statistiques$composantes
load.R charge le même moteur en anglais (ses messages, statuts et noms de colonnes), avec des
noms anglais : import_table(), define_model(), fit_model().
