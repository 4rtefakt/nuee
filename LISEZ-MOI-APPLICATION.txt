NUÉE — ACP, PLS, PLS-DA et OPLS, calculées en R
===============================================
(English guide: USER-GUIDE.txt)

Démarrer
--------
Deux façons d'installer Nuée, sans droits d'administrateur ; R est inclus dans les deux.
- Depuis le NAS : double-cliquez sur « Lancer Nuee.cmd ». Windows ne sait pas lancer
  l'application directement depuis le NAS ; ce lanceur la copie sur l'ordinateur (dans
  %LOCALAPPDATA%\Nuee) puis la démarre. La première fois la copie prend une à deux minutes ;
  ensuite seuls les fichiers modifiés sur le NAS sont recopiés, et l'application démarre tout
  de suite. Au premier lancement, des raccourcis « Nuée » sont créés sur le Bureau et dans le
  menu Démarrer : ils lancent l'application de la même façon (toujours à jour avec le NAS).
- Avec l'installateur : double-cliquez sur « Nuee-Setup-<version>.exe » et suivez les
  étapes (pour vous seul, ou pour tous les utilisateurs de l'ordinateur).
Dans les deux cas, Nuée apparaît dans Paramètres › Applications › Applications installées,
d'où on peut la désinstaller ; les projets et les réglages sont gardés.
Si Windows affiche « Windows a protégé votre ordinateur » (éditeur inconnu), cliquez sur
« Informations complémentaires » puis « Exécuter quand même ».

Sous Linux, Nuée utilise le R de l'ordinateur.
- Debian, Ubuntu et dérivées : sudo apt install ./Nuee-<version>-amd64.deb installe aussi R
  et les paquets R nécessaires. Nuée apparaît dans le menu des applications.
- Autres distributions : Nuee-<version>-x86_64.AppImage (le rendre exécutable, puis le
  lancer) ou Nuee-<version>-x64.tar.gz (le décompresser, puis lancer ./nuee). Installer
  d'abord R, puis dans R : install.packages(c("httpuv", "jsonlite", "openxlsx", "haven",
  "readxl", "foreign", "nlme", "mgcv", "MASS", "rpart", "cluster")).
Les projets .usp demandent python3. Pour un autre R que celui du PATH : lancer Nuée avec
RSCRIPT=/chemin/vers/Rscript. Les réglages sont dans ~/.config/Nuee.

Ouvrir
------
Fichier › Ouvrir (Ctrl+O) :
  - un projet .usp : données, modèles et résultats enregistrés dans le fichier ;
  - un projet enregistré par l'application (.nuee ; .json pour les versions avant 0.9.1) ;
  - un tableau, une ligne par observation :
      Excel .xlsx, .xlsm, .xls        texte .csv, .txt, .tsv (séparateur, virgule décimale et
      R .rds, .RData                    encodage reconnus, y compris le « texte Unicode »
      SPSS .sav, .zsav, .por            d'Excel)
      Stata .dta                      SAS .sas7bdat, .xpt
      jamovi .omv                     dBase .dbf, Weka .arff
      spectres JCAMP-DX .jdx, .dx, .jcm et SPC .spc (voir Spectres)
    La première colonne sert de nom d'observation si c'est du texte ou si elle s'appelle
    « ID », « Obs », « Nom »... (pour un fichier R, les noms des lignes) ; les autres colonnes
    de texte dont toutes les valeurs diffèrent (un code par observation) deviennent des
    identifiants secondaires : elles servent d'étiquettes mais n'entrent pas dans les modèles ;
    les autres colonnes de texte, les facteurs R et les variables étiquetées de SPSS ou Stata
    sont des variables qualitatives (dans l'ordre de leurs modalités). Pour un classeur à
    plusieurs feuilles ou un fichier R à plusieurs tableaux, l'application demande lequel ouvrir.
    Une colonne de mesures qui a quelques cellules de texte (<0,5, <LOD, nd, n.d., #N/A...)
    reste une variable quantitative : ces cellules sont lues comme manquantes, et la barre d'état
    dit combien, dans quelles variables (dont celles sous la limite de détection). Les dates et
    heures d'Excel restent des dates (2024-05-03), en texte, comme celles d'un fichier texte
    (telles qu'écrites : 14/05/2019) ou de R : une colonne de dates est une variable qualitative
    quand des dates reviennent (des secteurs comptés le même jour), un identifiant secondaire
    quand toutes diffèrent, le nom des observations si c'est la première colonne (la mettre
    alors plus loin pour en faire un temps) ; variable ou identifiant, elle peut être le temps
    (voir Le temps en dates). Un nombre d'Excel sans format de date (43599) reste un nombre. Un
    fichier texte dont une ligne a plus de valeurs que l'en-tête est refusé, avec le numéro de
    la ligne, plutôt que de décaler les colonnes. Un fichier R doit contenir des tableaux ; tout
    autre objet est refusé. Les fichiers R ne s'ouvrent qu'avec R 4.4 ou plus récent (celui de
    Windows) : avec un R plus ancien, comme celui d'Ubuntu 22.04 ou 24.04 ou de Debian 12, un
    .rds ou un .RData pourrait exécuter du code dès sa lecture (CVE-2024-27322) ; Nuée le refuse
    donc : enregistrez le tableau en CSV ou en Excel.
Fichier › Coller un tableau (Ctrl+V) : des cellules copiées dans Excel, LibreOffice, Google
Sheets ou jamovi deviennent un projet (la première ligne donne les noms des variables). Le
projet n'a pas encore de fichier : l'enregistrer (Ctrl+S).
Fichier › Importer des spectres : des fichiers de spectres réunis en un projet (voir Spectres).
Déposer des fichiers sur la fenêtre (glisser-déposer depuis l'Explorateur) les ouvre de même :
des spectres JCAMP-DX ou SPC ensemble font un seul projet, comme Importer des spectres ; les
autres fichiers s'ouvrent chacun comme avec Fichier › Ouvrir. Un double-clic sur un projet
.nuee dans l'Explorateur Windows l'ouvre dans Nuée (dans la fenêtre déjà ouverte s'il y en a une).
Les derniers fichiers ouverts sont dans Fichier › Ouvrir un fichier récent.
Pour essayer : Aide › Projet d'exemple ouvre 120 pommes inventées (quatre variétés, culture
bio ou conventionnelle, une douzaine de mesures et une note de dégustation) avec quatre
modèles prêts : une ACP, une PLS de la note, une PLS-DA des variétés et une OPLS-DA de la
culture. Le tableau d'origine, vergers.csv, est à côté (resources\exemple) pour essayer
l'ouverture d'un tableau.

Enregistrer et retrouver son travail
------------------------------------
Fichier › Enregistrer (Ctrl+S) écrit le projet (.nuee) avec ses données, ses modèles et la
séance en cours : modèles calculés, panneaux ouverts et leur disposition, réglages des
graphiques (axes, couleurs, étiquettes, titres), sélections, choix des VIP, groupes du
dendrogramme. En rouvrant le projet, les modèles sont recalculés et tout revient en place.
Le projet est écrit dans un fichier à côté, qui prend ensuite la place de l'ancien : une
coupure du réseau ou un disque plein pendant l'enregistrement laisse l'ancien intact. Si un
autre programme garde le fichier ouvert (synchronisation, antivirus), Nuée réessaie pendant
cinq secondes, puis le laisse tel quel et le dit : enregistrer de nouveau, ou Enregistrer
sous.... Si le fichier a été modifié ailleurs depuis qu'on l'a ouvert ou enregistré (un
collègue, sur un dossier partagé ; une autre fenêtre), Nuée le dit et propose Enregistrer
sous..., Écraser ou Annuler, aussi pour un projet repris après un arrêt inattendu. Le
fichier dit aussi quelle version de Nuée et de R l'a écrit ; un projet enregistré
par une version plus récente de Nuée est signalé à l'ouverture.
Rouvrir un fichier déjà ouvert (fichier récent, double-clic dans l'Explorateur) montre le
projet ouvert au lieu d'en ouvrir une seconde copie.
En fermant l'application avec des changements non enregistrés, elle propose « Enregistrer et
fermer ». Toutes les deux minutes, elle garde aussi une copie de secours des projets non
enregistrés : si elle s'arrête sans avoir été fermée (panne, coupure), elle propose au
lancement suivant de les récupérer. Fermer cette question sans répondre garde les copies pour
la fois suivante ; seul « Ignorer » les efface.
Édition › Annuler (Ctrl+Z) revient sur la dernière modification des données d'un projet
(valeur modifiée, nouvelle variable, classe, scores en variables, définition supprimée...),
jusqu'à 20 en arrière.
Notes : le résumé de chaque modèle a une zone de notes, enregistrée avec le projet et reprise
dans le rapport ; un crayon le signale dans l'explorateur.
Retirer un modèle (Modèle › Supprimer le modèle) demande confirmation. Sa définition reste
dans le projet ; pour un modèle fait dans l'application, une case permet de la supprimer
aussi (annulable).

Si le moteur R s'arrête
-----------------------
L'application le signale et propose de le redémarrer ; on peut aussi le faire soi-même
(Aide › Redémarrer le moteur R) si un calcul ne finit pas. Les projets se rouvrent avec leurs
modèles et leurs vues, depuis leur copie de secours s'ils avaient des changements, sinon
depuis le fichier où ils s'enregistrent ; les changements faits depuis la dernière copie de
secours (deux minutes au plus) sont perdus. Fermer Nuée quand le moteur ne répond plus garde
les copies de secours, proposées au lancement suivant. Au-delà d'une minute de calcul, la
barre d'état le rappelle.
Aide › Quoi de neuf : les nouveautés de chaque version (affichées une fois après une mise à
jour). La version installée (Nuee-Setup, ou les paquets Linux) cherche au démarrage s'il
existe une nouvelle version (une seule demande à GitHub, rien d'autre n'est envoyé) et la
signale dans la barre d'état ; sous Linux, un clic ouvre la page de la version. Sous Windows,
un clic propose de mettre à jour : le programme d'installation est téléchargé et
vérifié (son empreinte SHA-256 doit être celle que donne GitHub), puis Nuée se ferme (en
proposant d'enregistrer les projets modifiés), l'installe et redémarre. Pour une installation
pour tous les utilisateurs, Windows demande l'autorisation. Aide › Chercher une mise à jour
fait de même à tout moment, même sans la recherche au démarrage ; Aide › Chercher une nouvelle
version au démarrage arrête la recherche. La copie lancée depuis le NAS ne cherche pas : elle
se met à jour avec le NAS.

L'explorateur (à gauche)
------------------------
Projets, données, modèles importés d'un fichier .usp, modèles calculés et leurs vues.
Double-clic : ouvrir. Clic droit : toutes les actions (calculer, modifier, ajouter ou
retirer une composante, exporter, supprimer...). Double-cliquer un modèle importé le
recalcule en R ; le Résumé marque chaque valeur : « = » identique à la valeur enregistrée
dans le fichier, « ≈ » proche (moins de 0,01), « ≠ » différente. Le Q2 diffère en général : un
modèle importé est validé comme les autres (voir « Validation croisée ») ; « Centres et poids du
modèle complet (comme SIMCA) » redonne celui du fichier.

Nouveau modèle (Modèle › Nouveau modèle)
----------------------------------------
Onglet Général : type (ACP, PLS, PLS-DA, OPLS, OPLS-DA, modèles de classe, régression
linéaire, modèle linéaire mixte, modèle linéaire généralisé, modèle additif : voir Modèles
linéaires, généralisés et mixtes ; RDA et CA : voir Analyse de redondance et analyse des
correspondances ; arbre de décision, LDA et k-moyennes : voir Arbres de décision, analyse
discriminante linéaire et k-moyennes), nom, nombre de composantes
(automatique par défaut, par validation croisée), groupes de validation croisée (à tour de
rôle, G groupes ; ou un groupe par valeur d'un identifiant ou d'une variable, voir Validation
croisée), échelle par défaut.
Onglet Variables : rôle (X, Y, classe), échelle, bloc, modificateur et transformation de
chaque variable : racine carrée, racine quatrième, log10, ou personnalisée... (log10, ln ou
-log10 de C1*x + C2, exp(C1*x + C2), C1*x + C2, le logit ln((x - C1) / (C2 - x)) entre deux
bornes, ou la puissance (C1*x + C2)^C3 ; une valeur hors du domaine devient manquante) ; le filtre permet de régler d'un coup
toutes les variables affichées (un bloc : le taper dans « Bloc... » au-dessus de la liste,
puis Entrée). Pondération par blocs : les termes d'un même bloc ont leur poids divisé par la
racine carrée de leur nombre, pour qu'un bloc de 20 variables ne pèse pas 20 fois plus qu'une
variable seule ; une variable qualitative compte par ses catégories. Modificateur : multiplie
le poids de la variable après sa mise à l'échelle. Le bouton « Transformations proposées »
applique aux variables affichées le log10 proposé (voir Statistiques des variables).
Onglet Termes croisés : produits de deux ou trois variables X (A × B, A × B × C), carrés
(A × A) et cubes (A × A × A) ; une variable qualitative y entre par chacune de ses catégories,
une fois au plus. Chaque terme croisé a sa propre échelle, son bloc et son modificateur, comme
dans l'onglet Variables. Dans une régression, un facteur peut aussi être une variable sans rôle
(sous « Pas en X : sans effet principal ») : elle n'entre alors que par le terme croisé (voir
Termes croisés avec une variable qualitative).
Onglet Observations : cocher / décocher les observations du modèle, et le jeu de test (voir
Jeu de test) ; « Garder seulement les observations où… » les choisit par une condition (voir
Observations choisies par une condition).
« Modifier le modèle » (Ctrl+M) ouvre cette fenêtre réglée comme un modèle existant (y compris
les modèles importés) et crée un nouveau modèle.
Avant le calcul, l'application vérifie les données : variables ou observations avec plus de
50 % de valeurs manquantes, variables constantes. S'il y en a, elle les liste et propose
« Les exclure et ajuster » ou « Ajuster quand même ».

Graphiques : couleurs et étiquettes
-----------------------------------
Scores, DModX, T², observé / prédit : la liste « Couleur » colore les points par classe
(PLS-DA), par groupe du dendrogramme ou par n'importe quelle variable du projet (dégradé pour
une variable numérique). La liste « Étiquettes » écrit à côté de chaque point son nom, un
identifiant secondaire ou la valeur d'une variable.
Clic droit sur un graphique après une sélection : « Créer une classe à partir de la
sélection » range ces observations dans une classe d'une variable qualitative (nouvelle ou
existante), utilisable ensuite pour colorer ou comme classe d'une PLS-DA.
Édition › Sélection commune aux modèles du projet (cochée par défaut) : des observations
choisies dans un modèle le sont aussi dans les autres modèles du même projet.
Variables en évidence : un clic sur une variable (barre des VIP, des coefficients ou des
loadings, point des loadings, du biplot ou du S-plot, ligne d'un profil, ligne de la liste des
variables) la met en rouge sur tous les graphiques du modèle ; un cadre en choisit plusieurs
dans les nuages de points des variables. Échap efface la sélection et les variables en évidence.

Autres graphiques
-----------------
Biplot : scores et loadings dans le même graphique, mis à l'échelle des corrélations
(t(corr) et p(corr), ou pc(corr) avec les Y d'une PLS), tous dans le cercle de rayon 1.
Scores en 3D : trois composantes, à faire tourner à la souris ; un clic choisit un point.
S-plot (OPLS) : p[1] contre p(corr)[1] ; les variables aux deux extrémités sont celles qui
portent le lien avec Y (ou qui séparent les deux classes).

Mise en forme des graphiques (pour un article, un rapport)
-----------------------------------------------------------
Clic droit sur un graphique › Mise en forme, ou Édition › Mise en forme du graphique :
titre et titres des axes de ce graphique ; pour tous les graphiques : police, taille du
texte, taille des points, couleurs (dont une palette lisible par les daltoniens et des
niveaux de gris), grille, légende ; et « Exporter l'image » à la taille voulue (en pixels,
résolution ×1 à ×6) en PNG, SVG ou JPEG. Ces réglages sont gardés d'une fois sur l'autre.

Contributions
-------------
Graphiques › Contributions, ou clic droit sur une sélection : pour une observation (ou la
moyenne de plusieurs), la part de chaque variable dans son écart à l'observation moyenne du
modèle. Au choix : contribution au DModX (pourquoi l'observation est mal modélisée), au score
d'une composante, ou au T² (pourquoi elle est loin du centre) ; pondérée ou non par le
pouvoir de modélisation.

Prédire
-------
Prédiction › Prédire : les observations du projet hors du modèle, ou un jeu de prédiction
enregistré dans le fichier .usp.
Prédiction › Prédire un fichier : un tableau (dans l'un des formats ci-dessus) dont les colonnes portent les
noms des variables du modèle (sans tenir compte des majuscules ni des espaces au début et à
la fin ; les catégories par leur nom). Le résultat donne les scores, DModX, T² et Y prédits ;
les observations hors du domaine du modèle (DModX > DCrit ou T² > T²Crit 95 %) sont
signalées ; il s'exporte dans tous les formats d'export. Les variables X absentes du fichier sont
listées et traitées comme manquantes.
Le graphique au-dessus du tableau montre les scores, ou le DModXPS : la distance de chaque
observation prédite au modèle, comparée à DCrit (les observations du modèle en gris).

Modèles hiérarchiques
---------------------
Modèle › Scores en variables : les scores d'un modèle deviennent des variables du projet
($M1.t1(titre), $M1.t2(titre)...), qu'on peut prendre comme X d'un modèle de niveau
supérieur. Après avoir modifié le modèle de base, refaire cette étape puis réajuster les
modèles qui les utilisent (l'application les nomme). Pour prédire un fichier avec un modèle
hiérarchique, les modèles de base sont prédits d'abord, automatiquement.

Exporter vers d'autres logiciels
--------------------------------
Fichier › Exporter les données : le tableau du projet (noms des observations, identifiants,
variables). Fichier › Exporter les résultats du modèle (Ctrl+E) : les tableaux du modèle
(observations : scores, T², DModX, valeurs ajustées ; variables : loadings, VIP, intervalles ;
composantes ; coefficients ; variables Y). Formats : Excel (une feuille par tableau), CSV,
texte séparé par des tabulations, R (.rds : une liste de tableaux ; .RData), SPSS (.sav),
Stata (.dta), SAS transport (.xpt), jamovi (.omv), dBase (.dbf) et Weka (.arff) ; dans ces
derniers, un fichier par tableau (« M1.sav », « M1 - variables.sav »...). Les variables
qualitatives restent qualitatives (facteurs R, étiquettes de valeurs SPSS et Stata, nominales
jamovi). Pour SPSS, Stata, SAS et dBase, les noms de variables sont rendus valides (lettres
sans accent, chiffres, « _ ») ; le nom d'origine devient l'étiquette de la variable.
SAS : format de transport version 5, que SAS lit avec libname xport (noms de 8 caractères,
étiquettes de 40, textes de 200 au plus). dBase : textes en Windows-1252 ; dans LibreOffice,
choisir le jeu de caractères « Europe occidentale (Windows-1252) » à l'ouverture. Les
fichiers écrits ont été ouverts dans jamovi, PSPP (pour SPSS), Weka, LibreOffice et pandas.

Spectres
--------
Fichier › Importer des spectres : choisir un ou plusieurs fichiers (Ctrl+A dans un dossier
pour les prendre tous) ; ils deviennent un projet, une ligne par spectre, une colonne par
longueur d'onde (nommée par sa valeur : « 1450 », « 3999.69 »). Fichiers lus :
  JCAMP-DX (.jdx, .dx, .jcm)  toutes les écritures (nombres simples ou compressés : AFFN, PAC,
             SQZ, DIF, DUP), plusieurs spectres par fichier ; pas les tables de pics ni les
             NTUPLES (RMN complexe, spectrométrie de masse) ;
  SPC (.spc)  Galactic (GRAMS, Thermo), nouveau et ancien format, un ou plusieurs spectres ;
  texte (.csv, .txt...)  une colonne d'abscisses, puis une colonne par spectre, avec ou sans
             ligne d'en-tête ; les lignes que l'appareil écrit avant les nombres sont ignorées.
Un spectre est nommé d'après son fichier (et le titre du bloc ou son numéro quand un fichier en
a plusieurs). Si les spectres n'ont pas tous les mêmes abscisses, ils sont interpolés
(linéairement) sur celles du premier, dans la partie commune à tous ; la barre d'état le dit.
Des unités différentes (nm et cm-1, absorbance et transmittance) sont refusées.
Informations (facultatif) : un tableau (Excel, CSV...) dont la première colonne donne le nom de
chaque fichier, avec ou sans son extension, et les autres colonnes des informations à joindre
aux spectres (teneurs, classes, lots) ; elles prennent place avant les spectres. La barre
d'état dit combien de spectres n'ont pas trouvé leur ligne. Un seul fichier JCAMP-DX ou SPC
s'ouvre aussi avec Fichier › Ouvrir, et un fichier de nouveaux spectres sur la même grille se
prédit avec Prédiction › Prédire un fichier.

Nouveau modèle › Général › Prétraitement des spectres : chaque observation est un spectre
(ses variables X quantitatives, dans l'ordre du tableau), corrigé avant la mise à l'échelle
par une à trois étapes, dans l'ordre :
  SNV        chaque spectre centré sur sa moyenne et divisé par son écart-type ;
  MSC        chaque spectre ajusté sur le spectre moyen des observations du modèle (x = a + b r),
             puis remplacé par (x - a) / b ; une prédiction reprend ce spectre moyen ;
  Detrend    un polynôme de degré 2 en fonction de la longueur d'onde, ajusté sur le spectre,
             en est retiré (Barnes et al., 1989 ; souvent après SNV) ;
  Ligne de base  l'enveloppe convexe inférieure du spectre (les segments qui joignent ses points
             les plus bas, d'un bout à l'autre) en est retirée ; le spectre corrigé est positif
             ou nul ;
  Savitzky–Golay : lissage, dérivée première ou seconde, dans une fenêtre de n variables
             (impair) avec un polynôme de degré d. Chaque zone de variables voisines dans le
             tableau est traitée à part : une fenêtre ne passe pas par-dessus une zone retirée.
La longueur d'onde (pour Detrend et la ligne de base) est le nombre lu dans le nom des
variables quand chacune en a un, différent ; sinon leur place dans le tableau.
Pour des spectres, on centre souvent sans réduire (échelle « Centrage seul »). Seul le MSC
dépend des autres observations (le spectre moyen) : en validation croisée, chaque groupe est
corrigé avec le spectre moyen des autres observations. Graphiques › Profils (spectres) :
loadings, coefficients, VIP, ou les spectres eux-mêmes (avant ou après prétraitement) en
lignes ; l'axe horizontal est le nombre lu dans le nom des variables (« 1450 nm ») quand
chacune en a un ; les lignes s'interrompent là où des variables sont hors du modèle. Un clic sur
un spectre sélectionne son observation.
Zones de longueurs d'onde : cocher « Choisir des zones », puis faire glisser sur le graphique
(une ou plusieurs zones, en orange) ; « Nouveau modèle sans ces zones » (par exemple les
bandes de l'eau) ou « Nouveau modèle avec ces zones seules » ouvre Nouveau modèle avec les
réglages du modèle et ces variables X, à vérifier avant d'ajuster. Les autres variables X du
modèle (qualitatives) restent.
Graphiques › iPLS (intervalles du spectre), pour un modèle avec Y : le spectre (les variables X
quantitatives du modèle, dans leur ordre) est prétraité une fois, en entier, comme pour le
modèle (avec un MSC, aussi pour chaque groupe de la validation croisée, avec le spectre moyen
des autres observations), puis coupé en n intervalles de même largeur ; chacun est une PLS sur sa zone (avec la
mise à l'échelle du modèle et ses autres variables X), avec 1 à A composantes. Une barre par
intervalle donne son plus petit RMSEcv (dans les unités de Y, comme dans le résumé), avec ce
nombre de composantes écrit dessus ; en vert, les intervalles qui prédisent mieux que le
spectre entier (tirets rouges) ; la ligne grise est le spectre moyen après prétraitement.
Cliquer des barres pour choisir des intervalles, puis « Nouveau modèle avec ces intervalles »
ou « sans ces intervalles ». Un tel modèle prétraite ses propres variables : avec SNV, MSC,
detrend ou ligne de base, son RMSEcv peut différer de celui de la barre. Méthode : Nørgaard et
al. (2000), Applied Spectroscopy 54, 413–419.

Exporter vers R (script, R Markdown, Quarto)
--------------------------------------------
Fichier › Exporter vers R : un fichier qui refait le modèle sans Nuée, avec R seul, à
envoyer à un collègue ou à joindre à un article. Le calcul y est écrit pour ce modèle seul,
en R sans paquet (une régression : lm, ou nlme et mgcv, livrés avec R), commenté dans la
langue de l'export, en quatre parties :
  1. les fonctions : l'algorithme NIPALS, la validation croisée, et seulement ce que ce
     modèle utilise (valeurs manquantes, prétraitement des spectres, OPLS...) ;
  2. les données, dans le script ou dans un fichier CSV à côté (« M1 - donnees.csv »),
     les nombres écrits sans perte et les catégories dans leur ordre ;
  3. le modèle : ses termes X et Y (transformations, catégories, termes croisés), leur
     mise à l'échelle, l'ajustement, puis R2 et Q2, T2 et DModX avec leurs limites, VIP,
     coefficients, CV-ANOVA, classement pour une PLS-DA, jeu de test ;
  4. les résultats : les tableaux, le test de permutation (en commentaire) et les
     graphiques (scores, loadings, VIP, observé / ajusté, T2 et DModX).
Format : script R (.R) ; ou rapport R Markdown (.Rmd) ou Quarto (.qmd), qui y ajoute le texte
des méthodes, des tableaux et des graphiques (scores, loadings, VIP, observé / prédit, T2,
DModX) et les références ; il se compile dans RStudio (bouton Knit) ou avec quarto render, et
demande le paquet knitr. Fichiers en plus, au choix : renv.lock (versions de R et des paquets,
pour renv::restore()), les données et le modèle ajusté en .RData (load() les rend sans
recalculer), un projet RStudio (.Rproj, à mettre dans un dossier à part).
Modèles : celui-ci, ou tous les modèles de la séance (le dernier ajustement de chacun) dans un
seul script .R : les fonctions et les données une fois, puis un bloc par modèle sous son nom
(M1, M2...).
Avant d'écrire, l'application recalcule les modèles du script et vérifie qu'ils donnent les
mêmes résultats ; sinon elle le signale.

Le temps en dates
-----------------
Partout où un temps est demandé (Séries, BACI, Autocorrélation des résidus, l'autocorrélation
CAR1 d'un modèle mixte, precedent() et suivant() de Nouvelle variable), il peut être fait de
nombres (l'année ; 2019,5) ou de dates : 2019-05-14 (ISO, au besoin avec l'heure :
2019-05-14 10:30) ou 14/05/2019, aussi 14-05-2019 et 14.05.2019, l'année en quatre chiffres.
Le jour vient toujours d'abord, comme en France : 05/04/2019 est le 5 avril, jamais le 4 mai.
Une date devient une année décimale : l'année + (le jour de l'année − 1 + la fraction du jour)
/ le nombre de jours de l'année (366 les années bissextiles) ; le 1er janvier 2019 est 2019, le
14 mai 2019 est 2019,364. Années et dates se lisent ainsi de la même façon : une pente de Sen
ou le φ de CAR1 sont par an. Un temps est fait de nombres ou de dates, pas des deux : une
valeur de l'autre genre, ou une date qui n'existe pas (31/02/2019), est refusée en la nommant.
Un nombre reste un nombre : un numéro de jour d'Excel (43599) ne se distingue pas d'une année.
precedent() et suivant() gardent leur règle, le temps exactement un pas avant : elles vont
avec des temps réguliers (des années) ; avec des dates, ce temps-là existe rarement, et aucune
date proche n'est prise à sa place. L'export vers R lit les dates de la même façon.

Séries
------
Graphiques › Séries (ou dans l'explorateur, sous le projet) : une variable au fil du temps,
comme des figures de séries par secteur, une page par site. Choisir la variable, le temps (une
variable ou un identifiant fait de nombres, comme l'année, ou de dates : voir Le temps en
dates), les lignes (une variable qualitative ou un identifiant : le secteur) et, au choix, les
panneaux (le site) : un petit graphique par panneau, en grille, aux axes communs. Dans une
ligne, les temps qui se suivent à son propre pas (son plus petit écart) sont reliés, et un
secteur compté une année sur deux reste une ligne ; un temps manquant coupe la ligne, et
l'année sans comptage se voit. Des dates, rarement régulières, vont sur un axe de dates, et une
ligne relie tous ses points. Les couleurs vont par ligne dans chaque panneau, la légende est
rangée par panneau (un clic sur une entrée cache sa ligne) : elle reste lisible avec 30
secteurs. Au choix : la moyenne des lignes de chaque panneau, temps par temps (trait épais),
une échelle log (les valeurs ≤ 0 n'y sont pas montrées) et des événements, des temps tapés
« 2015 ; 2019 » (avec des dates, aussi 2019-05-14 ou 14/05/2019), en tirets dans chaque
panneau. Le survol donne le nom de l'observation, le temps et la valeur ; un clic ou un cadre
sélectionne des observations, qui le sont aussi dans les modèles du projet quand la sélection
leur est commune. Les observations sans temps, sans valeur, sans ligne ou sans panneau sont
laissées de côté et comptées ; une ligne qui a deux fois le même temps (des secteurs choisis
sans leur site) est signalée et montrée en points. Clic droit : copier ou enregistrer l'image.
Tendances (la case de la barre) : sous le graphique, un tableau donne pour chaque ligne de
chaque panneau, marquée de sa couleur, n (ses temps qui ont une valeur), son premier et son
dernier temps ; la pente de Sen (Sen, 1968 : la médiane des pentes entre toutes ses paires de
temps, par unité de temps, par an avec des dates) et son intervalle à 95 % (Gilbert, 1987 : les
pentes rangées, prises autour de la médiane d'après la variance de S ; sans bornes quand il y a
trop peu de temps) ; le τ de Kendall (tau-b), le S de Mann–Kendall et sa valeur p bilatérale
par la loi normale (variance corrigée pour les ex aequo, correction de continuité, comme
trend::mk.test et Kendall::MannKendall) ; et la valeur p corrigée sur les lignes
(Benjamini–Hochberg, ou Holm au choix). Une ligne de moins de 4 temps, qui a un même temps deux
fois ou la même valeur à chaque temps n'est pas testée, et le tableau dit pourquoi ; Ctrl+C le
copie. Le test tient les temps pour indépendants : une autocorrélation positive (des années qui
se ressemblent) rend p trop petite. Pour une tendance qui en tient compte : Graphiques ›
Autocorrélation des résidus, puis un modèle mixte avec une autocorrélation CAR1, l'année en X.
Dans la barre du tableau, deux options changent le test. Tenir compte de l'autocorrélation : le
test de Mann–Kendall modifié de Hamed et Rao (1998), calculé comme le calcule modifiedmk::mmkh :
la ligne privée de sa tendance (sa pente de Sen, sur ses vrais temps), les rangs de ce qui
reste, leur autocorrélation à chaque décalage (compté d'un temps au suivant : le temps qui suit
une année manquante est à un décalage), celles au-delà de ±1,96/√n gardées (les autres
comptent 0), et Var(S) multipliée par
n/n* = 1 + 2/(n(n − 1)(n − 2)) Σ (n − k)(n − k − 1)(n − k − 2) ρ(k) ; p et l'intervalle de la
pente viennent de cette variance, et la colonne n/n* donne le facteur (1 : aucune
autocorrélation gardée ; un facteur qui n'est pas positif, d'une forte autocorrélation négative,
laisse la ligne sans test). Il faut une longue série : une autocorrélation s'estime
mal sur peu de temps (Box et Jenkins, 1976, en demandent une cinquantaine), et avec 15 temps
seule une autocorrélation au-delà de ±0,51 compte ; même sur 60 à 90 temps, le test corrigé
rejette encore trop souvent une absence de tendance quand l'autocorrélation est forte (Blain,
2013). Il corrige chaque ligne seule : il ne remplace pas un modèle mixte avec une
autocorrélation CAR1, qui estime la tendance commune aux sites et à leurs secteurs, avec
l'autocorrélation dans chacun.
Saisons : le test de Kendall saisonnier (Hirsch, Slack et Smith, 1982), pour des relevés faits
plusieurs fois par an, la saison donnée par le mois d'un temps fait de dates, ou par une
variable qualitative ou un identifiant (la saison, le mois). L'année d'une valeur est la partie
entière de son temps (l'année civile d'une date) ; plusieurs valeurs d'une saison la même année
n'en font qu'une, leur médiane (comme le font certaines mises en œuvre ; EnvStats les
garderait toutes, en ex aequo de temps), et une note dit combien. Dans chaque saison vue au
moins 2 années : le S de Mann–Kendall entre ses années et sa variance avec les ex aequo ; S et
Var(S) sont additionnés sur les saisons, tenues pour indépendantes, et p vient de la loi normale
avec la correction de continuité, comme les calculent trend::smk.test et
EnvStats::kendallSeasonalTrendTest. La pente de Sen saisonnière est la médiane des pentes entre
années au sein de chaque saison (par an, ou par unité de temps), son intervalle à 95 % tiré de
Var(S) comme le fait Gilbert (1987) (les rangs arrondis, comme pour la pente de Sen plus haut ;
EnvStats interpole entre eux) ; τ est celui d'EnvStats : les τ des saisons en moyenne, pondérée
par leurs années. Une saison vue une seule année ne compte pas ; une ligne de moins de 4 valeurs
dans les saisons qui comptent, ou de la même valeur chaque année dans chaque saison, n'est pas
testée ; les observations sans saison sont laissées de côté par le test, et comptées. Le test
saisonnier tient les saisons pour indépendantes : une autocorrélation d'un mois au suivant rend
p trop petite, et Tenir compte de l'autocorrélation ne s'y applique pas (Hirsch et Slack, 1984,
donnent une correction, qui n'est pas faite ici). La colonne Test donne le test de chaque
ligne ; la correction sur les lignes reste la même.

Tests statistiques
------------------
Graphiques › Tests statistiques (ou dans l'explorateur, sous le projet), en quatre modes, au
choix en haut à gauche.

Entre classes, variable par variable : chaque variable quantitative comparée entre les classes
d'une variable qualitative.
  Deux classes (A, la référence, et B) : test t de Welch (par défaut, variances inégales), t de
  Student ou Mann–Whitney (sur les rangs). Effet : log2 du rapport des moyennes B / A (quand les
  deux moyennes sont positives) ou d de Cohen. Graphique volcan : l'effet contre -log10(p).
  Deux classes appariées par une clé (« Apparier par » : une variable ou un identifiant des
  observations, l'année pour deux secteurs suivis les mêmes années) : pour chaque variable, les
  lignes de A et de B qui ont la même clé, et une valeur, font les paires, et les différences
  B − A passent par le test t apparié (par défaut) ou par le test des rangs signés de Wilcoxon.
  Le tableau donne le nombre de paires de chaque variable et les moyennes de A et de B sur ces
  paires ; l'effet est le log2 du rapport de ces moyennes (quand les deux sont positives) ou le
  d_z de Cohen (la différence moyenne sur l'écart-type des différences). Une variable de moins
  de trois paires n'est pas testée. Une clé ne revient qu'une fois par classe : une clé en
  double dans A ou dans B est refusée, comme dans « Deux variables ».
  Toutes les classes : ANOVA à un facteur ou Kruskal–Wallis ; les variables rangées par p.
Les valeurs p sont corrigées pour les comparaisons multiples : Benjamini–Hochberg (taux de
fausses découvertes, par défaut), Bonferroni, ou aucune. En couleur : les variables dont le p
corrigé passe le seuil (et, pour deux classes, l'effet aussi).

Deux variables : le test qui convient à leurs types, ses conditions vérifiées, sur les
observations où les deux sont connues. Un identifiant des observations (site, secteur,
année...) peut faire les groupes, comme une variable qualitative.
  Deux variables qualitatives : le tableau de contingence et le khi² d'indépendance de Pearson,
  avec le V de Cramér. En rouge et en bleu, les cases plus ou moins fréquentes que si les deux
  variables étaient indépendantes (résidu ajusté au-delà de ±1,96). Quand les effectifs
  attendus sont trop petits pour le khi² (un sous 1, ou plus de 20 % sous 5 : règle de
  Cochran), le test exact de Fisher est conseillé ; pour un tableau 2 × 2, il est toujours
  donné, avec le rapport des cotes. Au-delà de 2 × 2 et de 200 observations, sa valeur p est
  simulée (100 000 tableaux).
  Une mesure et une variable qualitative : la mesure comparée entre les groupes, en boîtes à
  moustaches. Deux groupes : test t de Welch et Mann–Whitney (exact sous 50 valeurs de chaque
  côté sans ex aequo ; sinon par la loi normale avec la correction de continuité : le même
  calcul sous toutes les versions de R). Plus : ANOVA à un facteur, ANOVA de Welch et
  Kruskal–Wallis, chacun avec ses comparaisons deux à deux (Tukey, Games–Howell, Dunn avec la
  correction de Holm ; jusqu'à 50 groupes) : un clic sur un test les montre. Le test sur les
  rangs est conseillé quand la normalité est douteuse dans un groupe (Shapiro–Wilk p < 0,05, ou
  moins de trois observations), l'ANOVA de Welch quand les variances diffèrent
  (Brown–Forsythe p < 0,05).
  Une mesure et une variable qualitative, appariées par une troisième variable ou un
  identifiant (« Apparier par » : l'année, pour deux secteurs d'un site suivis les mêmes
  années) : les données restent en long, une ligne par secteur et par année. Deux niveaux A et
  B sont comparés sur les clés qu'ils ont tous deux : les différences B − A par le test t
  apparié (différence moyenne, son intervalle à 95 %, d_z de Cohen) et par le test des rangs
  signés de Wilcoxon, le test sur les rangs conseillé quand la normalité des différences est
  douteuse (Shapiro–Wilk p < 0,05 ; pas testée au-delà de 5 000 paires, ni avec des
  différences constantes, qui ne laissent que Wilcoxon). La p de Wilcoxon est exacte sous 50
  paires quand aucune différence n'est nulle ni ex aequo ; sinon, les différences nulles
  retirées, elle vient de la loi normale avec la correction de continuité, la même sous toutes
  les versions de R. Il faut au moins trois paires, et une clé ne revient qu'une fois par
  niveau. Les lignes restées sans partenaire, et celles sans valeur, sont comptées et
  listées ; le graphique relie chaque paire. Avec trois niveaux ou plus, le tableau du bas peut
  aussi lister toutes les paires de niveaux, chacune sur ses propres clés communes, avec la
  correction de Holm sur les paires testées, pour le test choisi au-dessus (un clic sur un
  test) : quand tous les niveaux ont les mêmes clés, celles de pairwise.t.test() et
  pairwise.wilcox.test() avec paired = TRUE. Une paire non testée (moins de trois clés
  communes, une clé deux fois dans un niveau, la même valeur dans chaque paire) dit pourquoi,
  et un clic sur une paire la compare ; quand A et B ne se comparent pas, le tableau reste,
  sous leur raison. « Paires de niveaux dans chaque » (une variable qualitative ou un
  identifiant : le site) garde les paires de niveaux d'un même groupe, les secteurs de chaque
  site comparés deux à deux. La correction de Holm porte sur les paires testées, tous les
  groupes ensemble ; la valeur p brute se lit site par site. Un niveau est du groupe que
  portent ses lignes : un niveau aux lignes de plusieurs groupes est refusé, et ceux sans
  groupe sont listés. Au-dessus des paires vient le test d'ensemble, pour les deux tests
  appariés : le test de Friedman sur les clés où chaque niveau a une valeur (les blocs
  complets ; les clés laissées de côté faute d'un niveau sont comptées), son χ², ses degrés de
  liberté et sa valeur p, avec le W de Kendall = χ² / (n (k − 1)) pour taille de l'effet (0 :
  aucun accord d'une clé à l'autre, 1 : le même classement des niveaux à chaque clé), en une
  phrase. Dans chaque groupe, un test de Friedman par groupe, sur ses propres niveaux et ses
  clés complètes, sa valeur p corrigée par Holm sur les groupes testés ; un groupe de moins de
  trois niveaux ou de moins de deux clés complètes n'a pas de test, et la raison est dite.
  Deux mesures : les corrélations de Pearson et de Spearman ; Spearman est conseillée quand la
  normalité de l'une des deux est douteuse. Appariées par « l'observation (même ligne) », deux
  mesures des mêmes lignes (avant et après, par exemple) sont comparées à la place : les
  différences Variable 2 − Variable 1, sur les observations où les deux sont connues, par les
  deux mêmes tests appariés.
Le résultat du test conseillé est donné en une phrase, prête pour un rapport (le bouton à côté
la copie), avec la taille de l'effet : V de Cramér, rapport des cotes, d ou d_z de Cohen,
corrélation rang-bisériale, η², ε², r ou ρ. Celle de Mann–Whitney nomme les deux groupes avec
leurs médianes.

Matrice des corrélations : les corrélations de Pearson ou de Spearman de toutes les variables
quantitatives (300 au plus), chaque paire sur les observations où les deux sont connues,
valeurs p corrigées pour le nombre de paires. Un clic sur une paire, dans la table ou le
graphique, la teste dans « Deux variables ».

Avant/après (BACI) : un changement de gestion sur certaines unités (l'impact) comparé à des
unités restées comme elles étaient (les témoins), comme dans un plan avant/après avec témoin.
Choisir une réponse quantitative, un temps (une variable ou un identifiant des observations :
l'année, ou des dates) et une unité (une variable qualitative ou un identifiant : le secteur),
puis cocher la ou les unités d'impact et la ou les unités témoins. À chaque temps, l'écart d_t
est la moyenne des lignes de l'impact moins celle des lignes des témoins, aux temps où les deux
ont une valeur (une ligne par unité et par temps donne la moyenne des unités ; les temps d'un
seul côté sont listés et laissés de côté) : avec des dates, l'impact et les témoins comptés le
même jour ; pour comparer des années, prendre l'année. L'événement est le premier temps compté
« après » (un nombre pour un temps fait de nombres ; une date pour un temps fait de dates, où
une année est son 1er janvier) : pour une densité de printemps qui répond à la gestion de
l'année d'avant, l'année qui suit le changement. Les temps qui le précèdent sont « avant » ; «
après » court jusqu'à une fin facultative, elle aussi du genre du temps (avec des dates,
31/12/2012 pour la fin de 2012 : une année seule est refusée, comme une date pour un temps fait
de nombres), les temps suivants en gris, hors du test. Avec au moins deux temps dans chaque
période, les écarts d'après sont comparés à ceux d'avant : test t de Welch (par défaut), t de
Student (variances égales : un modèle linéaire de l'écart sur la période) ou Mann–Whitney (sur
les rangs) ; l'effet est le changement de l'écart moyen, après
moins avant, avec son intervalle à 95 %, et le résultat vient en une phrase prête pour un
rapport. Le graphique montre les écarts dans le temps, l'événement et la moyenne de chaque
période ; tant qu'aucun événement n'est entré, les écarts seuls. Les temps sont tenus pour
indépendants : des écarts successifs qui se ressemblent (autocorrélation) rendent la valeur p
trop petite. « Ajuster le modèle mixte » en tient compte : il ajoute au projet deux variables
valant 0 ou 1, « période BACI (2007) » (1 à partir de l'événement, 0 avant) et « impact BACI
(S1 contre S2, S3) » (1 pour les unités d'impact, 0 pour les témoins, manquante pour les
autres unités), puis le modèle linéaire mixte y ~ période × impact + (1 | unité) sur les
lignes des unités d'impact et témoins dont le temps est connu, jusqu'à la fin s'il y en a
une : une ordonnée à l'origine aléatoire par unité et, avec « avec CAR1 dans le temps »
(cochée d'office quand chaque unité a au moins trois temps ; impossible quand une unité a
plusieurs lignes au même temps), une autocorrélation CAR1 le long du temps dans chaque unité.
Une variable de ce nom, ou de ce nom suivi de (2), (3)…, ou de son nom dans l'autre langue, qui
a déjà ces valeurs sert telle quelle ; sinon la variable prend le premier de ces noms qui est
libre (un nom tenu par d'autres valeurs : d'autres unités au-delà des trois nommées, un autre
temps, un temps corrigé depuis) ; Ctrl+Z les retire, comme une nouvelle
variable. Le modèle rejoint le projet (nommé « BACI <réponse> » ; les mêmes réglages
réajustent le même modèle) et ses vues s'ouvrent. De retour dans la vue BACI, son effet BACI,
le coefficient période × impact avec son intervalle à 95 % et sa valeur p, vient en une phrase
sous celle du test, qui dit que ce modèle tient compte des unités et, avec CAR1, de
l'autocorrélation. Son texte des Méthodes dit que c'est le modèle BACI et ce que valent ses
deux variables.

Modèles linéaires, généralisés et mixtes
----------------------------------------
Nouveau modèle › type « Régression linéaire » ou « Modèle linéaire mixte » : une variable Y
quantitative, les variables X de l'onglet Variables (transformations et termes croisés
compris ; une variable qualitative par ses catégories, l'une d'elles servant de référence).
Sans X : le modèle nul, utile pour comparer les AIC. L'échelle par défaut garde les unités
des variables (coefficients par unité) ; UV donne des coefficients par écart-type.
Un modèle mixte (nlme) ajoute des effets aléatoires emboîtés, du plus large au plus fin : une
ordonnée à l'origine aléatoire par site, puis par secteur dans son site (un identifiant des
observations ou une variable qualitative). Il peut ajouter une autocorrélation dans le temps
(CAR1, en temps continu : des années manquantes ne gênent pas ; le temps est un identifiant ou
une variable, de nombres ou de dates, et φ est alors d'une année à l'autre : voir Le temps en
dates) à l'intérieur du dernier niveau ou, par « dans chaque », d'un niveau plus fin qui n'a
pas d'effet aléatoire à lui : le secteur dans son site, quand seul le site a un effet
aléatoire. Les coefficients et les
variances sont estimés en REML ; la log-vraisemblance, l'AIC, l'AICc et le BIC viennent de
l'ajustement en ML, le seul qui compare des modèles aux effets fixes différents. La validation
croisée se fait par défaut par le premier effet aléatoire : chaque site est prédit par les
effets fixes du modèle ajusté sans lui, comme un site jamais vu.
Pentes aléatoires : sous chaque effet aléatoire choisi, « Pentes aléatoires par site » coche
les variables X quantitatives dont la pente change d'un site à l'autre, le plus souvent
l'année : chaque site a sa propre tendance, qui varie autour de la pente fixe du modèle ; c'est
(1 + annee | site) dans une formule R. La variable doit être aussi un terme X du modèle,
quantitatif et seul (transformé ou non), pas en courbe : sinon le modèle est refusé, en la
nommant. Avec nlme (un modèle mixte, ou un GLM ou un GAM à loi normale avec CAR1, ajusté par
mgcv::gamm), chaque niveau a la matrice de covariance générale de nlme
(random = ~ annee | site ; avec des niveaux emboîtés, la liste list(site = ~ annee,
secteur = ~ 1)) : la variance de son ordonnée à l'origine, celle de chaque pente et leur
corrélation. L'écart-type d'une pente, en unités de Y par unité de X, dit combien les tendances
des sites s'écartent de la tendance moyenne : environ 95 % des sites sont à ±2 écarts-types de
la pente fixe. La corrélation dit si les sites hauts ont des pentes plus fortes (au-dessus de
0) ou plus faibles (au-dessous) ; elle est celle de l'ordonnée à l'origine prise à x = 0. Le
Résumé donne la variance et l'écart-type de chaque ordonnée à l'origine et de chaque pente, et
la corrélation de chaque pente avec l'ordonnée à l'origine de son niveau (avec plusieurs pentes
à un niveau, leurs corrélations entre elles sont estimées mais pas dans ce tableau : summary(m)
du script d'Exporter vers R les donne). Avec une pente, la variance d'un niveau change avec x
et sa part de la variance aléatoire n'a plus une seule valeur : le Résumé donne la part de
chaque niveau, de sa variance moyenne sur les observations, et les R2 marginal et conditionnel
la prennent aussi, comme Johnson (2014) étend ceux de Nakagawa et Schielzeth : la moyenne sur
les observations de zᵢᵀΣzᵢ, Σ la matrice du niveau et zᵢ = (1, les valeurs de ses pentes).
Centrer : une variable loin de 0, comme l'année (≈ 2010), met l'ordonnée à l'origine aléatoire
loin des données (à l'an 0), où sa corrélation avec la pente est près de ±1 ; l'ajustement s'y
arrête souvent trop tôt, sur une pente d'écart-type presque nul. Nuée ne centre pas sans le
dire : le Résumé signale un ajustement singulier (une corrélation au-delà de ±0,99, ou
l'écart-type d'une pente, fois celui de sa variable sur les observations, sous 1 % de
l'écart-type résiduel) et, quand la variable est loin de 0 (sa moyenne au-delà de son
écart-type), conseille de la centrer, échelle Ctr ou UV dans l'onglet Variables : c'est le même
modèle, que nlme trouve alors le plus souvent, l'ordonnée à l'origine prise à la moyenne de la
variable. Une variable centrée et un ajustement singulier : les données ne permettent pas
d'estimer cette pente ou cette corrélation ; comparez par l'AIC le modèle sans elle. Un échec
de l'ajustement reste « Le modèle n'a pas pu être ajusté ».
Dans un GLM ou un GAM ajusté par mgcv::gam (une autre loi que la normale, ou sans CAR1), une
pente aléatoire est un terme s(site, annee, bs = "re") (Wood, 2017) : indépendante de
l'ordonnée à l'origine aléatoire, sans corrélation, mgcv ne sachant pas les corréler. Ce modèle
dépend de l'endroit où x vaut 0 : x centré, l'ordonnée à l'origine aléatoire est le niveau de
chaque site à la moyenne de x ; l'année non centrée ne laisse guère de place à la variance de
la pente. Le Résumé le dit. Refait avec CAR1 (mgcv::gamm), un tel modèle a ses pentes
corrélées, comme nlme.
Avec des pentes aléatoires : la validation croisée prédit un site jamais vu par les effets
fixes ; la sélection par AIC ne choisit que les effets fixes, et le groupe d'une variable qui a
une pente aléatoire reste dans chaque modèle (une pente aléatoire suit la pente fixe de sa
variable) ; dans Apport des blocs, sans cette variable, sa pente fixe seule est retirée et sa
pente aléatoire reste (le test de la pente moyenne, avec les mêmes effets aléatoires) ; deux
modèles aux pentes aléatoires différentes n'ont pas les mêmes effets aléatoires : pas de test
du rapport de vraisemblance entre eux, ils se comparent par l'AIC sur les mêmes observations ;
Ajuster avec CAR1 garde les pentes ; les prédictions sont celles des effets fixes. Non
couvert : dans nlme, une pente non corrélée à l'ordonnée à l'origine ((0 + annee | site),
(1 | site) + (0 + annee | site), ||), refusée dans la formule R ; la pente aléatoire d'une
variable qualitative, d'un terme croisé ou d'une courbe.
Type « Modèle linéaire généralisé (GLM) » ou « Modèle additif (GAM) » (mgcv), pour une
variable Y qui ne suit pas une loi normale. Loi de Y : Poisson pour des comptages ; binomiale
négative pour des comptages qui varient plus qu'une loi de Poisson ne le permet (son θ
estimé) ; binomiale pour la présence-absence (0 ou 1) ; gamma pour des valeurs positives ;
Tweedie pour des densités avec des zéros (sa puissance p estimée) ; ou normale. Le lien est
log (comptages, gamma, Tweedie), logit (binomiale) ou l'identité (normale). Effort
(décalage) : une variable comme une surface, une durée ou un nombre de passages, dont le log
entre dans le modèle avec un coefficient 1 : il décrit alors une densité (un effort nul ou
négatif est refusé). Des effets aléatoires comme ci-dessus en font un GLMM ou un GAMM. Avec la
loi normale et au moins un effet aléatoire, un GLM ou un GAM peut prendre aussi
l'autocorrélation dans le temps : il est alors ajusté par mgcv::gamm, comme un modèle mixte de
nlme dont les courbes sont des effets aléatoires (coefficients, courbes, variances et φ en
REML ; log-vraisemblance, AIC, AICc et BIC d'un ajustement en ML, comparables seulement à ceux
d'autres modèles ajustés ainsi). Avec une autre loi, elle est refusée : mgcv::gamm passerait
par une quasi-vraisemblance pénalisée (PQL), sans vraie vraisemblance ni AIC. Dans un modèle
additif, les variables X cochées dans la colonne Courbe de l'onglet Variables entrent par une
courbe lissée (une spline) plutôt que par une droite, pour un effet qui monte puis descend, ou
un seuil ; les données décident de sa courbure (son edf ; 1 est une droite). Sa dimension de
base k borne sa courbure : 10 au plus, moins quand la variable a peu de valeurs ; tapez-en une
autre (de 3 à 100) dans la case à côté de la coche, comme s(x, k = 5) dans R. Une courbe par
catégorie : la liste à côté de k offre les variables qualitatives X du modèle (« une par
secteur »), comme s(annee, by = secteur) dans mgcv : chaque secteur a sa courbe, de dimension k
chacune, avec son edf, son test, sa concurvité, son effet et ses seuils. Chacune est centrée sur
les observations de sa catégorie (la contrainte d'identifiabilité de mgcv) : la variable
qualitative doit rester en X, son effet principal donnant l'écart de niveau entre les
catégories ; sans lui, toutes les catégories auraient la même moyenne, et Nuée refuse alors le
modèle plutôt que d'ajouter ce terme sans le dire. Le facteur que mgcv voit vient des colonnes
0/1 des catégories du modèle (ses niveaux, les catégories observées, dans leur ordre) ; une
catégorie ajoutée aux données après la définition du modèle n'y a pas de colonne, donc pas de
courbe : ses lignes restent hors du modèle avec les observations incomplètes, et dans un jeu de
test, sans prédiction. Une variable en courbe par catégorie n'est pas aussi dans un terme
croisé avec une variable qualitative (chaque catégorie a déjà sa courbe). Les courbes et les
effets aléatoires sont estimés en REML, et l'AIC vient d'un ajustement en ML ; un GLM sans eux
est ajusté par maximum de vraisemblance, comme le font glm() et MASS::glm.nb(). Le résumé d'un
modèle de Poisson prévient quand les comptages sont surdispersés (le khi² de Pearson au-delà
de 1,5 fois ses degrés de liberté) : ses valeurs p sont alors trop petites, et la binomiale
négative convient mieux à ces comptages.
Formule R (onglet Général) : le modèle écrit comme dans R, par exemple
  y ~ a * b + log10(c) + I(a^2) + s(d) + offset(log(effort)) + (1 | site/secteur).
Modifiez-la puis Appliquer (Ctrl+Entrée) : elle règle les variables et leurs transformations
(log, log10, log1p, exp, sqrt, I(x^p), I(a * x + b), le logit log((x - a) / (b - x))), les
termes croisés (a:b ; a*b pour a, b et a:b ; a:b sans a : a entre sans effet principal ;
I(a^2) quand a est aussi dans le modèle, sinon le
carré de a), les courbes s(x), s(x, k = 5) et s(x, by = f) (une par catégorie de f, qui doit
être aussi un terme ; s(x, by = f, k = 5)), l'effort offset(log(x)) et les ordonnées à
l'origine aléatoires emboîtées (1 | site/secteur), du plus large au plus fin, avec leurs pentes
aléatoires comme lme4 les écrit : (1 + annee | site) ou (annee | site) ;
(1 + annee | site/secteur), une pente à chaque niveau ; un terme par niveau,
(1 + annee | site) + (1 | site:secteur). Une courbe rend le modèle additif, des
effets aléatoires le rendent mixte. R lit la formule sans jamais l'exécuter : tout le reste
(une autre fonction, du code) est refusé en disant pourquoi, et la formule n'est pas gardée,
seulement les réglages qu'elle donne.

Résidus d'un GLM ou d'un GAM à loi de Poisson, binomiale négative, binomiale ou gamma : à côté

et Smyth (1996), r = Φ⁻¹(u), F la loi du modèle à la valeur ajustée de chaque observation (ses

Graphiques › Autocorrélation des résidus : l'autocorrélation des résidus d'une régression dans

nlme::ACF : au décalage k, les observations à k pas l'une de l'autre dans l'ordre du temps de

résidus normalisés, qui n'en montrent plus quand CAR1 suffit (la note lit le décalage 1). Pour
un autre modèle, choisir le temps (un identifiant ou une variable, de nombres ou de dates :
l'année) et les groupes : par défaut ceux de ses effets aléatoires (le secteur dans son site),
sinon un identifiant ou une variable qualitative ; les uns comme les autres peuvent prendre un
niveau plus fin dedans (le secteur dans le site d'un effet aléatoire, ou un secteur dont les
noms se répètent d'un site à l'autre). Au-delà de la bande au décalage 1, la note propose une

((y − ajusté) / √variance) ou de déviance (la part signée de chaque observation dans la
déviance), les mêmes pour la loi normale ; les résidus d'un modèle mixte sont ceux de
l'intérieur de ses groupes (sachant les effets aléatoires), comme dans nlme::ACF. Nuée calcule
les résidus normalisés dans l'ordre du temps de chaque groupe : ceux de nlme ne sont justes que
sur des lignes rangées par groupe, puis par temps.
Dans les groupes de ses effets aléatoires, avec ou sans niveau plus fin, Ajuster avec CAR1 en

autocorrélation). La note dit quand ils ne se comparent pas : des observations sans temps ou
sans groupe restent hors du nouveau modèle, et la vraisemblance de mgcv::gamm ne se compare pas
à celle de mgcv::gam. Fichier › Rapport du modèle peut reprendre le graphique.
Graphiques › Sélection par AIC (aussi sous chaque régression, dans l'explorateur) : quelles

l'autocorrélation, l'effort et le réglage des courbes restent ceux du modèle, et le groupe

Graphiques › Puissance pour une tendance (aussi sous chaque régression linéaire ou modèle
linéaire mixte, dans l'explorateur) : avec tant de sites comptés chaque année, en combien
d'années une tendance est-elle détectée ? Choisissez le temps (un X quantitatif, non transformé :
l'année), la tendance à détecter (un changement par an dans les unités du Y du modèle ; avec une
réponse en log10 ou en ln, aussi en % par an, converti en la pente log(1 + %/100) sur cette
échelle, une approximation avec log10(x + 1), juste seulement là où x est grand devant 1), α (un
test bilatéral), les nombres d'années (de, à) et les nombres d'unités du premier effet aléatoire
(les sites ; celui des données y est toujours). Chaque unité est comptée une fois par an, ses
niveaux emboîtés comme dans les données, leurs nombres moyens arrondis (2,75 secteurs par site :
3) ; une régression linéaire compte des observations par an. Les variances sont les estimations
REML du modèle (effets aléatoires, variance résiduelle, φ de CAR1), et ses autres termes restent
hors des plans (leurs effets tenus pour constants). Pour chaque plan, la variance de
l'estimateur des moindres carrés généralisés de la pente, ces variances connues, (X'V⁻¹X)⁻¹ avec

z) : la puissance selon le nombre d'années, une ligne par nombre d'unités, la ligne des 80 %, une
phrase prête pour un rapport (« Avec 12 unités de « site », chacune comptée chaque année, une
baisse de 3 % par an de « densite » est détectée avec une puissance de 80 % après 11 ans »), et
le tableau. Chaque unité étant comptée chaque année, les ordonnées à l'origine aléatoires ne
changent rien à la variance de la pente : la variance résiduelle, φ, les années et le nombre de
séries comptées la font. Une simulation vérifie la formule à un plan (par défaut celui des
données) : N jeux de données (200 par défaut) tirés du modèle avec la tendance, chacun réajusté
par nlme avec la même structure (REML), la puissance étant la part des pentes de p ≤ α (Johnson
et al., 2015), avec son erreur de Monte-Carlo. Sa graine est fixe (les mêmes jeux à chaque fois ;
le hasard de la session reste tel qu'il était), et la vue dit d'abord combien de temps elle
prendra : le moteur R ajuste un modèle à la fois et ne fait rien d'autre en attendant (une
simulation qui prendrait plus d'un quart d'heure, ou de plus de 20 000 observations par jeu, est
refusée). Les deux peuvent différer : la simulation estime les variances et φ dans chaque jeu
(avec peu d'unités ou d'années, elles sont incertaines) et teste la pente par le t de nlme, quand
la formule les tient pour connues et prend la loi normale. Pas couverts, et refusés avec la
raison : les GLM et les GAM, des pentes aléatoires, un modèle sans X quantitatif qui puisse être
le temps, une autocorrélation CAR1 le long d'un temps d'autres unités que celui de la tendance.
Une fois calculée, le texte des méthodes la décrit, le rapport du modèle peut la contenir et
Exporter vers R la refait (la simulation avec les mêmes tirages).
Graphiques › Moyennes ajustées (aussi sous chaque régression qui a une variable qualitative,

les catégories de la première comparées dans chaque catégorie de l'autre, l'ajustement dans
chacune. « Pour chaque catégorie › la pente de x », pour une variable quantitative croisée avec
elle (annee × secteur) : la pente de x dans chaque catégorie (par unité du terme, transformé
s'il l'est), la dérivée des prédictions comme emtrends la prend (une différence avant d'un
millième de l'étendue de x), et les paires de pentes ; pour une droite, les pentes de la vue
Effets. Les degrés de liberté sont ceux qu'emmeans prend par défaut : les degrés de liberté
résiduels pour une régression linéaire, et pour un GLM ou un GAM dont l'échelle est estimée
(loi normale, gamma, Tweedie) ; la règle de confinement de nlme pour un modèle mixte (le plus
petit de ceux des coefficients qu'une moyenne ou une paire fait intervenir dans le codage par
défaut de R, la première catégorie en référence, comme emmeans sur l'ajustement de R ;
l'ordonnée à l'origine comptant pour le nombre de groupes du premier effet aléatoire moins un :
en général, la moyenne d'un secteur a le nombre de sites moins un, une paire de secteurs dans
les sites les degrés de liberté intérieurs ; pour un habitat qui ne change que d'un site à
l'autre, la moyenne du premier habitat a le nombre de sites moins un, les autres et les paires
ceux de l'habitat, les sites moins un moins ses coefficients) ; z (asymptotique) pour une loi
de Poisson, binomiale ou binomiale négative, comme emmeans pour glm() et comme les Coefficients
du modèle (sur un objet mgcv::gam, emmeans prend les degrés de liberté résiduels quelle que
soit la loi). Avec un lien log ou logit, les moyennes sont sur l'échelle de la réponse (exp ;
logit inverse : des probabilités), leurs intervalles transformés depuis l'échelle du lien, et
les paires sont des rapports de moyennes ou des rapports des cotes, testés sur l'échelle du
lien, comme type = "response" dans emmeans ; l'échelle du lien au choix. Une variable Y
transformée (log10, ln…) reste sur son échelle, et la vue le dit : ramenée sur l'échelle de la
variable, une moyenne de logarithmes est une médiane (une moyenne géométrique), non une
moyenne. Une combinaison de catégories qu'aucune observation n'a n'est pas estimable (emmeans :
nonEst) : sa moyenne et ses paires sont laissées de côté, et nommées. Un clic sur une paire du
tableau donne sa phrase pour un rapport (bouton copier) ; Ctrl+C copie les deux tableaux. Une
fois calculées, le texte des méthodes les décrit (Searle et al. 1980, emmeans de Lenth, Tukey
1953 et Kramer 1956, ou Holm 1979), le rapport du modèle peut les inclure, et Exporter vers R
les refait en R de base (la grille, les lignes L du modèle, la covariance et les degrés de
liberté : les mêmes nombres). Non couvert : d'autres poids qu'égaux (weights = "proportional"…
d'emmeans), d'autres contrastes que les paires (contre un témoin), une variable quantitative à
une autre valeur que sa moyenne.
Prédiction › Prédire les observations, Prédire un fichier : Y prédit par les effets fixes (pour
un modèle mixte, un groupe jamais vu), sur l'échelle de Y du modèle (sa transformation
comprise), à côté de Y observé quand il est connu. Les colonnes d'un fichier sont reconnues par
le nom des variables du modèle, l'effort compris (sans lui, les prédictions sont pour un effort
de 1, et la note le dit). ⚠ signale une valeur hors de l'étendue des observations du modèle :
une extrapolation.
Prédiction › Comparer les modèles : Q2 et RMSEcv pour tous les modèles ; AIC, ΔAIC et poids
d'Akaike (la probabilité que chaque modèle soit le meilleur de son ensemble) entre les seules
régressions de la même réponse sur les mêmes observations (un « ensemble AIC », lettré A,
B...), et seulement celles dont les vraisemblances se comparent : des modèles de Poisson et
binomiaux négatifs des mêmes comptages, mais pas un modèle normal de ces comptages ; des
modèles de Tweedie entre eux ; des GLMM et des GAMM (la vraisemblance conditionnelle de mgcv)
entre eux.
Sous le tableau des AIC, Modèles emboîtés : le test du rapport de vraisemblance entre chaque
paire de régressions emboîtées d'un même ensemble AIC, comme anova(m1, m2) sur des ajustements
en ML. Les termes fixes du petit modèle sont parmi ceux du grand (ses colonnes dans celles du
grand), avec la même loi, le même effort, les mêmes effets aléatoires (leurs pentes comprises)
et la même autocorrélation ; χ² = 2 × (logLik du grand − logLik du petit) sur Δddl, la
différence de leurs nombres de paramètres, et son p. Pour des régressions linéaires et des GLM,
c'est l'écart
de leurs logLik (de leurs déviances pour un GLM de Poisson ou binomial, comme anova(glm1,
glm2, test = "Chisq")). Les effets aléatoires et l'autocorrélation ne se testent pas ainsi :
une variance nulle est au bord de son domaine, où la loi du χ² ne tient plus ; comparez-les
par l'AIC. Avec des courbes ou des effets aléatoires de mgcv, les ddl sont des edf et le test
est approché, comme le dit le tableau. Toutes les paires emboîtées sont listées (2000 au
plus) ; la recherche du tableau trouve celles d'un modèle.
Prédiction › Comparer les modèles › Coefficients côte à côte (le choix en haut de la vue) :
plusieurs régressions comme les articles les présentent, une ligne par terme et une colonne par
modèle. Cochez les régressions du projet à montrer (toutes d'abord). Chaque case est
l'estimation avec son intervalle à 95 %, ou avec son erreur-type, du tableau de la vue
Coefficients du modèle (ses décimales celles de deux chiffres significatifs de l'erreur-type), en
rouge quand p ≤ 0,05, vide quand le modèle n'a pas le terme. Les lignes sont la constante et les
termes du premier modèle, puis ceux des autres dans leur ordre : deux modèles partagent une ligne
quand ils ont un terme du même nom. Dessous : n, AIC et AICc (ajustement en ML), R² (une
régression linéaire), R² marginal et conditionnel (un modèle mixte) ou part de la déviance
expliquée (un GLM ou un GAM), l'écart-type σ de chaque effet aléatoire (et le résiduel d'un
modèle de nlme), φ de CAR1 et l'edf de chaque courbe. Un modèle de lien log ou logit garde ses
estimations sur l'échelle du lien, comme dans sa vue Coefficients, et la note le dit. Ctrl+C (ou
le bouton de copie) met le tableau dans le presse-papiers en texte et en tableau, qu'Excel et
Word collent en tableau, avec des étoiles pour p (* ≤ 0,05, ** ≤ 0,01, *** ≤ 0,001) et leur
légende ; Fichier › Exporter les résultats du modèle (Ctrl+E), depuis cette vue, l'écrit, avec à
côté les coefficients de chaque modèle en nombres.
Fichier › Exporter : les observations (observées, ajustées, prédites en validation croisée,
résidus), les coefficients, la qualité de l'ajustement, les effets aléatoires (chaque
ordonnée à l'origine et pente aléatoire, et leur corrélation) et les courbes, un tableau
chacun. Fichier › Rapport du modèle : le résumé et les coefficients, l'effet de
chaque terme, les seuils de chaque courbe, observé / prédit et les résidus (aussi les résidus
quantiles, pour des comptages, une présence-absence ou des valeurs positives).
Fichier › Exporter vers R : un script ou un rapport pour une régression aussi, avec lm,
nlme::lme, mgcv::gam ou mgcv::gamm : ses lignes et ses termes, les ajustements (REML et ML ;
ses pentes aléatoires comprises), la validation croisée par ses groupes, puis les coefficients,
l'AIC, le R2, les variances, les courbes avec leur concurvité et leurs seuils (les mêmes
tirages que la vue Seuils), les résidus quantiles (les mêmes tirages que la vue Résidus), le
jeu de test et les graphiques, vérifiés contre les résultats de Nuée avant d'être écrits.
Termes croisés avec une variable qualitative (onglet Termes croisés, ou a * b et a:b dans la
formule R) : une variable qualitative entre dans un terme croisé par chacune de ses catégories,
une fois au plus (ni au carré ni au cube). année × secteur laisse la pente de l'année changer
d'un secteur à l'autre : ses coefficients sont, pour chaque secteur sauf celui de référence,
l'écart entre la pente de l'année dans ce secteur et sa pente dans le secteur de référence, qui
est le coefficient de l'année. La catégorie de référence est celle que l'ajustement laisse de
côté (la dernière catégorie observée), la même dans l'effet principal et dans le terme croisé.
Pour une densité suivie par secteur, un coefficient de 0,2 pour annee*secteur(S2), celui de
l'année valant 0,05, se lit : la densité gagne 0,25 par an dans S2, 0,2 de plus que dans le
secteur de référence. Sans l'année en X (un facteur sans rôle dans l'onglet Termes croisés, ou
y ~ secteur + secteur:année), chaque coefficient de année × secteur est la pente de l'année
dans ce secteur ; sans le secteur en X (y ~ année + année:secteur), les pentes diffèrent mais
les secteurs partagent une même ordonnée à l'origine. habitat × traitement : chaque coefficient
est l'écart entre l'effet d'un traitement (par rapport au traitement de référence) dans un
habitat et ce même effet dans l'habitat de référence ; trois variables (année × secteur ×
habitat) donnent des écarts d'écarts. Le coefficient d'une catégorie elle-même (secteur(S2))
est alors son écart à la catégorie de référence là où les termes croisés avec elle valent 0 :
là où l'année vaut 0 (avec les années dans leurs unités, l'an 0, loin des données ; l'année
moyenne quand l'année est centrée, Ctr ou UV), dans l'habitat de référence pour habitat ×
traitement. Les colonnes sont rangées comme R range ses termes, les effets principaux
d'abord : les résultats sont ceux de lm(), nlme::lme() et mgcv avec des facteurs dont le
premier niveau est la référence de Nuée. Une combinaison de catégories qu'aucune observation
n'a (un traitement jamais donné dans un habitat) ne peut pas être estimée : elle est laissée
de côté, et le Résumé la nomme parmi les termes jamais observés. Effets : un terme
quantitatif croisé avec des catégories a une droite par catégorie (une courbe quand le terme
est une courbe d'un GAM), de pente son coefficient plus celui de son produit avec la
catégorie, avec sa bande à 95 % tirée de la covariance des coefficients et, sous le graphique,
chaque pente par unité avec son intervalle. Pour une courbe, les Seuils sont ceux de la
catégorie choisie : la courbe commune plus la pente de cette catégorie ; une courbe par
catégorie (s(x, by = f), plus haut) donne à chaque catégorie sa propre forme, et non la même
courbe inclinée. Dans la sélection par AIC et la table des apports, un terme croisé entre et
sort en entier (toutes ses catégories), seulement avec ses effets principaux et ses termes
croisés d'ordre plus bas. Le texte des Méthodes nomme chaque catégorie de référence et dit ce
que valent le coefficient d'une catégorie et ceux des termes croisés. Prédiction : une
catégorie que le modèle a vue a sa propre prédiction ; une catégorie, ou une combinaison de
catégories, qu'il n'a pas vue (absente de ses observations, des autres groupes en validation
croisée, ou inconnue du projet dans un fichier) n'en a pas : le modèle la prédirait comme la
catégorie de référence, ou sans sa pente, et R refuse de même un niveau qu'il n'a pas vu.
C'est la règle de chaque variable qualitative d'une régression (effets principaux, termes
croisés, courbes par catégorie ; LM, LMM, GLM, GAM, mgcv::gamm), pas des autres modèles
(PLS...). Ces observations sont comptées et nommées : en validation croisée, le Résumé dit
combien sont restées sans prédiction et de quelle variable, Q2 et RMSEcv étant calculés sur
les autres ; quand il n'en reste aucune (des secteurs propres à chaque site, validés par
site), Q2 manque, et le Résumé dit que le modèle ne peut pas être validé par ces groupes avec
cette variable en X fixe : faites-en un effet aléatoire, ou choisissez d'autres groupes de
validation croisée. Le jeu de test les compte à part de son RMSEP, de son biais et de son Q2
externe ; Prédiction › Prédire les marque ⊘ (colonne Catégorie non vue, dans le tableau
exporté aussi). Le texte des Méthodes et le script d'Exporter vers R font de même.

Modèles de classe et graphique de Coomans
-----------------------------------------
Nouveau modèle › type « Modèles de classe » : une ACP par catégorie de la variable de classe,
sur les seules observations de cette catégorie (« M5.Gala », « M5.Golden »...), chacune avec
ses centres, ses échelles et son nombre de composantes. Une observation appartient à une
classe quand sa distance au modèle de la classe (DModX) ne dépasse pas la limite DCrit à 5 % :
à une classe, à plusieurs, ou à aucune (une observation d'un autre type que toutes les
classes connues). Graphiques › Graphique de Coomans : les distances de chaque observation à
deux des modèles, avec leurs limites en rouge ; la table donne, pour chaque classe, la part de
ses observations que chaque modèle accepte (attendu : vers 95 % pour sa propre classe, 0 %
pour les autres), puis les distances et les classes de chaque observation.

Analyse de redondance et analyse des correspondances
----------------------------------------------------
Nouveau modèle › type « RDA (analyse de redondance) » : ce que des variables explicatives X
expliquent d'un tableau de réponses Y (abondances d'espèces, mesures), et comment. Y : des
variables quantitatives ; X : les variables explicatives (une variable qualitative par ses
catégories, termes croisés compris) ; Z (covariable, dans la liste Rôle de l'onglet
Variables) : des variables dont l'effet est retiré d'abord (RDA partielle : le site, un
gradient connu...). Onglet Général : la transformation des réponses (Hellinger ou corde pour
des abondances, Legendre et Gallagher 2001 ; log(x + 1) ; ou aucune) ; les réponses centrées
(RDA sur les covariances, pour des réponses dans les mêmes unités) ou centrées-réduites (sur
les corrélations) ; le nombre de permutations des tests (999 ; 0 : aucun test), les groupes à
l'intérieur desquels elles restent (un identifiant ou une variable qualitative : un site suivi
plusieurs années n'est permuté qu'avec lui-même) et leur graine (la même graine donne les mêmes
permutations, donc les mêmes valeurs p). Une observation où une valeur manque, ou sans aucune
abondance avec Hellinger ou corde, est laissée de côté.

Vues : Résumé (l'inertie totale, la part des covariables, celle des X et ce qui reste ; R2 et
R2 ajusté ; le pseudo-F et sa valeur p par permutation) ; Ordination, le triplot (les
observations par leurs scores wa, sommes pondérées des réponses, ou lc, combinaisons linéaires
des X ; les réponses ; une flèche par X quantitative, allongée pour remplir le graphique du
facteur indiqué dans la légende, et un triangle au centroïde de chaque catégorie ; l'échelle 1
garde les distances entre observations, l'échelle 2 les corrélations entre réponses) ; Valeurs
propres (les axes contraints en bleu, les non contraints en gris) ; Tests par permutation
(chaque axe contraint après les précédents, chaque terme après tous les autres ; Sélection pas
à pas garde un terme qui augmente le R2 ajusté sans dépasser celui de tous les termes et dont
le test donne p ≤ 0,05, Blanchet et al. 2008 ; Partition de la variance partage le R2 ajusté
entre deux ou trois blocs de X, d'après la colonne Bloc de l'onglet Variables) ; les listes des
observations et des variables. Les résultats sont ceux du paquet vegan (rda, anova.cca,
RsquareAdj, ordiR2step, varpart) : mêmes valeurs propres, scores et pseudo-F, et pour les mêmes
permutations, mêmes valeurs p.

Type « Analyse des correspondances (CA) » : un tableau d'effectifs ou d'abondances (les
variables X, une observation par ligne, des valeurs positives ou nulles) ; les observations et
les variables sans aucune valeur sont laissées de côté. Vues : Résumé (l'inertie totale : le
khi² du tableau divisé par son effectif total) ; Ordination (lignes et colonnes en échelle 1, 2
ou 3 : distances du khi² entre observations, entre variables, ou symétrique) ; Valeurs
propres ; Contributions et cos² (la part de chaque ligne et de chaque colonne dans l'inertie
d'un axe, en bleu au-dessus de la moyenne, et la qualité de sa représentation) ; les listes.

L'une et l'autre exportent leurs tableaux (Fichier › Exporter), écrivent leur texte des
méthodes avec ses références et font un rapport. Fichier › Exporter vers R écrit un script, ou
un rapport R Markdown ou Quarto, qui les refait avec R seul, leurs tests avec les mêmes
permutations. Elles ne prédisent pas de nouvelles observations.

Arbres de décision, analyse discriminante linéaire et k-moyennes
----------------------------------------------------------------
Nouveau modèle › type « Arbre de décision » (rpart) : une variable Y quantitative (arbre de
régression) ou une variable de classe (arbre de classement), et des X par leurs valeurs
brutes, pour que les seuils se lisent dans leurs unités ; les valeurs manquantes des X sont
prises en charge par des variables de substitution. Onglet Général : au moins 20
observations par feuille, mais au plus le sixième des observations, pour que l'arbre puisse
se couper (un nœud n'est coupé que s'il en compte trois fois plus), au plus 5 niveaux,
cp = 0,001, 5 substitutions,
élagage par la règle 1-ET (le plus petit arbre à une erreur-type de l'erreur minimale) ou à
l'erreur minimale. L'élagage vient d'une validation croisée interne par les groupes de
validation croisée (pour des sites suivis plusieurs années, choisir le site), et le Q2 d'une
validation croisée externe : chaque groupe est prédit par un arbre refait entièrement sans
lui. Vues : Arbre (un clic sur un nœud choisit ses observations), Élagage, Règles des
feuilles, Importance des variables, Stabilité de la première coupure (200 tirages
bootstrap des groupes : la part des tirages où chaque variable fait la première coupure,
et son seuil médian), Observé / prédit et Résidus, ou Classement pour un arbre de
classement. Jeu de test et Prédire : une nouvelle observation suit l'arbre, substitutions
comprises.

Type « Analyse discriminante linéaire (LDA) » (MASS::lda) : une variable de classe et des X
par leurs valeurs brutes ; probabilités a priori proportionnelles aux effectifs ou égales.
Chaque observation va dans la classe de plus grande probabilité a posteriori ; en
validation croisée, chaque groupe est classé par le modèle ajusté sans lui. Vues : Scores
discriminants, Coefficients discriminants (corrélations de structure, coefficients dans
les unités des variables ou pour des variables d'écart-type 1), Classement, Probabilités a
posteriori. Jeu de test et Prédire.

Type « k-moyennes » : des X mis à l'échelle comme le dit l'onglet Variables (UV par
défaut), k groupes (algorithme de Hartigan et Wong, 25 départs, graine 1), numérotés du
plus grand au plus petit ; une observation où une valeur manque est laissée de côté.
Vues : Groupes (sur les deux premières composantes principales), Silhouettes, Choix de k
(de 2 à 10 : somme des carrés intra-groupes et silhouette moyenne), Centres des groupes.
« Groupes → variable » ajoute les groupes au projet comme une variable qualitative
(Édition › Annuler la retire) ; Prédire range une nouvelle observation dans le groupe du
centre le plus proche.

Pour les trois : texte des méthodes avec ses références, Exporter, rapport PDF ou Word,
Exporter vers R (un script ou un rapport R Markdown / Quarto qui refait l'analyse avec
rpart, MASS ou cluster, livrés avec R). Comparer les modèles donne le Q2 et le RMSEcv d'un
arbre de régression à côté des autres modèles.

Ajouter des colonnes d'un autre tableau
---------------------------------------
Édition › Ajouter des colonnes d'un tableau (ou clic droit sur les données du projet dans
l'explorateur) : les colonnes d'un autre tableau ajoutées aux observations par une clé, comme on
le ferait dans un tableur : l'habitat et l'altitude de chaque site d'un tableau des sites, la
météo de chaque année, ou de chaque site et de chaque année. Le tableau : un fichier dans tout
format que lit Fichier › Ouvrir (avec sa feuille ou son tableau pour un classeur ou un fichier
R ; un projet Nuée donne ses données), ou des cellules copiées dans un tableur (Coller des
cellules).
La clé : une ou plusieurs colonnes du projet (des variables, des identifiants ou le nom des
observations), chacune à côté de la colonne du tableau qui lui répond. L'application propose
des colonnes de même nom (sans tenir compte des majuscules ni des espaces autour, comme Prédire
un fichier) : celles avec lesquelles chaque clé ne vient qu'une fois dans le tableau et le plus
d'observations trouvent la leur, parmi les premières colonnes du tableau, le moins possible : le
site pour un tableau des sites, le site et l'année pour la météo par site et par année ; les
changer au besoin. Chaque clé ne doit venir qu'une fois dans le tableau : une clé qui revient
est refusée, en la nommant, plutôt que de prendre l'une de ses lignes au hasard.
Les clés se comparent en nombres quand la colonne du projet est une variable quantitative :
2019 et 2019,0 sont la même année (les valeurs du tableau lues en nombres comme les lit
Fichier › Ouvrir). Sinon, elles se comparent en texte, tel qu'écrit dans le tableau et dans le
projet, sans les espaces autour, les majuscules comptant : « S1 » n'est pas « s1 », ni « 01 »
« 1 » (une colonne de clé faite de « 01 », « 02 » n'est pas lue ici en nombres) ; un nombre du
tableau s'écrit alors comme R l'écrit (2019). Une clé dont une partie manque ne répond à rien.
Les colonnes à ajouter : toutes celles du tableau sauf la clé, cochées par défaut. Une colonne
de nombres donne une variable quantitative ; du texte, un facteur R ou une variable étiquetée
de SPSS ou Stata, une variable qualitative (les catégories d'un facteur dans leur ordre, sinon
les textes triés), comme à l'ouverture d'un tableau. Un nom déjà pris dans le projet, par une
variable ou un identifiant, devient « nom (2) », « nom (3) »... : rien n'est écrasé.
Chaque observation prend les valeurs de la ligne du tableau qui a sa clé, et les observations
gardent leur ordre : comme k <- match(clé du projet, clé du tableau), puis tableau[k, colonnes]
(merge() rangerait les lignes autrement). Une observation sans ligne qui lui réponde a des
valeurs manquantes. Le résultat dit ce qui a été ajouté et compte les observations sans
correspondance et les clés du tableau qui ne répondent à aucune observation, en nommant les
cinq premières de chacune ; les lignes du tableau sans clé sont comptées aussi. Si aucune
observation ne trouve sa clé, rien n'est ajouté, et le message montre des clés de chaque côté.
Édition › Annuler (Ctrl+Z) retire les colonnes ajoutées ; les modèles déjà ajustés ne changent
pas. Les « Actions de l'application » de la console R montrent l'appel, et le même calcul écrit
avec match() sur le tableau des données du projet.

Résumer par groupe
------------------
Édition › Résumer par groupe (ou clic droit sur les données du projet) : un nouveau projet d'une
ligne par groupe, à côté du projet, qui ne change pas : la densité moyenne de chaque secteur et
de chaque année d'après plusieurs placettes, avant BACI ou les séries. Les groupes : une ou
plusieurs variables ou identifiants (le secteur et l'année ; le site, le secteur et l'année).
Chaque groupe devient une observation nommée par ses valeurs (« S1 2019 ») ; les groupes
viennent dans l'ordre de ces colonnes (les catégories d'une variable qualitative dans leur
ordre, les nombres dans le leur), et ces colonnes restent des variables ou des identifiants,
comme dans le projet. Une observation sans valeur dans l'une d'elles est laissée de côté, et
comptée.
Les variables quantitatives à résumer (toutes sauf celles des groupes, cochées par défaut) et
les statistiques, une ou plusieurs, pour chacune d'elles : moyenne (par défaut), somme,
médiane, minimum, maximum, écart-type (n − 1, comme le calcule sd()), nombre de valeurs (n), en
colonnes « densite (moyenne) », « densite (n) »... (nommées dans la langue de l'interface). Les
valeurs manquantes sont ignorées et n compte les valeurs connues ; un groupe sans valeur connue
a des statistiques manquantes, et n = 0. Comme aggregate(d[variables], d[groupes], FUN) sur le
tableau des données du projet : les « Actions de l'application » de la console R le montrent
avec l'appel.
Une variable qualitative ou un identifiant dont les valeurs connues sont les mêmes dans chaque
groupe (l'habitat d'un secteur, le site d'un secteur) est gardé, avec cette valeur ; les autres
sont laissés de côté, et la barre d'état les nomme. Le nouveau projet n'a pas encore de
fichier : l'enregistrer (Ctrl+S).

Modifier les données, créer des variables
-----------------------------------------
Dans la vue Données, double-cliquer une case pour la modifier (Entrée pour garder, Échap pour
annuler ; vide = valeur manquante ; pour une variable qualitative, le nom de la catégorie).
Les modèles déjà ajustés ne changent pas : les réajuster.
Édition › Nouvelle variable : par une formule R sur les autres variables et les identifiants
des observations, par exemple log10(polyphenols), sucre / acidite, ifelse(poids >= 170,
"gros", "petit") (un résultat en texte donne une variable qualitative) ; par groupe,
moyenne_groupe(x, secteur), la moyenne de x dans le groupe de chaque observation (valeurs
manquantes ignorées ; une observation sans groupe n'en a pas), et ecart_groupe(x, secteur),
l'écart à cette moyenne : la moyenne d'un secteur comme covariable, ou une réponse centrée par
secteur. Ou des classes d'après les valeurs d'une variable, à des bornes données (10 ; 20
donne « ≤ 10 », « ]10 ; 20] », « > 20 ») ou en classes d'effectifs égaux. Ou Imputation
(ACP) : les valeurs manquantes des variables quantitatives choisies remplies les unes par les
autres par ACP itérative régularisée, comme le fait missMDA::imputePCA, avec le nombre de
composantes choisi par validation croisée généralisée des variables réduites, de 0 à 5, comme
le fait missMDA::estim_ncpPCA sur elles (0 : la moyenne de chaque variable), sauf si vous le
donnez ; les valeurs observées inchangées, une observation à qui manquent plus de la moitié
d'entre elles laissée manquante, les valeurs imputées gardées dans l'étendue observée de chaque
variable sauf si on décoche ; en nouvelles variables « x (imputée) » ou dans les variables
elles-mêmes (Ctrl+Z annule). Penser à enregistrer le projet.
Dans une formule de Nouvelle variable, d'une année à l'autre : precedent(x, annee, secteur), la
valeur de x l'année d'avant dans le même secteur, et suivant(x, annee, secteur), celle de
l'année d'après (pas = 2 : deux ans avant ou après). L'année cherchée doit exister : une année
manquante donne une valeur manquante, jamais celle d'une année plus ancienne, comme une
observation sans secteur ou sans année. Le temps est fait de nombres (un identifiant fait de
nombres, comme l'année, convient) ; des dates aussi, mais ces fonctions vont avec des temps
réguliers (voir Le temps en dates) ; le groupe, une variable qualitative, un identifiant ou
interaction(site, secteur) pour un secteur dans un site ; un même secteur deux fois la même
année est refusé, en le nommant. croissance(x, annee, secteur) donne le taux de croissance
log(x / x de l'année d'avant), manquant sauf si les deux valeurs sont positives : pour la
dépendance à la densité, la croissance contre precedent(densite, annee, secteur). En anglais :
previous, following et growth_rate.
Dans une formule de Nouvelle variable, la diversité de chaque relevé, sur plusieurs colonnes
d'espèces de sa ligne (comptages, densités, recouvrements : des nombres ≥ 0), comme la calculent
vegan::specnumber et vegan::diversity : richesse(...), S, le nombre de colonnes > 0 ;
shannon(...), H′ = −Σ p ln p (logarithme népérien, p la part de chaque espèce dans le total de
la ligne) ; simpson(...), 1 − Σ p² (l'indice de Gini–Simpson, le « simpson » de vegan) ;
pielou(...), l'équitabilité de Pielou J = H′ / ln S, manquante quand S ≤ 1. Les colonnes sont
nommées (shannon(Ablette, Brochet, Gardon)), ou une plage dans l'ordre des colonnes du tableau,
de l'une à l'autre, les deux comprises (shannon(Ablette:Vandoise), comme dplyr la lit), ou les
deux ; une colonne nommée deux fois compte une fois, et toute autre expression compte comme une
colonne de ses valeurs. Un relevé de zéros a S = 0, H′ = 0 et un Simpson de 0 (vegan donne 1 :
1 moins une somme vide), et pas de J ; une valeur manquante dans l'une des colonnes rend
l'indice manquant pour ce relevé (une valeur manquante n'est pas lue comme une absence) ; une
valeur négative est refusée, en nommant sa variable. En anglais : richness.

Historique du fichier
---------------------
Pour un projet venant d'un fichier .usp, l'explorateur montre « Historique du fichier » :
le journal enregistré dans le fichier (création, changements de jeu de travail, nombre de
composantes, modèles supprimés...), avec la date, la version du logiciel et l'utilisateur.
Clic droit sur un modèle importé › Historique du modèle : seulement ce qui le concerne.

OPLS et OPLS-DA
---------------
Des composantes prédictives, qui portent ce qui dans X est lié à Y, et des composantes
orthogonales, qui décrivent le reste de la variation de X : scores et loadings se lisent plus
facilement (t[1] contre to[1], S-plot). Une composante prédictive par variable Y, ou une de
moins que de classes pour l'OPLS-DA (t[1], t[2]... puis to[1], to[2]...) ; avec une seule,
les valeurs prédites sont celles d'une PLS au même nombre de composantes. Avec plusieurs Y
(ou plus de deux classes), chaque poids orthogonal est rendu orthogonal aux poids X'y de
toutes les colonnes de Y, si bien que les composantes orthogonales n'ont aucun lien avec Y
(depuis 0.9.0 ; la version 0.8.0 laissait un léger lien : les modèles OPLS à plusieurs
composantes prédictives qu'elle a faits changent un peu quand on les réajuste). Q2 par
validation croisée, comme pour les autres modèles (voir plus bas). Aucun des
projets .usp disponibles n'avait de modèle OPLS : ce calcul suit l'article de Trygg et Wold
(2002), sans comparaison possible avec des valeurs enregistrées ; il est vérifié contre une
seconde écriture de l'algorithme de l'article.

VIP
---
Le seuil est placé automatiquement à la plus grande marche des VIP triés autour de 0,8. On
peut taper un autre seuil ou faire glisser la ligne rouge, et faire Ctrl+clic sur une barre
pour garder ou écarter une variable (un simple clic la met en évidence sur les autres
graphiques du modèle). « Réajuster avec les variables VIP » refait le modèle avec les
variables retenues.

Validation croisée
------------------
Les observations du modèle sont réparties à tour de rôle en G groupes (7 par défaut : la 1re,
la 8e, la 15e... dans le groupe 1), ou bien un groupe par valeur d'un identifiant ou d'une
variable (Nouveau modèle › Groupes de validation croisée) : avec « site », toutes les années
d'un site sont dans le même groupe, et chaque site est prédit par un modèle qui ne l'a jamais
vu ; les observations sans valeur forment un groupe à part. Les modèles des fichiers .usp
gardent leurs groupes : par identifiant quand le fichier groupe les observations de même
valeur, sinon les groupes du fichier tels quels (« groupes du fichier »).
Trois façons de valider une ACP, une PLS ou une OPLS (Nouveau modèle › Validation croisée) :
- Centres recalculés, poids du modèle complet (par défaut, pour tous les modèles, importés
  compris) : chaque groupe est prédit par un modèle ajusté sans lui, comme de nouvelles
  observations ; ses centres (et le spectre moyen du MSC, les termes croisés) sont recalculés
  sur les autres observations, avec le même nombre de composantes. Le modèle ne sait rien du Y
  du groupe qu'il prédit. Ses poids restent ceux du modèle complet : les écarts-types de X ne
  dépendent pas de Y (une seule variable Y : son poids ne change pas les prédictions), et rien
  n'est remis à l'échelle sur moins d'observations, si bien qu'aucune prédiction n'explose.
- Centres et poids recalculés sans le groupe caché (la validation de 0.9.0 à 0.9.7) : de même,
  mais les poids aussi sont recalculés sur les autres observations. Plus sévère : un terme qui
  varie peu sans le groupe caché y prend un grand poids, et les prédictions du groupe s'en
  écartent. Garde-fou : un terme dont l'écart-type sur les autres observations tombe sous 10 %
  de celui du modèle complet (une variable qui ne varie que sur un site, validée par site)
  garde le poids du modèle complet ; sinon son poids, 1 / écart-type, serait multiplié
  d'autant, et les prédictions du groupe caché exploseraient (des Q2 de -8e11 sur un projet
  réel). Le Résumé dit lesquels, sans quel groupe.
- Centres et poids du modèle complet (comme SIMCA) : le centrage et la mise à l'échelle du
  modèle complet ; chaque composante est validée sur ce que laissent les précédentes du modèle
  complet, une composante ajustée sans chaque groupe. Q2 d'une composante : 1 - PRESS / SS des
  résidus avant elle ; Q2(cum) : 1 - le produit des (1 - Q2) des composantes, chacun compté
  pour -0,1 au plus bas. C'est la validation des fichiers .usp : elle redonne leurs Q2, leurs Q2
  par variable et les intervalles de confiance de leurs coefficients. Le Y prédit en
  validation croisée (RMSEcv, CV-ANOVA, classement) vient de sous-modèles ajustés sans chaque
  groupe sur les matrices du modèle complet. Plus optimiste, surtout avec peu d'observations ou
  des groupes par site : le centre de Y et les composantes précédentes connaissent déjà le
  groupe caché (sur du bruit pur, 6 observations et 20 variables, elle donnait Q2 = 0,98 pour
  une OPLS-DA ; les deux autres, moins de 0). Une OPLS a ses sous-modèles ajustés sur les
  matrices du modèle complet.
Les deux premières : PRESS, la somme des carrés des erreurs de prédiction ; Q2(cum) = 1 - PRESS
/ SS (SS : la variation de Y, ou de X pour une ACP) ; le Q2 d'une composante, 1 - PRESS / PRESS
de la précédente. ACP : chaque valeur est prédite par les scores de son observation calculés
sans les variables de son groupe de variables (réparties elles aussi en G groupes). Le RMSEcv,
la CV-ANOVA, le classement en validation croisée, les intervalles de confiance (jack-knife,
sur les G sous-modèles), le test de permutation et l'ajustement automatique suivent la
validation choisie.
Gain sur le modèle vide (les deux premières, PLS et OPLS) : le Résumé donne aussi le Q2 du
modèle vide, où chaque groupe caché est prédit par la moyenne de Y des autres observations, et
le gain du modèle sur lui, (Q2(cum) - Q2 du modèle vide) / (1 - Q2 du modèle vide) = 1 - PRESS
/ PRESS du modèle vide : la part de l'erreur de prédiction du modèle vide que le modèle évite.
Avec des groupes qui diffèrent (sites, départements), le Q2 du modèle vide est sous 0, et celui
d'un modèle qui prédit un peu mieux que lui aussi : le gain dit de combien il fait mieux. 0 :
pas mieux que la moyenne des autres groupes. Avec les centres et poids du modèle complet, le
modèle vide prédit la moyenne de toutes les observations, groupe caché compris (son Q2 vaut
0) : pas de gain. Aussi dans le texte des Méthodes, le rapport du modèle et l'export vers R.
Modèle hiérarchique (une PLS dont des X sont les scores d'autres modèles du projet,
$M1.t1...) : son Q2 prend ces scores tels quels, alors qu'ils ont été calculés avec le Y du
groupe caché. Son Résumé donne aussi un Q2(cum) honnête : à chaque tour, ses modèles de base
sont refaits sans le groupe caché (le site entier quand les groupes sont par site), puis leurs
scores, avec la validation du modèle (centres recalculés quand elle est celle du modèle
complet) ; un modèle de base qui n'a plus de variation sans ce groupe donne des scores nuls.
Le Q2 honnête a lui aussi son gain sur le modèle vide.

Validation (PLS et PLS-DA)
--------------------------
Test de permutation : les valeurs du Y (d'une PLS-DA : les classes) sont mélangées entre les
observations 20 fois (ou plus) et tout le modèle est réajusté, validation croisée comprise ;
les ordonnées à l'origine de R2 et Q2 mesurent le surajustement (modèle valide si Q2 < 0,05 et
R2 < 0,3 à 0,4, règle usuelle).
CV-ANOVA : p du modèle (résidus de validation croisée contre la moyenne) ; aussi dans le Résumé.
Classification (PLS-DA) : table des observations bien et mal classées, avec les valeurs
ajustées ou en validation croisée, et courbes ROC avec leur aire (AUC).

Jeu de test
-----------
Nouveau modèle › Observations › Jeu de test : des observations laissées hors du modèle et de la
validation croisée, puis prédites par lui, pour juger ses prédictions sur des données qu'il n'a
pas vues. Colonne « Test » : à la main ; « Sélection en test » : la sélection du modèle actif ;
« Choisir » : une part des observations (25 % par défaut), au hasard ou par Kennard–Stone (qui
garde pour le modèle les observations les plus éloignées les unes des autres, pour qu'il couvre
toute l'étendue des données, et laisse les autres en test) ; par classe pour une PLS-DA, pour
que chaque classe soit dans les deux. Après l'ajustement, le Résumé donne, pour chaque Y :
  RMSEP    racine de la moyenne des carrés des erreurs de prédiction (prédit - observé) ;
  biais    moyenne de ces erreurs ; SEP leur écart-type ;
  Q2ext    1 - somme (observé - prédit)² / somme (observé - moyenne du modèle)² ;
pour une PLS-DA, la part du jeu de test bien classée ; pour tous, le nombre d'observations du
test hors du domaine du modèle. Observé / prédit les montre en losanges rouges. Le jeu de test
est enregistré avec le modèle, repris par Exporter vers R et par le texte des méthodes.

Observations choisies par une condition
---------------------------------------
Nouveau modèle › Observations › « Garder seulement les observations où… » : une condition écrite
en R comme une formule de Nouvelle variable, sur les variables et les identifiants des
observations par leur nom (un nom avec des espaces entre `accents graves`), par exemple
site == "S1" & annee >= 2010, !is.na(densite), habitat %in% c("marais", "prairie") ou
annee != 2015. Sous le champ, combien des observations cochées la remplissent (« 312
observations sur 480 »), ou pourquoi elle ne se lit pas : un nom inconnu, une fonction qui n'est
pas permise, un résultat qui n'est pas TRUE ou FALSE (ou 1 et 0) pour chaque observation. Elle
est évaluée sur toutes les observations du projet, comme une formule de Nouvelle variable :
densite > median(densite, na.rm = TRUE) compare à la médiane de toutes les observations, pas à
celle des cochées. Le modèle prend les observations cochées où elle est vraie ; un résultat
manquant (densite > 5 pour une observation sans densité) compte pour faux.
La condition est enregistrée avec le modèle et refaite sur les données du projet à chaque
ajustement ou réajustement : à la réouverture du projet, à l'ajustement automatique, en ajoutant
ou en retirant une composante, Exclure la sélection et réajuster, Réajuster avec les variables
VIP, Ajuster ce modèle de la sélection par AIC, Ajuster avec CAR1. Après un changement des
données, un réajustement peut prendre d'autres observations. Les cases cochées ne changent pas :
vider la condition rend les observations qu'elle écartait. Le jeu de test garde ses propres
cases : la condition ne s'y applique pas. Les observations qu'elle écarte sont hors du modèle,
comme des décochées : Prédire les observations les prédit. Un modèle importé d'un fichier .usp
garde les observations de son fichier ; Modifier le modèle en fait un nouveau modèle, qui peut
prendre une condition. Deux modèles aux observations différentes ne sont jamais comparés par
leur AIC.
Le texte des méthodes dit « les 312 observations où site == "S1" & annee >= 2010 », le résumé
et le rapport du modèle donnent la condition, et Exporter vers R l'écrit en R avec les noms des
variables du script : les lignes cochées, la condition évaluée sur toutes les lignes du tableau
par with(), puis les lignes cochées où elle est vraie, exactement celles de Nuée (une fonction
de Nouvelle variable qu'elle appelle est écrite dans le script).
Permis dans une condition : les comparaisons, &, |, !, xor(), %in%, :, les calculs
(+ - * / ^ %% %/%), c(), is.na(), ifelse(), abs(), sqrt(), exp(), log(), log10(), log2(),
log1p(), round(), floor(), ceiling(), trunc(), signif(), as.numeric(), as.character(), nchar(),
substr(), substring(), startsWith(), endsWith(), tolower(), toupper(), trimws(), paste(),
paste0(), mean(), median(), min(), max(), sum(), quantile(), pmin(), pmax(), interaction(), et
les fonctions de Nouvelle variable moyenne_groupe(), ecart_groupe(), precedent(), suivant() et
croissance() (et leurs noms anglais). Rien d'autre : une condition est gardée dans le fichier du
projet et refaite à chaque ajustement, un projet reçu ne peut donc rien exécuter d'autre par
elle (une formule de Nouvelle variable, tapée et calculée une fois, n'est pas gardée et n'a pas
cette limite). Pour que cet ajustement reste rapide et borné, « : » ne va qu'entre deux nombres
entiers (annee %in% 2005:2010) et sur une plage d'au plus 100000 valeurs, et interaction() laisse
de côté les combinaisons vides : une condition courte ne peut pas construire un vecteur énorme qui
figerait un ajustement. Pour un indice de diversité (shannon()...), en faire d'abord une Nouvelle
variable, puis employer cette variable dans la condition.

Fenêtres
--------
Au centre, un onglet par modèle (« M1 · PLS »), et un onglet pour chaque vue du projet
(Données, Statistiques des variables, Historique). L'onglet d'un modèle est sa page : son
résumé à gauche, ses scores et ses loadings à droite ; ses autres vues (VIP, DModX...)
s'y ajoutent en onglets. Choisir un modèle dans l'explorateur affiche sa page ; fermer la
dernière vue d'une page ferme la page.
Dans une page comme au centre, les vues se déplacent par leur onglet (glisser-déposer),
se divisent et s'empilent ; glisser l'onglet d'un modèle à côté d'un autre permet de
comparer deux modèles. Clic droit sur un onglet, ou l'icône en haut à droite d'un groupe :
détacher dans sa propre fenêtre (par exemple sur un second écran), agrandir, fermer.
Fenêtre › Nouvelle fenêtre ouvre une deuxième fenêtre complète. Une sélection d'observations (cadre ou lasso dans un
graphique, clic sur un point ou une ligne de liste) apparaît dans toutes les vues et toutes
les fenêtres du même modèle.
Graphiques : molette pour zoomer ; clic droit pour copier l'image ou l'enregistrer (PNG, SVG),
voir les contributions de la sélection ou en faire une classe.
Ctrl+C dans une vue qui montre un tableau (résumé, listes, statistiques...) copie le tableau en
texte séparé par des tabulations, à coller dans Excel (une liste : toutes ses lignes, en pleine
précision) ; avec du texte sélectionné, Ctrl+C copie le texte comme d'habitude.
Affichage › Rechercher une commande (Ctrl+K) : taper une partie du nom d'une commande ou de son
menu (« vip », « exporter r »), puis Entrée.
Aide › Informations de diagnostic : les versions de Nuée, du système, de R et de ses paquets, à
coller dans un signalement de problème (github.com/4rtefakt/nuee/issues ; ni chemins ni
données).

Ce qui est identique aux valeurs enregistrées (vérifié sur 944 modèles de 133 projets .usp)
-------------------------------------------------------------------------------------------
Mise à l'échelle, R2X, R2Y, scores, loadings, valeurs propres, T2 et sa limite, DModX
(normal et pondéré) et DCrit, VIP, coefficients, RMSEE.

Ce qui diffère
--------------
- Q2 (et ce qui vient de la validation croisée : Q2 par variable, RMSEcv, CV-ANOVA, classement
  en validation croisée, intervalles de confiance) : par défaut, Nuée prédit chaque groupe par
  un modèle ajusté sans lui, ses centres recalculés (voir « Validation croisée ») ; les valeurs
  enregistrées viennent d'une validation faite avec le centrage et la mise à l'échelle de toutes
  les observations. Écart au Q2(cum) enregistré, en médiane, sur le corpus d'essai : 0,003 pour
  les PLS de plus de 200 observations, 0,01 de 50 à 200, 0,10 de 20 à 50, 0,22 en dessous, le
  Q2 de Nuée étant presque toujours plus bas ; 0,04 pour les ACP. Avec des groupes par
  identifiant (un site, un secteur), l'écart est plus grand : le modèle ajusté sans un site ne
  connaît pas non plus le niveau moyen de ce site. Validé avec « Centres et poids du modèle
  complet (comme SIMCA) », le Q2 enregistré revient exactement, groupes par identifiant
  compris : 773 PLS sur 809 du corpus d'essai (220 sur 220 sans données manquantes), 441 sur
  443 de quatre projets réels (moteur/tests/verifier_references.R), où les deux autres ont un
  tour sans aucune variation, dont la valeur enregistrée vient d'erreurs d'arrondi. Pour une
  ACP, il s'en écarte de 0,02 en médiane : le détail de la validation des fichiers n'est pas
  publié.

- Signe des composantes de nouveaux modèles : arbitraire (les modèles importés sont
  orientés comme dans le fichier).
- Dendrogrammes : méthode de Ward exacte ; les fusions du haut de l'arbre peuvent
  différer de celles de l'arbre enregistré.
- Ajustement automatique : les règles publiées, appliquées au Q2 de Nuée, peuvent choisir un
  autre nombre de composantes ; pour les ACP, la limite exacte utilisée dans les fichiers
  n'est pas publiée.
- Seuil VIP (marche autour de 0,8) : méthode propre à l'application.
- Intervalles de confiance des VIP d'un modèle à deux composantes ou plus (les VIP elles-mêmes
  sont les mêmes) : ceux du logiciel qui a écrit le fichier pondèrent les composantes de chaque
  tour de la validation croisée d'une façon qui n'est pas publiée ; à une composante, ce sont
  les mêmes.
- OPLS / OPLS-DA : pas de modèle enregistré pour comparer (voir plus haut).
- Transformation proposée : la règle publiée ne dit pas s'il faut l'asymétrie et Min/Max à
  la fois ; l'application les exige tous les deux.

-------

  validation_croisee.R   validation croisée (trois façons), Q2
  hierarchique.R         modèles hiérarchiques : Q2 honnête (modèles de base refaits)
  regression.R           modèles de régression (lm, nlme, mgcv), AIC, apport des blocs
  statistiques.R         T2, DModX, VIP, coefficients, intervalles, limites
  validation.R           permutations, CV-ANOVA, classement PLS-DA et courbes ROC
  opls.R                 OPLS et OPLS-DA
  diagnostic.R           contributions, vérification des données, statistiques des variables
  variables.R            scores en variables, classes, valeurs modifiées, variables calculées
  projet.R               lecture des projets, historique du fichier
  verification.R         comparaison avec les résultats enregistrés dans les fichiers .usp
  script.R               export d'un modèle en script ou rapport R autonome
  methodes.R             texte des méthodes et références
  comparaisons.R         tests statistiques
  modeles_classe.R       modèles de classe (une ACP par classe), graphique de Coomans

  jeu_test.R             jeu de test : prédiction, RMSEP, Q2 externe, Kennard–Stone
  condition.R            les observations d'un modèle choisies par une condition

  modele.R, prediction.R, classification.R (HCA), nouveau.R (tableaux, autoajustement)
Dans R : source("resources/moteur/charger.R"), puis par exemple
  p <- importer_tableau("mes_donnees.csv")
  d <- definir_modele(p, "PLS", x = 3:20, y = 2)
  m <- ajuster(p, d)
  m$statistiques$composantes
