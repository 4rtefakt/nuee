# Changes

What changed in each version: the same list as *Help › What's new* in the application
(in French: *Aide › Quoi de neuf*). Downloads: [Releases](https://github.com/4rtefakt/nuee/releases).

## 1.1.0 — 2026-11-16

- Living reports: next year’s data, and the whole project follows (Edit › Update the data…). Nuée reads the project’s data file again, or next year’s, its columns in another order or with new ones, and replays on it every change made to the data in Nuée. Its rows find their observations by their identifiers and its columns their variables by their names, so that each model keeps its definition; a new category goes just before the last one, so each regression keeps its reference category. Before anything changes, a preview says what will: the new observations, variables and categories, those that leave, the cells changed, a step that no longer applies and why, a model that can no longer be fitted. Then every model is fitted again, What changed compares their results before and after, and each value a document cites that changed is marked, old → new. One Ctrl+Z undoes the update and fits the models again on the data as they were. When the data file changes after it was read (a year added to it), the status bar says so.
- Data steps (Edit › Data steps…): a project made from a file keeps that file, its source (found again when the folder moves with its data), and every change made to its data in Nuée as a step, written with the variables’ names and the observations’ identifiers so that it replays on another file: a value edited, Find and replace, categories, a New variable, columns from another table, raster values, pasted cells, units, coordinates, a class from a selection, scores as variables. Remove shows first what removing a step would do, then replays the others on the source, as an update.
- What changed: two states of a project compared model by model on their key results — the fit (R², Q², AIC), each coefficient with its interval and p value, random effects, components and VIPs, indices and a trend’s class… The notable changes come first, in sentences written like the Results text (the coefficient of year goes from −0.021 to −0.026, still significant), then the table of the results that changed, marking a change of sign, the 5% threshold crossed, a value outside the former interval. After an update of the data, between a version and the project, and when a colleague’s version comes in.
- History (File › History…, or the clock in the status bar): Nuée keeps versions of each project by itself, in a hidden folder next to it, .nuee-versions — when it is saved (one an hour at most), when it is closed, before its data are updated —, each saying what changed (rows, variables, models, documents). On each version: Open (read-only, beside the project), Compare (with the project now), Name… (“submitted to the journal”), Restore… (the current state stays in the history). Nothing to install, and nothing leaves the computer unless the project is shared. Automatic versions are thinned out with time (one a day after 30 days, one a month after a year); named ones stay. Deleting the hidden folder deletes the history.
- Share a project on GitHub or GitLab (File › Share on GitHub or GitLab…): sign in with a short code typed on the site’s page — GitHub, GitLab or your institution’s GitLab —, and Nuée makes the project a private repository on your account; then Invite a colleague, by their user name. Your versions and theirs are exchanged in the background: when a project opens, when Nuée comes back to the front, after each version; an open project without unsaved changes updates itself and says what changed. Your colleague opens it with File › Open from GitHub or GitLab…, its versions with it. An existing repository works too, and any other server with a token; sign-ins and tokens are kept in the computer’s keychain.
- Working together: when you and a colleague both changed the project, Nuée merges the two by what changed, not line by line: models by name, setting by setting; documents passage by passage; figures; the data by their steps, replayed from the source, or cell by cell. With nothing clashing, the dialog lists what each side brought, then Merge both; otherwise each clash (a cell, a passage or a setting changed two ways) shows both sides, with Keep mine or Take theirs. The same on a shared network folder: when someone saves the project you have open, Nuée offers to merge their changes into yours, and Save offers it too rather than overwriting them.
- Which analysis? reads the data better: whole numbers with a unit (g, cm, %…) or a measurement’s name (a mean, a biomass…) are no longer taken for counts, a positive, skewed measurement gets the linear model first (its residuals tell after the fit, and gamma or the log are offered), and the groups compared are never the response itself.
- Faster, with identical results: boosted trees twice as fast (2,000 rows: from 70 to 32 seconds), distance sampling with covariates 1.5 times as fast (hazard-rate key), projects of spectra models about 12% faster to open and refit, TRIM’s stepwise changepoints a fifth to a quarter faster.
- Accessibility: Nuée works from the keyboard alone — the menu bar from Alt or F10, F6 from area to area, Ctrl+Tab from tab to tab, the explorer as a tree, every table as a grid, Shift+F10 for the menu of what has the keyboard — and with a screen reader, which names every field, button and view, and each plot by what it shows (Ctrl+C copies its numbers). Both themes meet WCAG AA contrast, a focus ring shows where the keyboard is, significance and selection are no longer shown by colour alone, and the system’s “reduce motion” setting is followed. The default plot colours stay apart for colour-vision deficiencies: five of them (red, green, orange, purple, pink) moved slightly.
- Clear answers to odd data: Nuée now says in words what was an R error or a meaningless number — a response that doesn’t vary, a model left without observations, too few observations for a regression (and how many it needs), a constant variable in a test, a PLS-DA of a single class, values too large or too small for R —, and Model conditions warns when the X separate the presences from the absences. Inf and NaN in a file become missing values, as the status bar says; texts no longer write NA, Inf or a hundred digits.
- Three new tutorials on the documentation website, from the question to the paper: the ground beetles of woodland, hedgerows and fields (rarefaction, NMDS, PERMANOVA, indicator species), the hay meadows of a mountain plateau on a map (Lambert-93, the elevation read from a raster, Moran’s I of the residuals, a GAM’s spatial smooth, a GeoPackage for QGIS), and their study written up as a report (values that follow the models, citations, a figure, Word, PDF and Quarto).
- Fixed: in a table of 100,000 rows or more, observations 100,000, 200,000… were read as missing: models left them out without saying so, and the Data view showed them empty.
- Fixed: the menus acted on the project last chosen in the explorer rather than on the one in front: with another project’s data in front, Ctrl+S saved the other project, and New document went into it. They now act on the project whose view is in front, or on the one just chosen in the explorer, and a table just opened comes to the front in its Data view.
- Fixed: a click beside a dialog with fields to fill in (New model, Export to R, New document…) closed it, and what was set was lost: it now stays until Esc or one of its buttons. Compare models no longer stacks two projects’ M2 into one bar; Ctrl+C on a table under a plot copies it at full precision; a saved project goes into Open recent; What’s new no longer opens on a first start; the map no longer proposes the table’s first two variables as coordinates.
- Fixed: an RDA or a CCA whose X are all qualitative failed; Rarefaction broke when its species columns were undone, and now computes as soon as it opens; a Mantel test on the geographic distance called it Euclidean; in English, the result columns of several analyses and of predictions kept French names; One model per response, the map and spatial autocorrelation follow a change of language. The map writes projected coordinates in whole metres, with the system in the axis titles, and NMDS and RDA draw the species in grey.
- Fixed in documents and Export to R: a document cites tables and plots in its own language, words and numbers, whatever the interface’s; the references of a Methods text it cites join its list of references, once (Wood 2017 no longer twice); Quarto compiles a document whose name has an apostrophe, # or %, or whose title has an @; a GAM’s Methods sentence reads correctly. After Edit › Categories gave a variable a new order, or renamed a class, Export to R and reproducible documents wrote a script that no longer gave the model’s results (LDA, trees, forests, ordinations, PERMANOVA, indicator species, TRIM, distance sampling): the script is now written on the data as the model saw them. A regression’s script also redraws the Effects view, GAM curves included.
- Fixed in the desktop app: closing the first window while a second one was open (Window › New window) closed both and quit Nuée without asking about unsaved projects; recovery copies stopped once the first window was closed; text typed in a document just before quitting could be lost; a file double-clicked while Nuée was starting, or given by its name alone on a command line, didn’t open; choosing Update twice broke the download; a second start of Nuée no longer starts R for nothing; R’s temporary folders stayed behind on Windows.

## 1.0.0 — 2026-11-15

- Nuée on macOS: Nuée.app, with its own R, in a .dmg for Apple silicon Macs (macOS 14 or later) and Intel Macs (macOS 13 or later), on the Releases page. An R already on the Mac is neither used nor changed. Every engine check also runs on both kinds of Mac, with the same results as on Windows and Linux.
- Maps and spatial data: a project has coordinates, two of its variables and their system (WGS 84 longitudes and latitudes, Lambert-93, CC zones, Lambert II étendu, UTM, LAEA Europe…), proposed from their names and saved with it. Plots › Map places the observations at equal scales, coloured and sized by a variable or by a column of a model’s results (scores, residuals, clusters), the selection shared with the models. A background map if you choose one, OpenStreetMap, IGN’s map or its aerial photographs, only on request: without one, nothing leaves the computer. The conversions are written in Nuée and give PROJ’s, the library QGIS uses, to the micrometre.
- GeoPackage, QGIS’s format: File › Open reads one of its layers (points, or the centres of lines and polygons) with the project’s coordinates; the data and a model’s results export as a point layer that QGIS opens with its coordinate system.
- Raster values at each site (Edit › Add raster values…, or from the map): a DEM’s elevation, land cover or a climate, read from a GeoTIFF (LZW, Deflate, PackBits, LZMA or ZSTD compressed, tiled or in strips, BigTIFF included) or an ESRI ASCII grid at each observation’s position converted to the raster’s system: the cell, a bilinear interpolation, or the mean or majority class within a radius in metres. One variable per band, undoable, whose origin the Methods text gives; only the blocks of the file that hold observations are read. The same values as terra::extract.
- Spatial autocorrelation (Plots › Spatial autocorrelation): Moran’s I of a variable or of a regression’s residuals, by randomisation and by permutations, the linear model’s residual test that accounts for the fit, a neighbourhood of the k nearest neighbours, a distance or the inverse distance; the correlogram and the semivariogram. The same numbers as spdep and gstat. “Mean by place” groups a plot surveyed several years.
- Spatial smooth in a GAM: a surface of the coordinates, a thin plate s(x, y) or a spline on the sphere for longitudes and latitudes, takes up the spatial structure the terms don’t explain (New model › General, or in the R formula). It goes through cross-validation, the AIC selection, predictions and the Methods text, and the map shows its value at each observation. It gives mgcv’s results. Export to R redoes it too.
- Distance-based community analyses (New model): PCoA (Lingoes and Cailliez corrections), NMDS (several starts, the Shepard diagram), PERMANOVA (sequential or marginal terms, permutations within groups) with the multivariate dispersion of each grouping (betadisper and its pairs), and the Mantel test (partial, Pearson or Spearman, and its correlogram). Nine distances (Bray–Curtis, Jaccard, Gower, Hellinger, chord…), on abundances or presences, and transformations (root, Wisconsin…); the explanatory variables fitted onto the ordination as arrows and centroids. The same numbers as vegan, and the same p values for the same permutations; Export to R redoes them with R alone, with the same permutations.
- Canonical correspondence analysis (CCA, and partial CCA): the triplot in scalings 1 to 3, tests by axis, by term and by margin, the adjusted R² and forward selection, the Methods text and Export to R, as vegan::cca.
- Indicator species (IndVal and IndVal.g, Dufrêne and Legendre 1997; De Cáceres and Legendre 2009): for each species, the group or combination of groups it indicates, its A and B components, the permutation test and the p value corrected over the species, as indicspecies::multipatt; Export to R redoes it with R alone.
- Rarefaction and accumulation (Plots › Rarefaction): each sample’s rarefaction curve and its rarefied richness at a common size, the species accumulation curve over the samples (exact), by group if chosen, and the richness estimators (Chao1, ACE; Chao2, first- and second-order jackknife, bootstrap), as vegan.
- TRIM, the trends and indices of monitoring counts (New model › TRIM), written from Statistics Netherlands’ method: time-effects models, linear trends with changepoints (chosen or stepwise) or no time effect, overdispersion and serial correlation estimated by GEE, missing counts imputed, covariates and weights. Indices on a base year and yearly totals with their standard errors, the overall slope and its class (strong increase, moderate increase, stable, uncertain, moderate decline, steep decline), Wald tests. The same numbers as rtrim, and Export to R redoes it with R alone.
- Distance sampling (New model › Distance sampling): animal density and abundance from line transects or point counts, as the Distance package computes them (ds() and dht2()). Half-normal, hazard-rate or uniform detection functions, with cosine, Hermite or polynomial adjustment terms chosen by AIC under monotonicity constraints; covariates of detection (as ds(formula = ~ …): the detection function’s scale by quantitative or qualitative variables, group size included, each animal’s probability of detection, dht2’s Horvitz–Thompson density, the average detection function and that of each category, and the AICs with and without covariates); right truncation (a distance or a percentage) and left truncation; exact or binned distances; groups; strata with their areas. The encounter rate’s variance (R2, P2) and the detection’s (delta method), log-normal intervals with Satterthwaite degrees of freedom (without stratum areas, the total’s with the strata’s weights, as its group size variance, where dht2 leaves these weights out and gives fewer degrees of freedom and, with groups, a larger standard error, hence a wider interval); goodness of fit (Cramér–von Mises, chi-square), the QQ plot and the detection function over the histogram of distances. Otherwise the same numbers as Distance, and Export to R redoes it with R alone.
- One model per response (Model › One model per response): the same regression fitted to each species ticked, each term’s p values corrected over the species (Benjamini–Hochberg, Holm or Bonferroni); the chosen term as a forest plot of coefficients, its effect in small multiples side by side, each model’s quality.
- Two more distributions for GLMs and GAMs: the zero-inflated Poisson (mgcv::ziP), for counts with more zeros than a Poisson gives, and the beta (mgcv::betar), for proportions between 0 and 1 (a cover, a share of time). With random effects, curves, the spatial smooth, cross-validation, the AIC selection, adjusted means (expected counts and their ratios; proportions and odds ratios), quantile residuals and Export to R. The same results as mgcv.
- Random forests and boosted trees (New model): a random forest (ranger), for a measurement or a class, with its out-of-bag error, the cross-validation by groups, permutation or impurity importance, each variable’s partial dependence, the error against the number of trees and each class’s votes with their ROC curves; boosted regression trees (BRT), as gbm computes them and as Elith et al. (2008) present them for ecologists, for a measurement, a presence-absence or counts, the number of trees chosen by cross-validation, with each variable’s relative influence. Test set and predictions for both; the same numbers as ranger and gbm. Export to R redoes them: boosted trees with R alone (and rpart), the forest with ranger, which Nuée installs with itself.
- Results text: {{M1.resultats}} in a document, and under the Methods text, says in sentences what the model shows, with its numbers: the fit, each coefficient with its interval and p value (a factor or an odds ratio for a log or logit link), the significant terms, curves and random effects; for a PCA, PLS or OPLS, the variance explained, Q², CV-ANOVA and the most important variables.
- Compose a figure (Plots › Compose a figure…, or right-click a plot › Add to a figure): plots side by side for a journal, as A, B, C panels in a grid (a panel can take two cells), one, one and a half or two columns wide (85 to 190 mm), text in points and line widths for print. Exported as vector PDF (in the desktop app, at the figure’s exact size), SVG, and PNG or TIFF at 300 or 600 dpi, their resolution written in the file. A map on a background has its points as vectors there, over its tiles fetched again at the export’s resolution, with their attribution. Figures are kept in the project and follow refitted models.
- Reproducible document (Quarto): a document exports as a reproducible .qmd, next to a folder with the Export to R script of each model it cites and its data; Quarto runs them again, and every number cited (Q², coefficients and their intervals…), plot and table is recomputed from the raw data. Before writing the .qmd, Nuée checks that each expression gives back exactly its text; what can’t be recomputed (the Methods text, a model without a script) stays written in, and the document says so.
- Zotero group libraries: Cite › Insert a citation offers My Library and each group library Zotero syncs, each with its collections; the library chosen is kept, and typing @ searches it. Better BibTeX’s picker picks in all of them. A key is only unique within its library: a reference whose key the document already gives to another work (the same key in My Library and in a group) is cited with a letter added, @bechet2019a, and the status bar says so; the same item, or the same work copied into a group, keeps its key. The document keeps which library each reference from Zotero came from. When Zotero doesn’t give its groups, the dialog says why and offers My Library alone.
- The model’s conditions, in a regression’s Summary: in words, with what to do, the residuals’ distribution, a spread that changes with the fitted values, influential observations, overdispersion and excess zeros in counts, collinear terms, confounded curves and the residuals’ spatial autocorrelation.
- Which analysis? (Model › Which analysis?, or the start page’s button): your question in plain words (compare groups, the effect of variables on a response, many species, a trend, where, explore, predict, diversity, a BACI design), the response and the design, proposed from the project’s variables (whole numbers, zeros, proportions, sites, years); then the recommended analysis, why and its conditions, the alternatives, and a button that opens New model already filled in (the type, the distribution, the roles, the random effect, the cross-validation groups) or the right view.
- Data workbench: Find and replace (Edit, Ctrl+H, and in the Data view) in one, several or all variables — the whole cell or part of it, case-sensitive or not, empty cells —, with a preview of what will change; a text variable whose values all become numbers turns quantitative. A qualitative variable’s categories renamed, merged, reordered, and the regressions’ reference category chosen. A unit and a description for each variable, in the column headers, axis titles, the Methods and Results texts, Export to R and exported files (a “Variables” sheet in Excel, a table in a GeoPackage). In the Data view, each column’s empty cells and distinct values, and a block of cells pasted from a spreadsheet. Ctrl+Z undoes each change.
- Import from KoboToolbox and ODK (File › Import from KoboToolbox or ODK…, or by opening an export): a forms export (a KoboToolbox workbook or CSV, an ODK Central zip) is recognised. Metadata columns are dropped (as chosen) and group prefixes removed; a single choice becomes a qualitative variable and a multiple choice 0/1 columns, a GPS point longitudes and latitudes that become the project’s coordinates, dates become times; a repeat group opens with its parents’ columns. The XLSForm, if given, brings the labels in the chosen language and the choices’ order. “Open as is” keeps the raw table. Checked on real exports of KoboToolbox and ODK Central, in all their settings.
- Problem report (Help › Diagnostic information): a .zip file to attach to a message, with that information and the session’s journal, and the project if ticked. Nothing is sent. A saved project also records the versions of the R packages that computed its models.
- Faster on large tables and spectra: on 2,000 spectra of 2,000 wavelengths, a PCA with automatic components goes from 26 to 2.5 minutes and a PLS from 30 to 4 seconds; a PLS’s 100-permutation test on 500 spectra, from 7.5 minutes to 32 seconds. Views send only what they draw (the Data view its shown columns; tables in slices), plots of more than 5,000 points switch to WebGL, and a 10-model project saves and reopens nearly three times faster. The results are identical.
- English by default: a new installation starts in English (View › Language to change it). An installation that ran an earlier version without choosing a language keeps French. The example project (Help › Example project) is in English, the same apples in French for the French interface. In R, load.R loads the engine in English, with English names (import_table(), define_model(), fit_model(); in the console, engine_folder(), reload_engine(), check_engine()); charger.R loads it in French, as before: scripts written for it give the same results, words included.
- In French, the interface’s numbers now have a decimal comma, like its texts: the views’ tables and summaries, their notes, hover texts and plot axes (0,959; CV 9,7 %), the report. A copied table has the same comma, at full precision, for a spreadsheet in French; Nuée reads either back. A number field takes 0,5 as well as 0.5, even on a system in English.
- .usp projects: each model of a file is fitted as the software that wrote it fits it, and gives back its results where they differed, all with missing values. NIPALS sometimes converges very slowly there, doesn’t converge or has several solutions: it now stops as that software does (a relative change of 10⁻⁵, 200 iterations at most), starts from the same column, validates each component starting from the full model, and treats observations without any X value and, in version 10 files, a term without any value as it does. On the 2003 projects, the 519 models compared match their file (513 before), coefficients and VIP included; on the test corpus, the fit and Q² of 805 PLS models out of 809 (771 before), the scores and loadings of 107 PCA models out of 111 (74 before). Nuée’s own models don’t change, and Export to R does the same.
- Fixed: a GLM or GAM with a single random effect and no curve lost that effect’s variance: the Summary left it empty, with a standard deviation of 0, and Export to R did the same.
- Fixed: Predict › Predict a file failed for a model whose spectral preprocessing has a Savitzky–Golay step (“the window exceeds the spectrum”): each wavelength of the file made a zone of its own.
- Fixed: in English, the columns of a model’s results (the observation list, the predictions, the map’s colours and sizes) kept their French names (observé, ajusté, résidu…), and so did the tables of exported results, their names and their columns’ (Excel sheets, files, GeoPackage layers).
- Fixed: adjusted means and the power to detect a trend, kept with their model, were only kept until the project was closed. They are now saved with it and come back when it is opened, the power’s simulation included: in their views, the Methods text, the report and Export to R.
- Fixed: each update removed Nuée from the taskbar when it was pinned there, and remade its Start menu and desktop shortcuts. Updates now keep them, the one to this version included.
- Fixed: in a small pane, a plot’s title ran into its vertical axis title, longer than the plot area: titles now start at that area’s left edge.

## 0.9.9 — 2026-11-14

- Documents: a project keeps documents (an article, a report, notes), written in Markdown beside their preview, drawn again as you type (File › New document). The project’s results are cited in them between double braces and take their values: {{M1.Q2}}, {{M1.R2Y:%}}, {{M1.vip.sugar}}, {{M5.coef.year}} (estimate, interval and p), a plot as it is in its window with its caption ({{M1.scores | Scores of the sites}}), a table of the model report ({{M1.table.resume}}) or the Methods text ({{M1.methodes}}). Type {{ to see the models, then what each offers with its value; the Insert button and the explorer (right-click) do the same. Numbers are written in the document’s language (0.65 or 0,65), plots and tables are numbered, and {{ref:label}} gives their number; a reference that can’t be resolved is in red, with the reason, and a model not computed yet is computed when the document cites it. Start from a blank document, an article (introduction, methods, results, discussion) or an analysis report, the models ticked already cited. Compile: Word, PDF, HTML, or a Quarto file (.qmd) with its plots, which Quarto compiles when it is installed (bibliography, cross-references, journal templates). The document is saved with the project, and Undo leaves it alone. The spell checker, in French and English, offers its corrections on right-click, in documents and in every field.
- Citations in documents, as in Quarto: [@wold2001], [see @wold2001, p. 33; @eriksson2006], @wold2001 in the sentence, [-@wold2001] without the author; the list of references comes at the end, or where the document puts {{bibliographie}}, author–year or numbered, in the document’s language. References come from BibTeX or CSL-JSON files (exported from Zotero, Mendeley, JabRef…; Cite › Link a file names them in the header, and Better BibTeX’s automatic export keeps them up to date), from Zotero open on the computer (Zotero 7: typing @, or Cite › Insert a citation, in the whole library or a collection; with Better BibTeX, its own picker, page included), or from pasted BibTeX. The document keeps a copy of what it cites: sent without the .bib, it still cites it. Compiled for Quarto, it keeps its citations, the references in a .bib beside it, for a journal’s CSL style (the PDF too), each with its language. Each document opens in a tab of its own, and plots in documents and model reports are drawn light, even in the dark theme.
- Gain over the empty model: when the centres are recomputed without the held-out group (the default validation, and “Centres and weights recomputed”), the Summary of a PLS or OPLS gives the Q² of the empty model, where each held-out group is predicted by the mean of Y over the other observations, and the model’s gain over it, (Q² − Q² empty) / (1 − Q² empty): the share of the empty model’s prediction error that the model avoids. With groups that differ (sites, departments), the empty model’s Q² is below 0, and a negative Q² can hide a model that does better than it: the gain says so. A hierarchical model’s honest Q² has its own. In the Methods text, the model report and Export to R.
- Fixed: with missing values in X, the coefficients of a PLS or OPLS (scaled and in the units of the data, with the constant), the w* weights and their confidence intervals were wrong, by a few percent as a rule: W* was computed as W (P′W)⁻¹, which no longer gives back the scores of complete observations when values are missing. It now is, component after component, as in .usp files: on a real project of 35 models with missing values, the coefficients and their intervals are those of the software that wrote the file (difference < 10⁻⁶), against differences up to 0.044 before. The “file” values the explorer shows for these coefficients had the same error: converting the project again fixes them. R², Q², VIP, scores and predictions don’t change, and nothing changes without missing values.

## 0.9.8 — 2026-11-13

- A choice of cross-validation (New model › Cross-validation), for a PCA, PLS or OPLS, and a new default, for every model: “Centres recomputed, full model’s weights”. Each group is predicted by a model fitted without it, its centres recomputed without the group: the model knows nothing of the Y of the group it predicts. Its weights stay the full model’s: the standard deviations of X don’t depend on Y, and nothing is rescaled on fewer observations, so no prediction blows up (Q² down to −8 × 10¹¹ on a real project, when a variable varied at one site only, validated apart). Every model’s Q² therefore changes a little from 0.9.7. “Centres and weights recomputed without the held-out group” is 0.9.7’s validation, stricter. “Full model’s centres and weights (like SIMCA)” validates each component on what the previous ones leave: it is the validation of .usp files, whose Q² it gives back (on four real projects, those of 441 models out of 443, with their Q² per variable and their coefficients’ confidence intervals); more optimistic, it isn’t the default. RMSEcv, CV-ANOVA, the cross-validated classification, the confidence intervals, the permutation test and autofit follow the validation chosen, as does Export to R.
- A guard in “Centres and weights recomputed without the held-out group”: a variable that hardly varies without the held-out group (less than 10 % of its standard deviation) keeps the full model’s weight in that round, instead of a weight, 1 / standard deviation, multiplied as much. The Summary says which variable, without which group, and the share of its standard deviation it kept.
- Honest Q² of hierarchical models: a model whose X include scores of other models of the project ($M1.t1…) has an “Honest Q2(cum)” in its Summary: in each cross-validation round, its base models are refitted without the held-out group, so their scores don’t use that group’s Y. Its Q² takes these scores as they are. The Methods text gives it too.
- The Methods text says how the model was validated, and the model report gives it at the top. R console: verifier_moteur() validates the models like their files and counts Q² in its status.
- Fixed: for a model with a single component, the Summary didn’t mark its values “=” or “≠” against the .usp file’s, and the explorer didn’t give its R2X and Q2.

## 0.9.7 — 2026-11-13

- Qualitative variables in cross terms: a regression (linear, mixed, GLM, GAM) takes cross terms with a qualitative variable, in the Cross terms tab or as a * b in the R formula. year × sector lets the year’s slope change from one sector to another, habitat × treatment a treatment’s effect from one habitat to another. The coefficients are those of lm, nlme and mgcv with the same reference category; without the year’s main effect (sector + year:sector), each coefficient is a sector’s slope. The Effects view draws one line (or curve) per category, with the table of slopes; the AIC selection, the contributions and the nested models take a cross term in or out whole, with its main effects.

- Model › Text for the Methods section: a paragraph written from the model, in French or English, with its references.
- Plots › Tests by variable: each variable compared between two classes (Welch’s or Student’s t, Mann–Whitney) or across all of them (ANOVA, Kruskal–Wallis), with the Benjamini–Hochberg correction and a volcano plot.
- New model › Class models: one PCA per class, and the Coomans plot to tell which class an observation belongs to (or none).
- OPLS with several Y and OPLS-DA with more than two classes (several predictive components).
- Exported files checked in jamovi, PSPP (SPSS), Weka, LibreOffice and pandas: jamovi now opens the .omv files; SAS transport in version 5, which SAS reads; dBase in Windows-1252, missing values left blank.

## 0.7.0 — 2026-11-01

- File › Open also reads R (.rds, .RData), SPSS, Stata, SAS, jamovi, dBase and Weka files, and old Excel workbooks (.xls). For a workbook with several sheets, the application asks which one to open.
- File › Paste a table (Ctrl+V): cells copied from a spreadsheet become a project.
- Export a project’s data and a model’s results to Excel, CSV, R, SPSS, Stata, SAS, jamovi, dBase or Weka.
- Spectra: SNV, MSC and Savitzky–Golay preprocessing (smoothing, derivatives) in New model, and the Profiles (spectra) view.
- Tab-separated text files, Windows-1252 files and Excel’s “Unicode text” now open correctly.
- The installed version mentions a new version at start-up (Help to turn it off).

## 0.6.0 — 2026-11-01

- Help › Example project: made-up data (120 apples) with four models ready to explore, to try Nuée.
- New icon, easier to read at small sizes; the logo on the welcome screen and in About.
- A lighter application (65 MB and a thousand files less): it copies and installs faster.
- Nuée is now free software (GPL-3.0 licence): github.com/4rtefakt/nuee.

## 0.5.0 — 2026-11-01

- The application is now called Nuée. Settings, preferences and recent projects carry over from the previous version.
- Nuée shows in the Start menu and in Settings › Installed apps, where it can be uninstalled.
- A new icon; the desktop shortcut is called “Nuée”.
- Help › Results and known differences: what the engine reproduces exactly from .usp files, and the known differences.

## 0.4.0 — 2026-11-01

- Closing with unsaved changes now offers “Save and close”.
- Automatic recovery copies of unsaved projects: after an unexpected stop, the application offers to recover them.
- If the R engine stops, the application says so and offers to restart it (also in Help › Restart the R engine).
- Edit › Undo (Ctrl+Z): reverse a data change, a new variable, a class…
- Removing a model asks for confirmation; a model made in the application can also leave the project.
- Notes: each model has a notes box in its summary, saved with the project and included in the report.
- R console: verifier_moteur() refits the imported models and compares them with the stored values.
- Settings (theme, language, plot format, console commands) are kept from one launch to the next.
